## 2. 핵심 주장

- **C1** 기존 아키텍처 평가 방법은 에이전트 아키텍처에 그대로 쓸 수 없음. 문헌 고찰 결과 기존 방법이
  자율성(autonomy)과 지속 진화(continuous evolution)를 다루지 못하고 에이전트용 일반 시나리오도 없기
  때문임 [§3 Methodology] [§1 Introduction]
- **C2** AgentArcEval은 ATAM의 원칙과 절차 위에 세워짐 — 특히 품질속성 시나리오 사용과 이해관계자 주도
  분석을 그대로 이어받고, 여기에 에이전트 고유 산출물(artefact)과 가드레일(guardrail)을 평가 과정에
  끼워 넣는 방식으로 확장함 [§4 The AgentArcEval Method]
- **C3** 시나리오 서술 양식은 전통 템플릿 6요소를 그대로 사용함 —
  `Source` · `Stimulus` · `Environment` · `Artefact` · `Response` · `Response measure`.
  요소를 추가하거나 빼지 않았음 [§5 General Scenarios]
- **C4** 품질속성 11개 각각에 대해 일반 시나리오(general scenario) 1건씩, 총 11건의 카탈로그를 제시함.
  편입 기준 2개를 통과한 것만 넣었음 — ① 실제 에이전트 배포에서 발생한 상황일 것 ② 6요소 표준 양식으로
  쓸 수 있어 결과를 객관적으로 검증할 수 있을 것 [§5 General Scenarios]
- **C5** 평가는 설계시점과 런타임 두 갈래로 나뉨. 설계시점에서는 맥락 시나리오를 정의·우선순위화하고,
  런타임에서는 위험을 계속 감시하며 시나리오를 갱신·재우선순위화함. 즉 1회성 심사가 아니라 운영 중에도
  되도는 절차로 설계됨 [§4.4 Steps]

## 6. 집필 시 주의

- 시나리오 개수 대조 결과 — `recommend-materials.md` 부록 A 기재 「시나리오 11종」은 원문과 **일치함**.
  원문 5장이 품질속성 11개에 1건씩 두어 총 11건임을 확인함. 정정 없음
- ATAM 6요소 계승 대조 결과 — 부록 A·B 기재 「ATAM 6칸 양식을 그대로 이어받음」도 원문과 **일치함**.
  다만 철자가 영국식 `Artefact`이고 요약 문자열의 순서가 ATAM 관례와 달리 `Environment`를 `Artefact`보다
  앞에 둠. 교재 표기는 한쪽으로 고정해야 함
- ISO/IEC 25010 어휘와의 관계 — 원문 전문에 `ISO`·`25010` 문자열이 **한 번도 나오지 않음**. 품질속성은 책임
  있는 AI 원칙과 아키텍처 서적에서 도출함. 「ISO 25010을 따른다」고 쓰면 어긋남. 어휘 고정은 9절로 올림
- 수치의 성격 — 4절 Q5 ~ Q8은 측정 결과가 아니라 **사례 프로젝트가 세운 목표값**임. 「Luna가 95% 정확도를
  달성했다」로 쓰면 오독이며, 달성 여부는 원문에 없음. 사례연구도 1건뿐이고 비교군이 없어 「검증된 방법」
  으로 쓰면 안 됨
- (추론) KT 3일 편성에는 양식(칸 구성)만 가져오고 절차는 제외하는 편이 맞음. 근거 — 원문 절차가 이해관계자
  워크숍 · 우선순위화 · 런타임 감시를 포함하는데, 커리큘럼은 팀당 카드 1장 작성 시간이 짧아 들어가지 않음
- ※ 상충: 해당 없음 — 5절 상충 2건(`C4에서 에이전트의 계층` · `역할 분해 방식`)은 본 자료 범위 밖임
- 유효기간 — 저자가 카탈로그의 노후 위험을 인정하고 살아 있는 문서로 갱신하겠다고 밝힘.
  인용은 v1(2025-10-23) 기준으로만 유효함

## 7. 연구 설계와 일반화 한계

- **대상·범위** — 파운데이션 모델 기반 에이전트의 아키텍처 평가. 방법 제안 + 품질속성 11개 일반 시나리오
  카탈로그 + 사례연구 1건으로 구성됨. 모델 성능 평가나 에이전트 벤치마크는 다루지 않음
  [§1 Introduction] [§5 General Scenarios]
- **표본 수** — 카탈로그 도출 기반은 배포된 에이전트 프로젝트 3건과 체계적 문헌 고찰 1회임.
  검증용 사례연구는 1건(Luna 세무 코파일럿, Empathetic AI)이며 맥락 시나리오 7건을 작성함
  [§5 General Scenarios] [§6 Case Study]
- **비교군** — 없음. 기존 평가 방법(ATAM 등)을 같은 대상에 적용해 결과를 견주는 대조 실험은 수행하지
  않았고, 기존 방법의 부적합성은 문헌 고찰의 4개 연구질문으로만 판정함 [§3 Methodology]
- **평가 지표** — 방법 자체의 성능 지표는 없음. 「유용성(usefulness)을 사례연구로 보인다」는 정성적
  서술이며, 정량 평가 지표·통계 검정은 `원문 미표기`임 [§6 Case Study]
- **재현 자료 유무** — 부분적임. 문헌 고찰 프로토콜과 추출 시트를 Google Docs 링크로 제시하나 원문이
  `for review purpose only`로 명시함. 사례연구 대상 시스템은 상용 서비스이며 코드·데이터 공개는
  `원문 미표기`임 [§3 Methodology] [§6 Case Study]
- **저자가 밝힌 한계(limitation)** — 2가지를 스스로 적음. ① 방법과 카탈로그가 제한된 수의 실제
  프로젝트 통찰에 기반함 — 완화책으로 선행 문헌 고찰과 고전 아키텍처 서적·책임 있는 AI 원칙 검토를 들었음
  ② 파운데이션 모델과 에이전트의 빠른 변화로 방법·카탈로그가 낡을 위험이 있음 — 완화책으로 살아 있는
  문서 공개와 커뮤니티 기여를 계획함 [§3 Methodology] [§7 Conclusion]
- **이해상충 관련** — 사례연구 대상 Luna의 소속사 Empathetic AI 인력 2인이 공저자로 참여함. 방법 제안자와
  적용·평가 주체가 겹치므로 독립 평가가 아님 [§저자 소속 표기] [§6 Case Study]

## 8. 확인 범위와 미확인

- 조회일 2026-08-05. 확보 수단은 `curl -sL` 저장 arXiv HTML(186,989바이트) → 태그 제거 텍스트 추출(75,634자).
  서지 페이지도 같은 방식으로 저장해 버전·제출일을 대조함. Playwright MCP는 사용하지 않음
- 판독 대상은 v1이며 최신판도 v1임 — 서지 페이지에 `[v1] Thu, 23 Oct 2025` 1건만 있고 개정 이력이 없음
- 판독한 것 — 초록 · 1 ~ 7장 본문 전 범위 · 일반 시나리오 11건의 6요소 전문 · 사례연구 맥락 시나리오 7건 ·
  저자·소속 표기 · 결론
- 판독하지 못한 것은 본문이 아닌 요소(arXiv 사이트 네비게이션 · 참고문헌 목록 상세 · 로고)뿐이므로
  FULL로 판정함
- 미확인(그림) — 본문 그림 14장(`x1.png` ~ `x14.png`)은 파일 경로와 캡션만 확인했고 이미지 안의 내용은
  판독하지 않음. 그림 2는 절차도, 그림 3 ~ 13은 일반 시나리오 11건, 그림 14는 Luna 컴포넌트 뷰임.
  본문 서술이 각 그림의 내용을 글로 반복하고 있어 서술로 대체 판독함
- 미확인(외부 링크) — 문헌 고찰 프로토콜·추출 시트 Google Docs 2건은 열지 않음(`for review purpose only`
  표기). 동료심사 게재 여부와 후속 비교 연구 발표 여부도 확인하지 않음

## 9. 열린 질문

- 품질속성 어휘를 어느 쪽으로 고정할지 결정 필요. 커리큘럼 4-4절과 `recommend-materials.md` 4-1절은
  ISO/IEC 25010:2023 어휘 고정을 전제하나, 본 논문은 ISO를 참조하지 않고 `contestability`(이의제기성) ·
  `observability`(관측성) 같은 고유 어휘를 씀. 두 어휘를 섞으면 산출물 ① 리뷰가 성립하지 않음
- 카드 칸 수를 9칸 그대로 쓸지, `Priority`를 빼고 8칸으로 줄일지 결정 필요(3일 편성 시간 제약)
- (추론) 품질속성 11개 중 금융 도메인에 맞는 3 ~ 4개만 골라 제시하는 편이 나음.
  근거 — 커리큘럼이 우선 품질 3개 선정을 요구하고, 11개 전체 제시는 선정 실습의 취지를 흐림
- ATAM(2000) 원문을 각주 이상으로 쓸 일이 생기면 별도 확보가 필요함(현재 미확보, 본 정리본은 계보 서술만 함)
