## 2. 핵심 주장

- **C1** 지식그래프를 RAG 저장소로 쓰는 근거는 성능 우위가 아니라 **정형·비정형을 한 DB에 함께 두는 것**임  
  [§1.4 p.14/PDF35]. 비정형만으로는 필터·개수 세기·집계가 불가하다고 명시함 [§1.4 p.15/PDF36].  
  파인튜닝으로 지식 컷오프를 메우는 방안은 사전학습 비용 때문에 비현실적이라고 먼저 기각함  
  [§1.3.1 p.9~10/PDF30~31].
- **C2** 벡터 유사도 검색만으로는 품질이 모자라 전문 검색(full-text search, 낱말 그대로 찾기)을 더한  
  하이브리드로 보완함 [§2.3 p.27/PDF48]. 다만 **하이브리드조차 데이터 복잡도가 커지면 품질·정확도·성능이  
  여전히 제한적**이라고 저자가 직접 한계를 밝힘 [§2.4 p.29/PDF50].
- **C3** 검색 정확도 개선의 1차 수단은 모델 교체가 아니라 **질의 재작성**(step-back prompting)과  
  **임베딩 단위와 반환 단위의 분리**(parent document retriever)임 [§3.1 p.34/PDF55][§3.2 p.36/PDF57].  
  파인튜닝·리랭킹·메타데이터 필터는 존재만 언급하고 구현은 책 범위 밖으로 둠 [§3 p.33~34/PDF54~55].
- **C4** 집계·필터·정렬 질문은 벡터 검색이 **원리적으로** 답할 수 없고 질의어 생성(text2cypher)이 담당함  
  [§4.2 p.47/PDF68]. 정확도 개선 수단은 few-shot 예시 · 프롬프트에 스키마 제공 · 용어 매핑 ·  
  출력 형식 지시 **4가지로 한정**해 제시함 [§4.3 p.47~52/PDF68~73].  
  스키마 표기 형식 자체는 성능에 큰 영향이 없다는 것이 Neo4j 내부 연구 결과라고 밝힘  
  [§4.3.2 p.48/PDF69]. 다만 근거 데이터는 공개하지 않음.
- **C5** 평가는 도구 선택 · 검색 맥락 관련성 · 답변 생성 · 전체(end-to-end) **4개 지점으로 분리**해  
  측정함 [§8 p.116~117/PDF137~138]. 정답(ground truth)을 고정 문자열이 아니라 **Cypher 질의로 정의**해  
  원본 데이터가 바뀌어도 벤치마크가 유효하게 유지함 [§8.1.1 p.119/PDF140].

## 6. 집필 시 주의

- ※ 혼동 금지: text2cypher ≠ NL2SQL — Cypher는 그래프 질의어, SQL은 관계형 질의어  
- ※ 이해상충: 저자 소속·배포 주체가 Neo4j임 — GraphRAG 우위 서술은 벤더 주장으로 취급함  
- ※ 상충: `recommend-materials.md` 5절의 상충 2건(C4 에이전트 계층 · 역할 분해 방식)은 본 도서가  
  다루지 않는 주제여서 해당 없음. 대신 GraphRAG 우열 판단이 4-3절 자료 간 상충 지점임  
- GraphRAG가 벡터 RAG보다 낫다는 취지를 옮길 때는 반대 근거 `GraphRAG-Bench(ICLR 2026)`를 같은  
  자리에 병기함 — "GraphRAG가 일반 RAG보다 못한 경우가 잦다"가 그 자료의 문제 제기임  
- CH7의 커뮤니티 탐지·전역 검색은 **개념 대비용으로만** 인용하고 실습 근거·구현 지시로 쓰지 않음  
- ※ 지면 코드 노후화: OpenAI Structured Outputs 호출 — 도서는 `client.beta.chat.completions.parse`와  
  `gpt-4o-2024-08-06`을 씀 [§6.1.2 p.79/PDF100]. context7 조회(2026-08-05) 결과 현행 공식 예제는  
  `client.chat.completions.parse`(beta 제거)이며 모델 예시도 세대가 다름  
- ※ 지면 코드 노후화: RAGAS 지표 임포트 — 도서는 `ragas.metrics`의 소문자 지표 객체와 `evaluate()`를  
  씀 [§8.2.5 p.124/PDF145]. context7 조회 결과 v0.4에서 `ragas.metrics.collections`로 이관되었고  
  구 API는 v1.0에서 제거 예정임. 스타터 리포지토리는 신 API로 작성함  
- ※ 지면 코드 노후화: 도서는 `neo4j-graphrag-python` 패키지를 쓰지 않고 드라이버 + 직접 Cypher로  
  구현함. KT 실습이 해당 패키지를 쓰면 코드 구조가 도서와 달라지므로 대조표가 필요함  
- 도서 예제 코드는 실행 검증하지 않았음 — 본 문서에 코드를 옮기지 않았으며, 옮길 경우 `미검증 스케치`로 표기함  
- 서지 쪽수 불일치 — `recommend-materials.md` 3-1절은 `176쪽`으로 적었으나 확보한 PDF는 179쪽임.  
  앞부속·색인 포함 여부 차이로 보이며, 인용 시 PDF 실측값을 씀  
- 유효기간 — 2025-07 발행. LLM API·평가 라이브러리 표기는 1년 이내 재확인 필요.  
  반면 청킹·하이브리드·질의 생성의 **개념 서술**은 노후화 위험이 낮아 슬라이드 인용에 적합함

| CH7 | Microsoft GraphRAG 구현 | 109 ~ 136 | 해당 없음(개념 대비용) | 범위 밖 |

- CH8 지표 계산은 자체 구현이 아니라 **RAGAS 라이브러리**를 씀 — `evaluate()`에 `answer_correctness` ·  
  `context_recall` · `faithfulness` 3개를 넘김 [§8.2.5 p.124/PDF145].
- CH8 3지표와 커리큘럼 4지표(Precision · Recall · Faithfulness · Relevance) 대조 결과 —  
  `faithfulness`는 동일, `context_recall`은 커리큘럼 `Recall`에 대응, 커리큘럼 `Precision`에 해당하는  
  지표는 도서에 없음 [§8.2 p.121~123/PDF142~144].
- `answer correctness`가 커리큘럼 `Relevance`와 같은 지표인지는 **원문 미표기** — 도서는 정답 대비  
  TP/FP/FN 분류로 정의하고 "factual accuracy와 relevance를 함께 본다"고만 서술함  
  [§8.2.3 p.122~123/PDF143~144]. 판정은 9절로 올림.
- CH6 규칙·LLM 경계 — LLM에 맡기는 것은 **스키마 기반 정형 추출**이고, 개체 중복 해소는 문자열 매칭 ·  
  군집화 · 도메인 규칙·온톨로지로 처리하며 도메인 전문가가 일치 기준을 정하라고 권고함  
  [§6.2.2 p.85/PDF106]. 도서는 이 단계의 코드를 제공하지 않음.
- CH6 적재 질의는 `randomUUID()` 사용으로 **멱등하지 않음**을 저자가 직접 밝힘 — 재실행 시 계약 노드가  
  중복 생성됨 [§6.2.1 p.83/PDF104]. 실습 지시문에 재실행 경고가 필요함.
- CH7 실행 환경 제약 — Neo4j Aura 무료 등급은 GDS 라이브러리를 제공하지 않아 CH7만 AuraDS가 필요함  
  [§A.2.3 p.133/PDF154]. KT가 CH7을 제외한 결정과 방향이 일치함.
- 도서가 쓰는 주요 패키지·진입점 — `neo4j` 파이썬 드라이버(`driver.execute_query`) · `openai`  
  (`client.beta.chat.completions.parse`) · `pydantic` · `tiktoken` · `ragas` · Neo4j APOC · GDS  
  [§2.2 p.23~24/PDF44~45][§4.3.2 p.49/PDF70][§6.1.2 p.79/PDF100][§8.2 p.124/PDF145].
- 환경 판본 — Neo4j Desktop 5.9.0 이상 권장, Docker 예시는 `neo4j:5.26.0`에 APOC·GDS 플러그인 자동  
  설치임 [§A.2 p.130~133/PDF151~154].
- 부속 코드는 `github.com/tomasonjo/kg-rag` 저장소의 장별 노트북으로 제공됨 [§2 p.18/PDF39].
- CH2 유사도 함수 선택 — 코사인 유사도와 유클리드 거리를 비교한 뒤 **텍스트 챗봇에는 코사인**을  
  쓴다고 밝히고 책 전체를 코사인으로 통일함 [§2.1.1 p.18~19/PDF39~40]. 값 범위는 0 ~ 1임.
- CH2 운영 주의 — 임베딩 모델을 바꾸면 벡터 인덱스를 **전량 재적재**해야 하고, 인덱스 생성 시 차원 수를  
  고정하므로 차원이 다른 모델로 교체하면 인덱스를 다시 만들어야 함 [§2.1.1 p.19/PDF40][§2.2.5 p.23/PDF44].
- CH3 실무 순서 — 문단·섹션 같은 **구조 요소로 먼저 나눈 뒤** 크기 기준 분할을 적용하라고 권고함  
  [§3.2 p.37/PDF58]. 정규식으로 제목을 찾아 9개 섹션으로 나눈 것이 예시임.
- CH5 종료 조건 — 답변 비평기(answer critic)는 **1회만 수행**하고 그 뒤에는 불완전해도 그대로 반환함  
  [§5.3.4 p.69/PDF90]. 루프 상한을 반드시 두라는 서술이 §5.1.3에 함께 있음 [p.58/PDF79].
- CH8 관측 결과 — text2cypher를 거치지 않는 질의가 지연이 뚜렷하게 낮았고, LLM을 심판으로 쓰는 탓에  
  점수가 일관되지 않는 사례가 있었다고 기록함 [§8.2.6 p.125/PDF146].

## 9. 열린 질문

  판정 불가함. 4지표 확정 전 Ragas 문서 대조가 필요함.
