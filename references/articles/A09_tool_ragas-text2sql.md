## 2. 핵심 주장

- **C1** SQL 채점의 기준은 **실행 결과**임. 문자열이 달라도 같은 데이터를 돌려주면 맞은 것으로 봄.
  원문은 이를 정확성의 최종 시험이라고 표현함 [§Define evaluation metrics, /stable/ 2026-08-05 조회 기준]
- **C2** 이 페이지의 채점 함수 `execution_accuracy`는 Ragas **내장 지표가 아니라 문서 안에서 직접 정의하는
  커스텀 이산 지표**임. `@discrete_metric` 데코레이터로 만들고 허용값을 2개로 고정함
  [§Setting up metric functions, /stable/ 2026-08-05 조회 기준]
- **C3** 채점은 정답 SQL과 생성 SQL을 **둘 다 실제 DB에서 실행**한 뒤 두 결과 표를 `datacompy`로 비교해
  이뤄짐. 어느 한쪽이라도 실행에 실패하면 `incorrect`임
  [§Setting up metric functions 코드, /stable/ 2026-08-05 조회 기준]
- **C4** 점수를 올린 수단은 모델 교체가 아니라 **프롬프트 개정 반복**임. 같은 모델·같은 99문항에서
  프롬프트만 3판으로 고쳐 정확도가 2.02% → 60.61% → 70.71%로 올라감
  [§Compare results 표, /stable/ 2026-08-05 조회 기준]
- **C5** 개선 규칙은 **문항별 땜질이 아니라 스키마에 근거한 일반 규칙**으로 쓰라고 못 박음.
  개별 사례를 넣으면 그 데이터에만 맞춰지기 때문이며, 정확도가 2 ~ 3회 연속 정체하면 멈추라고 함
  [§Key principles for continued iteration, /stable/ 2026-08-05 조회 기준]

## 6. 집필 시 주의

- **라이선스 제약** — BookSQL은 비상업 연구 전용임. 유상 교육 교재·실습에 원본 데이터를 그대로 실을 수
  없음. 절차와 코드 구조만 참고하고 데이터는 합성 마이데이터로 갈아야 함
- **읽기 전용 요구사항** — 채점 러너가 모델이 만든 SQL을 실제로 실행하므로 아래를 요구사항으로 전달함
  - 생성 SQL 실행은 조회(`SELECT`) 전용이어야 하며 쓰기(INSERT · UPDATE · DELETE)는 허용하지 않음.
    원문 프롬프트 템플릿도 `SELECT` 질의만 만들라고 지시함
  - 결과 행 수 상한과 질의 타임아웃이 필요함. 두 값 모두 **원문 미표기**이므로 별도 확정이 필요함
  - DB 계정·권한·인증 방식은 **커넥니(도구 연동 엔지니어) 담당 영역**이므로 본 문서에서 확정하지 않음
- **수치 성격** — 4절 Q4는 회계 도메인 공개 데이터에서 특정 모델 1종으로 얻은 값임.
  도메인·스키마·모델이 다르면 재현되지 않으므로 교재 목표치의 근거로 쓸 수 없음
- **내장 지표는 다른 페이지에 있음** — 이 페이지는 커스텀 지표만 정의함. 2절 4번이 지목한
  `Execution based Datacompy Score`는 `concepts/metrics/available_metrics/sql` 소속이며 본 원문 비등재임
- ※ 상충: 해당 없음(5절 상충 2건과 무관). Spider 2.0 수치는 2절 6번 ① 권고에 따라 사용하지 않음
- (추론) 정답 SQL을 만드는 일이 이 절차의 최대 병목임. 근거 — 채점 코드가 정답 SQL을 받아 직접
  실행하므로, 정답이 없으면 지표 자체가 성립하지 않음
- 유효기간 — `/stable/`은 버전 표기가 없어 내용이 예고 없이 바뀜. 예제 모듈도 함께 바뀔 수 있음

실행 기반 채점의 전제 조건 4항목 [§Setting up metric functions 코드, /stable/ 2026-08-05 조회 기준].

- ① **실행 가능한 DB 필요 여부** — 필요함. 정답 SQL과 생성 SQL을 **둘 다 실제로 실행**해 결과 표를
  받아 옴. 문자열 비교만으로 끝나지 않음 [§Setting up metric functions]
- ② **정답 SQL 필요 여부** — 필요함. 채점 함수가 `expected_sql`을 인자로 받아 그 자리에서 실행함.
  미리 만들어 둔 정답 결과 표만 주는 방식은 원문에 없음 [§Setting up metric functions]
- ③ **결과 비교 방식** — 인덱스 위치 기준 **행 단위** 대조이며 행 순서가 다르면 불일치로 처리됨.
  부동소수 허용 오차는 절대·상대 모두 `1e-10`임. 양쪽 다 빈 결과면 `correct`, 한쪽만 비면
  `incorrect`임. 열 단위 비교 모드는 본 원문에 없음 [§Setting up metric functions 코드]
- ④ **실행 실패 처리 규칙** — 정답 SQL 실행 실패 · 생성 SQL 실행 실패 · 그 밖의 예외 발생
  3경우 모두 `incorrect`로 매김. 실패를 결측으로 빼지 않고 오답으로 셈 [§Setting up metric functions]

구/신 API 이관 여부 — 원문 대조 결과

- ① `ragas.metrics` → `ragas.metrics.collections` 이관 — **본 원문에서는 확인 불가**.
  이 페이지는 폐기 고지를 싣지 않으며, 쓰는 경로는 `ragas.metrics.discrete` ·
  `ragas.metrics.result`와 최상위 `ragas`의 `experiment` · `Dataset`임. 두 경로 모두
  `collections` 이관 대상으로 언급되지 않음 [§Setting up metric functions 코드, /stable/ 2026-08-05 조회 기준]
- ② `Relevance` → `Response Relevancy` 개명 — **본 원문에서는 확인 불가**.
  이 페이지의 지표 범위에 `Relevance` 계열이 없어 대조 대상 자체가 없음
  [§Define evaluation metrics, /stable/ 2026-08-05 조회 기준]

## 8. 확인 범위와 미확인

- 조회일 2026-08-05. 확보 수단은 `curl -sL` 1회 성공이며 재시도 불필요
- 판독한 것 — H1 1개 · H2 9개 · H3 15개 전부, 본문 텍스트 16,253자 전문, 코드블록 25개 전부,

- 못 본 것 — 본문 요소 중 판독하지 못한 것은 없음. 접었다 펴는 상세 블록(`📋` 표시) 내용도
  본문 텍스트에 포함되어 판독됨. 제외한 것은 좌측 네비게이션 등 **본문이 아닌 요소**뿐이라 FULL임
- 원문에 이미지·다이어그램은 0건임(추출 결과 `=== IMAGES ===` 항목이 비어 있음)
- `context7` MCP 대조 수행함(`/websites/ragas_io_en_stable`, 2026-08-05).
  `execution_accuracy` 정의 코드와 실험 함수 코드가 원문과 문자 단위로 일치함 — **불일치 0건**.
  같은 조회로 내장 `Execution based Datacompy Score`가 별도 `sql` 페이지 소속임도 확인됨
- 코드는 실행해 보지 않았으므로 본 문서에 옮긴 코드 구조는 **미검증 스케치**임
- 미확인 — 원문은 `execute_sql`의 내부 구현(타임아웃 · 행 수 상한 · 접속 권한)을 싣지 않음.
