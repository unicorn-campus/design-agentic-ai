# 기존 구현 대비 비교

대상은 `hybrid-ai-lab/s3.1`의 청킹, `s3.2`의 Vector 검색·답변,
`s3.3`의 Hybrid·질문 변환·Rerank 구현임.

## 결론

새 Vector 앱은 추출부터 검색·답변 API까지 두 개의 LangGraph 앱으로 통합함.
원천·문서·청크 수와 KURE-v1 1,024차원 인덱스는 목표값과 일치함.

사용자가 승인한 A안으로 Rerank 후보 계약을 기존 기준선과 맞춘 뒤 동등성을 다시 측정함.
네 조합 모두 포함 건수와 평균 순위 기준을 충족하여 전체 동등성 판정이 통과임.

## 이식하면서 바로잡은 동작

### 답변 관문

Hybrid 융합 점수는 후보 집합 안에서 정규화된 상대 점수임.
새 앱은 모든 모드에서 최종 1위의 원래 Vector 코사인 유사도 `vector_score`를 0.62와 비교함.
BM25에만 잡힌 1위처럼 `vector_score`가 없으면 안전하게 `needs_check`로 종료함.

### 질문 변환 관문

기존 `s3.3`은 Hybrid 융합 Top-1 점수를 0.70과 비교함.
새 앱은 원 질문 Vector Top-1 코사인 유사도를 0.70과 비교함.

상대 점수인 Hybrid 융합값을 절대 임계값과 비교하던 문제를 제거한 정정임.
이 변경은 의도적 개선이므로 기존과 결과가 달라질 수 있음.

### 질문별 Rerank

원 질문과 각 변환 질문의 후보를 자기 질문으로 각각 Rerank한 뒤 병합함.
복합 질문의 하위 후보를 원 질문 하나로만 채점하던  
계획 초안의 오류를 구현 전에 정정한 결과임.

### 가명화와 출력 안전성

기존 추출 단계에서는 가명화 선택지가 있었으나  
새 Indexer에서는 상담 가명화가 항상 적용됨.
출력 폴더가 원문 폴더와 같거나 하위인 경우도 명시적으로 차단됨.

통과 기준은 포함 건수가 기준 이상이고 평균 기대 청크 순위가 기준 이하인 경우임.

## A안 적용 결과

최종 Top-K 5는 유지하고 `hybrid_rerank`의 질문별 융합 목표를 10건으로 복원함.
`CANDIDATE_MULTIPLIER=4`는 최종 결과 수가 아니라 질문별 검색·융합 목표 수에 적용됨.

| 모드 | 질문별 검색·융합 목표 | 검색기별 원시 후보 | Rerank 입력 | 최종 결과 |
|---|---:|---:|---:|---:|
| `vector` | 5건 | 20건 | 해당 없음 | 5건 |
| `hybrid` | 5건 | 20건 | 해당 없음 | 5건 |
| `hybrid_rerank` | 10건 | 40건 | 10건 | 5건 |

코드의 `candidate_sizes()`가 모드별 `raw_k`와 `fused_k`를 계산함.
`HYBRID_RERANK_FUSION_MULTIPLIER=2`이므로 Rerank의 융합 목표는 최종 5건 × 2 = 10건임.
원시 후보는 융합 목표 10건 × `CANDIDATE_MULTIPLIER=4` = 검색기별 40건임.

q6의 `hybrid_rerank/auto` 최종 Top-5는 다음과 같음.

```text
D1_0010, D2_0005, D2_0010, D2_0003, D1_0009
```

기대 청크 `D1_0010`은 1위, `D2_0003`은 4위로 모두 최종 결과에 포함됨.

## 변경 전 이력

A안 적용 전 후보 계약은 검색기별 원시 후보 20건 → 융합 후보 20건 →  
Rerank 최종 5건이었음.
당시 `hybrid_rerank/auto`는 6/7·1.625로 기준선 7/7·1.375에 미달했음.
q6에서 `D2_0003`이 최종 Top-5에 포함되지 않았으며 전체 판정은 부분 통과였음.

사용자 승인에 따라 A안을 적용하고 같은 7개 질문을 다시 평가함.
재측정에서는 q6의 두 기대 청크가 모두 포함되어 7/7·1.375로 기준선을 충족함.
따라서 별도 기준선 승인이나 q6 전용 규칙 추가 결정은 더 이상 필요하지 않음.
