# K8 커뮤니티 요약 시험 (2026-10-23)

v0에 넣은 K8 커뮤니티 요약(`indexer/graphrag/v0/community.py`, 오케스트레이터 `--communities`)을  
실제 Neo4j, OpenSearch, Groq로 돌려 본 기록임.

- 환경: 새 compose 컨테이너 `neo4j`(2026.09.0 Community + APOC + GDS 2026.09.0, bolt 7687), `opensearch`(2.19.1, 9200)
- 묶기: GDS Leiden(randomSeed 42, concurrency 1, 한 단계). 엔티티 그래프만 투영(청크 노드, FROM_CHUNK 제외)
- 보고서: Groq `openai/gpt-oss-120b`, 엔티티 3개 이상 묶음만, 보고서 판 v2. 임베딩은 KURE-v2(768차원)
- 표본: `v0/data/sample-chunks.json`(약관 청크 2, 혜택 안내 4, 상담 4), 증분은 `sample-chunks-v2.json`

## 파일

| 파일 | 내용 |
|------|------|
| `run-a.log` ~ `run-d.log` | 실행 로그(시험 a ~ d) |
| `probe.py` | 활성 세대의 묶음 구성과 거시 질문(Q23 ~ Q25) 상위 3개 보고서를 뽑음(읽기만 함) |
| `result.json` | 묶음 목록(제목, 요약, 핵심 사실, 문서 종류), 거시 질문 상위 3개, 실행 a ~ d 수치 |
| `active_before.json` | 시험 전 활성 세대 파일 |

## 거시 질문(e)

활성 세대(`gen-sample-016`, 증분 뒤) 커뮤니티 13개를 질문 임베딩으로 찾은 상위 3개.

| 질문 | 상위 보고서 | 정답 요점이 들어 있나 |
|------|------|------|
| Q23 고객군별 불만 주제 | 연회비 대비 혜택 부족에 대한 고객 불만 및 제안 거절 / 명세서 항목 이해와 거래 확인 지원 / 할부 거래 철회 요청 절차와 제한 요건 | 6개 주제 중 1개(장기보유 연회비 가치)만. 표본 상담 4건에 불만형 고객이 M-1042 하나뿐이라 나머지 주제는 데이터에 없음 |
| Q24 받아들여진 제안의 공통점 | 같은 상담 묶음 2개가 1, 2위 | 「화면을 같이 보며 짚어 드림」, 「주문 내역으로 대조」 수용과 「종이 영수증」 거절이 들어 있음. 공통점(할 일이 늘지 않음, 글로 남음)을 끌어낼 재료는 일부만 있음 |
| Q25 불만 주제별 약관 조항과 카드 혜택 | 연회비 불만 묶음 / 카드 이용, 관리 주요 조항 요약 / 명세서 묶음 | 연회비 불만과 약관 조항이 서로 다른 묶음에 있어 한 보고서로 이어지지 않음. 정답의 제9조, 제34조, 제5조는 표본 약관 청크에 본문이 없음 |

- 묶음 13개가 모두 한 문서 종류 안에서만 생김(약관 8, 혜택 안내 3, 상담 2, 섞인 묶음 0).  
  엔티티 사이 관계가 추출 단위 안에서만 생겨 문서를 건너는 관계가 없기 때문임
- 보고서 첫 판(v1)은 본문에 입력용 엔티티 번호(「(e13)」, 「e1 ~ e7」)가 섞여 나와, 프롬프트에 금지를 넣고 남은 번호를 코드로 지운 v2로 다시 만듦.  
  v2 보고서 13개에는 남은 번호가 없음

## 판단

- K8 자체는 설계대로 동작함: 결정적 묶음, 지문 재사용, 증분에서 바뀐 묶음만 다시 요약, ④ 추가 검사
- 거시 질문 품질은 이 표본으로 판단할 수 없음. 상담 4건, 약관 청크 2개로는 정답 재료가 거의 없음.  
  전체 청크(218개) 재색인 뒤 Q23 ~ Q25를 다시 재야 함(K2 LLM 약 260번, K8 묶음 수십 개 예상)
- 문서 건너기(Q25)는 커뮤니티로 풀리지 않음. 상담의 불만과 약관 조항을 잇는 관계(예: 불만 → 관련 조항)를 KG에 넣거나,  
  여러 보고서를 모아 답하는 Global Search식 답변 단계가 필요함
