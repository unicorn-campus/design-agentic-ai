# 약관 추출 단위 재시험: Claude Opus 5.5

「약관은 조항 단위로 나눠야 조건, 기한, 처리 노드가 나온다」는 판단이 모델 탓인지 확인하는 실험.  
gpt-oss-120b로 한 1차(청크째)와 2차(조항 단위) 채우기 시험을 LLM만 Opus 5.5로 바꿔 다시 돌림.

- 같은 것: 표본, 스키마 초안, 기대 답, 질문 매핑, 채점(`schema/doc/tools/fill_test.py` 함수 그대로)
- 바꾼 것: LLM(`claude-opus-5-5`, effort medium, 온도 지정 없음, 응답 거절 시 서버 대체 모델 사용)

## 파일

| 파일 | 내용 |
|------|------|
| `run_opus.py` | 시험 실행. `chunk`는 1차 재현, `unit`은 2차 재현 |
| `output-chunk/` | 청크째 5건 결과(`fill_calls.jsonl`, `fill_report.md`, `fill_metrics.json`) |
| `output-unit/` | 조항 단위 30건 결과 |

## 실행

neo4j-graphrag 1.22.0과 anthropic SDK가 든 가상환경에서 실행. 키는 `secrets/.env`의 `CLAUDE_API_KEY`를 읽음.

```bash
python run_opus.py chunk
python run_opus.py unit
```

## 결과 (2026-10-23)

청크째 5건, 질문별 뽑음 비율

| 질문 | gpt-oss-120b | Opus 5.5 |
|------|------|------|
| R1 조항 | 100% | 80% |
| R2 조건 | 0% | 100% (2 / 2) |
| R3 기한 | 0% | 100% (2 / 2) |
| R4 상황별 처리 | 0% | 80% |
| R5 이전 판 | 100% | 100% |
| 나온 노드 종류 | 조항, 문서뿐 | 조항, 문서, 조건, 기한, 처리 |

조항 단위 30건은 두 모델 결과가 거의 같음(R3 뽑음만 56%에서 69%로 오름, 잘못 뽑음은 0%에서 29%로 늘어남).

같은 조항 5개(제6조의2 ~ 제10조)만 담은 청크 `b3d99960…`를 두 방식으로 넣은 Opus 노드 수

| 방식 | 조항 | 기한 | 처리 | 조건 |
|------|------|------|------|------|
| 청크째 1번 호출 | 5 | 4 | 6 | 1 |
| 조항 단위 5번 호출 합 | 5 | 5 | 7 | 4 |

## 관찰

- 1차 시험의 「조항과 문서 노드만 나옴」은 gpt-oss-120b의 한계였음. Opus 5.5는 청크째로도 조건, 기한, 처리 노드를 뽑음
- 그래도 조항 단위가 조금 더 촘촘함. 같은 청크에서 조건 노드가 1개 대 4개로 차이가 가장 큼
- 청크 `30f9dce5…`는 표지와 차례(목차)뿐이라 Opus는 문서 노드 하나만 냄. 기대 답은 차례의 조항 제목을 답으로 적어 둬서
  R1, R4에서 「못 뽑음」으로 셈. 기대 답 쪽 문제로 봄
- R5 「값 다름」은 두 모델 모두 같은 원인임. 값은 맞게 뽑았으나 기대 답에 `version:` 같은 이름표가 붙어 채점에서 떨어짐
- 표본이 청크 5건뿐이고 한 번씩만 돌렸음. 같은 입력을 다시 돌리면 수치가 바뀔 수 있음
