# 약관 추출 단위 재시험: NuExtract 2.0 8B

추출 전용 모델 NuExtract 2.0 8B가 범용 LLM(gpt-oss-120b, Claude Opus 5.5)을 대신할 수 있는지 보는 실험.  
표본, 기대 답, 채점은 앞 시험(`schema/doc` 채우기 시험, `verify/kg-unit-opus`)과 같음.

- 모델: `hf.co/numind/NuExtract-2.0-8B-GGUF:Q8_0`(NuMind 공식 GGUF), Ollama 0.40, RTX 4090 Laptop 16GB, 온도 0
- 입력: 모델 카드의 대화 틀(`# Template:`, `# Context:`)을 그대로 만들어 raw로 보냄
- 다른 점: NuExtract는 스키마 설명을 받지 않고 JSON 틀만 받음. 노드 5종을 틀 하나로 옮기고 필드 이름으로 뜻을 드러냄.  
  예시(in-context example)는 넣지 않음

## 파일

| 파일 | 내용 |
|------|------|
| `run_nuextract.py` | 시험 실행. `chunk`는 청크째 5건, `unit`은 조항 단위 30건 |
| `output-chunk/`, `output-unit/` | 호출 기록(`fill_calls.jsonl`, 모델이 돌려준 JSON 포함), 보고서, 지표, 실행 로그 |

## 실행

Ollama에 모델을 받아 두고 `schema/doc/.venv`의 파이썬으로 실행.

```bash
ollama pull hf.co/numind/NuExtract-2.0-8B-GGUF:Q8_0
python run_nuextract.py chunk
python run_nuextract.py unit
```

## 관찰

- 조건(R2)과 기한(R3)을 거의 못 뽑음. 조항 단위로 나눠 넣어도 30건 중 기한 1건, 조건 1건뿐임
- 상황별 처리(R4)는 뽑지만, 조건이나 기한 문장도 처리로 넣는 경향이 있음
- 차례(목차)가 든 청크 `e98b48c1…`에서 차례의 조항 제목 35개를 모두 조항으로 뽑음. Opus는 본문 있는 조항 2개만 뽑음
- 범용 LLM과 달리 노드마다 해당과 비해당 설명을 줄 수 없어 경계가 흐린 노드(조건, 기한, 처리)가 약함.  
  예시를 틀과 함께 넣으면 나아질 수 있으나 이번에는 시험하지 않음
- 표본이 적고 한 번씩만 돌렸음
