# 8단계 결정: 채우기 시험 1라운드 결과와 다음 할 일

- 정할 것: 이 결과로 통과(9단계 스키마 파일 생성)할지, 아래 고칠 안을 반영해 5 ~ 8단계를 다시 할지(2라운드)
- 반복 한도: 5회 중 1회 사용. LLM은 Groq `openai/gpt-oss-120b`(사용자 결정, 2026-10-23)
- 결론 먼저: **연결 검사는 통과**했고, **질문별 점수는 21개 중 5개만 통과**함. 미달의 상당수는 채점 방식이나 기대 답 오류 탓이고,
  실제 추출 품질 문제는 상담의 불만, 제안 성격, 혜택의 업종 이름, 약관의 기한에 몰려 있음

- 값 같음: 뽑은 것 중 기대 답과 같은 비율. 기준 60% 이상. X와 A 질문은 대표 이름이 글자까지 같아야 맞음.
  나머지는 기대 답 글자의 두 글자 묶음 중 40% 이상이 뽑은 값에 있으면 맞음

## 2. 연결 검사 결과

**개념 설명.** 세 문서 종류의 시험 결과를 한 그래프로 합쳐, 공통 노드를 거쳐 문서끼리 실제로 이어지는지 셈.
주제와 업종은 띄어쓰기를 뺀 대표 이름으로, 카드 상품은 정형 상품 이름으로 찾은 상품 ID로 합침. 고객군, 가명 회원, 상담 주제는 메타데이터로 채움.

| 검사 | 결과 | 기준 | 판정 |
|---|---|---|---|
| 공통 노드에 잇지 못한 단위 | 6%(약관 4/28, 혜택 안내 0/36, 상담 기록 1/18) | 30% 이하 | 통과 |
| X1 경로(불만 → 주제 ← 조항) | 8건 중 6건(75%) | 60% 이상 | 통과 |
| X2 경로(상담 → 카드 상품 → 혜택) | 상담의 카드 언급 13개 중 0개 | 기준 없음(참고) | 참고 |

열 뜻

- 결과: 셈한 값. 괄호 안은 문서 종류별 못 이은 단위 수와 대상 단위 수
- 기준: 7단계에서 승인한 값

덧붙임

- X2 경로 0건은 표본 탓임. 상담에 나온 카드 6종 중 4종이 혜택 시험 표본에 있었으나, 카드 목록과 카드 개요 청크에만 있고
  그 카드의 혜택 상세 청크는 시험 표본에 없었음. 키(상품 ID)는 양쪽 모두 맞게 채워짐(예: 한빛 가족돌봄 → D2-C021)
- 연결 검사 통과는 주제를 고를 수 있다는 뜻이지 맞게 골랐다는 뜻은 아님. 상담 쪽 주제 값은 1절의 X1, A1처럼 틀린 것이 많음

## 3. 미달 원인

**개념 설명.** 미달에는 세 갈래가 있음. 채점 방식이 맞는 답을 틀렸다고 센 것, 7단계 기대 답이 틀린 것, 실제로 추출이 잘못된 것.
앞의 둘은 스키마를 고칠 일이 아니고, 셋째만 스키마 설명(description)을 고칠 일임.

| 질문 | 원인 | 근거(예) |
|---|---|---|
| R1 | 채점 | 기대 답은 "제18조(포인트)"인데 채점이 조항 제목 칸만 봐서 "포인트"를 값 다름으로 셈. 잘못 뽑음 1건은 제2조(용어의 정의)를 조항으로 뽑은 것으로, 기대 답 "없음"이 틀렸을 수 있음 |
| R5 | 채점 | 뽑은 값 "1.2 2027-01-15 1.1"이 맞는데, 기대 답에 "version:" 같은 칸 이름이 섞여 글자 겹침이 낮게 나옴(22건) |
| R4 | 기대 답(대부분) | 잘못 뽑음 11건 중 다수가 실제로 "~하면 ~함" 꼴의 상황별 처리임(예: 제16조의3 "계약이 취소된 경우 회원은 지급 보류를 요청할 수 있습니다"). LLM 기대 답 초안이 덜 뽑았음 |
| B1 | 채점과 추출 반반 | 기대 답이 혜택 여러 개를 이었는데 일부만 뽑힘(15건). 크기는 맞게 뽑힌 경우가 많음 |
| 혜택 X2 | 기대 답(2건)과 추출(1건) | 카드 청크인데 기대 답이 "없음"인 2건(한빛 소소캐시백, 한빛 우리집). 나머지 1건은 카드 목록 청크에서 카드 34개를 뽑은 것 |

| C1, A1 | 추출 | 불만이 없는 상담 5건에서 불만을 뽑음(예: "종이 영수증은 이미 버려서 설명하기 번거로워요"). 그 불만에 주제가 붙어 A1도 잘못 뽑음 |
| 상담 X1, A1 값 | 추출 | 불만 주제를 "명세서와 결제"로 고르는 일이 잦음(혜택 불만 3건 포함). 불만의 원인이 아니라 상담 장면(명세서를 보며 통화)을 보고 고른 것으로 보임 |
| 혜택 X1 | 추출(설계) | 업종 이름 40개가 거의 모두 가맹점 이름이 섞인 자유 글(예: "가상수소충전망푸른수소현장결제")이라 같은 이름으로 합쳐지지 않음. 혜택 받는 방식은 대부분 "알 수 없음" |

- 원인: 채점(맞는 답을 틀렸다고 셈), 기대 답(정답이 틀림), 추출(스키마로 뽑은 결과가 틀림), 설계(스키마 구조를 바꿔야 풀림)
- 근거: 실제 시험 결과에서 본 예. 전체 예는 `{doc}/output/fill_report.md`

## 4. 2라운드에 반영할 고칠 안

**개념 설명.** 스키마는 그대로 두고 채점과 기대 답을 바로잡는 것(가, 나), 노드 타입 설명을 고치는 것(다),
스키마 구조를 조금 바꾸는 것(라)으로 나눔. 라는 5단계 설계를 바꾸는 일이라 따로 승인받음.

| 번호 | 구분 | 고칠 내용 | 기대 효과 |
|---|---|---|---|
| 가1 | 채점 | R1은 조항 번호와 제목을 함께 비교, R5는 칸 이름을 빼고 값만 비교 | R1, R5 통과 예상 |
| 나1 | 기대 답 | 혜택 X2의 카드 청크 2건을 카드 이름으로 고침 | 혜택 X2 잘못 뽑음 3건 → 1건 |
| 나2 | 기대 답 | R4 잘못 뽑음 11건을 다시 읽어, 실제 상황별 처리면 기대 답에 넣음. R1의 제2조도 다시 봄(고친 칸은 검토 파일로 보여 드림) | R4, R1 판정이 실제 품질을 반영 |
| 다1 | 설명 | Deadline: 해당에 "~ 전에 안내", "사전에 안내", "청구 전에" 같은 미리 알리는 시점을 예와 함께 넣음 | R3 뽑음 향상 |
| 다2 | 설명 | Complaint: 비해당에 "사정 설명(영수증을 버림, 시간이 없음)", "할 수 없다는 말", "확인 요청"을 넣고, "불만, 불편, 답답, 부담" 같은 감정 표현이 고객 말에 있을 때만 해당으로 좁힘 | C1, A1 잘못 뽑음 감소 |
| 다3 | 설명 | Topic(불만 쪽): "불만의 원인이 된 대상으로 고름. 상담이 일어난 장면(명세서를 보며 통화 등)으로 고르지 않음"과 주제마다 한 줄 뜻을 넣음 | 상담 X1, A1 값 같음 향상 |
| 다4 | 설명 | ProposalTrait: 6개 성격마다 뜻과 예를 넣음(예: 글로 남는 안내 = 이메일, 문자, 서면으로 정리해 보냄) | A2 값 같음 향상 |
| 다5 | 설명 | Benefit.apply_method: "신청, 등록, 응모 문구가 없으면 자동 적용"으로 판단 기준을 넣음 | 혜택 X1 방식 값 향상 |
| 라1 | 설계 | MerchantCategory를 Topic처럼 **대표 이름 목록**에서만 고르게 바꿈. 이번 시험에서 나온 이름 40개를 15개 안팎으로 묶어 목록을 만듦(예: 대중교통, 주유와 충전, 편의점, 장보기, 커피와 음식점, 온라인쇼핑, 통신, 해외 결제). 가맹점 이름은 넣지 않음 | 업종이 문서끼리 합쳐짐. 혜택 X1, 상담 X1 값 같음 향상 |
| 라2 | 설계 | 앞 상담 연결(FOLLOWS)을 LLM 대신 코드가 채움. 같은 가명 회원의 상담을 날짜순으로 이음(메타데이터만 씀) | C5가 100%가 됨. LLM 부담 감소 |
| 라3 | 설계 | 혜택 안내의 표지와 카드 목록 청크(4건)도 엔티티 추출에서 뺌(설계 참고 출처와 같은 처리) | 카드 목록에서 카드 34개를 잘못 뽑는 일이 없어짐 |

열 뜻

- 번호: 고칠 안을 가리킬 때 쓰는 번호. 가는 채점, 나는 기대 답, 다는 설명, 라는 설계
- 고칠 내용: 무엇을 어떻게 바꾸는지
- 기대 효과: 예상일 뿐이며 2라운드 시험으로 확인함

덧붙임

- 라1의 업종 목록과 다3의 주제별 한 줄 뜻, 다4의 성격별 뜻은 2라운드 전에 검토 파일로 따로 보여 드리고 승인받음
- 2라운드 비용 예상: 1라운드와 같은 86건 추출에 토큰 약 37만 개(1라운드 실측 370,549개)
