## 1. 기대 답

**개념 설명.** 기대 답은 시험용 표본 한 건에서 질문마다 "이 정도는 뽑혀야 한다"고 미리 정해 둔 정답임.
8단계에서 스키마로 뽑은 결과를 이 정답과 대조해 점수를 매김. 답이 "없음"인 표본은 잘못 뽑는지를 보는 데 씀.
문서 하나 범위 질문은 원문 문장을 그대로 옮기고, 여러 문서 종류 범위와 전체 모음 범위 질문은 그 단위가 이어져야 할 공통 노드의 이름을 적음.

- 기대 답 전체는 `output/expected_answers_review.md`에서 한 건씩 볼 수 있음

## 2. AI가 맞춘 곳

**개념 설명.** LLM 초안끼리 또는 기존 정답표와 서로 맞지 않는 곳을 규칙으로 고친 것임. 고친 곳은 모두 `consistency_fixes`에 남김.

| 문서 종류 | 고친 곳 | 규칙 | 건수 |
|---|---|---|---:|
| 상담 기록 | 정답표에 불만(C1)이 없는데 불만 주제(X1, A1)가 적힌 곳 | 불만 주제는 "없음". X1의 업종은 고객이나 상담사가 말했으면 남김. 이 규칙은 스크립트에 넣어 다시 돌려도 같게 함 | 17칸 |
| 상담 기록 | X1에 원문 발화를 통째로 적은 곳(2건) | 정답표에 불만이 없어 "없음" | 2칸 |
| 상담 기록 | 불만이 있는데 주제가 비었거나 엉뚱한 곳(2건) | "실적을 못 채우면 혜택이 사라지는 구조", "신청 방법을 다시 확인해야 하는 점" → 주제 "부가서비스와 포인트" | 4칸(X1, A1) |
| 상담 기록 | A2에 목록에 없는 글을 적었거나, 정답표에 결정이 있는데 "없음"인 곳(3건) | 정답표의 제안, 결정, 이유를 보고 제안 성격을 고름(예: 이메일 정리 수용 → 글로 남는 안내) | 3칸 |
| 혜택 안내 | 본문 아님(카드 목록)인데 X2에 카드 이름 3개가 적힌 곳 | 본문 아님은 모두 "없음" | 1칸 |

- 상담 기록 A2 초안은 LLM이 제안 성격을 고르는 품질이 낮았음(2번 다시 만들어도 형식 어긋남이 나옴). 고치지 않은 A2 칸도 한 번 더 봐 주시기를 권함
- 고친 칸마다 고치기 전 값, 고친 값, 이유가 `consult_log/expected_answers.json`의 `consistency_fixes`에 있음

열 뜻

- 고친 곳: 어떤 모순을 찾았는지
- 규칙: 어느 쪽에 맞췄는지
- 건수: 고친 표본 수와 칸 수

## 3. 상담 원문 v4와 다시 만든 것(사용자 지시)

**개념 설명.** 첫 판에서는 상담 청크 48건 어디에도 "한빛 ○○" 꼴의 카드 이름이 없어, 상담에서 말한 카드를 거쳐 혜택으로 가는 X2 경로를 시험할 수 없었음.
그래서 상담 원문에 회원이 실제로 가진 카드 이름을 넣고(v4), 색인을 건드리지 않는 방식으로 청크를 다시 만든 뒤 상담 기록 기대 답을 다시 씀.

| 무엇 | 한 일 | 결과 |
|---|---|---|
| 상담 원문 6개 파일 | 상담마다 상담사 마무리 발화 한 줄에 카드 이름 구만 끼워 넣음(예: "‘장보기 결제 경로 확인’ 내용을 **한빛 반려동행 카드 상담으로** 기록하겠습니다.") | 48줄 고침. 기존 글자, 줄 수, 순서는 그대로. 줄끝 CRLF 그대로 |
| 카드 고르기 | 실습 DB에서 그 회원이 가진 카드 중 상품 ID가 가장 앞선 것. 카드 중복 상담 4건은 고객이 같은 역할이라 한 여행 카드 두 장(한빛 하늘여정, 한빛 자유여행) | 회원 12명 모두 DB 보유 카드에서 고름 |
| 고치지 않은 줄 | 평가셋(ragas, group2)이 인용하는 줄, 개인정보 줄, DB 집계 줄 | 평가셋 정답 근거는 그대로 |
| 함께 고친 파일 | 원문 버전 v3 → v4, 강사용 대조표와 생성검증의 `source_version`, `docs/D3_README.md`에 「v4 변경」 | 대조표 인용 글과 발화 통계(768개, 서로 다른 발화 675개)는 그대로 |
| 청크 | 인덱서 `--dry-run --thread-id cardname-20261023`으로 새 청크 파일만 만듦 | 218개. 상담 48개만 본문과 청크 ID가 바뀜. 약관과 혜택 안내 170개는 그대로. 활성 세대와 색인은 바뀌지 않음 |
| 표본 계획 | 3단계에서 승인한 표본 구성은 그대로 두고, 상담 청크 ID만 같은 상담 번호의 새 ID로 바꿈 | 상담 표본 48개 ID 바꿈 |
| 기대 답 | 상담 기록만 다시 씀. 약관과 혜택 안내는 그대로 | 상담 X2 답 있음 0건 → 18건 |

열 뜻

- 무엇: 바뀐 대상
- 한 일: 어떻게 바꿨는지
- 결과: 바뀐 뒤 확인한 숫자와 상태

덧붙임

- 다시 돌리지 않은 것: 4단계 후보 뽑기와 5단계 초안. 상담 청크마다 마무리 발화 한 줄만 바뀌어 스키마 후보에 주는 영향이 작다고 봄
- 영향: 지금 검색엔진 색인, 벡터 색인, GraphRAG v0 그래프는 v3 원문 기준임. v4 기준으로 쓰려면 다시 인덱싱해야 함
- 카드 이름은 모든 상담에서 같은 꼴(마무리 발화)로 한 번씩만 나옴. 그래서 X2 추출은 실제 상담보다 쉬운 조건일 수 있음
- 고친 스크립트와 계획: `tools/add_card_names.py`, `output/card_name_plan.json`. LLM으로 끼워 넣기를 먼저 해 봤으나 원래 글자를 자주 바꿔
  48건 중 15건만 검사를 통과해, 규칙 방식으로 바꿈

## 4. 합격 기준

**개념 설명.** 8단계 시험 점수가 이 기준을 넘으면 그 문서 종류의 스키마를 통과로 봄. 기준을 넘지 못하면 description(타입 설명)을 고쳐 5 ~ 8단계를 다시 함(5회까지).
이번에는 연결 검사 기준을 새로 둠. 연결 검사는 세 문서 종류의 시험 결과를 한 그래프로 합쳐, 공통 노드를 거쳐 문서끼리 실제로 이어지는지 재는 것임.

| 기준 | 제안값 | 이전 실행 | 뜻 |
|---|---|---|---|
| 뽑음 | 질문마다 0.8 이상 | 0.8 | 답이 있는 표본 중 스키마로 그 답을 뽑은 비율 |
| 잘못 뽑음 | 질문마다 0.2 이하 | 0.2 | 답이 없는 표본 중 무언가를 뽑아 버린 비율. 답 없는 표본이 0건인 질문은 보지 않음 |
| 값 일치 | 질문마다 0.6 이상 | 0.6 | 뽑은 값이 기대 답과 같은 뜻인 비율. 공통 노드 질문은 대표 이름이 글자까지 같아야 맞음 |
| 연결: 공통 노드에 잇지 못한 단위 | 0.3 이하 | 없음(새로 둠) | 기대 답에 공통 노드가 있는 단위 중, 시험 그래프에서 공통 노드에 하나도 잇지 못한 비율 |
| 연결: X1 경로 | 0.6 이상 | 없음(새로 둠) | 불만이 있는 상담 중, 주제를 거쳐 약관 조항까지 이어진 비율 |
| 허브 경고 | 경고 0건(구조용 관계 제외) | 없음(새로 둠) | 노드 하나가 그 문서 종류 노드의 30% 이상과 이어지면 경고 |

열 뜻

- 기준: 무엇을 재는지
- 제안값: 이번에 쓸 기준값
- 이전 실행: 2026-10-18 실행의 기준(자동 승인)
- 뜻: 그 비율을 어떻게 세는지

덧붙임

- 상담 기록은 시험용이 18건이라 한 건이 비율을 0.05 이상 움직임. 기준 근처의 결과는 넓게 흔들릴 수 있음
- 제안 성격(A2) 점수는 5단계에서 말씀드린 대로 목록을 정답에 맞춘 효과가 섞일 수 있음
