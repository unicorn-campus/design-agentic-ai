## 순서 판정 기록 — ③④ 번호·순서 교환 (2026-08-06)

**바뀐 것** — 기존 `①②③(역할)⑤(지식)④(시퀀스)⑥⑦`(번호와 읽는 순서가 달랐음) →
**`①②③(시퀀스)④(역할)⑤(지식)⑥⑦`**. 번호와 작성 순서를 일치시킴.

| 항목 | 내용 |
|------|------|
| 제기 | 사용자 — "시퀀스 설계를 한 후 역할과 필요한 지식을 설계하는 게 자연스럽다" |
| 근거 | 마이크로서비스 설계 관행 — `논리 아키텍처 → 시퀀스 → API → 클래스 → 데이터`. MAS도 같음. **프로세스를 확정해야 각 노드를 갖고 에이전트 역할을 설계하고, 필요한 지식·도구를 설계할 수 있음** |
| 1차 검토 | 클로니가 플로니(③④ 소유)·지식니(⑤ 소유)에게 병렬 위임 → 둘 다 현행 유지 권고 |
| 재검토 결론 | **팀 권고를 기각함.** 반대 근거의 핵심이 "④ 단계 표의 참여 주체 열이 ③을 인용한다"였는데, 그것은 **순서를 그렇게 정해 놓았기 때문**이지 필연이 아님. 시퀀스의 참여 주체는 **② 논리 아키텍처의 구성요소**에서 나옴 — 순환 논증이었음 |
| 판정자 | 사용자(최종) · 클로니(수용·반영) |

**교재에 반영한 것**

| 지점 | 고친 내용 |
|------|----------|
| 슬라이드 순서 | 시퀀스 2장을 9·10으로, 역할 2장을 11·12로, 지식 2장을 13·14로 이동 |
| 번호 기호 | 시퀀스 `④` → `③`, 역할 `③` → `④`(제목·breadcrumb) |
| 이미지 파일명 | 슬라이드 번호에 맞춰 재배치(`s13`↔`s09` 등 6개) |
| `s03` 이미지 | 카드를 `목표·구조·순서·역할·지식·관측·배포` 순서로 다시 그림. 번호 1 ~ 7이 순서대로 |
| `s04` 관계도 | 노드 순서와 의존 화살표를 다시 그림 — 굵은 선 4개(`목표→순서`·`구조→순서`·`순서→역할`·`순서→지식`) |
| S03 우측 | `번호 순이 아님` → `번호가 곧 쓰는 순서임` · 콜아웃에 MSA 유추를 근거로 적음 |
| 상호 참조 | `④에서 시간 예산` → `③에서` · `출력 칸 이름 달라 ④가 못 붙임` → `③에 못 붙임` · `중단 조건 횟수는 ④가 씀` → `③이 씀` 등 4곳 |
| 새 콜아웃 2건 | ③에 "이 시점에 ④ 역할은 아직 없음 — 참여 주체는 ②에서 가져옴" · ④에 "③의 단계를 묶어 나눔" |

**아직 안 고친 것** — `guides/` 7종 · `prompts/architecture/` · `design/` 9종의 번호·파일명·연결도는
**교재와 어긋난 상태임.** 같은 판정을 그쪽에도 적용해야 함(파일명 교환 + `③④` 기호 전수 교체 +
각 가이드 1절 연결도 + `00-산출물규격.md` 임계 경로).

## 2차 검토와 재생성 기록 (2026-08-06)

1차 빌드 뒤 **20장을 전수 재확인**했고, 사용자 지적("이미지에 글씨가 없는 게 많다")이 사실로 확인됨.
**1차 생성 20장 중 6장이 큰 도형을 텅 빈 채로 그렸음.** 원인은 프롬프트에 "모든 도형에 라벨을
넣어라"를 안 쓴 것임. 규격 5절에 규칙 7 ~ 10으로 반영함.

| 이미지 | 무엇이 문제였나 | 어떻게 고쳤나 |
|--------|---------------|--------------|
| `s03` | 7개 막대가 전부 빈칸(숫자만) | 막대마다 `목표`·`구조`·`역할`·`지식`·`순서`·`관측`·`배포` 라벨을 넣음 |
| `s05` | 오른쪽 6개 카드가 빈칸 · 왼쪽 개수 12개(본문은 14건) | 카드에 번호 1 ~ 3 · 왼쪽을 14개로 맞추고 `지표 후보 14` 라벨 |
| `s09` | 우측 3개 박스가 전부 같은 `멀티` 라벨에 속은 빈칸 | 박스마다 번호 1 ~ 3을 넣고 좌측 단일에도 번호 3개 |
| `s10` | 도식은 `아니오`, 표는 `판정 불가`로 낱말이 갈림 | 도식 태그를 `불가`로 통일 · 후보안을 `안 A`·`안 B`로 구분 |
| `s11` | **본문은 5가지인데 도식은 4갈래**(사전 누락) | `사전` 박스를 넣어 5갈래로 맞춤 |
| `s13` | `착지` 화살표가 **거꾸로**(착지 → 다른 길) | `다른 길 → 착지 → 종료` 방향으로 다시 그림 |
| `s14` | 예산 기준선이 `3,420` 박스와 겹쳐 선이 끊김 | 기준선을 두 합계 박스 오른쪽으로 떼어 놓음 |
| `s15` | `우리 안` 내부 3개 박스와 외부 박스가 빈칸 | 내부에 번호 1 ~ 3 · 외부 박스에 `외부` 라벨 |
| `s17` | 저장소 실린더 3개(다른 장은 `저장소 6개`) | 실린더 6개 + 브래킷에 `저장소 6` 표기 |
| `s19` | 7개 문서 아이콘 빈칸 · `대조표`에 숫자 `7`이 들어가 오해 | 아이콘에 번호 · 대조표에는 표 기호와 `1장 더` 라벨 |
| `s20` | 점검표 5줄이 무텍스트 | 패널에 `점검표`·`통과` 라벨을 넣음 |
| `s06` | 판정 분류가 가이드와 어긋남(판정 J-2) | `1·3 → 책임 밖`, `2·4 → 공동 책임`으로 다시 그림 |

**텍스트도 함께 고침** — 도식과 표가 같은 대상을 다른 낱말로 부르던 곳을 통일했음.

| 슬라이드 | 고친 것 |
|---------|--------|
| S06 | `p95 3초 이내` → `3초 이내(95%)` · 콜아웃에 `p95`가 무슨 뜻인지 한 줄 |
| S12 | `하드필터` → `먼저 걸러내기` · 좌측에 `벡터 = 문서 검색` 병기 |
| S14 | 콜아웃에 `p95` 뜻풀이 |
| S15 | 콜아웃에 `토큰`이 무슨 뜻인지 한 줄 |
| S16 | 표 `오류 메시지` → `오류 로그`(도식과 통일) |
| S17 | 캡션 `덩어리 6개` → `런타임 5 + 앱 1`(저장소 6개와 헷갈리지 않게) |

**고치지 않고 남긴 것** — 이유를 적어 둠.

| 항목 | 왜 남겼나 |
|------|----------|
| S03 표가 7행(규격 5행 상한 초과) | 7종 전체를 한눈에 보이는 표가 이 장의 본체임. 행 높이를 재어 12pt 가독성은 확보됨 |
| S11 좌측 항목 5개(규격 4개 상한 초과) | 판정 J-1 — 가이드 판정 트리가 5갈래이고 런치픽이 실제 쓴 경로가 `사전` 1건뿐임 |
| S04·S08 우측 하단 여백 | 생성 이미지 **안쪽**의 여백임. 다시 만들면 도식 품질이 떨어질 위험이 더 큼 |
| 표지(`s01`) 무텍스트 | 표지 배경 아트로 의도한 것임 |

## 검증한 것과 안 한 것

**실제로 확인함**

| 항목 | 방법 | 결과 |
|------|------|------|
| 슬라이드 수 | pptx 압축 해제 후 `ppt/slides/` 개수 | 20개 |
| 슬라이드 크기 | `presentation.xml`의 `sldSz` | `14630400 × 8229600` EMU = 16″ × 9″ |
| 이미지 임베딩 | `ppt/media/` 개수 | 20개 전부 |
| 폰트 | 슬라이드 XML에서 금지 서체 검색 | `Calibri`·`Arial`·`맑은 고딕` 0건 |
| 최소 폰트 | 빌드 코드의 `fs12()` 강제 | 12pt 미만 0건(위반 시 빌드 실패) |
| 렌더링 | PowerPoint COM으로 20장 PNG 내보내기 | 20장 생성 · 육안 확인 |
| 이미지 한글 라벨 | 20장 전부를 열어 육안 확인(2회 — 1차 생성 후 · 재생성 후) | 깨짐 0건 · **빈 도형 6장을 찾아 재생성** |
| 슬라이드 전수 검토 | 렌더 20장을 리뷰어가 항목 7개로 점검 | HIGH 1건 · MED 13건 → 처리 후 재빌드 |

**안 한 것 — 정직하게 남김**

| 항목 | 내용 |
|------|------|
| Pretendard 실제 표시 | 서체 지정만 확인함. **뷰어에 Pretendard가 없으면 폴백 서체로 보임** |
| 수강생 대상 검증 | 초급자가 실제로 이해했는지는 **확인하지 않았음** |
| 예시의 성격 | 교재 예시로 쓴 런치픽 설계서 7종은 **미검증 설계**임(구현·호출·배포·측정을 하지 않음). S19에 1회 명시함 |
| 강의 시간 | 20장을 몇 분에 강의할 수 있는지 **재지 않았음** |

## 다시 만들 때

```bash
node textbook/build.js
```

- 이미지를 바꾸려면 `script/*.md`의 이미지 프롬프트를 고치고 `gpt-image-mcp`로 재생성해
  `images/`의 같은 파일명으로 덮어씀
- 슬라이드 문구를 바꾸려면 `build.js`의 `SLIDES` 배열을 고침(스크립트 `.md`도 함께 고쳐 둘을 맞춤)
- **좌측 열이 한계를 넘으면 빌드 시 경고가 뜸** — `⚠ Sxx 좌측 열이 …″ 까지 내려감`
