# 개발 환경 정보 기입란 — 개발 프롬프트 9종 공용 입력

> 개발 프롬프트 9종(`prompts/develop/01-*.md` ~ `09-*.md`)이 **공통으로 읽는 단 하나의 입력 파일**임.  
> 프롬프트를 실행하기 **전에** 이 파일을 먼저 채움. 여기가 비면 프롬프트가 시작 지점에서 막힘.

**이 파일이 설계서와 다른 점** — 설계서는 "무엇을 만들 것인가"를 정함.  
이 파일은 **"무엇으로 만들 것인가"**를 정함. 설계서에 없는 값만 여기에 둠.

---

## 1. 쓰는 법

- 이 파일을 복사하지 않고 **여기에 직접 값을 적음**. 프롬프트가 이 경로를 그대로 읽음
- 값을 모르면 빈칸으로 두지 않고 `프로젝트 확정 필요`라고 적음
- 값을 적은 행마다 **정한 사람과 날짜**를 함께 적음. 팀이 정한 값이면 `개발판단`이라고 적음

**차단 규칙** — 어떤 프롬프트를 실행할 때 그 프롬프트가 쓰는 변수가 `프로젝트 확정 필요`로
남아 있으면 프롬프트는 **코드를 만들지 않고 사용자에게 문의함.** 비운 채 진행하지 않음.

**설계서에 있는 값을 여기에 다시 적지 않음** — 모델 벤더·시간 상한·반복 상한·포트·비밀값 목록은
설계서가 주인임. 여기에 또 적으면 두 곳이 어긋났을 때 어느 쪽이 진짜인지 모르게 됨.

| 여기에 적는 것 | 설계서가 주인이라 여기에 안 적는 것 |
|---------------|--------------------------------|
| 언어 · 프레임워크 · 디렉터리 · 시험 도구 | 모델 벤더 · 모델명(④ 사용 모델) |
| 저장 백엔드 제품 · 배포 런타임 제품 | 시간 상한 · 재시도 · 반복 상한(③) |
| 환경변수 이름 규격 | 포트 · 비밀값 목록 · 배포 단위 수(⑦) |
| 관측 백엔드 제품 | 기록 항목 · 가릴 필드(⑤⑥) |

## 4. 기입 완료 점검

프롬프트를 돌리기 전에 아래를 확인함.

- [ ] `D-01` ~ `D-12` 중 이번에 돌릴 프롬프트가 쓰는 변수가 전부 채워졌는가
- [ ] `프로젝트 확정 필요`로 남은 행이 몇 개인지 숫자로 셌는가
- [ ] `D-05` 디렉터리 이름이 설계서 ②의 「내부 구성도」 노드 이름과 어긋나지 않는가
