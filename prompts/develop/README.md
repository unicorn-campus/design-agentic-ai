`output/design/`의 **설계서 7종을 입력으로 받아 코드를 만드는** 프롬프트 세트임.  
특정 서비스 전용이 아니라 **어느 프로젝트에나 씀**.

## 1. 이 프롬프트가 설계 프롬프트와 다른 점

| | 설계 프롬프트 `prompts/design/` | **개발 프롬프트(이 폴더)** |
|---|---|---|
| 판단 기준 | `guides/` 가이드 7종 | **없음 — 설계서가 이미 판단을 끝냈음** |
| 구현할 값 | (판단으로 만들어 냄) | `{출력 루트}`의 설계서 7종 |
| 프로젝트 값 | `prompts/design/_shared/프로젝트정보.md` `V-01` ~ `V-12` | `_shared/개발환경정보.md` `D-01` ~ `D-12` |
| 본문이 가리키는 것 | 가이드의 **절 번호** | 설계서의 **표 이름** |
| 산출물 | 마크다운 설계서 1건 | 실행되는 코드 + 시험 + README |

**왜 절 번호가 아니라 표 이름으로 가리키나** — 설계서는 문서마다 절 번호가 다름(①은 9절, ②는 10절).
절 번호로 가리키면 설계서가 조금만 길어져도 전부 어긋남. 반면 본문 표 이름은
`guides/README.md`의 「산출물 1건은 무엇으로 이뤄지나」가 7종 전부 고정하고 있음.

**프롬프트에는 값이 없음.** 프로젝트 값은 설계서와 `개발환경정보.md`에서만 옴.
그래서 설계서를 새로 만들면 같은 프롬프트로 다른 프로젝트 코드를 만들 수 있음.

## 3. 쓰는 순서

### 준비 (한 번만)

1. 설계서 7종을 먼저 끝냄(`prompts/design/`). 개발 프롬프트는 그 값을 읽음
2. `_shared/개발환경정보.md`를 열어 변수 12종을 채움
3. 모르는 값은 빈칸이 아니라 `프로젝트 확정 필요`로 적음

**여기를 건너뛰면 프롬프트가 코드를 만들지 않고 멈춤**(각 프롬프트 `[처리]` 1단계 차단 규칙).

### 실행

프롬프트 파일 **전체를 복사해** AI 코딩 도구에 붙여 넣음. 1건씩 순서대로 함.

```mermaid
flowchart LR
  P["설계서 ①~⑦<br/>+ 개발환경정보 D-nn"] --> R
  R["1 runtime"] --> D["2 dataset"]
  R --> C["4 connector"]
  R --> G["5 guardrail"]
  D --> K["3 knowledge"]
  K --> W["6 workflow"]
  C --> W
  G --> W
  W --> A["7 api-ui"]
  A --> Y["8 deploy"]
  A --> E["9 eval"]
```

| 규칙 | 내용 |
|------|------|
| 1이 먼저 | 상태 타입과 설정 규격을 뒤 프롬프트가 전부 가져다 씀 |
| 2 · 4 · 5는 병렬 가능 | 1이 끝나면 동시에 돌려도 서로 안 부딪힘 |
| 6은 3 · 4 · 5가 다 끝나야 | 담당자 모듈이 검색 · 도구 · 검사를 전부 부름 |
| 8 · 9는 병렬 가능 | 배포와 평가는 서로를 안 기다림 |

## 4. 실행 전에 알아 둘 4가지

| # | 규칙 | 왜 |
|---|------|-----|
| 1 | **설계서에 값이 있으면 그 값을 씀.** 없으면 지어내지 않고 되물음 | 짐작한 값 위에 코드를 세우면 나중에 전부 다시 씀 |
| 2 | **값의 주인을 넘지 않음** — 키 이름은 ④, 민감 필드 ID는 ⑤, 시간 상한 · 반복 상한은 ③ | 같은 값이 두 곳에 생기면 어느 쪽이 진짜인지 모르게 됨 |
| 3 | **설계서 문장을 코드 주석에 옮겨 붙이지 않음** | 코드는 값만 받음. 문장이 들어가면 설계서를 고칠 때 코드가 어긋남 |
| 4 | **context7 MCP를 코드 작성 직전에 씀** | 프레임워크 API 변화가 커서 기억으로 쓰면 안 맞음 |

## 5. 프롬프트 1건의 구성

`references/prompt-guide.md`의 8섹션 표준을 씀. `[예시]`까지 8개를 전부 채움.

| 섹션 | 무엇이 들어가나 |
|------|---------------|
| `[목표]` | 만들 코드 산출물 1문장. **프로젝트 이름을 쓰지 않음** |
| `[역할]` | `AGENTS.md` 팀원 인격 |
| `[맥락]` | 내 상황 · 담당 경계 · 값의 주인 · 결과물 독자 |
| `[입력]` | 우선순위 8행 표 + `없으면` 열 |
| `[처리]` | 1 시작 조건 확인 → 2 적용 판정 → 3 되묻기 → 4 이후 구현 → 시험 → README → 자가 점검 |
| `[출력]` | `D-05` 기준 경로 · 파일 목록 · 톤앤매너 |
| `[제약조건]` | MUST · MUST NOT · 완료조건(증거 기준) |
| `[예시]` | 형식만 보여 주는 표 + 해서는 안 되는 예 1건 |

**`[처리]` 앞 3단계는 9건이 똑같음.**

| 단계 | 하는 일 |
|:----:|--------|
| 1 | **시작 조건 확인** — `D-nn`과 주 입력 설계서가 있는지 봄. 없으면 **코드를 만들지 않고** 무엇이 비었는지 보고 |
| 2 | **적용 판정** — 설계서가 무엇을 채택했는지 읽음. 판정 결과를 먼저 보여 사용자가 되돌릴 수 있게 함 |
| 3 | **되묻기** — 설계서에 칸이 없는 항목을 기본값과 함께 물음. `기본값으로 진행`이라 하면 되묻지 않음 |

## 6. 자주 막히는 곳

| 증상 | 원인 | 할 일 |
|------|------|------|
| 프롬프트가 코드를 안 만들고 멈춤 | `개발환경정보.md`에 `프로젝트 확정 필요`가 남아 있음 | 그 변수를 채움. 비운 채 넘기지 않음 |
| 주 입력 설계서가 없다고 함 | 설계서를 아직 안 만들었음 | `prompts/design/`으로 먼저 그 설계서를 만듦 |
| 선행 설계서 인용 자리가 비어 있음 | 인용할 설계서가 아직 없음 | **정상임.** `[확인필요: 선행 미생성]`으로 두고 진행한 뒤 나중에 1회 갱신 |
| 키 이름이 설계서와 다름 | 개발이 새 이름을 지었음 | ④의 「입출력 형식」 이름을 그대로 베낌. 새 이름 금지 |
| 설계서가 안 고른 검색 방식까지 만들어짐 | `[처리]` 2단계 적용 판정을 건너뛰었음 | ⑤의 「비정형 경로」에서 채택한 방식만 만듦 |
| 시간 상한이 설계서와 다름 | 개발이 값을 새로 정했음 | ③이 값의 주인임. 안 맞으면 ③에 되돌려 물음 |

## 7. 이 세트가 다루지 않는 것

- **설계서 만들기** — `prompts/design/` 소관임
- **`references/dev-prompt-guide.md`의 제품·수치 고정값** — 참조 자료일 뿐 규칙이 아님.
  특정 모델 벤더 · 벡터 DB · 청크 크기 · 검색 가중치 · 평가 도구는 쓰지 않음.
  그 자리는 설계서와 `D-nn`이 채움
- **가이드 개선 3건** — 상태 병합 함수 · 병렬 합류 규칙 · 사람 확인 구현 형태는
  `guides/03-*` 3절에 열이 없어 되묻기로 임시 대응함.
  자세한 것은 작성계획 12절임
