# 개발 프롬프트 — 런치픽 v1 프론트엔드

> 용도: 아래 `[목표]` ~ `[예시]` 전문을 AI 코딩 도구에 붙여 넣어 프론트엔드 코드를 생성함  
> 준용: `references/prompt-guide.md`(8섹션 표준) · `references/dev-prompt-guide.md`(dp: 특화 규칙)  
> 채택 기술 모듈: dev-prompt-guide **3.9**(개발 디렉토리) + **3.1 · 3.2 중 프론트에 닿는 부분만**  
> 부분 채택 사유 — 3.1 · 3.2는 `모든 dp: 요청에 적용`이나 프론트엔드는 LangChain · LLM을 **직접 실행하지  
> 않고** 백엔드 API를 부름. 따라서 3.1의 `Structured Output 스키마 공유`와 `LCEL 실행 방식 선택`이  
> 낳는 **스트리밍 소비 규격**만 가져오고, LangGraph · 체크포인터 · 모델 파라미터는 넣지 않음.  
> 3.3 ~ 3.8은 미채택 — 도구 루프 · 검색 · 평가 · 수집은 전부 백엔드·검색 담당 프롬프트 소관임

> 실행 순서 — ① `gen-data` → ② `index-rag` → ③ `index-graphrag` → ④ `testset-rag` →  
> ⑤ `testset-graphrag` → ⑥ `backend` → ⑦ `frontend`.  
> ⑥ 백엔드는 ③까지 끝나면 ④⑤를 기다리지 않고 시작 가능함(평가는 백엔드를 막지 않음). ⑦ 프론트는 ⑥의 API 경계가 확정된 뒤 시작함

## [목표]
런치픽(LunchPick) v1 프론트엔드를 **React + Vite + TypeScript**로 구현하여, 제공된 프로토타입 HTML의
화면 구조를 컴포넌트로 옮기고 백엔드 API 5종을 붙인 동작 화면 · 시험 · README를 `src/v1/front/`에 산출함.

## [역할]
당신은 React · TypeScript 기반 프로덕션 프론트엔드 개발 경력 9년의 프론트엔드 개발자임.  
서버 스트리밍 응답(조각으로 나눠 오는 응답)을 화면에 안전하게 흘려 보내는 작업과,
디자인 시안을 컴포넌트 경계로 나누는 작업을 다수 수행했음.  
**빌드가 통과하는 것과 화면이 뜨는 것은 다른 일**이라는 원칙을 지킴 — 브라우저 콘솔 오류를 반드시 확인함.  
전문 용어는 처음 쓸 때 괄호로 쉬운 설명을 1회 붙임(예: SSE = 서버가 조각을 이어서 밀어 주는 통신 방식).

## [맥락]
- 내 상황: 같은 서비스의 v0 확인용 화면이 `src/front/`에 있으나 **디자인 시안 기반이 아니라 동작 확인용**임.
  이번 v1은 프로토타입 HTML을 근거로 화면을 다시 만들고 v1 백엔드 API에 붙이는 것임
- 대상 서비스: **런치픽 — 직장인 점심 메뉴 추천**. 수도권 오피스 25 ~ 35세 직장인 대상.
  위치 · 취향 · 컨텍스트(날씨 · 요일 · 시간대)를 근거로 **추천 3건 + 추천 이유 문장 + 확신 스코어**를 냄
- 결과물 독자: 이 코드를 받아 로컬에서 띄우고 화면을 고칠 프론트엔드 개발자
- 협업 경계 — 아래 담당 밖 영역은 **인터페이스만 가정하고 직접 만들지 않음**

| 영역 | 담당 | 프론트가 하는 일 |
|------|------|-----------------|
| 백엔드 API · LangGraph 워크플로우 · 가드레일 | `prompts/develop/backend.md` | 정의된 **엔드포인트 5종을 호출**하고 응답 · 오류를 화면에 표시함 |
| RAG · GraphRAG 검색 · 평가 | 검색 담당 프롬프트 | 아무것도 하지 않음. 검색 결과는 백엔드 응답에 실려 옴 |
| 합성 데이터 생성 | `prompts/develop/gen-data.md` | 아무것도 하지 않음 |

## [처리]

### 0. 시작 전 사용자 확인 3건

값을 정하지 않은 채 진행하지 않음. 기본값을 그대로 쓰기로 하면 되묻지 않고 넘어감.

| # | 무엇을 묻나 | 기본값 | 안 물으면 무엇이 막히나 |
|---|-----------|--------|----------------------|
| 0-1 | 코드 base directory | `src/v1/` | 산출 경로 접두가 어긋나 v0 화면을 덮어쓸 위험이 있음 |
| 0-2 | 백엔드 주소(개발 서버 프록시 대상) | `http://localhost:8080` | API 호출이 전부 실패함 |
| 0-3 | 프로토타입 HTML의 디자인 토큰(색 · 간격 · 서체)을 그대로 옮길지, 기존 v0 스타일에 맞출지 | 프로토타입을 그대로 옮김 | 화면이 시안과 달라져 검수에서 되돌아옴 |

`{base}`는 0-1에서 정한 값을 뜻하며 이 문서의 모든 산출 경로에 접두로 붙음.

### 1. 프로토타입 HTML 해체 — 먼저 하고 코드를 씀

1. `<프로토타입-HTML>` 전문을 읽고 **화면 요소 목록 표**를 먼저 만듦.
   열은 `요소 이름`·`역할`·`상태 유무(정적/상태 있음)`·`대응 컴포넌트명`·`프로토타입 위치(선택자 또는 줄)`임
2. 컴포넌트 경계는 **"상태를 들고 있는가"** 하나로 나눔. 상태가 없는 것은 표시 전용 컴포넌트로 둠
3. 프로토타입에 **없는 화면**(오류 · 빈 상태 · 로딩)은 지어내지 않고 표에 `프로토타입 미포함`으로 적은 뒤
   3-3절 규정대로 최소 형태로 만들고 그 사실을 README에 남김
4. 프로토타입의 인라인 스크립트로 된 동작은 그대로 옮기지 않고 **React 상태로 다시 씀**.
   `document.querySelector`로 DOM을 직접 만지는 코드를 남기지 않음

### 2. 프로젝트 구성

- 스택 고정 — **React 18 이상 + Vite + TypeScript**, 패키지 매니저는 **npm**
- `vite.config.ts`에 **`plugins: [react()]`를 반드시 넣음.** 빠지면 빌드는 통과하고 화면이 비게 됨
  (v0에서 실제로 난 사고임. 5-2절 완료조건이 이것을 콘솔 오류 0건으로 검사함)
- 개발 서버는 `/v1` · `/health` 경로를 0-2에서 정한 백엔드 주소로 **프록시**함(CORS 우회를 코드로 하지 않음)
- 디렉터리는 아래로 고정함(dev-prompt-guide 3.9절 `프론트엔드: front/`에 `{base}` 접두를 붙인 것임)

```
{base}/front/
├─ index.html
├─ vite.config.ts
├─ package.json
├─ tsconfig.json
├─ .env.example          # 실제 값이 든 .env는 커밋하지 않음
└─ src/
   ├─ main.tsx
   ├─ App.tsx
   ├─ api/               # 엔드포인트 호출 · SSE 소비 · 오류 정규화
   ├─ types/             # 백엔드 스키마와 짝이 되는 형 정의
   ├─ components/        # 표시 전용 컴포넌트
   ├─ features/          # 상태를 들고 있는 화면 단위
   └─ styles/
```

### 3. 화면 요구

#### 3-1. 요청 시각 선택

- 화면 상단에 **요청 시각 입력**을 둠. 기본값은 현재 시각임
- 이 값은 추천 요청뿐 아니라 **거절 · 새로고침 요청에도 함께 실림.** 빠지면 서버가 현재 시각으로
  다시 계산해 영업 시간 필터가 다르게 걸리고 후보가 통째로 사라짐(v0에서 실제로 난 사고임)
- 요청 시각이 점심 시간대 밖이면 후보 0건이 **정상 동작**임. 오류로 표시하지 않고 3-3절 빈 상태로 안내함

#### 3-2. 추천 카드 3건

- 카드 1건에 **식당 · 메뉴 · 추천 이유 문장 · 확신 스코어**를 함께 표시함.
  이유 문장과 스코어 중 하나라도 없으면 카드를 그리지 않고 그 건을 빈 카드로 두고 사유를 표시함
  (근거 없는 추천이 화면에 나가지 않게 하는 것이 목적임)
- 카드마다 **거절** 동작을 둠. 거절하면 `reject`를 부르고 대체 1건을 그 자리에 채움
- 목록 전체를 다시 받는 **새로고침** 동작을 별도로 둠
- 추천 1건에 대한 **만족 여부 피드백**을 보낼 수 있게 함

#### 3-3. 빈 상태 · 오류 · 로딩 3종

프로토타입에 없더라도 아래 3종은 반드시 만듦. 사용자가 다음에 무엇을 할지 알 수 있게 문구를 씀.

| 상태 | 언제 | 화면에 담을 것 |
|------|------|--------------|
| 빈 상태 | 후보 0건(영업 시간 밖 · 반경 내 없음 · 하드필터 전건 차단) | 이유 1줄과 **요청 시각을 바꿔 보라는 안내** |
| 오류 | 백엔드가 오류를 반환하거나 통신이 끊김 | 사람이 읽을 메시지 · 오류 코드 · `trace_id` **3종을 모두 표시**하고 다시 시도 동작을 둠 |
| 로딩 | 요청 전송 후 첫 조각이 오기 전 | 진행 표시. 스트리밍 중에는 받은 조각까지 먼저 그림 |

- `trace_id`를 화면에서 **복사할 수 있게** 둠. 문의 · 장애 추적의 유일한 연결 고리임
- 오류 메시지에 서버 원문 스택 · 내부 경로를 그대로 노출하지 않음

### 4. 백엔드 API 연동

`prompts/develop/backend.md` 8절이 단일 출처임. 아래와 다르면 백엔드 쪽 값을 따름.

| 메서드 · 경로 | 프론트가 보내는 것 | 프론트가 받는 것 | 소비 방식 |
|--------------|------------------|----------------|----------|
| `POST /v1/recommendations` | 회원 식별자 · 좌표 · **요청 시각** · 지역 코드 | 추천 3건 + 이유 + 스코어 + `trace_id` | SSE 스트리밍 |
| `POST /v1/recommendations/reject` | 추천 식별자 · 거절 식당 · **요청 시각** | 대체 1건 | SSE 스트리밍 |
| `POST /v1/recommendations/refresh` | 추천 식별자 · **요청 시각** | 추천 3건 재생성 | SSE 스트리밍 |
| `POST /v1/feedback` | 추천 식별자 · 만족 여부 | 접수 결과 | 단발 요청 |
| `GET /health` | — | 서비스 · 의존성 상태 | 단발 요청 |

- **형 정의를 손으로 두 벌 만들지 않음.** `{base}/front/src/types/`의 형은 백엔드 응답 스키마와
  **같은 이름 · 같은 필드**로 두고, 어긋나면 백엔드 스키마를 기준으로 고침
- **SSE 소비 규격**
  - 첫 조각이 오면 로딩을 끝내고 받은 만큼 먼저 그림
  - 중간에 끊기면 **받은 조각을 지우지 않고** 오류 표시를 함께 띄움. 화면을 비우지 않음
  - 사용자가 화면을 떠나거나 새 요청을 보내면 **앞 요청을 반드시 취소**함(`AbortController`).
    취소하지 않으면 늦게 온 응답이 새 결과를 덮어씀
  - 서버가 보낸 문자열을 **그대로 HTML로 넣지 않음**(`dangerouslySetInnerHTML` 금지).
    추천 이유 문장은 모델이 만든 값이므로 문자열로만 그림
- 오류는 `{base}/front/src/api/`에서 **한 벌로 정규화**함. 컴포넌트마다 따로 해석하지 않음

### 5. 시험 · 문서

#### 5-1. 시험

- 프레임워크: **Vitest + React Testing Library**. 화면 단위로 시험을 나눔
- **백엔드 호출은 전부 Mock/fixture로 대체함.** 실제 서버를 띄워야 하는 시험은
  `integration` 태그로 분리해 기본 실행에서 빠지게 함
  (dev-prompt-guide 2절의 `pytest` · `integration 마커` 규정을 프론트 스택에 대응시킨 것임.
  같은 절이 `프론트엔드는 요청 시 별도 명시`를 허용하므로 그 조항으로 처리함. 이 사실을 README에 1줄로 남김)
- 아래 5건은 **반드시** 시험으로 고정함
  1. 요청 시각을 바꾸면 요청 본문의 시각 값이 함께 바뀜
  2. 거절 · 새로고침 요청에 요청 시각이 실려 나감
  3. 후보 0건 응답에서 빈 상태가 뜨고 오류 화면이 뜨지 않음

**anti-example(금지)**

- `추천 카드를 적절히 배치함` — 무엇을 기준으로 배치하는지 없어 검증 불가임
- 거절 요청 본문에 요청 시각을 빼고 보냄 — 서버가 현재 시각으로 다시 계산해 후보가 사라짐(v0 실제 사고)
- `npm run build`가 통과했으므로 동작을 확인했다고 보고함 — 빌드는 통과하고 화면이 빌 수 있음(v0 실제 사고)
- 추천 이유 문장을 `dangerouslySetInnerHTML`로 그림 — 모델이 만든 문자열이므로 그대로 실행하지 않음
