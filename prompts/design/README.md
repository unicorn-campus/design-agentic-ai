# AI 앱 아키텍처 설계 프롬프트 7종

`guides/`의 설계 가이드 7종과 **1:1로 짝지은 작성 프롬프트**임.  
가이드는 사람이 읽고 스스로 판단하는 문서이고, 이 프롬프트는 **AI 코딩 도구가 산출물을
자동 생성하게 하는 지시문**임.

---

## 1. 프롬프트가 가이드를 어떻게 쓰나

**프롬프트에는 판단 기준이 없음.** 판단 기준·작성 규칙·점검표는 전부 가이드에 있고,
프롬프트는 그것을 **어떤 순서로 어디에 만드는가**만 정함.

| 가이드의 절 | 프롬프트가 쓰는 자리 |
|------------|--------------------|
| 1절 이 설계서가 답하는 질문 | 프롬프트 `[맥락]` — 왜 이걸 쓰는가 |
| 2절 시작 전 판정 | `[처리]`의 판정 단계 — 적힌 순서 그대로 돌리고 예/아니오와 이유를 남김 |
| 3절 설계항목 작성법 | `[처리]`의 작성 단계 — `설계항목` 열 = 채울 칸 목록, `무엇을 적나`의 **규격 한 줄**(형태·비면·주인·대조) = 값의 규격, 대시 불렛 = 작성 요령, `예시` = 모양 대조 |
| 4절 제출 전 자가 점검표 | `[제약조건]`의 완료조건 — 항목별 판정 표를 증거와 함께 제시 |
| 5절 다음으로 넘기는 값 | `[처리]`의 후행 소비처 단계 |

**가이드를 고쳐도 프롬프트는 그대로 씀.** 프롬프트가 가이드의 *내용*이 아니라 *절 번호*를
가리키기 때문임. 가이드의 절 구조 5개는 `guides/_shared/가이드-공통규격.md` 1절이 고정함.
2026-08-08에 가이드가 7절에서 5절로 줄어 이 프롬프트 8건의 절 참조를 함께 맞췄음.

산출물의 목차·부속 표 열 구성·근거 출처 약칭도 프롬프트에 베끼지 않고
`guides/README.md`를 참조함.

## 3. 쓰는 순서

### 준비 (한 번만)

1. `_shared/프로젝트정보.md`를 열어 변수 12종을 채움
2. 모르는 값은 빈칸이 아니라 `프로젝트 확정 필요`로 적음
3. 값을 적은 행마다 근거 출처를 함께 적음

**여기를 건너뛰면 ⑦ 배포가 시작 지점에서 막힘.** 비밀값 도출이 `V-07`에 걸려 있음.

### 실행

프롬프트 파일 **전체를 복사해** AI 코딩 도구에 붙여 넣음. 1건씩 순서대로 함.

```
① → ② → ③ → ④ ⇄ ⑤ → ⑥ → ⑦
```

```mermaid
flowchart LR
  P["_shared/프로젝트정보.md<br/>변수 12종"] --> C1
  C1["① 목표/품질 카드"] --> C2["② 논리아키텍처"]
  C2 --> C3["③ 패턴/시퀀스"]
  C3 --> C4["④ 역할계약서"]
  C4 <-->|"왕복 1회"| C5["⑤ 지식/도구"]
  C5 --> C6["⑥ 가드레일/관측"]
  C6 --> C7["⑦ 배포"]
  C3 -.->|"분해 결과 회신"| C1
```

**되돌아가는 자리 2곳** — 이 두 번만 앞 산출물을 다시 엶.

| 언제 | 무엇을 고치나 |
|------|-------------|
| ③이 끝난 뒤 | ①의 분해 회신 칸을 1회 갱신함. 안 하면 ①은 결과를 모른 채 닫힘 |
| ⑤가 끝난 뒤 | ④의 민감 필드 ID 인용을 1회 갱신함. **왕복은 1회로 끝냄** |

## 4. 실행 전에 알아 둘 3가지

| # | 규칙 | 왜 |
|---|------|-----|
| 1 | **값이 없으면 지어내지 않음.** `[확인필요: 무엇]`으로 적고 미확정 항목 표에 1행 남김 | 숫자가 없는 상태를 드러내는 것이 채워 넣는 것보다 나음 |
| 2 | **값의 주인을 넘지 않음.** 뒤 산출물이 소유한 값을 앞에서 확정하지 않음 | 같은 값이 두 문서에 생기면 어느 쪽이 진짜인지 모르게 됨. 소유 관계는 `guides/README.md`의 소유 관계 표 |
| 3 | **점검표 판정 표 없이 완료 보고를 받지 않음** | 실제 설계 테스트에서 칸의 개수만 보는 점검이 칸 사이의 모순을 통과시켰음 |

## 5. 자주 막히는 곳

| 증상 | 원인 | 할 일 |
|------|------|------|
| ⑦ 배포가 비밀값을 못 뽑음 | `V-07` 기술 스택 6행이 비어 있음 | 프롬프트 ⑦의 3단계가 대체 출처로 도출함. 비운 채 넘기지 않음 |
| ④ 역할계약서가 ⑤를 기다림 | ⑤가 아직 없음 | **정상임.** `[확인필요: 선행 미생성]`을 적고 진행한 뒤 ⑤ 완료 후 1회 갱신 |
| ⑥의 타임아웃이 ③과 다름 | ⑥에서 값을 새로 적었음 | ⑥은 인용만 함. 안 맞으면 ③의 `변경요청` 표에 1행 남김 |
| 산출물에 가이드 문장이 그대로 들어감 | 가이드를 복사했음 | 산출물은 **이 프로젝트의 값만** 담음. 가이드 문장을 옮기지 않음 |
| 가이드의 `예시` 열 값이 산출물에 남음 | 3절 `예시` 칸을 베꼈음 | 그 칸은 값이 아니라 **형태**를 보여 주는 자리임 |

## 6. 이 프롬프트 세트가 다루지 않는 것

- **7종이 다 끝난 뒤 만드는 `00-반영대조표.md`** — 대응 가이드가 없어 이번 범위에서 제외함
  (`guides/README.md`의 「산출물 1건은 무엇으로 이뤄지나」 절 마지막 문단 참조)
- **설계서의 검증** — 산출물 7종은 구현·호출·배포·측정을 하지 않은 설계임.
  ⑥⑦은 문서 머리에 `미검증 설계`로 적음
