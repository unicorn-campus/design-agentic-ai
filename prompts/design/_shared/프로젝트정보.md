# 프로젝트 정보 기입란 — 설계 프롬프트 7종 공용 입력

> 설계 프롬프트 7종(`prompts/design/01-*.md` ~ `07-*.md`)이 **공통으로 읽는 단 하나의 입력 파일**임.  
> 프롬프트를 실행하기 **전에** 이 파일을 먼저 채움. 여기가 비면 뒤 산출물이 시작 지점에서 막힘.

---

## 1. 쓰는 법

- 이 파일을 복사하지 않고 **여기에 직접 값을 적음**. 프롬프트가 이 경로를 그대로 읽음
- 값을 모르면 빈칸으로 두지 않고 `프로젝트 확정 필요`라고 적음
- 값을 적을 때는 **근거 출처를 같은 행에 함께 적음**. 출처 표기 형식은
  `guides/README.md`의 「근거 출처 표기법」을 따름
- 팀이 정한 값이면 출처 칸에 `설계판단`이라고 적음

**차단 규칙** — 어떤 프롬프트를 실행할 때 그 산출물이 쓰는 변수가 `프로젝트 확정 필요`로
남아 있으면 프롬프트는 **작성을 시작하지 않고 사용자에게 문의함.** 비운 채 진행하지 않음.

**적힌 값을 그대로 믿지 않음** — 실제 테스트에서 잘못 적힌 값 때문에 없는 데이터 위에 설계가
선 사례와, `0건`으로 적힌 점검 항목이 실은 해당했던 사례가 있었음.  
두 사례의 내용은 `guides/README.md`의 「시작 전에 반드시 채울 것」 절에 있음. 그 절을 읽고
`V-04`·`V-10`은 **기획 산출물 원문에서 다시 확인한 뒤** 씀.

### V-07 기술 스택 6행

**6행을 지우지 않음.** 안 쓰는 행은 `해당 없음`이라고 적음.  
**행 이름은 `guides/07-배포설계-가이드.md` 2-3절 표의 `스택 행`과 1:1로 맞춰 둠** —
⑦ 배포가 행마다 비밀값을 뽑으므로 이름이 어긋나면 대응이 끊김.  
`프로젝트 확정 필요`로 남으면 ⑦ 배포가 가이드 2-3절의 대체 출처로 도출함.

| 2 | 정형 접근 | 프로젝트 확정 필요 | |
| 3 | 비정형 접근 | 프로젝트 확정 필요 | |
| 4 | 도구 연결 규격 | 프로젝트 확정 필요 | |
