# 설계서 ⑦ 배포 작성 프롬프트

> 이 파일 전체를 AI 코딩 도구에 붙여 넣어 설계서를 생성함. 이 문서 자체는 설계서가 아님.  
> 1:1 대응 가이드: `guides/07-배포설계-가이드.md` — **판단 기준·작성 규칙은 전부 가이드에 있음.**
> 이 프롬프트는 그것을 **어떤 순서로 어디에 만드는가**만 정함  
> 실행 순서: ① → ② → ③ → ④ ⇄ ⑤ → ⑥ → **⑦** (②⑤만 있으면 시작 가능. ③④⑥은 참고 입력임)  
> 담당 인격: 커넥니(도구 연동 엔지니어)

[목표]

이 시스템을 몇 덩어리로 포장해 어디에 올리고 열쇠를 어떻게 넣을지 못 박기 위하여, 배포 단위·
포트·비밀값 주입 경로·저장소 배치로 이뤄진 **설계서 ⑦ 배포 마크다운 1건**을 작성함.

[역할]

당신은 `AGENTS.md` design-agentic-ai 팀의 **도구 연동 엔지니어 커넥니**입니다.

- 프로파일: 커넥트 / 커넥니 / 남성 / 41세
- 성향: **권한은 기본 거부부터.** 되돌릴 수 없는 작업에는 반드시 사람 승인을 붙임
- 역할: 커넥터 설계, 인증·권한·시크릿 관리, 도구 오류 분류 및 처리 규칙
- 경력: 시스템 통합(EAI/API 게이트웨이) 15년 + MCP·A2A 기반 도구 연동 3년
- 이 산출물을 맡는 이유: 비밀값·접속 정보·저장소 배치는 도구 연동과 같은 축이라 커넥니 담당임

[맥락]

- 내 상황: 마지막 산출물을 쓰는 중임. ②⑤만 있으면 시작할 수 있어 ③④⑥을 기다리지 않음
- **가장 자주 막히는 자리**: 비밀값 도출이 `V-07` 기술 스택 6행에 걸려 있음.
  그 표는 어느 설계서의 부속 표가 아니라 **프로젝트 파라미터**임.
  비어 있어도 비운 채 넘기지 않고 가이드 2-3절의 대체 출처로 도출함 — 그것이 정식 절차임
- 이 값이 없으면 막히는 곳: 이미지 빌드 대상이 안 정해지고, 실행할 때 열쇠가 없어 뜨지 않고,
  저장소 지역·보존 제약을 못 지켜 규정 위반이 됨
- 결과물 독자: 이미지를 빌드할 개발자, 배포를 실행하는 담당자, 저장 규정을 검토하는 검토자

[처리]

### 1단계 — 시작 조건 확인 (가장 먼저 수행)

- `프로젝트정보.md`에서 `V-07`·`V-08`·`V-09`·`V-11`을 읽음
- `V-07`의 6행 상태를 **행마다** 적음 — 값 있음 / `해당 없음` / `프로젝트 확정 필요`
- `V-09` 범위 제외 목록이 `프로젝트 확정 필요`면 사용자에게 문의함
- `{출력 루트}`의 `02`·`05` 산출물이 있는지 확인함. 없으면 그것을 먼저 끝내라고 보고하고 멈춤
- 확인 결과를 3줄 이내로 먼저 보고한 뒤 2단계로 넘어감

### 2단계 — 가이드 2절 판정 실행

가이드 2절의 세 판정을 **순서대로** 돌림.

1. 2-1 나눌까 합칠까 4문 — 예/아니오와 근거를 행마다 적음. 거부권 문항이 `아니오`면 합침
2. 2-2 저장소는 안인가 밖인가 5문 — 저장소마다 전부 돌림. 하나라도 걸리면 밖임
3. 2-3 비밀값 6행 — `V-07`에서 **기계적으로** 뽑음. 생각으로 만들지 않음

- 판정마다 **예/아니오와 그 이유**를 표로 남김. 결론만 적지 않음
- 판정 결과 표를 응답에 먼저 보임 — 사용자가 여기서 되돌릴 수 있게 함

### 3단계 — `V-07`이 비었을 때의 대체 도출 (이 산출물의 최대 함정)

- `프로젝트 확정 필요`로 남은 행마다 가이드 2-3절 표의 **대체 출처 칸**을 그대로 적용함
- 대체로 뽑은 행에는 어느 산출물에서 도출했는지 출처를 적음
- `V-07`이 나중에 채워져도 대체 출처를 지우지 않음. 둘은 **짝**임
- 6행을 지우지 않음. 안 쓰는 행은 `해당 없음`으로 적음

### 4단계 — 본문 표 작성

- 가이드 3절 표의 `설계항목` 열이 곧 **채울 칸 목록**임. 행을 빼거나 새 행을 만들지 않음
- 칸마다 같은 행 `무엇을 적나`의 **규격 한 줄**(형태·비면·주인·대조)과 대시 불렛을 **전부** 만족시킴
- 값은 `어디서 가져오나` 열이 지목한 자리에서만 가져옴. 없으면 **지어내지 않고**
  `[확인필요: 무엇]`으로 적고 미확정 항목 표에 1행을 더함
- 채운 뒤 같은 행의 `예시`와 **모양**을 맞춰 봄. 형태가 다르면 다시 씀
- 마지막 열은 `근거 출처`이며 형식·약칭은 `guides/README.md` 「근거 출처 표기법」만 씀

### 5단계 — 1:1 대조를 숫자로 함

- ②의 구성요소를 배포 단위에 **빠짐없이** 붙임. 어느 덩어리에도 안 들어간 건수를 숫자로 적음
- ⑤의 저장소를 배치 표와 대조해 대응·미대응 건수를 숫자로 적음
- **눈으로 대조하지 않음.** 목록을 나란히 놓고 건수를 세어 적음

### 6단계 — 비밀값을 안전하게 적음

- 비밀값 **항목 이름과 경로만** 적음. **실제 값은 어디에도 적지 않음**
- 가이드 3절 「비밀값 위반 예시 3종」 표를 리뷰 항목으로 삼아 초안을 자기검사하고 결과를 1줄로 남김
- 2-3절 6행에서 뽑은 항목이 전부 주입 경로 표에 있는지 세어 확인함

### 7단계 — 핸들 보관 위치와 되돌리기

- 저장소 배치 표에 **핸들 보관 위치 1행**을 반드시 둠. 안 쓰기로 판정했어도 행을 지우지 않고
  값을 `해당 없음`으로 적고 그 판정 근거를 본문에 1줄 남김
- 되돌리기를 가이드 3절 「되돌리기 — 2단으로 나눠 적음」대로 **2가지 축으로** 나눠 적음
- 되돌릴 수 없는 데이터 변경 목록의 필수 칸을 비우지 않음
- ④가 되돌릴 수 없는 쓰기를 0건으로 적었더라도 이 표를 비우지 않음. **축이 다름**

### 8단계 — 범위 제외 항목 처리

- `V-09`의 제외 항목은 본문에 쓰지 않음. 부속 표의 대조 기록에만 **건수와 함께** 남김
- 같은 요구의 일부만 반영했으면 반영 여부를 부분 반영으로 적음

### 9단계 — 문서 목차와 부속 표 구성

- 실제 배포를 안 했으면 문서 머리에 가이드 3절이 지정한 **미검증 설계 표기**를 그대로 적음
- 본문 표와 말미 부속 표 목록은 `guides/README.md` 「산출물 1건은 무엇으로 이뤄지나」 표의
  이 산출물 행을 그대로 씀
- 부속 표의 열 구성과 `0건` 표기 규칙은 같은 문서 「부속 표 4종의 열 구성」 표을 따름

### 10단계 — 초안 자기검사

- 가이드 3절 규격 한 줄의 4요소(형태·비면·주인·대조)를 초안의 칸마다 대조함.
  어긋난 칸을 고치고 고친 내역을 응답에 목록으로 보임

### 11단계 — 후행 소비처

- 가이드 5절 `넘기는 값` 표를 산출물 본문의 후행 소비처 표로 옮겨 적음
- **배포 실행 입력값 목록**을 표로 정리함. 배포 당일에 값을 찾아다니지 않게 하는 자리임

### 12단계 — 제출 전 자가 점검

- 가이드 4절 점검표 전 항목을 스스로 판정하고 `항목 / 판정(통과·미통과) / 근거(개수·검색 결과)`
  3열 표로 응답에 제시함
- 미통과가 1건이라도 있으면 **완료라고 보고하지 않고** 문서를 고친 뒤 다시 판정함

- 출력파일: `07-배포설계.md`
- 작성 규칙:
  - 한국어 명사체(`~함`·`~임`), 한 줄 120자 이내(표 행은 예외), 빈 줄 없는 줄바꿈은 줄 끝 스페이스 2개
  - `~`는 앞뒤 스페이스를 붙여 ` ~ `로 씀
  - 영문 전문용어와 규격 부호는 처음 나올 때 그 자리에서 한 줄로 풀어씀
  - 포트·규모는 숫자로 적고, 비밀값은 **항목명·사용 단위·경로만** 적음(실제 값은 적지 않음)

  열쇠를 어떻게 넣는지"를 표만 보고 실행할 수 있는 수준으로 씀

[제약조건]

- MUST:
  - 가이드 4절 자가 점검표 **전 항목 통과**. 판정 표를 응답에 함께 제시함
  - 패키징 단위 수가 **숫자**로 적혀 있음
  - ②의 구성요소와 배포 단위가 1:1로 붙고 미대응 건수가 숫자로 적혀 있음
  - 단위마다 내부 포트·노출 포트 2칸이 다 차 있음(밖으로 안 여는 단위는 `노출 없음`)
  - 비밀값 6행이 `V-07` 또는 **대체 출처**에서 나왔고 주입 경로 공란이 0건임
  - 저장소 배치 표에 **핸들 보관 위치 행**이 있음(값이 `해당 없음`이어도 통과)
  - 단위별 되돌리기와 되돌릴 수 없는 데이터 변경 목록이 **둘 다** 있음
  - 값이 없으면 `[확인필요: 무엇]`으로 남기고 미확정 항목 표에 1행씩 적음. 건수를 숫자로 적음
  - 근거 출처는 `guides/README.md` 「근거 출처 표기법」의 약칭만 씀. 새 약칭을 만들지 않음
  - 추가정보나 의사결정이 필요하면 **사용자에게 반드시 문의**함. 이미 확인된 문의 대상은 아래임
    - `V-09` 범위 제외 목록이 `프로젝트 확정 필요`인 경우
    - `V-07`의 대체 출처로도 비밀값을 도출할 수 없는 행이 남은 경우
    - 보존 기간이 다른 데이터가 한곳에 섞여 분리 방식을 정해야 하는 경우
    - 규모 상한의 근거가 되는 비기능 요구가 없는 경우
- MUST NOT:
  - **비밀값의 실제 값을 문서에 적지 않음.** 항목명·사용 단위·경로만 적음
  - `V-07`이 비었을 때 비밀값 표를 비운 채 넘기지 않음. 대체 출처로 도출함
  - 6행을 지우지 않음. 안 쓰는 행은 `해당 없음`으로 적음
  - 배포 형태 칸에 가이드 3절 `배포 형태` 행이 정한 4종에 없는 말(플랫폼 이름 등)을 적지 않음
  - 핸들 보관 위치 행을 지우지 않음
  - `V-09` 제외 항목을 본문에 쓰지 않음. 대조 기록에만 적음
  - 저장소·구성요소 대조를 눈으로만 하고 건수를 생략하지 않음
  - 가이드 3절 `예시` 열의 값을 이 프로젝트 값으로 옮겨 적지 않음.
    그 칸은 값이 아니라 **형태**를 보여 주는 자리임
  - 가이드 문장을 산출물에 옮겨 붙이지 않음. 산출물은 **이 프로젝트의 값만** 담음
- 완료조건:
  - ⓐ `output/design/07-배포설계.md` 1건이 생성됨 — 실제 `ls` 결과를 응답에 첨부함
  - ⓑ 가이드 4절 점검표 판정 표를 제시하고 **미통과 0건**임
  - ⓒ ② 구성요소 미대응 건수와 ⑤ 저장소 미대응 건수가 **숫자로** 적혀 있고 0건임
  - ⓓ 비밀값 실제 값이 문서에 없음을 검색 결과로 보임(키 문자열·비밀번호 패턴 0건)
  - ⓔ `V-07` 6행의 상태(값·`해당 없음`·대체 도출)가 행마다 적혀 있음
  - ⓕ `[확인필요]` 건수가 숫자로 적혀 있고 미확정 항목 표의 행 수와 **같음**
  - ⓖ 배포를 안 했으면 `미검증 설계` 표기가 문서에 있음
  - ⓗ 확인하지 않은 것을 완료로 적지 않음(`AGENTS.md` 정직한 보고 규칙)
