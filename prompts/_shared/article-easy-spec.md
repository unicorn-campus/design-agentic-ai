## 0. 두 산출물의 차이

| 구분 | 정리본 `A{NN}_{유형}_{슬러그}.md` | **해설본 `A{NN}_easy_{슬러그}.md`** |
|------|--------------------------------|----------------------------------|
| 목적 | 교재 집필자가 인용을 찾는 참조용 | 강사·수강생·팀원이 내용을 이해하는 학습용 |
| 독자 | 원문을 곧 읽을 사람 | 원문을 읽지 않을 사람 |
| 문체 | 기술 문서체, 앵커·인용 중심 | 쉬운 설명체, 비유·그림 중심 |
| 출처 앵커 | 모든 사실 문장에 필수 | **사용 금지**(읽기 흐름 우선) |
| 이미지 | 없음 | **2 ~ 6개 필수** |
| 커리큘럼 대응 | 5절에 상세 표 | 1문단으로만(중복 금지) |
| 분량 | 120 ~ 250줄 | 150 ~ 350줄 |

- 두 문서는 서로를 참조함. 해설본은 마지막 절에 `정리본: A{NN}_{유형}_{슬러그}.md` 1줄을 둠
- **같은 내용을 두 번 쓰지 않음** — 해설본에 인용표·앵커를 넣지 않고, 정리본에 비유·그림을 넣지 않음

## ① 해설본 섹션 구조

고정 섹션 8개. 제목 문자열을 **글자 그대로** 사용함.

| 순서 | 섹션 제목(고정 문자열) | 무엇을 쓰는가 | 분량 상한 |
|------|----------------------|--------------|----------|
| 0 | `# A{NN} {한국어 제목} — 쉬운 해설` | H1 1줄 | 1줄 |
| 1 | `## 한 줄 요약` | 이 글이 답하는 질문 1문장 + 그 답 1문장 | 4줄 |
| 2 | `## 3분 요약` | 이것만 읽어도 되는 핵심. 불릿 5개 이하, 각 2줄 이내 | 12줄 |
| 3 | `## 왜 우리에게 중요한가` | 우리 교육 2건과의 연결. **1문단**(정리본 5절과 중복 금지) | 8줄 |
| 4 | `## 본문 풀이` | 원문 목차 순서를 따라 쉬운 말로 풀어씀. 아래 소제목 규칙 적용 | 150줄 |
| 5 | `## 그림으로 보기` | 이미지 2 ~ 6개와 캡션 (③ 규칙 적용) | 60줄 |
| 6 | `## 용어 풀이` | 영문 전문용어를 우리말로. `용어 / 우리말 / 한 줄 설명` 3열 표 | 표 12행 |
| 7 | `## 헷갈리기 쉬운 곳` | 오해하기 쉬운 지점과 바로잡기. 불릿 3 ~ 5개 | 20줄 |
| 8 | `## 원문 정보와 확인 범위` | URL · 발행일 · 접근 방법 · 확인 상태 · 못 본 것 · 정리본 링크 | 15줄 |

**4절 소제목 규칙** — 원문 목차를 그대로 따라감. 형식은 아래로 고정함.

```
### {번호}. {한국어로 옮긴 제목} — {원문 소제목 그대로}
```

- 원문 헤딩(H2·H3)을 순서대로 옮기되, 본문과 무관한 항목(`Related posts`, `Cookie settings`,
  `Acknowledgements`, 사이트 네비게이션)은 제외함
- 원문 소제목이 10개를 넘으면 성격이 같은 것을 묶고, 묶은 사실을 8절에 1줄 기록함

**총 분량** — 1건당 **150 ~ 350줄, 15,000자 이내**. 하한 미달은 미완성으로 봄.

## ② 쉬운 언어 검증 규칙

`CLAUDE.md` Lessons Learned의 `[Highly Important] 쉬운 언어 사용`을 측정 가능한 규칙으로 편 것임.

- **E1 문장 길이** — 한 문장 60자 이내를 원칙으로 함. 표·코드블록·인용은 제외.
  60자를 넘는 문장이 전체 문장의 10%를 넘지 않아야 함
- **E2 용어 풀이 의무** — 영문 전문용어가 처음 나오면 ① 그 자리에서 한 줄로 풀어쓰고
  ② 6절 용어 풀이 표에 반드시 등재함. 표에 없는 전문용어가 본문에 있으면 규칙 위반임
- **E3 비유·예시 최소 3개** — 추상적 개념 3개 이상에 대해 일상 비유 또는 우리 교육 케이스
  (마이데이터 금융상품 추천 / 카드사 상담)를 든 예시를 붙임
- **E4 앵커 금지** — `[§3.2]` 같은 출처 앵커를 쓰지 않음. 위치 표시가 필요하면
  4절 소제목의 원문 제목으로 대신함
- **E5 인용 최소화** — 원문 직접 인용은 **최대 2건**, 각 영문 40단어 / 국문 100자 이내.
  인용이 더 필요하면 해설본에 넣지 않고 정리본으로 넘김
- **E6 코드 최소화** — 코드블록은 최대 2개, 각 15줄 이내. 코드 대신 말로 설명할 수 있으면 말로 씀
  (Mermaid 다이어그램은 코드블록 수에 포함하지 않음)
- **E7 독자 수준** — 비전공 신입 사원이 사전 지식 없이 읽고 이해하는 수준을 기준으로 함
- **E8 정직성** — 원문에 없는 내용을 추가할 때는 문장 앞에 `(해설자 보충)`을 붙임.
  원문이 말하지 않은 결론을 원문 주장처럼 쓰지 않음

## ③ 원문 접근과 이미지 규칙 — 실측 기반

### 실측 결과 (2026-08-05, A01 원문으로 검증)

| 수단 | 결과 |
|------|------|
| `mcp__claude-in-chrome__get_page_text` | **실패** — `No text content found` 반환 |
| `mcp__claude-in-chrome__computer` + `save_to_disk:true` | **파일 경로 미반환.** Downloads·TEMP에서 파일 못 찾음 |
| `mcp__pw__browser_evaluate` (textContent, style·script 제거) | **성공** — 본문 23,856자 · 헤딩 22개 확보 |
| `mcp__pw__browser_take_screenshot` (`filename` 지정) | **성공** — 지정 경로에 PNG 실제 저장 확인 |

→ **Playwright MCP(`mcp__pw__*`)를 주 경로로 채택함.** Chrome 확장은 Playwright 실패 시 폴백임.

### 원문 접근 절차 (순서 고정)

1. `ToolSearch`로 도구 로드:
   `select:mcp__pw__browser_navigate,mcp__pw__browser_evaluate,mcp__pw__browser_take_screenshot,mcp__pw__browser_close,mcp__pw__browser_wait_for`
2. `browser_navigate`로 원문 URL 이동
3. `browser_evaluate`로 **목차 먼저 확보** — 이 목차가 4절 본문 풀이의 뼈대가 됨
4. `browser_evaluate`로 **본문 확보** — `style` · `script` · `noscript` 제거 필수
5. 이미지 목록 확보 후 ③ 이미지 규칙 적용
6. 작업이 끝나면 `browser_close`로 정리함
7. Playwright가 실패하면 `mcp__claude-in-chrome__*` → `curl -sL` 순으로 폴백하고,
   어느 수단으로 확보했는지 8절에 기록함

본문·목차 추출 스니펫(그대로 사용 가능):

```js
() => {
  const a = document.querySelector('article') || document.querySelector('main') || document.body;
  const c = a.cloneNode(true);
  c.querySelectorAll('style,script,noscript,nav,footer').forEach(e => e.remove());
  const text = c.textContent.replace(/\s+/g, ' ').trim();
  const headings = [...document.querySelectorAll('h1,h2,h3')]
    .map(h => h.tagName + '|' + h.textContent.trim()).filter(x => x.length > 4);
  const figures = [...document.querySelectorAll('figure, article img, main img')]
    .map(e => ({ tag: e.tagName, src: e.getAttribute('src') || '', alt: e.getAttribute('alt') || '' }));
  return { len: text.length, headings, figures, text: text.slice(0, 20000) };
}
```

### 이미지 저장·표기 규칙

- 저장 위치: `references/articles/easy/images/` (자료별 하위 폴더 없이 평면 배치)
- 파일명: `{ID}-{순번2자리}-{내용슬러그}.png` (예: `A05-01-reference-architecture.png`)
- 마크다운 삽입: 상대경로 `![{대체텍스트}](images/A05-01-reference-architecture.png)`
- **원문 이미지 내려받기 요령** — CDN이 서명 파라미터를 요구하는 경우가 있음(LangChain 문서의
  mintcdn이 그러함. 쿼리스트링을 자르면 `Invalid query parameters` 반환).
  저장한 HTML의 `<img src>`를 **`&amp;` 디코딩해 통째로** 사용하고 `Referer` 헤더를 붙임
- **캡션 필수** — 이미지 바로 아래 1줄. 출처를 반드시 구분함

```
> 그림 1. {무엇을 보여주는 그림인지} — 원문 「{원문 소제목}」 캡처 (2026-08-05 조회)
> 그림 2. {무엇을 보여주는 그림인지} — **정리자 작도. 원문에 없는 그림임**
```

- **자체 작도한 그림에 `정리자 작도. 원문에 없는 그림임`을 반드시 붙임.**
  이 표기가 빠지면 원문 그림으로 오독되므로 규격 위반임
- 이미지 개수: **`## 그림으로 보기` 섹션 기준 2 ~ 6개**. 4절 본문 풀이의 핵심 개념을 우선 그림으로 만듦
  - **본문 풀이(4절) 안에 넣는 삽화는 이 개수에 포함하지 않음.** 항목마다 그림이 붙는 편이
    이해에 낫다면 본문에 직접 넣어도 됨(A02 패턴 5종이 그 사례임)
  - 본문 삽화도 캡션 규칙은 동일함. 원문 그림이면 `*원문 「{소제목}」 그림 캡처 ({조회일} 조회)*`,
    자체 작도면 `정리자 작도. 원문에 없는 그림임`을 붙임
- 이미지를 확보하지 못하면 `> 그림 미확보 — {사유}` 1줄로 남기고 빈칸으로 두지 않음
- **저작권** — 본 문서는 대외 공개·외부 전송 금지 자료임(`recommend-materials.md` 머리말).
  원문 캡처 이미지는 내부 교육 목적 인용이며, 캡션에 출처 URL을 남기고 외부 배포하지 않음.
  캡처 대상은 이해에 필요한 최소 범위로 한정함

### 확인 상태 표기

정리본과 같은 4단계를 씀 — `FULL` / `PARTIAL` / `META` / `FAIL`.
`META` 이하이면 2 ~ 7절을 작성하지 않고 1·8절에 사유만 남김.

```text

- 목적이 다름 — 산출물 1(정리본)은 교재 집필자가 인용을 찾는 참조용이고,
  산출물 2(해설본)는 원문을 읽지 않을 사람이 내용을 이해하는 학습용임.
  같은 내용을 두 번 쓰지 않음. 해설본에는 출처 앵커·인용표를 넣지 않음
- 원문 접근은 **Playwright MCP를 주 경로**로 사용함 (2026-08-05 실측으로 확정)
  - `ToolSearch`로 도구 로드:
    `select:mcp__pw__browser_navigate,mcp__pw__browser_evaluate,mcp__pw__browser_take_screenshot,mcp__pw__browser_close,mcp__pw__browser_wait_for`
  - `browser_navigate` → `browser_evaluate`로 **목차 먼저** 확보 → 본문 확보 → 이미지 처리 → `browser_close`

    `textContent`를 사용함(`innerText`는 렌더 문제로 0자가 나올 수 있음 — 실측 확인됨)
  - 실패 시 `mcp__claude-in-chrome__*` → `curl -sL` 순으로 폴백하고 확보 수단을 8절에 기록함
