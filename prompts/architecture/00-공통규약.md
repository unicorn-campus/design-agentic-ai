프롬프트 7건이 공유하는 항목임. 각 프롬프트는 아래를 전제로 하며 중복 기재하지 않음.

**프롬프트 헤더 형식(3줄 고정)** — 프롬프트 파일 7건(01-목표품질속성카드.md~07-배포설계.md) 각 프롬프트의 `text` 코드블록 직전에 아래 3줄을 둠.

| 줄 | 형식 | 미기입 시 |
|----|------|----------|
| 1 | **작성 시점** — {작성 체제·병렬 순번 표}의 {W-n}({수행 형태}). 표 미기입 시 본 줄을 제거하고 `선행 산출물` 줄로 대체함(직렬 실행 순서 {n}번째) | `{작성 체제·병렬 순번 표}` 미기입 시 본 줄을 제거하고 `선행 산출물` 줄로 대체함 |
| 2 | **담당 역할** — {작성 체제·역할 배정}의 {번호} 배정 역할. 미기입 시 `단일 작성자` | `단일 작성자`로 줄여 씀 |
| 3 | **선행 산출물** — [설계 산출물 7종과 의존관계](00-산출물규격.md) 1절 「산출물 7종과 출력 파일명」 규격표의 `선행(강도)` 값 | 해당 없음(전 프롬프트 필수) |

표기 고정 규칙 — 7건 전부가 위 3줄 형식을 그대로 사용함. 2번 줄의 주체 명칭은 `배정 역할` 1종으로 고정하며  
`배정 주체`를 쓰지 않음. 1번 줄의 `직렬 실행 순서 {n}번째` 함께 적기와 미기입 처리 문구를 7건 전부에 둠.

## 2. 공통 출력 경로 규칙

- 형식: `{출력 루트 경로}{번호}-{산출물명}.md`
- 산출물 번호는 `01`~`07` 두 자리 고정, 부속 대조표는 `00`을 사용함(6절). 산출물명은  
  [설계 산출물 7종과 의존관계](00-산출물규격.md) 1절 「산출물 7종과 출력 파일명」 표의 `출력 파일명` 열 값을  
  그대로 사용함(임의 개명 금지)
- 출력 디렉터리 `{출력 루트 경로}`가 존재하지 않으면 먼저 생성한 뒤 파일을 씀
- 산출물 본문 최상단에 `{프로젝트 프로파일·취급 표기}` 1줄을 둠. 미기입 시 이 줄을 두지 않음
- 같은 경로에 파일이 이미 있으면 7절 재실행 갱신 규칙을 적용함(전체 덮어쓰기 금지)

## 3. 공통 작성 규칙

- 한국어, 명사체 종결(`~함`/`~임`)
- 한 줄 120자 이내, 빈 줄 없이 줄바꿈 시 줄 끝 스페이스 2개.  
  표 행은 셀 내용 기준으로 판단하며 행 전체 길이는 예외로 함
- 설명은 산문보다 표를 우선함. 항목 대비·나열은 반드시 표로 작성함
- 도식은 Mermaid 코드블록으로 작성함(관계도는 `flowchart`, 시퀀스는 `sequenceDiagram`)
- 전문 기술용어는 처음 등장 시 괄호로 쉬운 설명을 1회 붙임
- 기획 산출물에 정량값(숫자로 재는 것)이 있으면 신설하지 않고 인용함([기획 산출물 참조 규약](00-기획산출물참조규약.md) 6절 R-1).  
  신설 시 `신설` 태그를 붙임
- `{범위 제외 목록}`에 해당하는 요구는 설계에 반영하지 않고 말미 `기획 산출물 대조 기록` 표에만 남김
- `{작성 체제·작성 주체 범례}` 기입 시 표 하단에 작성 주체 구분 범례를 둠. 미기입 시 이 줄을 두지 않음

교육 운영·조직 고유 서술을 산출물에 쓰지 않음. 아래 치환 사전을 고정 적용함.

| 원 표현 | 치환 표현 |
|---------|----------|
| 강사 / 강사가 작성함 | 작성자 / 레퍼런스 산출물로 작성함 |
| 수강생 팀(레퍼런스 열람) | 후행 설계 산출물 작성자 |
| Day 2 구현 담당 | 구현 단계 담당자 |
| 레퍼런스 솔루션(강사용 참조 구현) | 레퍼런스 산출물 |
| Day 1 / Day 2 / Day 3 | `{작성 체제·단계 라벨}`:`{해당 행 키}`(미기입 시 설계 단계 / 구현 단계 / 배포 단계. 값이 `해당 없음`인 단계는 `구현 단계 이후`로 읽음) |

## 4. 공통 제약조건

- `{범위 제외 목록}`의 제외 항목을 내용에 포함하지 않음. 항목별 차단 위치는 6절 대조표에서 확인함
- `{권위 문서·기술범위}`와 `{기술 스택}`에 없는 기술 스택·도구·제품명을 신설하지 않음.  
  `{권위 문서·기술범위}` 미기입 시 본 줄을 `{기술 스택}에 없는 …`으로 줄여 씀  
  ([파라미터 블록](00-파라미터블록.md) 2절 V-12 미기입 시 동작)
- 기록·측정 수단은 `{권위 문서·기술범위}` 또는 `{기술 스택}`에 있는 수단으로 한정함
- 기획 산출물에 정량값이 있는 대상의 값을 신설·완화·강화하지 않음  
  ([기획 산출물 참조 규약](00-기획산출물참조규약.md) 6절 R-1·R-2)
- 조회 실패 항목을 추정값·업계 통상치·유사 사례값으로 채우지 않음(5절)
- 8번째 산출물을 신설하지 않음. 커버되지 않는 관심사(소유처를 정해야 하는 설계 항목)는 기존 7종 중 1건에 흡수함  
  ([설계 산출물 7종과 의존관계](00-산출물규격.md) 6절 `공백 흡수 판정` — 빠진 항목을 기존 7종 중 1건에 넣는 판정)
- 웹 검색을 수행하지 않음. 명시된 입력 파일만 근거로 사용함
- 완료조건은 존재 검사·개수 검사·공란 검사·수치 비교 4형식만 사용함. `적절히`·`충분히` 등 뜻이 흐린 말을 금지함

### 4-1. 7종 공통 완료조건 2종

프롬프트 7건이 각자의 `[작업방법]` 자기 점검 단계와 완료조건에 **아래 2종을 반드시 포함**함.
근거는 실제 설계 적용에서 나온 결함 2종임 — 칸이 다 차 있는데 칸끼리 모순이었고,
`공란 0건` 요구가 `추정값 금지` 요구와 부딪혀 둘 중 하나를 어겨야 했음.

| ID | 완료조건 문장 | 프롬프트가 추가로 지정할 것 |
|----|-------------|---------------------------|
| 공통-1 | `칸과 칸이 서로 어긋난 행이 0건임` | **무엇과 무엇을 대조하는지 대조 쌍을 산출물마다 명시함.** 대조 쌍 미지정은 미충족으로 판정함 |
| 공통-2 | 값이 필수인 칸은 `값이 있거나 [확인필요: {항목명}]로 되물어진 상태임(빈 칸 0건)` | 없음. 문장을 그대로 씀 |

- 공통-2는 종전 `공란 0건` 요구를 **대체**함. 두 문장을 함께 두지 않음
- 공통-1의 대조는 **존재·개수 검사만으로는 통과하는 모순**을 잡는 것이 목적임.
  같은 값을 두 표가 각각 적는 자리(소유자와 인용자)를 대조 쌍으로 고름
- 대조에서 어긋난 행이 나오면 값을 임의로 맞추지 않고 소유 산출물 쪽에 `변경요청` 1행을 남김
  ([설계 산출물 7종과 의존관계](00-산출물규격.md) 6절 G-4·G-11·G-12·G-13의 소유 판정을 따름)

### 4-2. 두 산출물의 값을 곱하거나 나누는 계산의 담당

값의 **소유자**만 정하고 계산 담당을 정하지 않으면 아무도 계산하지 않음. 실제 적용에서 이 자리에서만
중대 결함 5건이 나왔음. 계산 담당을 아래로 고정하며, 계산 결과가 선행 산출물의 목표값과 어긋나면
**계산한 쪽이 값을 완화하지 않고** 선행 산출물에 `변경요청` 1행을 남김(7절 갱신 규칙으로 재실행).

| # | 계산 | 담당(값을 내는 곳) | 되돌리는 곳 |
|---|------|-------------------|-----------|
| M-1 | `응답시간 총량 ÷ 단계 수` — 단계별 예산 배정과 `p95 합계`·`최악값 합계` 2줄 검증 | ③ | ① |
| M-2 | `1 + (max_iter × 반복 1회 호출 증분)` — 요청당 모델 호출 배수. **값은 ③이 1회만 계산하고 ⑥은 인용함** | ③ | ⑥(인용) · ①(되돌림) |
| M-3a | `기간 상한 ÷ 건수 전제` — 품질 목표(시간·비율)의 단위를 요청 1건당으로 환산 | ① | — |
| M-3b | `기간 상한 ÷ 건수 전제` — **비용 금액**을 요청 1건당으로 환산(비용 환산 `C-3`) | ⑥ | ① |
| M-4 | `M_최악 = M_재시도 × M_루프` — 최악 비용 배수. `M_재시도`는 재시도 **계층별 `(1 + 재시도 횟수)`의 곱**, `M_루프`는 `M-2` 값임 | ⑥(계층 값은 ③이 소유) | ③ |
| M-5a | `동시 사용자 수 × (요청당 자원 점유 시간 ÷ 응답 마감선) ≤ 동시 처리 상한` — 커넥션·동시 실행 슬롯 관점 | ③ | ① |
| M-5b | `동시 사용자 수 × 요청당 자원 점유 비율 ≤ 런타임 규모 상한` — 배포 자원 관점 | ⑦ | ① |

- **`M-3a`와 `M-3b`는 나누는 대상이 다름**(시간·비율 ↔ 금액). 같은 값을 두 번 나누지 않음
- **`M-5a`와 `M-5b`는 상한의 이름이 다름**(`동시 처리 상한` ↔ `런타임 규모 상한`).
  두 이름을 `자원 상한` 한 낱말로 합쳐 쓰지 않음
- `M-2`의 산식은 3개 문서가 **같은 문자열**을 씀 — 본 표 · [기획 산출물 참조 규약](00-기획산출물참조규약.md)
  4절 `C-5`의 `M_루프` · ⑥ 비용 상한 작업방법. `1 + max_iter`로 줄여 쓰지 않음(증분이 2 이상이면 값이 갈라짐)
- 계산에 쓰는 전제값이 기획 산출물에 없으면 추정하지 않고 `[확인필요: {전제값 이름}]`을 남기며
  그 계산 행을 비율(%)로만 채움([기획 산출물 참조 규약](00-기획산출물참조규약.md) 4절)

### 4-3. 식별자 표기 구분

같은 글자를 다른 뜻으로 쓰는 자리가 있음. 인용할 때 **앞에 계열 이름을 붙여** 구분함.

| 글자 | 두 가지 뜻 | 인용 표기 |
|------|-----------|----------|
| `C-n` | (1) CYCLE 순환 쌍 `C-1` ~ `C-3` (2) 비용 상한 환산 절차 `C-1` ~ `C-7` | `CYCLE C-1` / `비용 환산 C-1` |
| `G-n` | (1) 공백 흡수·소유 판정 `G-1` ~ `G-13`(규격 문서 안) (2) ① 성공 기준 행 번호(산출물 안) | `판정 G-4` / `① 성공 기준 G-1` |
| `S-n` | ③ 시퀀스 단계 전용임. 다른 산출물의 행 번호로 쓰지 않음 | ⑦ 저장소는 `DS-n`, ③ 시퀀스는 `S-n` |

| 태그 형식 | `[확인필요: {항목명}]`. 항목명은 조회하려던 정보의 이름을 그대로 씀 |
| 붙이는 위치 | 해당 표의 칸에 남기고 칸을 비우지 않음. 추정값을 함께 적지 않음 |
| 실행 시점 태그 | `[확인필요: 선행 미생성]`(선행 설계 산출물 부재), `[확인필요: {변수명}]`(선택 변수 미기입으로 도출 불가) |
| 중단 금지 | 조회 실패가 있어도 작성을 중단하지 않고 시작 가능한 항목부터 진행함 |
| 추적 | `{미확정 정보 목록}`이 기입된 프로젝트는 항목명을 그 목록의 행과 대조함. 목록에 없는 항목은 작성자가 행을 추가함. **갱신 대상은 [파라미터 블록](00-파라미터블록.md) 5절 기입란 1곳으로 한정**하며, 산출물 측에는 각 산출물 말미 `미확정 항목` 표(열: `ID`·`필요 정보`·`미확정 근거`·`차단 대상 프롬프트`)에 1행씩 기록함 |
| 처리 순서 | [기획 산출물 참조 규약](00-기획산출물참조규약.md) 6절 R-5의 3단계(도출 → 선택지 나열 후 미결 → 태그만 남김)를 상위 단계부터 적용함 |
| 계열 미해당 처리(그 묶음의 행이 0건일 때의 처리) | 프롬프트가 참조한 `{규제·안전 점검 항목}:{계열명}`의 행이 0건이면 **아래 `계열 0건 재판정` 관문을 먼저 통과한 뒤에만** 해당 작업방법 단계·MUST·완료조건 항목을 **제거**하고, 말미 `기획 산출물 대조 기록` 표에 `유형=계열 미해당`으로 1행 남김. 계열(같은 성격끼리 묶은 묶음) 행 없이 규칙을 신설하지 않음 |
| 계열 0건 재판정(관문) | `0건` 표기를 그대로 믿지 않음. 제거하기 전에 기획 산출물 원문에서 그 계열에 해당하는 요구가 있는지 **다시 확인**하고, 해당하면 `{규제·안전 점검 항목}`에 행을 더한 뒤 제거하지 않음. 확인 결과를 `기획 산출물 대조 기록` 표에 `유형=계열 재판정`으로 1행 남김(`계열명`·`재판정 결과(해당·미해당)`·`확인한 원문 위치`). 원문 확인이 불가하면 제거하지 않고 `[확인필요: {계열명} 해당 여부]`로 남김 |

## 6. 반영 대조표 2종 규격

7종 작성 완료 후 범위·점검 항목의 반영 여부를 대조하는 표 2종임. 행 값은 변수에서 생성하며  
항목 수를 고정하지 않음.

**점검 항목 반영 대조표** — 행은 `{규제·안전 점검 항목}` 전부임.

| 점검 항목 | 계열 | 반영 프롬프트 | 반영 지점 |
|-----------|------|-------------|----------|
| `{규제·안전 점검 항목}`의 `점검 항목` 열 값 | 같은 행의 `계열` 열 값 | 같은 행의 `반영 산출물` 열 값 | 같은 행의 `반영 지점` 열 값(작업방법 번호·MUST 번호) |

**제외 범위 미포함 대조표** — 행은 `{범위 제외 목록}` 전부임.

| 제외 항목 | 차단 위치 |
|-----------|----------|
| `{범위 제외 목록}`의 `제외 항목` 열 값 | 같은 행의 `차단 위치` 열 값(4절 공통 제약 + 해당 프롬프트 MUST NOT) |

- 두 표는 7종 작성 완료 후 1회 작성하며 `{출력 루트 경로}`에 `00-반영대조표.md`로 둠
- 반영 프롬프트·차단 위치가 공란인 행이 1건이라도 있으면 미충족으로 판정함
- 대조 결과 미반영 건수를 숫자로 명시함. 0건이어도 `0건`으로 표기함

## 7. 재실행 갱신 규칙

CYCLE(서로 주고받음) 재실행은 같은 프롬프트를 그대로 사용하되 기존 파일 전체를 덮어쓰지 않고 변경된 칸만 갱신함.  
갱신한 칸은 문서 말미 `개정 이력` 표에 `갱신 일시 · 갱신 칸 · 갱신 사유(되돌림 ID)` 3열로 1행씩 기록함.  
파라미터 값을 바꾼 뒤 재실행하는 경우도 같은 규칙을 적용하며, 갱신 사유 칸에 `파라미터 변경: {변수명}`을 씀.
