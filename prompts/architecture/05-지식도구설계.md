# 프롬프트 ⑤ — 지식·도구 설계

{프로젝트 프로파일·취급 표기}

**이 파일** — 산출물 ⑤를 생성하는 프롬프트 1건임  
**상위 진입점** — [퀵스타트](../design-architecture.md)  
**함께 읽을 파일**(실행 전 필수 참조) — [기획 산출물 참조 규약](00-기획산출물참조규약.md) · [공통 규약](00-공통규약.md) ·  
[파라미터 블록](00-파라미터블록.md) · [설계 산출물 7종과 의존관계](00-산출물규격.md)(`{권위 문서·산출물규격}` 미기입 시 산출물 규격의 대체 출처임)  
**실행 순번** — 직렬 실행 순서 5번째(`① → ② → ③ → ④ → ⑤ → ⑥ → ⑦`). 선행 ②(HARD)·①(SOFT)·④(C-1)·③(C-2).  
HARD는 없으면 못 채움, SOFT는 없어도 시작 가능, CYCLE은 서로 주고받음.  
③·④는 ⑤보다 **먼저** 쓰이므로 C-1·C-2는 앞으로 넘기는 값이 아니라 이미 쓰인 값에 맞추고 되돌리는 값임  
**원문 대응** — 분할 전 `architecture.md` 9절 프롬프트 ⑤

---

**작성 시점** — `{작성 체제·병렬 순번 표}`의 ⑤ 초안·④↔⑤ 되돌려 반영·마감·③↔⑤ 서로 맞춤 순번. 표 미기입 시 본 줄을 제거하고 `선행 산출물` 줄로 대체함(직렬 실행 순서 5번째)  
**담당 역할** — `{작성 체제·역할 배정}`의 ⑤ 배정 역할. 미기입 시 `단일 작성자`  
**선행 산출물** — ②(HARD) 신뢰 경계선(믿을 수 있는 내부와 밖을 가르는 선) · ①(SOFT) 우선 품질속성 · ④(C-1) 접근 항목 · ③(C-2) 데이터 형식

```text
[목표]
{케이스 정의·업무 정의}를 수행하는 시스템에서 질문 유형별 지식 경로를 판정하고,
정형·비정형 `접근 경로 목록`과 {기술 스택}:도구 연결 규격 기반 커넥터 목록(커넥터는 외부 시스템에
붙는 연결 부품임)·입출력 규격, 민감 필드 분류표, 등급별 보존·삭제 범위, 원천 데이터 오류율,
검색 품질 평가셋(골든셋 — 질문과 정답을 미리 정해 둔 채점지)을 정의한 「지식·도구 설계」 1건 작성

[역할]
당신은 ISO/IEC/IEEE 42010(아키텍처 문서화 국제표준)·arc42(아키텍처 문서 서식 표준)·OWASP 에이전트 보안 지침에 근거한 지식 접근 경로·도구 계약 설계
경력 11년의 데이터·검색 아키텍트입니다.
{케이스 정의·도메인} 영역에서 규제 대상 정보의 변환 지점 판정과 접근 경로별 적합성 판단을
다수 수행했습니다.
{기술 스택} 중 `정형 접근 방식`·`비정형 접근 방식`·`도구 연결 규격` 행 값 기반 검색·연동 설계에
정통하며, 검색 품질을 모델 교체가 아니라 원천 데이터 품질과 평가셋으로 먼저 다룹니다.

[맥락]
- 내 상황: {프로젝트 프로파일·프로젝트명} {작성 체제·기간 라벨}의 설계 단계 산출물 7종 중 ⑤를
  레퍼런스 산출물로 작성함. ⑤는 ②에서 HARD로 1건을 받고 ⑦에 HARD로 1건을 넘김. ④(C-1)·③(C-2)와는
  서로 주고받는 관계 2건에 함께 걸려 있어 전체 일정을 좌우하는 사슬 안에 있음. 접근 경로가 정해지지
  않으면 ③ 검색 단계와 ⑦ 저장소 배치를 시작할 수 없음
- 실행 순서: ③·④가 ⑤보다 먼저 작성됨. 따라서 ⑤는 두 산출물이 이미 정한 이름에 맞추는 쪽이며
  새 이름을 지어내지 않음
- 소유 방향이 서로 반대임: 민감 필드 ID(`F-n`)는 ⑤가 소유하고 ④가 인용함(G-11).
  입출력 키 이름은 ④가 소유하고 ⑤가 맞춤(G-12). 커넥터는 외부 시스템 접근만 해당함(G-13)
- 결과물 독자: 후행 설계 산출물 작성자와 구현 단계 담당자

[입력정보]

  ({권위 문서·절 매핑}에서 `기술 개념 범위`·`검색 방식`·`도구·인프라`·`점검 항목`·`제외 범위` 해석)

    `Cost Structure — 변동비용(외부 API 항목)`, `Unfair Advantage`(데이터 축적형일 때만)
  - US 유저스토리 문서: {기획 산출물 경로·US} — 읽는 절: `[입력 요구사항]`, `[검증 요구사항]`
    조회형 항목, `[처리 결과] 성공 시`, NFR 보안 계열(같은 성격끼리 묶은 묶음) `[체크리스트]`, NFR 컴플라이언스 계열(보존·삭제)

[작업방법]
0. 입력 가용성을 확인함. 기획 산출물 3종과 선행 설계 산출물의 존재 여부를 점검하고,
   부재 항목을 `[확인필요: 선행 미생성]` 또는 `[확인필요: {항목명}]`으로 기록한 뒤 시작 가능한
   항목부터 작성을 진행함. 작성을 중단하지 않음
1. `질문 유형·경로 판정표`를 작성함. 사용자가 실제로 칠 문장을 US `[검증 요구사항]` 조회형 항목에서
   3개 이상 인용하고, 질문 1개마다 아래 6줄을 위에서부터 예/아니오로 통과시켜 경로를 정함.
   열은 `표본 질문`·`질문 유형`·`선택 경로`·`판정 근거`·`버린 대안`·`근거 출처`임
   (1) 답이 조건에 맞는 목록·정렬인가 → 예: `정형 조회`(검색이 아님) / 아니오: 다음 줄
   (2) 답이 개수·합계·추이인가 → 예: NL2SQL(말을 SQL로 바꿔 표를 조회함) / 아니오: 다음 줄
   (3) 답이 문서 1~2군데 문장인가 → 예: 벡터 RAG(뜻이 가까운 문단을 찾아옴) / 아니오: 다음 줄
   (4) 관계를 2번 이상 건너가야 하나 → 예: GraphRAG(개체를 선으로 이어 그 선을 따라감) / 아니오: 다음 줄
   (5) 사내 코드·용어를 1:1로 고정해야 하나 → 예: 용어사전·온톨로지 / 아니오: `[확인필요: 질문 유형 분류]`
   (6) 이 판정이 틀리면 되돌릴 수 없나 → 예: 고른 경로 앞에 결정론 단계(모델을 쓰지 않고 규칙으로만
       판정하는 단계)를 따로 두고 LLM 입력 규격에서 그 필드를 제거함 / 아니오: 그대로 진행
   `버린 대안` 칸에 검토했으나 고르지 않은 경로와 버린 이유를 1줄로 적음. 표본 질문이 한 경로로만
   몰리면 질문을 다시 뽑은 뒤 본 단계를 다시 수행함
2. `정형 접근 경로` 표를 작성함. 방식은 {기술 스택}:정형 접근 방식으로 고정하고 대상은
   {데이터 원천·정형} 범위로 한정함. 열은 `대상`·`조회 목적`·`연결 키`·`접근 금지 항목`·`행 수 상한`·
   `근거 출처`이며 조회 목적과 필수 조회 항목은 US `[입력 요구사항]`에서 인용함.
   `접근 금지 항목`은 `대상.열` 꼴로 적고 막는 이유를 괄호로 붙이며, 막을 항목이 없으면
   `없음(전 항목 허용)`을 적고 칸을 비우지 않음. `행 수 상한`은 한 번에 가져올 최대 행 수를 숫자로 적고
   못 정했으면 `[확인필요: 행 수 상한]`으로 적음. 본 경로는 읽기 전용 계정 전제이며 쓰기 SQL을 두지 않음
3. `비정형 접근 경로 구분` 표를 작성함. {기술 스택}:비정형 접근 방식의 방식 전부를 1행씩 두고 열은
   `접근 경로`·`채택 여부`·`사용 질문 유형`·`대상 문서`·`선택 근거`·`버린 이유`·`근거 출처`임.
   대상 문서는 {데이터 원천·비정형}, 사용 질문 유형은 1단계 판정표의 `선택 경로` 값과 대조해 인용함.
   미채택 행은 `버린 이유`에 1줄을 적고 `해당 없음` 처리와 구분함. 유행·인지도를 근거로 쓰지 않음.
   해당 행이 `[확인필요: 기술 스택 비정형 접근 방식 세부]`이면 본 표를 `[확인필요]` 1행으로 대체함.
   2·3단계 산출을 합쳐 `접근 경로 목록` 이름으로 쓰며 ④③가 되돌림 반영 시 이 명칭으로 인용함
4. `비정형 경로 방식별 스펙` 표를 작성함. 3단계에서 채택한 방식마다 아래 필드를 채우고 미채택 방식은
   `해당 없음`으로 적음. 못 정한 칸은 `[확인필요: {항목명}]`으로 남김
   - 벡터 RAG — 인덱스명 · 문서 범위·기준일 · 청킹 단위/크기/중첩(청킹은 문서를 조각으로 자르는 것임) ·
     임베딩 모델명·버전 · 검색 방식·top-k(상위 몇 건을 가져올지)·리랭킹 여부(뽑아온 후보를 다시 줄 세우기) ·
     메타데이터 필터 키
   - GraphRAG — 노드 타입 목록 · 관계 타입·방향 · 노드 고유키 규칙 · 추출·검수 방법 ·
     최대 홉 수(관계를 몇 번 건너갈지)·결과 상한 · 커뮤니티 요약 사용 여부
   - 온톨로지·용어사전 — 사전 파일 위치·형식 · 대표어·동의어 목록 · 적용 지점(질의 확장/검색 후/출력 표기) ·
     1:N 충돌 처리 규칙 · 미등록어 처리 규칙 · 갱신 주체·주기
   메타데이터 필터 키는 ④에 있는 이름을 인용만 하며 ⑤에서 새 이름을 짓지 않음.
   GraphRAG를 채택하면 그래프 구축·재적재 비용과 적재 지연이 커지므로 그 대가와 감당 근거를
   `선택 근거` 칸에 1줄로 함께 적음
5. {데이터 원천·관계 특성}을 근거로 관계 검색의 강점 구간·한계 구간을 각각 1줄 이상 기재함.
   해당 필드 미기입 시 본 단계를 제거하고 5단계 산출 항목을 문서에서 뺌
```
