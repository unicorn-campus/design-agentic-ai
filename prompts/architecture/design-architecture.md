# {프로젝트 프로파일·프로젝트명} — 다중 에이전트 시스템 설계 산출물 7종 작성 프롬프트 템플릿

작성일: {프로젝트 프로파일·작성일} · 용도: 설계 산출물 7종의 레퍼런스 산출물 작성용 지시 프롬프트 모음  
근거 문서: {권위 문서·기술범위}(기술·제외 범위·점검 항목의 출처), {권위 문서·산출물규격}(산출물 7종 규격·공백·필요 정보의 출처),  
`references/prompt-guide.md`(프롬프팅 가이드 8섹션 표준)

{프로젝트 프로파일·취급 표기}

**본 문서의 성격** — MVP 주제·도메인에 독립적인 **재사용 템플릿**임. [파라미터 블록](architecture/00-파라미터블록.md)의 변수 15종만 교체하면  
같은 프롬프트 7건을 다른 MVP 주제에 그대로 사용 가능함. 프롬프트 본문에 도메인 고유 값을 직접 쓰지 않으며, 도메인 의존은 변수 슬롯으로만 따로 떼어 둠.  
**사용 대상** — 설계 산출물 7종의 레퍼런스 산출물을 작성하는 작성자임. 프롬프트 7건을 순서대로 실행하여 7종을 생성함.  
**취급 주의** — `{프로젝트 프로파일·취급 표기}`가 기입된 프로젝트는 산출물 7종 전부와 본 문서 사본에 같은 표기를  
최상단 1줄로 유지함. 미기입 프로젝트는 취급 표기 관련 줄·칸을 제거하고 대체 문구를 만들지 않음.

## 실행 순서

프롬프트 배치 번호 순이 아니라 아래 확정 순서를 따름. 번호 순이 아닌 근거는 [설계 산출물 7종과 의존관계](architecture/00-산출물규격.md) 3절 임계 경로(전체 일정을 좌우하는 가장 긴 작업 사슬)임.

```
직렬 1회      ① → ② → ③ → ④ → ⑤ → ⑥ → ⑦   (번호 = 실행 순서)
CYCLE 재실행   ④ → ⑤ → ③ → ⑥ → ⑦ → ①   (마지막 ①은 되돌림 반영용 1회 갱신)
7종 확정 후    반영 대조표 2종을 {출력 루트 경로}00-반영대조표.md로 1회 작성
```

**③ 패턴/시퀀스가 ④ 역할계약서보다 앞인 이유**(2026-08-06 판정) — 흐름을 먼저 확정해야 그 단계를 누가
맡고(④) 무슨 지식이 필요한지(⑤) 정해짐. ③은 ② 논리 아키텍처의 구성요소를 참여 주체로 그리며,
키 이름은 붙이지 않고 `키 집합 식별자`까지만 소유함. 설계 절차 9단계의 개념 순서(역할 계약이 4번째)와
우리 실행 순서가 다른 근거는 [설계 산출물 7종과 의존관계](architecture/00-산출물규격.md) 4절임.

CYCLE(서로 주고받음) 재실행은 같은 프롬프트를 그대로 쓰되 기존 파일을 덮어쓰지 않고 변경 칸만 갱신함([공통 규약](architecture/00-공통규약.md) 7절). 순서 전문은 [설계 산출물 7종과 의존관계](architecture/00-산출물규격.md) 5-1절임.  
`{작성 체제·병렬 순번 표}`가 기입된 프로젝트는 다인 병렬(동시에 실행) 작성 시 [설계 산출물 7종과 의존관계](architecture/00-산출물규격.md) 5-2절 `W-1`~`W-n` 순번을 사용하며, 단일 작성자는 위 직렬(차례로 실행) 순서만 사용함.

## 사람이 직접 설계할 때는 가이드를 봄

같은 산출물 7종을 **사람이 읽고 스스로 판단하며** 만들 때는 [`guides/`](../guides/README.md)의 가이드 7종을 씀.
프롬프트는 AI 코딩 도구가 규격을 빠짐없이 훑는 순서이고, 가이드는 사람이 실제로 판단하는 순서임.

| 쓰는 때 | 보는 것 |
|--------|--------|
| 산출물을 자동 생성할 때 | 본 디렉터리의 프롬프트 7건 |
| 직접 설계할 때 · 생성 결과를 검토할 때 | [`guides/`](../guides/README.md) 7종의 `2절 판정 → 3절 설계항목 → 6절 점검표` |

두 계열은 같은 판정을 공유함 — 소유 판정 `G-4`·`G-5`·`G-10`·`G-11`·`G-12`·`G-13`,
7종 공통 완료조건 2종, 두 산출물의 값을 곱하거나 나누는 계산의 담당.
마지막 항목은 프롬프트 측에서만 `M-1` ~ `M-5b` 부호를 붙였고 가이드는 같은 내용을 부호 없이 서술함
(`guides/_shared/가이드-공통규격.md` 4-2절). 부호로 가이드를 찾지 않음.
값이 어긋나면 프롬프트 쪽 규격 파일([공통 규약](architecture/00-공통규약.md) ·
[설계 산출물 7종과 의존관계](architecture/00-산출물규격.md))이 단일 출처임.

## 다른 주제에 적용할 때

1. 이 디렉터리 전체의 프로젝트 사본을 생성함
2. 사본에서 [부록](architecture/99-부록.md)의 2~5절(부록 A·B·C·D)을 삭제함(선택 아님). 1절 사례 대입 예시는 템플릿 규격이므로 유지함.  
   다른 프로젝트의 고유 기술명이 남으면 7건 MUST NOT의 신설 허용 목록으로 잘못 읽힘
3. [파라미터 블록](architecture/00-파라미터블록.md) 5절 기입란의 변수 15종을 새 주제 값으로 교체함.  
   프롬프트 본문에 도메인 고유 값을 직접 쓰지 않음
