# 기획 산출물 참조 규약

{프로젝트 프로파일·취급 표기}

**이 파일** — 설계 7종이 기획 산출물 3종을 소비하는 방식을 규정함  
**상위 진입점** — [퀵스타트](../architecture.md)  
**함께 읽을 파일** — [파라미터 블록](00-파라미터블록.md) · [공통 규약](00-공통규약.md) · [설계 산출물 7종과 의존관계](00-산출물규격.md)  
**필수 참조** — 프롬프트 7건(①~⑦) 전부가 이 파일을 가리킴. 프롬프트 실행 전 반드시 읽음  
**원문 대응** — 분할 전 `architecture.md` 4절 기획 산출물 참조 규약

설계 산출물 7종이 기획 산출물 3종을 어떻게 소비하는지 규정한 규약임. 본 규약은 MVP 주제·도메인과 무관하게  
성립하며 도메인 고유 내용은 변수 참조로만 등장함.

## 2. 소비 매핑표

소비 대상 절을 행으로 실었음. 총 52행 구성 — **소비 행 48건 + 범위 검사·범위 한정 행 4건(BM-36·US-13·  
US-19·US-21) + 미소비 통합 2행(BM-99·US-99)**. 미소비(`X`) 항목은 문서별 `미소비 절 목록` 1행으로 통합함.

`절·항목` 열은 3절 (7) `소비 성격` 라벨을 기준 표기로 삼고 절 이름은 괄호 안 참고 예시로 둠.  
기획 파이프라인 버전에 따라 절 이름이 다를 수 있으므로 절 이름 일치를 판정 기준으로 쓰지 않음(3절 매칭 규칙).

**BM 비즈니스 모델 문서 — 소비 24행 + 미소비 통합 1행**

**(7) BM Lean Canvas 9블록의 소비 성격**

| 블록 | 소비 성격 | 설계 소비처 요약 |
|------|----------|----------------|
| Problem | 기준선 제공 | ① 개선 전 기준선. 개선 후 목표값은 여기서 가져오지 않음 |

| Solution | 군집 경계 | ④ 에이전트 후보 군집, ② 내부 구성 단위 후보 |
| Channels | 부분 소비 | Delivery만 ②·⑦이 소비함. Acquisition·Retention은 `X` |
| Revenue Streams | 부분 소비 | 플랜별 기능 차등만 ④·⑤가 소비함. 가격·LTV·전망은 `X` |
| Cost Structure | 상한 산정 | ⑥ 비용 상한(4절 환산 절차), ⑦ 배치 규모 |
| Key Metrics | 목표값 제공 | 5절 선별 기준 통과 지표만 ①·⑥ |
| Unfair Advantage | 조건부 소비 | 데이터 축적형일 때만 ⑤·⑦. 그 외 유형은 `X` |

- `Problem`은 `개선 전 기준선` 칸에만, `Key Metrics·비즈니스가치 연계 지표`는 `목표값` 칸에만 넣음.  
  두 칸을 교차 사용하지 않음
- `Channels`의 Delivery 항목이 US 스토리로 이미 기술되어 있으면 US를 우선하고 BM을 참조하지 않음
- `Revenue Streams`는 등급이 데이터·기능 접근 범위를 나눌 때만 소비함. 금액·결제 조건만 다르면 `X`임

  출처가 계약·인력·브랜드·특허·자본이면 `X`임
- `GTM`은 원칙적으로 `X`이며, 인허가·신고 항목이 US 컴플라이언스 NFR에 없을 때만  
  `{규제·안전 점검 항목}` 보완 후보로 ⑥ 말미에 1행 기록함

**절 이름 매칭 규칙** — 기획 파이프라인 버전에 따라 절 이름이 다를 수 있음. 절 이름이 일치하지 않으면  
위 `소비 성격` 열로 매칭하고, 매칭 결과를 `절 이름 대응 기록` 표(열: `본 규약 절 이름`·`실제 절 이름`·`매칭 근거`)에  
1행 남김. 매칭되는 절이 없으면 `[확인필요: {절 이름}]`으로 표기하고 해당 행을 미소비로 처리하지 않음.  
같은 상위 블록 안에서 절 이름이 어긋나는 건이 3건 이상이면 `절 이름 대응 기록`을 항목마다 적지 않고  
**블록 단위 1행**으로 묶어 적음(예: `Key Metrics 상세 블록 5항목 → AARRR 5블록에 산재`).

## 4. 정량값 인용 절차와 비용 상한 환산

기획 산출물이 정량 지표를 이미 가지므로 ①의 성격은 **지표 신설이 아니라 선별 + 인용**임.  
작업 순서를 아래 6단계로 고정함.

1. BM `비즈니스가치 연계 지표` → BM `Key Metrics 상세` → PR `프로세스 성과 지표` 순으로 후보를 모음
2. 5절 테스트 4개로 `시스템 책임`·`공동 책임`·`책임 밖` 3분류함
3. `시스템 책임` 지표 중에서 성공 기준 3개와 우선 품질속성 3개를 고름(`공동 책임`은 ① 인용 금지)
4. 목표값·측정 시점을 원문 그대로 옮기고 근거 출처 ID를 붙임
5. 6개 칸 중 기획 산출물에 대응 값이 없는 칸만 신설하고 `신설` 태그로 표기함
6. 신설 건수가 3건을 넘으면 기획 산출물 미확보 가능성이 있으므로 `[확인필요: 지표 출처]`를 남김
7. `시스템 책임` 지표가 3건 미만이면 부족분을 **행 단위로** 신설(표에 행을 새로 추가해 채움)하되  
   신설 행의 `근거 출처` 칸에 `설계판단`을, `측정 방법`·`목표값`에 `신설` 태그를 붙이고 신설 행 수를  
   ① 말미에 숫자로 명시함. 행 단위 신설분은 5~6단계의 칸 단위 신설 3건 상한 집계에 포함하지 않음

`신설` 태그는 감사 대상임. 인용 가능한 값이 있었는데 신설한 경우 6절 R-1 위반임.

**비용 상한 환산(단위를 바꿔 다시 계산함) 절차 C-1~C-7** — ⑥이 소유하는 `단계별 비용 상한` 값의 산출 절차임.

| 단계 | 작업 | 산출물 |
|------|------|--------|
| C-1 | BM 변동비용에서 모델 호출 비용 항목 1건과 계산에 쓰는 전제값(기간·이용 규모·일 처리 건수)을 원문 그대로 인용함 | 원래 값 `B`(기간당 금액), 전제 `N`(기간당 처리 건수) |
| C-2 | 기간 단위를 통일함. 연 단위 값은 12로 나누어 월 단위로 내림 | `B_월` |
| C-3 | 요청 1건당 허용 비용을 계산함 — `C_req = B_월 ÷ N_월` | `C_req` |
| C-4 | ③ 시퀀스에서 모델 호출이 발생하는 단계 목록과 단계별 호출 횟수 `n_i`를 인용함 | 단계 목록, `n_i` |
| C-5 | 재시도 여유를 반영함 — `C_설계 = C_req ÷ (1 + R)`. `R`은 ③ 재시도 표의 단계별 재시도 횟수 가중 평균임 | `C_설계` |
| C-6 | 단계별 상한을 나눠 배정함 — 기본은 호출 횟수 비례 `w_i = n_i ÷ Σn`, 단계별 상한 `= C_설계 × w_i`. 비례해 나눠 배정하는 방식을 바꾸면 다시 나눠 배정한 사유를 1줄 기재함 | 단계별 상한 표 |
| C-7 | 표 하단 합계 행에서 `Σ 단계별 상한 ≤ C_설계`를 검증함. 초과 시 C-6으로 되돌아감 | 검증 결과 |

- 계산에 쓰는 전제값 `N`이 BM에 없으면 C-3을 수행하지 않고 `[확인필요: 이용 규모 전제]`로 표기한 뒤  
  단계별 상한을 **비율(%)로만** 나눠 배정함. 금액을 추정하지 않음
- 원래 값 `B`가 BM에 없고 `{비용 예산 상한}`도 미기입이면 C-2~C-7을 수행하지 않고 `[확인필요: 비용 원값]`을  
  표기한 뒤 단계별 상한을 호출 횟수 비례 비율(%)로만 나눠 배정함. 금액을 추정하지 않음
- `{비용 예산 상한}`이 기입되어 있으면 C-3 결과와 대조하여 **더 엄격한 값**(더 작은 값)을 `C_req`로 채택하고  
  버린 값·채택 근거(6절 R-3c)를 `기획 산출물 대조 기록` 표에 `유형=값충돌`로 1행 남김
- 계산 형식 예시(사례 B 실값) — `B_월 = 3,000,000`, `N_월 = 10,000 × 30 = 300,000`, `C_req = 10`,  
  `R = 1`, `C_설계 = 5`, 호출 3회 단계 비중 `w = 0.5`이면 해당 단계 상한 `= 2.5`임

## 5. 시스템 책임 지표 선별 기준

기획 산출물의 지표에서 ①·⑥이 인용할 지표를 고르는 기준임. 테스트 4개를 모두 통과한 지표만 인용함.

| 테스트 | 판정 문장 |
|--------|----------|
| T-1 관측 가능성 | 시스템이 실행 중 남기는 기록(관측 로그·응답 페이로드·저장 데이터)만으로 값을 계산할 수 있음. 페이로드는 요청·응답에 실려 오가는 본문 데이터임 |
| T-2 인과 귀속 | 값의 변동 원인이 설계 산출물 ①~⑦의 결정으로 설명됨. 마케팅·영업·가격·조직 활동이 개입하면 탈락함 |
| T-3 단위 환원 | 요청 1건 또는 배치 1회를 기준으로 값이 나옴. 기간을 모아 낸 값이라도 한 번 실행되는 단위의 값을 합쳐 만든 것이면 통과함 |
| T-4 설계 개입 | 목표 미달 시 설계 산출물 7종 중 최소 1건을 고쳐 개선할 수 있음 |

| 분류 | 조건 | 처리 |
|------|------|------|
| 시스템 책임 | 4개 전부 통과 | ① 성공 기준 또는 ⑥ 측정 대상으로 인용함 |
| 공동 책임 | T-2만 부분 통과(시스템 요인과 비시스템 요인이 함께 작용) | ① 성공 기준으로 인용하지 않음. **⑥ 측정 대상으로만** 인용하고 `관측 항목`만 정의하며 목표값 칸에 `공동 책임 — 목표 미설정`을 기재함 |
| 책임 밖 | T-1·T-3·T-4 중 1개 이상 탈락 | 인용하지 않음. ① 말미 `제외 지표` 표에 탈락 테스트 번호와 함께 1행 기록함 |

판정 형태 확인용 예시임(도메인 값 아님). 규칙 본문에서 이 표의 값을 참조하지 않음.

| 지표 예시 | T-1 | T-2 | T-3 | T-4 | 분류 |
|----------|-----|-----|-----|-----|------|
| 응답 지연 p95(100건 중 95번째로 느린 값) | 통과 | 통과 | 통과 | 통과 | 시스템 책임 |
| 결과 수락률 | 통과 | 통과 | 통과 | 통과 | 시스템 책임 |
| 고객획득비용(CAC) | 탈락 | 탈락 | 탈락 | 탈락 | 책임 밖 |
| 월간반복수익(MRR) | 탈락 | 탈락 | 탈락 | 탈락 | 책임 밖 |
| 30일 재방문율 | 통과 | 부분 | 통과 | 부분 | 공동 책임 |

`책임 밖` 판정은 지표의 중요도를 낮게 본다는 뜻이 아니며, 설계 산출물이 그 값을 약속하지 않는다는 뜻임.

## 6. 인용 충돌 해소 규칙 R-1~R-7

**R-1 인용 우선 원칙** — 기획 산출물에 정량값이 존재하면 설계에서 같은 대상의 값을 신설하지 않음.  
원래 값을 인용하고 출처 ID를 표기함. `존재`의 판정 범위는 3종 문서 전체이며 절 이름이 달라도  
같은 대상을 가리키면 존재로 봄.

**R-2 값 변환 허용 범위**

| 변환 유형 | 허용 여부 | 표기 의무 |
|----------|----------|----------|
| 단위 환산(연→월, 초→밀리초) | 허용 | 원래 값·환산식·결과값 3개 함께 적기 |
| 총량의 단계별 나눠 배정(예산 분해) | 허용 | 나눠 배정 규칙과 합계 검증 행 필수 |
| 통계량 해석(평균→p95 등 · 통계량은 p50·평균처럼 값을 요약한 수치임) | 조건부 허용 | 해석 근거 1줄 필수. 근거 없으면 `[확인필요: 통계량 해석]` |
| 값의 완화(목표 낮춤) | 금지 | R-6 절차로 처리함 |
| 값의 강화(목표 상향) | 금지 | 원래 값을 유지하고 설계 여유는 별도 열로 표기함 |

**R-3 출처 우선순위** — 같은 대상의 값이 2곳 이상에서 다를 때의 채택 순서임. 숫자가 작을수록 우선함.

| 순위 | 출처 | 우선 근거 |
|------|------|----------|
| 1 | US NFR `[체크리스트]`의 항목마다 따로 정한 수치 | 대상이 분해되어 있어 검증 단위와 일치함 |
| 2 | US 개별 스토리 `[검증 요구사항]`의 수치 | 기능 단위로 한정되어 적용 범위가 명확함 |
| 3 | BM `비즈니스가치 연계 지표` | 시스템 책임 범위를 이미 겨냥한 지표임 |
| 4 | BM `Key Metrics` 표 | 집계 단위가 크고 비시스템 요인이 섞임 |
| 5 | US NFR 헤더 문장 | 개괄 표현이며 대상별 예외를 담지 못함 |
| 6 | PR `프로세스 성과 지표` | 프로세스 전체 값이며 시스템 구간 값과 다를 수 있음 |

- **R-3a** 같은 문서 안에서 헤더 문장과 `[체크리스트]`·`[검증 요구사항]`이 다르면 **분해된 쪽**을 채택함
- **R-3b** 두 값 중 한쪽에만 요약 방식(p50·p95·평균)이 적혀 있으면 적힌 쪽을 씀. 적히지 않은 값도  
  같은 요약 방식으로 읽고, 그렇게 읽었다는 사실을 `통계량 해석` 태그로 적음
- **R-3c** 우선순위가 같은 두 값이 충돌하면 **엄격한 쪽**(더 좁은 범위·더 짧은 시간·더 강한 제약)을 채택함

**R-4 범위 제외 목록과 충돌하는 요구의 처리** — 5단계임.

1. 기획 산출물의 요구 1건을 **항목 단위로 분해함**. 요구 전체를 통째로 제외 판정하지 않음
2. 항목별로 `{범위 제외 목록}`과 대조함
3. 해당하는 항목은 설계에 반영하지 않고 태그만 남김 — 태그 형식 `[범위외: {제외 항목명} · 출처 {근거ID}]`
4. 태그는 설계 표 본문 칸에 넣지 않고 산출물 말미 `기획 산출물 대조 기록` 표에 1행씩 모음
5. 같은 요구 안의 비제외 항목은 정상 반영함. 부분 반영 사실을 근거 출처 칸에 `부분반영` 태그로 표기함

**R-5 정보 부재 시 처리** — 3단계 순서임. 상위 단계에서 해결되면 하위로 내려가지 않음.

| 단계 | 조건 | 처리 |
|------|------|------|
| 1 | 다른 기획 산출물의 값에서 도출 가능함 | 도출식과 출처 ID를 함께 적어 사용함. `도출` 태그를 붙임 |
| 2 | 도출 불가하나 `{기술 스택}`·`{범위 제외 목록}`으로 범위가 좁혀짐 | 선택지를 나열하고 미결로 둠. `[확인필요: {항목명}]` |
| 3 | 어느 근거로도 좁혀지지 않음 | `[확인필요: {항목명}]`만 남기고 칸을 비우지 않음 |

전 단계 공통 금지 — 업계 통상치·추정값·유사 사례값으로 칸을 채우지 않음.

**R-6 앞 단계로 되돌려 고침** — 설계에서 기획 값을 달성 못해도 값을 완화하지 않음. `기획 산출물 대조 기록` 표에  
`변경요청` 유형으로 1행 기록하고 원래 값을 그대로 유지함.

**R-7 값의 단일 소유** — 같은 값이 설계 산출물 2건 이상에 등장하면 소유 산출물 1건을 선언하고 나머지는  
인용 표기만 함. 인용 측은 값 옆에 `({소유 산출물 번호} 인용)`을 붙임. 새 소유 관계를 만들지 않음.

**기획 산출물 대조 기록(부속 기록 표 1종)** — R-3·R-4·R-6의 기록을 1개 표로 통합함.  
산출물 7종 전부의 말미에 두며 해당 건이 0이면 `0건`으로 명시함. 이 표는 부속 기록이며  
[설계 산출물 7종과 의존관계](00-산출물규격.md) 1절 `필수 출력 항목`이 아님(8번째 산출물 신설로 보지 않음).

| 유형 | 근거 ID | 내용 | 처리 |
|------|--------|------|------|
| `범위외` | 대상 근거 ID | 요구 항목 · 대응 제외 항목 | 미반영 사유 1줄 |
| `값충돌` | 대상 근거 ID | 채택값 · 버린 값 | 채택 근거 순위(R-3 순위 번호) |
| `변경요청` | 대상 근거 ID | 기획 원래 값 · 설계상 달성 가능값 | 달성 불가 근거 1줄 |
| `계열 미해당` | — | 참조한 `{규제·안전 점검 항목}:{계열명}`과 제거한 단계·MUST·완료조건 항목 | 계열 행 0건 근거 1줄([공통 규약](00-공통규약.md) 5절) |

`유형` 4종의 뜻 — `범위외`는 제외 목록에 걸려 반영하지 않음, `값충돌`은 두 값이 어긋남,  
`변경요청`은 기획 쪽 수정을 요청함, `계열 미해당`은 그 묶음의 행이 0건임을 뜻함.

## 7. 추적성 표기 규약(추적성 — 값이 어디서 왔는지 되짚을 수 있음)

**근거 열의 범위** — 아래 지정 표에만 `근거 출처` 열을 두며 그 외 표에는 두지 않음.  
위치는 `후행 소비처` 열의 바로 앞으로 고정함. 도식(Mermaid)은 열을 가질 수 없으므로 도식 직후에  
`노드·간선 근거 대조표`(열: `노드·간선 식별자`·`근거 출처`·`비고`)를 둠.  
`후행 소비처`는 뒤 산출물 중 이 값을 쓰는 곳이고, 간선은 도식에서 노드를 잇는 선임.

| 산출물 | 근거 열이 필수인 표 | 추적 대상 |
|--------|------------------|----------|
| ① | 성공 기준 표, 품질속성 표 | 지표 출처와 목표값 출처 |
| ② | 외부 서비스 목록 표, 노드·간선 근거 대조표 | 외부 연계 지점의 출처 |
| ④ | 에이전트별 계약 표(전 항목) | 에이전트 후보의 근거 스토리 ID |
| ③ | 시퀀스 단계 표, 단계 간 데이터 형식 표, 출력 스키마 표 | 단계·필드의 근거 스토리 ID |
| ⑤ | 민감 필드 분류표, 정형 접근 경로 표, 비정형 접근 경로 구분 표 | 보안·컴플라이언스 NFR 출처 |
| ⑥ | 가드레일 규칙 표, 품질 측정 대상 표, 비용 상한 표 | 차단형 검증 요구·지표·비용 출처 |
| ⑦ | 비밀값 주입 표, 저장소 배치 표 | 보안 NFR 출처 |

**ID 표기 형식** — `{문서 약칭}:{항목 ID}#{하위 항목}`

| 요소 | 규칙 | 예시 형태 |
|------|------|----------|
| 문서 약칭 | `BM`·`US`·`PR` 3종 고정(상수) | `US` |
| 항목 ID | 기획 산출물에 부여된 ID 원문. 형식 점검은 `{기획 산출물 경로·ID 체계}`로만 수행함 | `UFR-REC-010`, `NFR-SYS-010` |
| 하위 항목 | 블록명 + 순번. 블록명은 `입력`·`검증`·`성공`·`실패`·`체크리스트` 5종 고정 | `#검증3` |
| ID 없는 절 | 절 번호 + 절 제목을 줄여 씀 | `BM:4-비즈니스가치연계#고객1` |

- 복수 근거는 `;`로 구분하며 최대 3건까지 표기함. 4건 이상이면 상위 항목 ID로 묶어 1건으로 표기함
- 근거가 없는 행은 공란으로 두지 않고 `설계판단`으로 표기하며 표 하단에 판단 근거 1줄을 각주로 남김
- 범위외 처리된 근거는 `[범위외: {제외 항목명}]`을 근거 출처 칸에 함께 적음
- 태그(`P1`·`부분반영`·`신설`·`도출`·`통계량 해석`)는 근거 출처 칸 말미에 함께 적음

**역방향 대조표 2건** — 기획 산출물 항목이 설계에 반영되었는지 확인함.

| 대조표 | 위치 | 대상 | 필수 기재 |
|--------|------|------|----------|
| 기능 요구 반영 대조표 | ④ 말미 | US의 기능 요구 전부 | 반영 산출물·미반영 사유·미반영 건수(숫자) |
| 비기능 요구 반영 대조표 | ⑥ 말미 | US의 NFR 전부 | 반영 산출물·범위외 여부·미반영 건수(숫자) |

P2 스토리는 `설계 제외(P2)`로, 범위외 처리 건은 `범위외`로 표기하며 미반영 건수에 포함하지 않음.  
나머지 미반영만 숫자로 집계함. P2 스토리는 `{범위 제외 목록}`에 올리지 않으므로  
[공통 규약](00-공통규약.md) 6절 `제외 범위 미포함 대조표`의 대상이 아니며,  
두 표기가 같은 항목에 중복 적용되지 않음([파라미터 블록](00-파라미터블록.md) 2절 V-09 `무엇을 담는가`).
