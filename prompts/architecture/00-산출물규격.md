## 2. 의존관계 판정표

`HARD`는 앞 산출물이 없으면 뒤 산출물 칸을 아예 채울 수 없는 관계임. `SOFT`는 없어도 시작할 수 있으나  
앞이 확정되면 다시 손봐야 하는 관계임. `CYCLE`은 서로를 참고해야 해서 한 번 되돌려 반영해야 하는 관계임.

| # | 선행 → 후행 | 강도 | 근거 한 줄 |
|---|------------|------|-----------|
| D-01 | ① → ③ | HARD | 응답시간 목표가 없으면 단계별 타임아웃 예산을 나눠 배정 불가 |
| D-02 | ① → ⑥ | HARD | 우선 품질속성 3개가 없으면 품질 측정 대상·문항 수를 결정 불가 |
| D-03 | ① → ② | SOFT | ①이 모든 설계 결정의 판정 기준이므로 미확정 시 경계 재조정이 발생함 |
| D-04 | ① → ④ | SOFT | 에이전트별 성공 기준은 시스템 성공 기준의 분해이므로 재작성이 발생함 |
| D-05 | ① → ⑤ | SOFT | 설명가능성 품질 채택 여부가 검색 경로 선택 근거의 상세도를 바꿈 |
| D-06 | ② → ⑤ | HARD | 신뢰 경계가 표시되어야 민감정보 변환 지점이 결정됨 |
| D-07 | ② → ③ | HARD | 외부 서비스 관계도가 없으면 시퀀스 참여 주체를 배치 불가 |
| D-08 | ② → ⑦ | HARD | 내부 구성도가 없으면 이미지 분할 단위를 결정 불가 |
| D-09 | ② → ④ | SOFT | 외부 서비스 목록이 `사용 도구` 후보를 좁히나 책임·성공 기준은 선작성 가능 |
| D-10 | ③ → ④ | HARD | 단계 목록·키 집합 식별자가 없으면 책임 묶음과 입출력 형식을 확정 불가 |
| D-11 | ④ → ⑦ | SOFT | 에이전트 수·사용 모델이 이미지 분할 판단에 영향하나 단일 이미지 선택도 가능 |
| D-12 | ③ → ⑥ | HARD | ⑥은 시퀀스 위 오버레이이므로 시퀀스 없이 작성 대상이 없음 |
| D-13 | ③ → ⑦ | SOFT | 최종 출력 형식이 프론트·API 분리 여부에 영향함 |
| D-14 | ⑤ → ⑦ | HARD | 저장소 종류가 정해져야 배치 위치를 지정 가능 |
| D-15 | ⑥ → ⑦ | SOFT | 관측 기록의 적재 위치가 저장소 배치에 영향하나 미확정으로도 배포 단위 확정 가능 |
| D-16 | ④ ↔ ⑤ | CYCLE | 민감 필드 분류표 ↔ 에이전트별 권한 상호 참조(C-1) |
| D-17 | ③ ↔ ⑤ | CYCLE | 접근 경로 목록 ↔ 커넥터 입출력 규격 상호 참조(C-2) |
| D-18 | ③ ↔ ⑥ | CYCLE | 타임아웃 값을 양쪽이 중복 소유(C-3) |

판정 요약 — HARD 8건·SOFT 7건·CYCLE 3건임. HARD로 받는 것이 가장 많은 산출물은 ③·⑥·⑦(각 2건)이고,  
HARD로 넘겨주는 것이 가장 많은 산출물은 ②(D-06·D-07·D-08)임. ②가 늦어지면 ③⑤⑦이 한꺼번에 멈춤.

CYCLE 3건 상세임.

| ID | 순환 쌍 | 정방향 근거 | 역방향 근거 | 해소 방법 |
|----|--------|------------|------------|----------|
| C-1 | ④ ↔ ⑤ | ⑤의 민감 필드 분류표가 없으면 ④의 `접근 가능한 정보 항목`을 필드 단위로 나열 불가 | ④의 에이전트별 권한이 없으면 ⑤의 변환 지점을 어느 경로에 걸지 확정 불가 | 필드 목록 초안 → ④ 권한 배정 → ⑤ 변환 지점 확정의 1회 되돌려 반영 |
| C-2 | ③ ↔ ⑤ | ⑤의 커넥터 입출력 규격은 ③가 정한 단계 간 데이터 형식에 맞춰야 함 | ⑤가 경로를 바꾸면(예: 문서 검색 → 표 조회) ③의 단계·타임아웃을 고쳐야 함 | ③ 단계 초안 → ⑤ 경로 확정 → ③에 `변경요청` 1행으로 1회 되돌려 반영 |

## 3. 임계 경로

임계 경로(전체 일정을 좌우하는 가장 긴 작업 사슬)는 HARD 간선(도식에서 노드를 잇는 선)만으로 구성한  
최장 경로임.

```
① 목표·품질속성 카드
  └→ ② 논리 아키텍처
       └→ ③ 오케스트레이션 패턴 + 시퀀스 설계   ← 참여 주체는 ②의 구성요소에서 가져옴
            └→ (④ 에이전트 역할 계약서 ↔ ⑤ 지식·도구 설계 : 1회 되돌려 반영 동기화)
                 └→ ⑥ 가드레일·관측 설계

[임계 경로 밖] ⑦ 배포 설계 — ②·⑤ 확정 시 시작 가능. ③·⑥ 완료를 대기하지 않음
```

근거는 D-07·D-10·D-06·D-12의 HARD 연쇄와 C-1 순환임. ⑦은 배포 단계의 선행 조건이므로  
설계 단계 내 완료 대상임.

## 4. 설계 절차 9단계 매핑

9단계 — `목표·품질속성 → 시스템 경계 → 단일·멀티 판정 → 역할 계약 → 조직구조·패턴 선정 →  
상호작용·상태 → 지식·도구 → 가드레일·관측·평가 → 배치·비용`

| 단계 | 단계명 | 대응 산출물 | 대응 유형 | 판정 근거 |
|------|--------|------------|-----------|----------|
| 1 | 목표·품질속성 | ① | 1:1 | ①이 성공 기준 3개·우선 품질 3개를 측정 가능 문장으로 정의함 |
| 2 | 시스템 경계 | ② | 1:1 | ②가 AI 서비스·외부 서비스 관계와 신뢰 경계선을 표시함 |
| 3 | 단일·멀티 판정 | 없음 → ④ 흡수 | 미대응 | 7종에 판정 근거 칸이 없음. 6절 G-1로 ④에 흡수함 |
| 4 | 역할 계약 | ④ | 1:1 | ④이 7개 계약 칸을 정의함 |
| 5 | 조직구조·패턴 선정 | ③(전반) | N:1 | ③가 패턴을 고르고 근거를 남기는 부분에 대응함 |
| 6 | 상호작용·상태 | ③(후반) | N:1(부분) | ③가 처리 순서·데이터 형식·출력 형식·타임아웃·재시도를 담음. `상태`는 6절 G-2로 흡수 |
| 7 | 지식·도구 | ⑤ | 1:1 | ⑤가 정형·비정형 접근 경로·커넥터·민감 필드 분류표를 정의함 |
| 8 | 가드레일·관측·평가 | ⑥ | 1:1 | ⑥이 단계별 태그·기록 지점·품질 측정 대상과 문항 수를 명시함 |
| 9 | 배치·비용 | ⑦(배치) + ⑥(비용) | 1:N 나뉨 | ⑦은 배포 단위·포트·비밀값·저장소 배치, 비용 상한은 ⑥에 위치함 |

매핑 결과 — 9단계 중 8단계가 7종으로 커버되고, 3단계는 대응 산출물이 없어 흡수 판정으로 처리함.  
5·6단계는 ③ 한 곳으로 모임(N:1)이고 9단계는 ⑦·⑥으로 나뉨(1:N)임.

**9단계 번호와 우리 산출물 번호는 순서가 다름에 주의함.** 9단계는 개념 계보 순서(역할 계약이 4번째)이나
우리 실행 순서는 **③ 패턴·시퀀스를 ④ 역할 계약서보다 앞**에 둠. 흐름을 먼저 확정해야 그 단계를 누가
맡을지 나눌 수 있기 때문임(2026-08-06 판정, 3절 임계 경로 참조).

## 5. 실행 순서

### 5-1. 직렬 실행 순서

프롬프트 배치 번호 순이 아니라 아래 확정 순서를 따름. 근거는 3절 임계 경로임.

1. 직렬 1회 실행 — `① → ② → ③ → ④ → ⑤ → ⑥ → ⑦`(번호 = 실행 순서)
2. CYCLE 3건 재실행 — `④`(C-1 되돌려 반영) → `⑤`(C-1·C-2 되돌려 반영) → `③`(C-2·C-3 되돌려 반영) →  
   `⑥`(갱신된 ③의 타임아웃·단계 목록 인용 갱신) → `⑦`(③ 최종 출력 형식·⑥ 관측 적재 위치 SOFT 반영).  
   `⑥`·`⑦` 재실행은 [공통 규약](00-공통규약.md) 7절 갱신 규칙에 따라 변경 칸만 갱신함
3. 7종 확정 후 [공통 규약](00-공통규약.md) 6절 반영 대조표 2종을 `{출력 루트 경로}00-반영대조표.md`로  
   1회 작성함 (작성 주체는 `{작성 체제·역할 배정}` 미기입 시 `단일 작성자`)

`{작성 체제·병렬 순번 표}`가 기입된 프로젝트는 다인 병렬 작성 시 5-2절 `W-1`~`W-n` 순번을 사용함.  
단일 작성자가 레퍼런스 산출물을 작성할 때는 위 직렬 순서만 사용함.

앞 프롬프트가 생성한 파일이 뒤 프롬프트의 `[입력정보]`에 경로로 이미 기재되어 있으므로, 별도 붙여넣기 없이  
파일이 존재하는 상태에서 다음 프롬프트를 실행함.

### 5-2. 병렬 순번 표

기본은 5-1절 직렬 순서임. `{작성 체제·병렬 순번 표}`가 기입된 프로젝트만 아래 병렬 순번을 사용함.

| 순번 | 수행 형태 | 대상 | 권고 사유 |
|------|----------|------|----------|
| W-1 | 전원 공동 | ① 확정 | 모든 설계 결정의 판정 기준임 |
| W-2 | 전원 공동(단시간) | ②의 전체 관계도·신뢰 경계선 | HARD로 넘겨주는 것 3건을 개인 작업에 두지 않음 |
| W-3 | 3병렬 | ② 내부 구성 마감 / ④ 초안 / ⑤ 초안 | ② 확정 후 병렬 구간. 역할 배정 유지 |
| W-4 | 동기화 1회 | ④ ↔ ⑤ 되돌려 반영 | 접근 정보 항목과 민감 필드 분류표를 필드 단위로 서로 맞춤(C-1) |
| W-5 | 3병렬 | ③ 작성(③ 담당) / ⑥ 측정 문항 초안(예외 담당) / ⑦ 초안(⑦ 담당) | ③ 담당 대기 제거, 측정 문항을 역량 보유자에게 배정 |
| W-6 | 동기화 1회 | ③ ↔ ⑤ 커넥터 규격 서로 맞춤, ③ ↔ ⑥ 타임아웃 소유 선언 | C-2·C-3 해소 |
| W-7 | 병렬 | ⑥ 오버레이 완성 + ⑦ 마감 / ③ 마감 / `{규제·안전 점검 항목}` 대조 | 후반 부하 완화, 점검 항목 누락 방지 |
| W-8 | 전원 | 7종을 형상 저장소(버전을 관리하며 산출물을 보관하는 곳)에 넣음 | 산출물 확보 시점 고정 |

식별자 규약 — 작성 순번은 `W-n`(work), ③의 시퀀스 단계는 `S-n`(sequence)로 구분함. 두 접두어를 혼용하지 않음.  
③·⑥의 인용 출처 표기는 `③ 타임아웃 표 S-n 행` 형식으로 고정함.

## 6. 공백 흡수 판정 5건

공백 흡수 판정(빠진 항목을 기존 7종 중 1건에 넣는 판정) 5건임. 9단계 중 소유처가 없는  
관심사(소유처를 정해야 하는 설계 항목)를 기존 7종에 흡수한 확정 판정이며 8번째 산출물을 신설하지 않음.

| ID | 공백 내용 | 판정 | 반영 위치 | 근거 |
|----|----------|------|----------|------|
| G-1 | 9단계 3단계 `단일·멀티 판정` 근거를 기록할 칸이 없음 | ④에 흡수 | ④ 작업방법 1번, 완료조건 (a) | 판정 결과가 곧 에이전트 목록이므로 계약서 머리말이 최소 거리임. 3줄 이내로 한정함 |
| G-2 | 상태(state) 스키마 설계 칸이 없음 | ③에 흡수 | ③ 작업방법 상태 스키마 단계 | 9단계 6단계가 `상호작용·상태`이며 ③가 6단계를 담당함 |
| G-3 | 메모리 설계 항목이 없음 | ③에 흡수(최소 기재) | ③ 작업방법 대화 이력 보존 범위 단계 | 대화 이력 보존 범위 1줄로 제한함. 상세 설계는 금지함 |
| G-4 | 타임아웃이 ③·⑥ 양쪽에 등장하여 단일 출처가 없음 | ③가 값을 소유, ⑥은 참조만 | ③ MUST / ⑥ MUST NOT | ③가 응답시간 예산을 나눠 배정하는 주체이므로 산정 주체와 소유를 일치시킴 |
| G-8 | 모델 선택 근거를 남기는 칸이 미명시 | ④에 흡수 | ④ 작업방법 `사용 모델` 단계 | ④에 `사용 모델` 칸이 이미 있으므로 배정 이유 1줄을 같은 칸에 덧붙여 적으면 새 항목을 만들지 않고 해결됨 |
