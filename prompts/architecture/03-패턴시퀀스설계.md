[작업방법]
0. 입력 가용성을 확인함. 기획 산출물 3종과 선행 ①②의 부재 항목을 `[확인필요: 선행 미생성]` 또는
   `[확인필요: {항목명}]`으로 기록한 뒤 시작 가능한 항목부터 작성함. 작성을 중단하지 않음
1. 오케스트레이션 패턴 후보를 3개 이상 하나씩 적고 장단점을 표로 대비한 뒤 1개를 선택함. 후보는 패턴
   수준으로 한정하며 구현 프레임워크를 후보로 올리지 않음. 선택 근거에 ①의 우선 품질속성 중 최소 1개와
   BM `UVP — 핵심 가치`(인용 코드 `R`)를 명시적으로 인용함
2. `처리 순서(시퀀스)`를 Mermaid `sequenceDiagram`으로 작성하고 단계마다 식별자를 부여함.
   실행 트리거(처리를 시작시키는 계기)가 다른 흐름(동기 요청 / 스케줄 배치 / 이벤트)은 시퀀스를
   트리거별로 분리하고 단계 식별자에 트리거 구분을 붙임(`S-R1`~ 동기 요청 / `S-B1`~ 스케줄 배치 / `S-E1`~ 이벤트). 트리거가 1종이면
   `S-1`~`S-n`을 사용함. 큰 틀은 PR `To-Be 프로세스 흐름`을, 각 단계는 US 시나리오 3부분을 변환하여
   채움(`Q`) — `상황`은 진입 조건, `행위`는 단계 1건(외부 호출 포함 시 분할), `결과`는 종료 상태로 옮김.
   참여 주체와 처리 노드(도식에서 하나의 상자·지점)는 ②의 구성 요소·저장소·외부 서비스로 한정함.
   ④은 아직 없으므로 에이전트 이름을 신설하지 않으며, 어느 에이전트가 맡을지는 ④에서 정함.
   단계 전부를 `시퀀스 단계 표`(`단계`·`트리거`·`참여 주체(② 인용)`·`행위`·`종료 상태`·`근거 출처`)로 함께 적음
3. 사전 조건 확인 지점을 시퀀스의 독립 노드로 배치하고 확인 실패 시 분기 경로를 표기함. 위치 근거는
   PR `인간 개입(확인·승인) 지점`과 US NFR 컴플라이언스 계열이며(`Q`),
   {규제·안전 점검 항목}:사전 조건 확인의 반영 지점임(해당 계열 행이 0건이면 00-공통규약.md의 미확정 정보 태그 규칙 `계열 미해당 처리`를
   적용하고 본 단계와 대응 MUST·완료조건 (b)의 확인 단계 행 요구를 제거함)
4. `단계 간 데이터 형식` 표를 정의함. 간선(도식에서 노드를 잇는 선)마다 송신 노드·수신 노드·전달 키 집합 식별자·
   필수 여부·`근거 출처`를 기재함. 본 산출물은 **키 집합 식별자만 확정하고 키 이름·타입을 나열하지 않음**
   (형식 — `③ {송신 단계} → {수신 단계} · {집합명}`). 키 이름은 후행 ④이 이 식별자에 붙여 채우며 그 단일
   출처는 ④임(G-12). 필수 여부·값 제약은 US `[입력 요구사항]`을 인용함(`Q`)
5. `상태(state) 스키마`를 정의함. 그래프 전체가 들고 다니는 필드명·타입·갱신 주체를 표로 기재하고,
   코드베이스의 상태 스키마 구성을 조회할 수 없으면 `[확인필요: 상태 스키마 필드 구성]`을 칸에 남김
6. `대화 이력 보존 범위`를 1줄로 기재함. 보존 대상(직전 N턴 / 요약본 / 미보존)과 사유만 씀
7. 「{최종 산출물·명칭}」 출력 형식을 스키마(필드명·타입·필수 여부·설명·`근거 출처`)로 정의함. 필드는
   US `[처리 결과] 성공 시`를 인용하여 채우고(`Q`), {최종 산출물·구성 단위}의 반복 항목과
   {최종 산출물·근거 항목}을 담는 필드를 각각 1개 이상 포함함
8. `타임아웃·재시도` 표를 단계별로 작성함. `직렬/병렬` 열(차례로 실행 / 동시에 실행)을 두고 ①의
   응답시간 목표값을 총 예산으로 인용하여 나눠 배정하되, 항목마다 따로 정한 수치는
   US NFR 성능 계열 `[체크리스트]`를 우선 채택함(`Q`, 출처 1순위).
   합계 검증은 **동기 요청으로 시작하는 흐름에만** 함. 차례로 실행되는 가장 긴 길의 합계가 총 예산
   이하인지를 표 아래 합계 행에서 확인하며, 동시에 실행되는 구간은 그 구간에서 가장 큰 값 1건만 합계에
   넣음. 배치·이벤트 트리거 시퀀스는 ①의 배치 완료 목표값으로 검증하며 부재 시
   `[확인필요: 배치 완료 목표시간]`을 남김. ①의 응답시간 목표값이 `[확인필요: 목표값]`이면
   총 예산 칸을 `[확인필요: ① 응답시간 목표값]`으로 표기하고 합계 검증을 단계별 비율(%) 나눠 배정으로
   대체함. 재시도는 횟수와 백오프(재시도 간격을 점점 늘리는 방식) 유무를 표기함
9. 문서 머리말에 고정 문구 `타임아웃 값의 단일 출처는 본 산출물임`을 1줄 선언함
10. ⑤의 접근 경로 목록과 대조하여 검색·조회 단계 배치와 커넥터(외부 시스템에 붙는 연결 부품) 입출력
    규격이 일치함을 확인함(CYCLE C-2). 불일치는 `값충돌` 유형으로 `기획 산출물 대조 기록` 표에 1행 남김
11. 각 설계 항목의 소비처를 `후행 소비처`(뒤 산출물 중 이 값을 쓰는 곳) 표로 작성함 —
    ④ 책임 묶기·입출력 형식(HARD) / ⑥ 오버레이(HARD) / ⑦ 최종 출력 형식(SOFT). 시퀀스 단계
    목록의 개수와 명칭을 확정 출력물로 명시하여 ④이 단계를 묶어 역할을 나누고 ⑥이 단계 추가·삭제·병합
    없이 오버레이할 수 있게 함
