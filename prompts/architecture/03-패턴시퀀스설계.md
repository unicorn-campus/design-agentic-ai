[작업방법]
0. 입력 가용성을 확인함. 기획 산출물 3종과 선행 ①②의 부재 항목을 `[확인필요: 선행 미생성]` 또는
   `[확인필요: {항목명}]`으로 기록한 뒤 시작 가능한 항목부터 작성함. 작성을 중단하지 않음
1. 오케스트레이션 패턴 후보를 3개 이상 하나씩 적고 장단점을 표로 대비한 뒤 1개를 선택함. 후보는 패턴
   수준으로 한정하며 구현 프레임워크를 후보로 올리지 않음. 선택 근거에 ①의 우선 품질속성 중 최소 1개와
   BM `UVP — 핵심 가치`(인용 코드 `R`)를 명시적으로 인용함
2. `처리 순서(시퀀스)`를 Mermaid `sequenceDiagram`으로 작성하고 단계마다 식별자를 부여함.
   실행 트리거(처리를 시작시키는 계기)가 다른 흐름(동기 요청 / 스케줄 배치 / 이벤트)은 시퀀스를
   트리거별로 분리하고 단계 식별자에 트리거 구분을 붙임(`S-R1`~ 동기 요청 / `S-B1`~ 스케줄 배치 / `S-E1`~ 이벤트). 트리거가 1종이면
   `S-1`~`S-n`을 사용함. 큰 틀은 PR `To-Be 프로세스 흐름`을, 각 단계는 US 시나리오 3부분을 변환하여
   채움(`Q`) — `상황`은 진입 조건, `행위`는 단계 1건(외부 호출 포함 시 분할), `결과`는 종료 상태로 옮김.
   참여 주체와 처리 노드(도식에서 하나의 상자·지점)는 ②의 구성 요소·저장소·외부 서비스로 한정하며
   저장소도 참여 주체로 그림. 비동기 경로는 뒤 담당자를 직접 부르지 않고 저장소를 거치게 그림.
   ④은 아직 없으므로 에이전트 이름을 신설하지 않으며, 어느 에이전트가 맡을지는 ④에서 정함.
   단계 전부를 `시퀀스 단계 표`(`단계`·`트리거`·`참여 주체(② 인용)`·`행위`·`종료 상태`·`근거 출처`)로 함께 적음
3. 사전 조건 확인 지점을 시퀀스의 독립 노드로 배치하고 확인 실패 시 분기 경로를 표기함. 위치 근거는
   PR `인간 개입(확인·승인) 지점`과 US NFR 컴플라이언스 계열이며(`Q`),
   {규제·안전 점검 항목}:사전 조건 확인의 반영 지점임(해당 계열 행이 0건이면 00-공통규약.md의 미확정 정보 태그 규칙 `계열 미해당 처리`를
   적용하고 본 단계와 대응 MUST·완료조건 (b)의 확인 단계 행 요구를 제거함)
4. `단계 간 데이터 형식` 표를 정의함. 간선(도식에서 노드를 잇는 선)마다 송신 노드·수신 노드·전달 키 집합 식별자·
   필수 여부·`근거 출처`를 기재함. 본 산출물은 **키 집합 식별자만 확정하고 키 이름·타입을 나열하지 않음**
   (형식 — `③ {송신 단계} → {수신 단계} · {집합명}`). 키 이름은 후행 ④이 이 식별자에 붙여 채우며 그 단일
   출처는 ④임(G-12). 필수 여부·값 제약은 US `[입력 요구사항]`을 인용함(`Q`)
5. `상태(state) 스키마`를 정의함. 그래프 전체가 들고 다니는 필드명·타입·갱신 주체·갱신 방식을 표로
   기재하되 필드마다 갱신 주체를 **1개만** 둠. 동시에 실행되는 구간이 쓰는 필드는 갱신 방식을
   `누적만`으로 둠 — 갱신 기본이 덮어쓰기라 병렬 결과 중 1건만 남음. 필드를 갈라 둘 수 있으면 갈라
   두기를 먼저 적용하고 안 되는 경우에만 누적을 씀. 단계 사이를 흐르는 입력 키가 상태 필드의 1순위
   후보임. 코드베이스의 상태 스키마 구성을 조회할 수 없으면 `[확인필요: 상태 스키마 필드 구성]`을 칸에 남김
6. `대화 이력 보존 범위`를 1줄로 기재함. 보존 대상(직전 N턴 / 요약본 / 미보존)과 사유만 씀
7. 「{최종 산출물·명칭}」 출력 형식을 스키마(필드명·타입·필수 여부·설명·`근거 출처`)로 정의함. 필드는
   US `[처리 결과] 성공 시`를 인용하여 채우고(`Q`), {최종 산출물·구성 단위}의 반복 항목과
   {최종 산출물·근거 항목}을 담는 필드를 각각 1개 이상 포함함
8. `타임아웃·재시도` 표를 단계별로 작성함. 열은 `단계`·`직렬/병렬`(차례로 실행 / 동시에 실행)·
   `p95 배정값`(요청 100건 중 95건이 이 시간 안에 끝나는 값)·`타임아웃(상한)`·`재시도 계층`·`재시도`·
   `최악값`·`초과 시 처리`·`근거 출처`임.
   `재시도 계층`은 같은 요청을 다시 부르는 층의 이름임 — 예로 `호출부 재시도`·`큐 재처리`·`DLQ 재시도`.
   **한 요청에 두 층이 겹치면 배수가 곱해짐**(5회 × 3회 = 15배). 층이 1개면 그 이름을 적고,
   층이 없으면 `없음`으로 적음. ⑥이 이 열을 세어 `M_재시도`를 계산함
   ([공통 규약](00-공통규약.md) 4-2절 `M-4`). 표 머리에 트리거별 `응답 마감선`(이 시간을 넘기면 바깥에서 연결을
   먼저 끊는 하드 상한) 1줄을 출처와 함께 먼저 적음 — 단계별 열이 아니라 시퀀스당 1개임. 출처는
   동기 요청이면 API 게이트웨이·로드밸런서·클라이언트 타임아웃 중 가장 짧은 값, 스케줄 배치면 실행 창,
   이벤트면 메시지 가시성 타임아웃·리스 기간임. 확인 못 하면 `[확인필요: 응답 마감선]`을 남기고
   지어내지 않음. 총 예산은 ①의 응답시간 목표값을 인용해 나눠 배정하되 항목마다 따로 정한 수치는
   US NFR 성능 계열 `[체크리스트]`를 우선 채택함(`Q`, 출처 1순위).
   단계 최악값은 `타임아웃 × (1 + 재시도 횟수)`로 계산함. 합산은 같은 호출을 다시 하면 **곱하고**
   (재시도), 다른 경로로 넘어가면 앞 단계 타임아웃을 소진한 뒤 그 경로 시간을 **더함**(폴백).
   대체 경로에도 시간을 배정함 — 배정이 없으면 폴백 최악값이 0으로 잡힘. 직렬 구간은 더하고
   병렬 구간은 그 구간의 최댓값 1건만 씀. ①의 응답시간 목표값이 `[확인필요: 목표값]`이면 총 예산 칸을
   `[확인필요: ① 응답시간 목표값]`으로 표기하고 단계별 비율(%) 나눠 배정으로 대체함. 재시도는
   횟수와 백오프(재시도 간격을 점점 늘리는 방식) 유무를 표기함
8-1. `반복 상한` 표를 루프마다 1행씩 작성함. 열은 `루프`·`max_iter`(같은 구간을 되풀이하는 최대 횟수)·
   `반복 1회의 비용 증분`(되풀이 1회가 더 부르는 모델 호출 수)·`초과 시 처리`·`근거 출처`임.
   표 아래에 요청당 모델 호출 배수를 `1 + (max_iter × 반복 1회 호출 증분)`으로 계산한 1줄을 두고,
   그 값을 ⑥의 비용 상한 산정 근거로 넘김(11번 `되돌려 보내는 값` 표에 1행).
   **이 값은 본 산출물이 1회만 계산하며 ⑥은 다시 계산하지 않고 인용함**
   ([공통 규약](00-공통규약.md) 4-2절 `M-2`). 상한 값을 US에서 못 찾으면
   `[확인필요: 반복 상한]`으로 남기되 `초과 시 처리` 칸은 비우지 않음. 증분이 0이 아닌데 상한 값이
   없으면 그 행에 비용 상한 표시를 함께 붙임
8-2. `상한 초과 처리`를 상한마다 1개씩 정함. 상한이 생기는 자리는 `시간`(8번 표)·`반복`·`비용`
   (8-1번 표) 3유형뿐임. 갈 곳(착지 노드 — 상한에 닿았을 때 대신 들어가는 단계)을 3종 중 1개로
   정하며 아래 순서로 물어 처음 `예`에서 멈춤 — (가) `부분 결과로 계속`(품질을 낮춘 답을 줌. 낮춘
   사유 필드와 그 경로의 시간·비용 배정이 함께 있어야 함) / (나) `사람 확인`(사람이 판단해야 하고
   기다릴 수 있을 때. 동기 요청이면 확인 대기 상태만 남기고 응답을 닫음) / (다) `안전 종료`(멈추고
   안내함). `폴백`은 (가)만 가리키므로 3종 전체를 부르는 이름으로 쓰지 않음. 착지는 상한에 닿기 전 마지막 여유에서
   들어가는 분기이며, 착지 경로가 같은 유형의 상한을 다시 쓰면 착지가 아님 — 착지의 시간·비용이
   예산 안이라는 것을 1줄로 적음
8-3. `대조 2줄`을 타임아웃 표 아래에 작성함. 두 줄이 서로 다른 기준을 쓰므로 1줄로 합치지 않음 —
   (1) `p95 합계 ≤ 총 예산`(큐잉 포함·재시도 제외) (2) `최악값 합계 ≤ 응답 마감선 − 착지 경로 시간`.
   두 줄 모두 통과해야 하며, (1)을 넘으면 `시간` 상한의 `초과 시 처리`가 채워져 있어야 함. 대조 대상은
   동기 요청 트리거이고 배치·이벤트는 ①의 배치 완료 목표값·전달 지연 목표로 대조하며 부재 시
   `[확인필요: 배치 완료 목표시간]`을 남김. 단계마다 최악값을 다시 더하는 대신 진입 노드가 마감 시각
   필드 1개를 상태에 넣고 각 단계가 시작 전에 남은 시간을 보는 방식도 허용함(그 필드의 갱신 주체는
   진입 노드 1개이며 이후 불변임). `총 예산 ÷ 단계 수` 나눠 배정이 ①의 목표값을 못 맞추면 값을 낮추지
   않고 ①에 `분해 회신` 1행으로 되돌림(11번 `되돌려 보내는 값` 표에 1행)
8-4. `부하 조건` 표를 트리거마다 1행 작성함. 열은 `동시 사용자 수`·`요청당 자원 점유 시간`·
   `동시 처리 상한`(커넥션 풀·동시 실행 슬롯처럼 **동시에 쓸 수 있는 수**)·`판정`이며
   판정식은 `동시 사용자 수 × (요청당 자원 점유 시간 ÷ 응답 마감선) ≤ 동시 처리 상한`임
   ([공통 규약](00-공통규약.md) 4-2절 `M-5a`). 시간을 마감선으로 나눠 **비율로 바꾼 뒤** 곱함.
   나누지 않고 시간을 그대로 곱하면 좌변과 우변의 단위가 달라 판정이 성립하지 않음.
   **배포 자원 관점의 검산(`M-5b`, `런타임 규모 상한`)은 ⑦ 소유이며 본 산출물이 하지 않음.**
   두 상한을 `자원 상한` 한 낱말로 합쳐 쓰지 않음.
   `동시 사용자 수`는 US NFR 확장성·성능 계열에서 인용하고(`Q`), ①의 응답시간 목표값에 부하 전제
   (평시·피크)가 적혀 있으면 함께 인용함. 없으면 `[확인필요: 부하 전제]`를 남김. 네 칸 중 하나라도
   없으면 `[확인필요: {항목명}]`을 남기고 `판정` 칸에 `통과`를 적지 않음
8-5. `재개 경계`(끊긴 실행을 다시 들어가는 자리) 표를 트리거마다 1행 작성함. 열은 `재개 단위`·
   `경계 단계`(`S-` 식별자)·`재실행 부작용`(있음/없음)·`중복 방지 키`임. 동기 요청은 재개하지 않고
   재시도로 끝내며 그 판정을 1줄 적음. 배치·이벤트는 재개 단위를 `실행 1회` 또는 `대상 1건` 중 1개로
   고름. 시작했다가 못 끝낸 단계는 재개 때 다시 실행되므로 그 단계가 밖을 바꾸면(적재·발송·결제)
   중복 방지 키가 필수이며, 부작용이 `있음`인데 키가 비면 `통과`로 적지 않음. 저장 방식·체크포인트
   API·저장 백엔드 선택은 구현 단계 소관이므로 본 산출물에서 지정하지 않음
9. 문서 머리말에 고정 문구 `타임아웃 값의 단일 출처는 본 산출물임`을 1줄 선언함
10. ⑤의 접근 경로 목록과 대조하여 검색·조회 단계 배치와 커넥터(외부 시스템에 붙는 연결 부품) 입출력
    규격이 일치함을 확인함(CYCLE C-2). 불일치는 `값충돌` 유형으로 `기획 산출물 대조 기록` 표에 1행 남김

    `처리 결과`). 타임아웃 값의 소유가 본 산출물이므로 ⑥은 값을 직접 고치지 않고 본 표에 `변경요청`
    1행을 보냄(G-4). ⑥이 가드레일을 걸 단계가 시퀀스에 없어 보내는 `트리거 추가` 요청, ④이 중단

    받음. 요청마다 값을 고쳤는지 거절했는지를 `처리 결과` 칸에 사유 1줄과 함께 적고 비우지 않음
10-2. 재시도·폴백·타임아웃의 실패 대응 통합 확인 지점은 본 산출물임(G-5). `시간`·`반복`·`비용`
    3유형의 상한과 착지 노드를 한 표에서 대조해 착지 노드가 빠진 상한이 0건임을 확인함. ④의 중단
    조건은 "무엇을 보면 멈추나"까지이고 ⑥은 관측 항목으로 결과를 검증만 하므로, 두 산출물의 값을
    본 산출물이 인용하지 않고 본 산출물의 값을 두 곳이 인용함

- MUST: 모든 단계에 타임아웃 값이 표기되고, 트리거마다 `응답 마감선` 1건이 출처와 함께 기재되며,
  대조 2줄이 각각 존재함 — `p95 합계 ≤ 총 예산`(병렬 구간은 그 구간의 최댓값 1건만 넣음)과
  `최악값 합계 ≤ 응답 마감선 − 착지 경로 시간`. 배치·이벤트 트리거 시퀀스는 ①의 배치 완료
  목표값으로 대조하며 부재 시 `[확인필요: 배치 완료 목표시간]`을 남김.
  고정 문구 `타임아웃 값의 단일 출처는 본 산출물임`을 머리말에 1줄 선언함
- MUST: 시퀀스 단계 표·단계 간 데이터 형식 표·출력 스키마 표에 `근거 출처` 열이 존재하며 근거 없는
  행은 `설계판단`으로 표기함
- MUST: 상한이 생기는 자리(`시간`·`반복`·`비용`)마다 `초과 시 처리` 칸이 3종(`부분 결과로 계속`·
  `사람 확인`·`안전 종료`) 중 1개로 채워지고 공란이 0건임. `부분 결과로 계속` 행에는 낮춘 사유
  필드와 그 착지 경로의 시간·비용 배정이 함께 기재됨
- MUST: 루프마다 `max_iter`·`반복 1회의 비용 증분`·`초과 시 처리`가 기재되고, 요청당 모델 호출
  배수 `1 + (max_iter × 반복 1회 호출 증분)` 계산 결과 1줄이 존재함
- MUST: `타임아웃·재시도` 표의 모든 행에 `재시도 계층` 값이 기재됨(층이 없으면 `없음`).
  ⑥이 이 열로 `M_재시도`를 계산하므로 공란을 두지 않음
- MUST: 상태 스키마의 필드마다 갱신 주체가 1개이고, 동시에 실행되는 구간이 쓰는 필드의 갱신 방식이
  `누적만`임
- MUST: 트리거마다 `부하 조건` 판정 1행과 `재개 단위`·`경계 단계` 1행이 존재하고, 재실행 부작용이
  `있음`인 행의 `중복 방지 키` 공란이 0건임
- MUST: `변경요청 수신` 표가 존재하며 ⑥의 타임아웃 값 불일치·트리거 추가 요청과 ④의 재시도 값·
  `공유` 키 되돌림을 본 표로 받음(G-4). 실패 대응(재시도·폴백·타임아웃) 통합 확인의 기준 산출물은
  본 산출물임(G-5)
- MUST NOT: {범위 제외 목록} 중 본 산출물이 차단 위치인 항목을 내용에 포함하지 않음
- MUST NOT: {권위 문서·기술범위}와 {기술 스택}에 없는 기술 스택·도구·제품명을 신설하지 않음
- MUST NOT: 기획 산출물에 정량값이 있는 대상의 값을 신설·완화·강화하지 않음
- MUST NOT: 조회 실패 항목을 추정값·업계 통상치로 채우지 않음
- MUST NOT: 웹 검색을 수행하지 않음. 명시된 입력 파일만 근거로 사용함
- MUST NOT: 패턴 후보에 구현 프레임워크를 올리지 않음. {기술 스택}:오케스트레이션 프레임워크는 구현
  수단으로만 기재함
- MUST NOT: 상태 스키마 필드를 코드베이스 확인 없이 확정하지 않으며, 메모리 설계를 대화 이력 보존 범위
  1줄을 넘어 상세 설계하지 않음. 한 필드에 갱신 주체를 2개 이상 두지 않음
- MUST NOT: 단계 간 데이터 형식·상태 스키마에서 키 이름을 지어내 확정하지 않음. 본 산출물은 키 집합
  식별자까지만 소유하며 키 이름의 단일 출처는 후행 ④임(G-12)
- MUST NOT: `응답 마감선`을 실제 설정 확인 없이 지어내지 않음. 확인 불가 시 `[확인필요: 응답 마감선]`으로 남김
- MUST NOT: 착지 경로가 같은 유형의 상한을 다시 쓰는 설계를 두지 않음(폴백이 타임아웃을 또 소진하거나
  모델을 다시 부르는 경우). `폴백`을 상한 초과 처리 3종 전체를 부르는 이름으로 쓰지 않음
- MUST NOT: 최악값을 총 예산에 맞추려고 정상 경로의 타임아웃을 깎지 않음. 못 맞추면 값을 낮추지 않고
  ①에 `분해 회신` 1행으로 되돌림
- 완료조건: 출력 경로에 파일이 생성되고, (a) Mermaid `sequenceDiagram` 블록이 1개 이상 존재함,
  (b) 시퀀스 단계 표의 행 수가 도식의 단계 수와 같고 사전 조건 확인 단계 행이 1행 이상 존재함,
  (c) 출력 스키마 표에 {최종 산출물·근거 항목} 대응 필드 행이 1행 이상 존재함, (d) 타임아웃 표의 모든
  단계 행에 `p95 배정값`·`타임아웃(상한)`·`직렬/병렬` 값이 있고 트리거마다 `응답 마감선` 행이 1건
  이상이며 대조 2줄(`p95 합계 ≤ 총 예산` · `최악값 합계 ≤ 응답 마감선 − 착지 경로 시간`)이 각각 1건
  이상 존재함 — ①의 응답시간 목표값이 `[확인필요]`이면 총 예산 칸이 `[확인필요: ① 응답시간
  목표값]`이고 단계별 비율(%) 합이 100%임으로 대체 판정함, (e) 고정 문구 `타임아웃 값의 단일 출처는 본
  산출물임`이 문서에서 1건 이상 문자열 검색됨, (f) `근거 출처` 열 필수 3개 표의 공란
  칸이 0건이고 `기획 산출물 대조 기록` 표가 존재함(해당 건 0이면 `0건` 명시),
  (g) 상한 3유형(`시간`·`반복`·`비용`)의 `초과 시 처리` 칸 공란이 0건이고 값이 3종 중 1개임,
  (h) `반복 상한` 표의 루프마다 3칸이 채워지고 요청당 모델 호출 배수 계산 1줄이 존재함,
  (h-1) `타임아웃·재시도` 표의 `재시도 계층` 열 공란이 0건임,
  (i) 상태 스키마 표에서 갱신 주체가 2개 이상인 행이 0건임,
  (j) `부하 조건` 판정 행이 트리거마다 1건 이상이고 `재개 경계` 표에서 부작용 `있음` 행의
  `중복 방지 키` 공란이 0건임, (k) 칸과 칸이 서로 어긋난 행이 0건임 — 대조 3쌍은 `시퀀스 단계 표의
  단계 ↔ 도식의 단계`, `상한 표의 상한 ↔ 상한 초과 처리의 착지 노드`, `상태 스키마 필드 ↔ 단계 간
  데이터 형식의 키 집합 식별자`임, (l) 값이 필수인 칸이 값을 갖거나 `[확인필요: {항목명}]`으로
  되물어진 상태임(빈 칸 0건)
