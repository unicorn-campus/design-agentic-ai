## 슬라이드 1. 별칭 자동 생성과 정식명 치환

- breadcrumb: `Ⅲ. 문서 검색 아키텍처 › Pre-Retrieval › 7. 별칭 처리`
- 제목: `별칭 자동 생성과 정식명 치환`
- 리드문: 별칭은 정식명 목록에서 규칙으로 만들고 위험한 후보만 사람이 검수함 — 분석 뒤 별칭 토큰을 정식명 토큰으로 바꿔야 BM25가 같은 단어로 셈

### 좌측 도식 — ① 별칭 자동 생성

```
(문서 모양) 정식명 목록(문서 메타데이터에서 자동) ──▶ [별칭 후보 만들기(정식명 ⇒ 별칭)]
                                                    접두어 떼기      모아생활
                                                    띄어쓰기 없애기  한빛모아생활
                                                    카드 붙이기      모아생활카드 · 한빛모아생활카드
                                                    등급 접미어      가게모음프리미엄
                                                          ▼
[걸러 내기 검사]  ┄┄┄┄▶  ◇ 검사 통과? ─예▶ (원통) 별칭 사전(정식명 ⇒ 별칭)
 일반 명사와 겹침(예: 대중교통)      │아니오               ▲ 승인분 추가(점선)
 정식명 여러 개를 가리킴           ▼                    │
 두 글자 이하                    [사람 검수] ───────────┘
```
- 하단 캡션: `애칭(예: 모생)은 규칙으로 못 만듦 → 질문 로그에서 찾아 추가`
- 하단 연결 문구(블루 굵게): `생성 결과를 뒤집어 ②의 역방향 대응표(별칭 → 정식명)로 사용 ▶`

### 우측 도식 — ② 정식명 치환

```
[문서] (문서 모양) "한빛 모아생활 카드의 생활 포인트…" ──▶ [한빛모아생활] [카드] [생활] [포인트]
[질문] (말풍선) "모아생활 연회비 안 내려면?"
          ├─ 치환 없음 ──▶ [모아생활] [연회비]      ✗ 다름
          └─ 치환 있음 ──▶ [한빛모아생활] [연회비]  ✓ 일치   ← 문서 토큰과 같은 색
```
- 문서 줄 아래 캡션: `정식명 = 메타데이터 카드명(「카드」 제외) · 붙여 쓴 형태도 별칭으로 정식명에 맞춤`
- 수정(클로니): ①의 예시에서 화살표를 없앰 — 화살표(→)는 ②의 「별칭 → 정식명」 방향에만 씀(①은 정식명 ⇒ 별칭 생성)
- 치환 과정 갈매기 3단계:
  ① **Kiwi 분석** — 정식명 + 별칭 등록(별칭이 쪼개지지 않게)
  ② **대응표 조회** — 별칭만 정식명으로(정식명 · 일반 단어는 그대로)
  ③ **겹친 토큰 정리** — 붙여 쓴 복합어의 조각과 원형이 겹치면 1개만 남김
- 역방향 대응표: `key(별칭) → 정식명 · 정식명은 key가 아니라 그대로 유지`  
  `[모아생활] [모아생활카드] [한빛모아생활카드] → [한빛모아생활]`
- 메모: `문서 쪽에도 같은 치환 · 색인과 질문의 토크나이저를 똑같이`
- 수정(클로니): 방식 카드(바꾸기 · 덧붙이기)와 대상 ID 캡션은 공간 확보를 위해 발표자 노트로 옮김

### 하단

- 콜아웃: `사용자 사전은 「고유명사를 쪼개지 않게」, 별칭 사전은 「별칭과 정식명을 같은 이름으로」 — 둘 다 있어야 BM25가 맞춤`
- 출처: W3C SKOS(prefLabel · altLabel) · 별칭만 사전 등록 시 검색 미반영: 2026-10-02 실측(우리 시스템) · 생성 · 치환 규칙: 설계 가이드(교재 외)

### 발표자 노트

- 별칭 사전은 처음부터 사람이 쓰는 것이 아님. 정식명 목록이 이미 문서 메타데이터에 있으므로 규칙으로 후보를 만들고, 걸러 내기 검사에 걸린 것만 사람이 봄.
- 가장 위험한 것은 일반 명사와 겹치는 별칭임. 「대중교통」을 카드명으로 등록하면 문서의 일반 문장까지 카드명으로 바뀜.
- 오른쪽 그림이 핵심임. 사용자 사전만 있으면 「모아생활」이 깨지지는 않지만, 문서 토큰 「한빛모아생활」과 다른 단어로 셈. 실제 검증에서 핵심어는 잘 뽑혔는데 검색이 실패한 이유임.
- 치환은 질문과 문서 양쪽에 같게 적용해야 함. 상담 로그처럼 별칭만 적힌 문서도 정식명 토큰으로 색인돼야 같은 카드로 검색됨.
- 치환 과정: ① Kiwi 사용자 사전에 정식명과 별칭을 모두 등록해 쪼개지지 않게 함 ② 토큰마다 역방향 대응표를 한 번 조회해 별칭만 정식명으로 바꿈  
  ③ 붙여 쓴 복합어는 조각과 원형이 함께 나오므로, 바꾼 결과가 같은 위치 조각과 겹치면 하나만 남김.
- 역방향 대응표의 key는 카드마다 별칭 2 ~ 3개임. 띄어 쓴 「모아생활 카드」는 「모아생활」만 바뀌면 되므로 key가 따로 필요 없음.  
  「역색인」은 BM25의 단어→문서 표를 가리키므로 이 표와 구분함.
- 바꾸기와 덧붙이기 중 바꾸기를 권장함. 둘 다 남기면 같은 대상을 두 번 세어 점수가 부풀 수 있음.  
  정식 토큰 자리에 대상 ID를 쓰면 이름 표기가 바뀌어도 흔들리지 않음.
- SKOS 용어로 정식명은 prefLabel, 별칭은 altLabel임. 이 대응표가 이후 시소러스의 출발점이 됨.
