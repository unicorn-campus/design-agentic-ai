## 슬라이드 1. 불확실 판정 시 LLM이 기법 선택

- breadcrumb: `Ⅲ. 문서 검색 아키텍처 › Pre-Retrieval › 6. 불확실 판정 후 변환`
- 제목: `불확실 판정 시 LLM이 기법 선택`
- 리드문: 코드는 판정 근거를 사실로 계산하고, LLM이 정보를 보고 기법을 골라 질문을 변환함 — 규칙은 금지 조건만 검사

### 좌측 도식 — LLM에 무엇을 함께 주나

```
◇ CRAG 채점: 불확실 ──▶ [코드: 판정 근거 계산 — 점수 구간 · 1·2위 격차 · 핵심어 유무 · 검색기 일치]
                                    │ 판정 근거(사실)
 [원 질문]                      ─┐     ▼
 [검색 결과 조각 + 제목]         ─┼──▶ ⬡ LLM: 기법 선택 · 질의 작성 ──▶ ◇ 금지 규칙 검사 ─통과▶ (원통) 재검색(상한)
 [이전 시도 기록: 같은 변환 반복 방지] ─┤                                  └위반▶ [keep · clarify]
 [기법 가이드 · 허용 선택지]      ─┘
                     [금지 규칙] 대상명 없음+대상 섞임 → clarify / 같은 기법·질의 반복 금지 / 상한 도달 → keep
```
- 허용 선택지 = 5기법 전체 + keep + clarify

### 우측 도식 — 원인별 기법 가이드 (LLM 참고용)

| 원인 | ▶ | 기법 |
|---|---|---|
| 핵심어가 결과에 하나도 없음 | ▶ | Multi-Query · Rewriting |
| 핵심어가 결과에 있는데 점수가 상한 미달. 질문이 상대적으로 짧음 | ▶ | HyDE |
| 구체 사례를 묻는데 상위 주제 문서만 걸림 | ▶ | Step-Back |
| 1 · 2위 격차 작음(비슷한 대상끼리 경쟁) | ▶ | Rewriting(대상명 없으면 clarify) |

- 캡션: `가이드는 참고용 — 맞지 않으면 다른 선택 + 이유 기록`

### 하단 ① — 핵심어 뽑는 법 (갈매기 5단계, 시소러스 없이)

1. **형태소 분석** — 명사 · 고유명사 · 숫자 · 영문/코드만 남김(한국어는 Kiwi 등)
2. **대상명 묶기** — 엔터티 목록 · 사용자 사전으로 고유명을 한 단어로
3. **불용어 제거** — 「알려주세요 · 방법 · 어떻게」 같은 질문 상투어 빼기
4. **중요도 순** — 색인 통계의 IDF가 높은(드물게 나오는) 단어 우선
5. **결과와 대조** — 상위 결과 조각을 같은 토크나이저 · 정규화로 잘라 포함 여부 확인

- 동의어를 놓쳐 「없음」이 나와도 그 자체가 단어 불일치 신호 → LLM이 결과 조각을 보고 바로잡음

### 하단 ② — 가드레일 칩 4개(한 줄)

1. 권한 필터 후 결과만 — 권한 밖 문서 조각 유출 방지
2. 결과 조각은 데이터로 — XML 태그로 감싸 지시 차단
3. 조각 수 · 길이 상한 — 토큰 · 비용 · 지연 억제
4. 원 질문 보존 — 원 질문과 상관없는 변환 안되게 함

### 발표자 노트

- 실무에서는 기법 선택을 LLM에 맡기는 방식이 일반적임. 교재도 라우터를 LLM Router와 Semantic Router로 나누며, LangGraph 예제도 채점 · 재작성을 LLM 노드로 둠.
- 코드가 계산한 사실(점수 구간 · 격차 · 핵심어 유무 · 검색기 일치)과 결과 조각을 함께 줘서 LLM이 짐작하지 않게 함.
- 핵심어는 시소러스 없이 형태소 분석 + 색인 IDF로 계산함. 형태소 분석기와 색인 통계는 BM25를 쓰는 시스템이면 대부분 이미 있음.
- 핵심어 유무는 관문이 아니라 LLM에게 주는 참고 사실임. 계산이 조금 거칠어도 LLM이 결과 조각을 읽고 바로잡을 수 있음.
- 규칙은 금지만 함. 평가셋에서 LLM 선택이 자주 틀리는 유형이 보이면 그 유형에만 규칙을 추가하고, 필요한 범위만큼 시소러스를 만듦.
