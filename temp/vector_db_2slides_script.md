- 슬라이드 수: 정확히 2장
- 크기: 16 × 9인치
- 서체: Pretendard
- 제목: 48pt ExtraBold
- 본문 최소 크기: 14pt
- 배경: 흰색 `#FFFFFF`
- 기본 색상: Deep Navy `#1E2A5C`, Bright Blue `#2E74C6`, Ink `#2B3242`, Slate `#4A5364`
- 보조 색상: Light Blue `#EEF3FA`, Pale Blue `#F5F8FC`, Border `#D9E0EC`, Line `#EDF0F6`
- 시각화: PowerPoint 기본 도형과 연결선으로 제작하여 편집 가능하게 유지함
- 공통 측정 원칙: 같은 질문셋으로 `Recall@k`, p95 검색 지연, 인덱스 메모리를 함께 비교함
- `top_k`: 사용자에게 최종 반환할 결과 개수임. 검색 중 살펴보는 후보나 군집 수와 구분함

## 슬라이드 1. HNSW: 연결을 따라 가까운 벡터 찾기

### 슬라이드 목적

벡터DB가 질의 벡터와 가까운 문서 벡터를 빠르게 찾는 역할을 설명하고, HNSW의 세 파라미터가
인덱스 구조·구축 비용·검색 후보 목록에 각각 영향을 준다는 점을 보여 줌

### 화면 문구

- breadcrumb: `벡터DB 구성 원리 › 검색 인덱스 튜닝`
- 제목: `HNSW: 연결을 따라 가까운 벡터 찾기`
- 한 문장 설명: `벡터DB는 질의 벡터와 가까운 문서 벡터를 찾아 top_k개를 반환합니다.`
- 그래프 상단 라벨: `상위 계층 · 먼 구간을 빠르게 이동`
- 그래프 하단 라벨: `하위 계층 · 가까운 이웃을 세밀하게 비교`
- 시작점: `진입점`
- 질의점: `질의 벡터`
- 결과 표시: `가까운 문서 후보`
- 주의 문구: `top_k는 반환 개수 · ef_search는 검색 후보 목록 크기`

### HNSW 계층 그래프 시각화

- 영역: x 0.65, y 2.05, w 8.65, h 4.60
- 흰색 캔버스 위에 Layer 2, Layer 1, Layer 0의 수평 기준선을 배치함
- 각 계층에 원형 노드를 배치하고 같은 계층의 이웃을 얇은 Slate 선으로 연결함
- 일부 노드는 위아래 계층에도 존재하도록 수직 연결함
- 진입점에서 상위 계층을 이동한 뒤 아래 계층으로 내려오는 검색 경로를 Bright Blue 3pt로 강조함
- 검색 경로의 마지막 근처 노드 4~5개를 Light Blue 원으로 묶고 `가까운 문서 후보`라고 표시함
- 질의 벡터는 별 모양 대신 테두리가 굵은 파란 원으로 표시함
- 그림이 실제 노드 방문 횟수나 실제 거리값을 나타내지 않는다는 캡션을 14pt로 둠
  - `개념도 · 실제 그래프 연결과 탐색 경로는 데이터와 구현에 따라 달라짐`

### 오른쪽 파라미터 설명

- 영역: x 9.65, y 2.05, w 5.70, h 4.60
- 세 파라미터를 위에서 아래로 정렬하되 카드처럼 과도하게 꾸미지 않고 구분선으로 나눔

| 파라미터 | 화면 설명 | 값이 커질 때 주로 늘어나는 비용 |
|---|---|---|
| `M` | 그래프 연결 밀도를 조정하는 값 | 인덱스 메모리·구축 작업량 |
| `ef_construction` | 인덱스를 만들 때 유지하는 후보 목록 크기 | 구축 시간·메모리 작업량 |
| `ef_search` | 검색할 때 유지하는 후보 목록 크기 | 검색 지연·후보 비교량 |

- `M` 아래 14pt 보충 문구
  - `연결이 많으면 재현율에 유리할 수 있으나 검색 속도는 데이터·구현에 따라 달라짐`
- `ef_construction` 아래 14pt 보충 문구
  - `크게 잡으면 더 좋은 연결을 찾을 기회가 늘지만 인덱스 구축이 무거워짐`
- `ef_search` 아래 14pt 보충 문구
  - `크게 잡으면 재현율이 높아질 가능성이 커지지만 보통 검색 시간이 늘어남`
- 오른쪽 하단에 네이비 외곽선 콜아웃 배치
  - 제목: `측정하며 조정`
  - 본문: `같은 질문셋 · Recall@k · p95 지연 · 인덱스 메모리`

### 정확성 표시

- `ef_search`를 `실제 방문 노드 수`라고 쓰지 않음
- `ef_search`는 검색 과정에서 유지하는 동적 후보 목록 크기로 설명함
- 제품마다 파라미터 이름과 허용 범위가 다를 수 있음을 발표자 노트에서 설명함
- `M`이 커지면 검색이 반드시 느려진다고 단정하지 않음
- 데이터 규모를 기준으로 HNSW 사용을 필수라고 주장하지 않음

### 짧은 발표문

HNSW는 모든 벡터를 차례로 비교하지 않고 연결 그래프를 따라 가까운 후보로 이동합니다. 상위 계층에서
먼 구간을 빠르게 건너고, 아래 계층에서 이웃을 더 자세히 살펴봅니다. `M`은 그래프의 연결 수,
`ef_construction`은 구축 후보 목록, `ef_search`는 검색 후보 목록의 크기를 조정합니다. `top_k`는 이 과정과
별개로 최종 반환할 결과 수입니다. 좋은 값은 고정 숫자가 아니라 같은 질문셋의 재현율, p95 지연, 메모리를
함께 측정해 정합니다.

### 발표자 노트

- HNSW의 계층 그래프는 근사 최근접 이웃을 빠르게 찾기 위한 검색 구조임
- `M`은 그래프 연결 밀도와 메모리에 영향을 줌. 실제 차수의 단순 상한은 아니며 검색 속도도 단정할 수 없음
- `ef_construction`은 인덱스 구축 시 사용하는 후보 목록의 크기임
- `ef_search`는 검색 시 유지하는 후보 목록의 크기임. 최종 반환 개수인 `top_k`와 다름
- `ef_search`를 높이면 더 많은 후보를 검토할 여지가 생겨 일반적으로 재현율은 좋아지고 지연은 커지지만,
  실제 변화 폭은 데이터 분포·거리 함수·필터·제품 구현에 따라 측정해야 함
- 참고 문서의 `M=16`, `ef_construction=200`, `ef_search=100`은 문서가 제안한 시작값일 뿐 모든 제품의
  기본값이나 보장값이 아님
- 제품별 최신 이름과 범위는 Chroma, Milvus, Qdrant, pgvector 공식 문서에서 확인해야 함

## 슬라이드 2. IVF: 가까운 군집부터 좁혀 찾기

### 슬라이드 목적

IVF가 벡터를 여러 군집으로 나누고 질의에 가까운 중심점의 군집만 먼저 검색하는 원리를 설명하며,
`nlist`와 `nprobe`를 고정 공식보다 측정으로 조정해야 함을 보여 줌

### 화면 문구

- breadcrumb: `벡터DB 구성 원리 › 검색 인덱스 튜닝`
- 제목: `IVF: 가까운 군집부터 좁혀 찾기`
- 한 문장 설명: `벡터를 군집으로 나누고, 질의와 가까운 중심점의 군집부터 살펴봅니다.`
- 전체 공간 라벨: `전체 벡터 공간`
- 중심점 라벨: `centroid · 군집 중심점`
- 질의 라벨: `질의 벡터`
- 강조 군집 라벨: `이번 검색에서 살펴볼 군집`
- 예시 배지: `설명용 시작 예시`
- 예시 문구: `벡터 10,000개 · nlist 100 · nprobe 5~10`
- 주의 문구: `top_k는 반환 개수 · nprobe는 검색할 군집 수`

### IVF 군집 시각화

- 영역: x 0.65, y 2.05, w 9.10, h 4.85
- 벡터 공간을 표현하는 큰 흰색 사각형 안에 8개의 불규칙한 점 군집을 배치함
- 각 군집은 7~12개의 작은 원과 하나의 중심점으로 구성함
- 중심점은 Deep Navy 테두리의 큰 원으로 표시하고 `C1`, `C2`처럼 짧게 표기함
- 질의 벡터는 Bright Blue 굵은 테두리의 원으로 표시함
- 질의와 가까운 중심점 2개까지의 거리를 Bright Blue 점선으로 표시함
- 선택된 2개 군집은 Light Blue 반투명 배경으로 강조함
- 나머지 군집은 Pale Blue 점과 Slate 테두리만 사용함
- 8개 군집은 구조를 설명하기 위한 축약 그림이며 `nlist=100`을 실제 100개 도형으로 그리지 않음
- 하단 캡션
  - `개념도 · nlist는 전체 군집 수, nprobe는 한 번의 검색에서 살펴볼 군집 수`

### 오른쪽 파라미터와 시작 예시

- 영역: x 10.05, y 2.05, w 5.30, h 4.85
- 상단에 `설명용 시작 예시` 배지를 Bright Blue로 배치함
- 배지 아래에 큰 숫자 흐름을 세 줄로 배치함
  - `N = 10,000 벡터`
  - `nlist = 100 군집`
  - `nprobe = 5~10 군집 검색`
- `~` 값은 제품 기본값이나 정답이 아니라 튜닝을 시작할 예시라고 14pt로 명시함
- 가운데에 두 파라미터 설명을 배치함

| 파라미터 | 의미 | 커질 때의 일반적 변화 |
|---|---|---|
| `nlist` | 전체 벡터를 나눌 군집 수 | 군집은 더 잘게 나뉨 · 학습과 분포 품질 영향 증가 |
| `nprobe` | 검색할 군집 수 | 재현율 가능성 증가 · 검색 지연 증가 |

- 아래에 네이비 외곽선 콜아웃 배치
  - 제목: `공식보다 측정`
  - 본문: `같은 질문셋 · Recall@k · p95 지연 · 인덱스 메모리`
- 맨 아래 14pt 주의 문구
  - `nprobe=nlist는 모든 리스트를 살펴본다는 뜻이며, 모든 IVF 방식에서 정확 전수 검색을 보장하지 않음`

### 정확성 표시

- `nlist ≈ √N`을 필수 공식으로 제시하지 않음
- `10,000 / 100 / 5~10`은 설명용 시작 예시라고 화면과 발표자 노트에서 명시함
- `nprobe=nlist`이면 모든 inverted list를 검색하지만, IVF 종류에 따라 정확도 조건이 다름
- IVFFlat은 원본 벡터를 같은 거리 함수로 정확 비교하는 조건에서 전수 검색과 같은 후보 비교가 가능함
- IVFPQ는 압축 벡터로 거리를 근사하므로 모든 리스트를 보더라도 정확 전수 검색과 동등하다고 단정하지 않음
- 데이터 규모를 기준으로 IVF 사용을 필수라고 주장하지 않음

### 짧은 발표문

IVF는 벡터를 여러 군집으로 나눈 뒤 질의와 가까운 중심점의 군집부터 살펴봅니다. `nlist`는 전체 군집 수,
`nprobe`는 한 검색에서 확인할 군집 수입니다. 10,000개 벡터를 100개 군집으로 나누고 5~10개 군집부터
검색하는 값은 원리를 설명하기 위한 시작 예시입니다. 실제 값은 같은 질문셋의 Recall@k, p95 지연,
인덱스 메모리를 비교해 정합니다. 최종 반환 개수인 `top_k`는 `nprobe`와 다른 값입니다.

### 발표자 노트

- IVF는 학습 단계에서 중심점을 만들고 각 벡터를 가까운 inverted list에 배치함
- 검색할 때 질의와 가까운 중심점을 고르고 해당 리스트의 벡터부터 비교함
- `nlist`가 너무 작거나 너무 크면 데이터 분포와 학습 품질에 따라 검색 효율과 재현율이 달라질 수 있음
- `nprobe`를 늘리면 더 많은 군집을 보므로 일반적으로 재현율은 좋아지고 지연은 늘어남
- `N=10,000`, `nlist=100`, `nprobe=5~10`은 참고 문서가 제안한 설명용 시작값임. 제품 기본값이 아님
- `nprobe=nlist`는 모든 inverted list를 살펴본다는 뜻임
- IVFFlat에서 원본 벡터를 같은 거리 함수로 정확 비교하고 후처리 조건이 같다면 전수 비교 결과와 같아질 수 있음
- IVFPQ는 product quantization으로 압축한 표현을 비교하므로 모든 리스트를 보더라도 정확 전수 검색과
  동일하다고 보장할 수 없음
- `top_k`는 최종 반환 건수이며 `nprobe`는 검색 범위임
