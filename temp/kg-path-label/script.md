## 슬라이드 1 — KG 예시로 보는 '노드 탐색'과 '탐색된 노드의 제목'

- 리드문: 자주 바뀌는 비중은 SQL로 계산해 출발 노드만 정하고, 그래프에서는 노드를 탐색하고 제목을 읽음

### 왼쪽 — KG 예시 (블루 헤더 바 + 질문 + 도형)

- 질문: "M-6001 회원이 많이 쓰는 업종에 혜택을 주는 카드는?"
- 단계 표시: ① 출발 노드 정하기(SQL) / ② 노드 탐색(그래프) / ③ 탐색된 노드의 제목(그래프)
- 정형 DB 상자(표): 식비 63.7% · 쇼핑 20.8% · 생활 10.6% · 주유 1.1% · 그 외 4개 3.9% → "1위 업종 = 식비"  
  화살표 → 그래프의 업종 노드 식비
- 그래프 상자(열: 업종 · 혜택 · 상품(ID · 제목))

| 업종 | 혜택(제목) | 상품(ID + 제목) | 표시 |
|------|-----------|----------------|------|
| 식비 | 시간대 할인 | D2-C005 한빛 하루절약 | 강조 |
| 식비 | 배달앱 할인 | D2-C033 한빛 한끼친구 | 강조 |
| 식비 | 주말 외식 적립 | D2-C035 한빛 일상포인트 | 강조 |
| 쇼핑 | 생활쇼핑 할인 | D2-C058 한빛 반려동행 | 회색(안 감) |
| 주유 | 선택 주유소 할인 | D2-C007 한빛 주유동행 | 회색(안 감) |

- 관계(화살표는 찾아가는 방향으로 그림): 업종 → 혜택 '해당 혜택', 혜택 → 상품 '제공 상품'
- 아래 주: 화살표 = 찾아가는 방향. 저장은 '혜택 →대상→ 업종'·'상품 →제공→ 혜택'이며 거꾸로 따라감

### 오른쪽 — 세 단계가 뜻하는 것 (네이비 헤더 바 + 카드 3 + 답 상자)

| # | 단계 | 뜻 | 쓰는 것 |
|---|------|----|--------|
| 1 | 출발 노드 정하기 · SQL | 매달 바뀌는 소비 비중은 SQL로 계산 | 결과: 식비 |
| 2 | 노드 탐색 · 그래프 | 업종명으로 출발 노드를 찾고, 관계로 갈 길을 거름 | 업종명, 관계(대상·제공) |
| 3 | 탐색된 노드의 제목 · 그래프 | 도착한 노드의 ID 대신 사람이 읽는 제목을 씀 | 상품명, 혜택명 |

- 답 상자: 하루절약 · 한끼친구 · 일상포인트 / 연회비·혜택률은 상품 ID로 따로 가져옴

### 발표자 노트

- 소비 비중은 매달 바뀌는 집계값이라 그래프에 넣지 않음. 600명 × 8업종 관계(4,694개)를 매달 다시 맞출 필요가 없어짐
- 노드 탐색: '업종명=식비'로 출발 노드를 찾고 '대상'·'제공' 관계만 거꾸로 따라감(저장 방향과 반대여도 비용 같음).  
  비중은 2025-08 ~ 2026-08 승인 거래 기준. 쇼핑·주유 쪽 혜택은 출발 노드가 아니라 들르지 않음
- 탐색된 노드의 제목: 도착한 상품·혜택 노드에는 ID와 함께 제목(상품명·혜택명)이 있어 그대로 답에 씀.  
  Neo4j 도구에서는 이를 표시 이름(caption)이라고 부름
- 회원-업종 관계는 "비슷한 회원 찾기"처럼 회원끼리 비교하는 질문을 쓸 때만 월 1회 배치로 만듦
- '대상' 관계는 혜택 문서에서 뽑아야 하며, 이 장의 관계는 설명용 예시임
