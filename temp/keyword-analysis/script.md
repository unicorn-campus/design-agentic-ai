## 장표 1. 키워드 분석은 파이썬에서 자르고, 점수는 검색 엔진이 셈

- 제목: 검색 갈래 ② 키워드 분석
- 리드문: 파이썬에서 Kiwi로 낱말을 잘라 넣고, BM25 점수는 검색 엔진이 검색할 때 계산함

**도형 구성**

1. 위쪽 두 줄 흐름도(y 1.9 ~ 5.0)
   - 왼쪽 다크 배지 세로 라벨: `색인 때`, `검색 때`
   - 색인 때 줄: [청크 색인용 본문 (머리말 포함)] → [Kiwi 토크나이저] → [text_tokens 필드 (낱말을 공백으로 이음)] → [whitespace 분석기 (공백으로만 자름)] → [역색인 (낱말 → 청크 목록)]
   - 검색 때 줄: [질문] → [Kiwi 토크나이저 (같은 것)] → [match 질의] → [BM25 점수 계산 (k1 1.5, b 0.75)] → [상위 청크]
   - 두 줄의 토크나이저 박스는 네이비로 강조하고 사이를 점선으로 이어 "같은 사전, 같은 규칙" 라벨
   - 역색인과 BM25 점수 계산 사이를 점선 화살표로 이어 "검색할 때 통계를 읽어 점수 계산"
   - text_tokens 박스 아래 칩 예시: `한빛가족돌봄 카드 30000 원 이상 결제 kb pay 할인 받 30000원 kb-pay`
   - Kiwi 토크나이저 박스 안 3줄: 표기 통일, 카드명 사전과 별칭 사전, 조사와 어미 빼고 원형 보충
2. 아래 왼쪽(y 5.3 ~ 7.95): 「벡터DB 인덱싱의 BM25 색인과 다른 점」 헤더 바 + 3행 비교(행 라벨 칩 + 두 칸 카드)
   - 점수 계산: 색인 때 점수표를 미리 만들어 저장 / 검색할 때 역색인 통계로 계산
   - 갱신: 하나만 바뀌어도 점수표를 다시 만듦(항상 전체 재색인, 괄호 앞에서 줄바꿈) / 바뀐 문서만 지우고 넣음 (증분 색인)
   - 전체 재색인: 임시 폴더에서 만든 뒤 폴더 교체 / 새 세대 인덱스를 채운 뒤 별칭 전환
   - 증분 색인은 지금 쓰는 인덱스에 바로 쓰고 별칭은 그대로임. 별칭 전환은 전체 재색인 때만 하므로 두 행으로 나눔
3. 아래 오른쪽: 「nori 대신 Kiwi」 강조 헤더 바 + 틴트 박스 3줄
   - 1-a의 토큰화 규칙과 사전을 그대로 씀
   - 검색 엔진에 형태소 플러그인을 깔지 않음
   - 대신 질문도 반드시 같은 토크나이저로 잘라야 함(어긋나면 조용히 못 찾음)
4. 맨 아래 각주(x 0.557, y 8.16, 전폭, 14pt `#7C8598`, 한 줄)
   - ※ 점수 계산: 낱말마다 청크 안 빈도, 전체 청크 중 희소성, 청크 길이 보정을 합쳐 계산 (k1은 빈도, b는 길이 보정의 세기)

**사람 검토 반영(2026-10-19)**

- 사용자가 PowerPoint에서 1장을 고침: 토크나이저 칸 "별칭 사전", 비교 3행 "증분색인", 점수 계산 각주 추가
- 검토 뒤 반영: 3행 "증분색인"은 2행 "갱신"과 겹치고 증분 색인과 별칭 전환을 한 칸에 섞어서,
  2행에 증분 색인을 합치고 3행을 "전체 재색인"으로 바꿈. 각주는 문장을 다듬고 왼쪽 선과 캡션 색을 맞춤
- 고친 덱(`키워드분석.pptx`)은 다시 빌드하지 않고 해당 도형만 수정함. 고치기 전 파일은 `키워드분석.before-fix.pptx`

**발표자 노트**

키워드 분석 단계는 한국어 문장을 BM25가 셀 수 있는 낱말로 바꾸는 일입니다. 1-b에서는 이 일을 검색 엔진에 맡기지 않고
파이썬에서 Kiwi로 미리 자릅니다. 자른 낱말을 공백으로 이어 text_tokens 필드에 넣으면, 검색 엔진은 공백으로만 잘라 역색인을 만듭니다.
검색할 때는 질문을 같은 토크나이저로 잘라 넣고, BM25 점수는 그때 검색 엔진이 계산합니다.
1-a와 가장 큰 차이는 점수표를 미리 만들어 두지 않는다는 점입니다. 그래서 문서 하나만 지우고 다시 넣는 증분 색인이 가능해집니다.

## 장표 2. 카드명 사전과 별칭 사전은 한 쌍으로 씀

- 제목: 카드명 사전과 별칭 사전은 한 쌍
- 리드문: 카드명 사전만 넣으면 줄여 부른 카드명 질문이 문서의 카드명 낱말과 겹치지 않음

**도형 구성**

1. 위쪽 예문 줄(y 1.9 ~ 2.6): 필 라벨 `문서` + 문장, 필 라벨 `질문` + 문장
2. 가운데 세 칸(y 2.8 ~ 6.0): 사전 없음 / 카드명 사전만 / 카드명 사전 + 별칭
   - 각 칸 헤더 바(가운데 칸은 회색 다크 배지, 오른쪽 칸은 강조 블루)
   - `문서` 줄: 카드명 부분 낱말 칩
     - 사전 없음: 한빛, 가족, 돌봄, 가족돌봄 / 사전만과 사전+별칭: 한빛가족돌봄
   - `질문` 줄: 카드명 부분 낱말 칩
     - 사전 없음과 사전만: 가족, 돌봄, 가족돌봄 / 사전+별칭: 한빛가족돌봄
   - 겹친 칩은 블루 채움, 안 겹친 칩은 흰 바탕 회색 글자
   - 칸 아래 판정 카드
     - 사전 없음: 겹치지만 구분이 약함. "한빛"은 카드 64종 모두, "가족"은 한빛 가족통신에도 있음
     - 사전만: 카드명이 하나도 안 겹침. 줄여 부르면 그 카드를 못 찾음
     - 사전+별칭: 그 카드 한 단어로 정확히 겹침
   - 세 칸 아래 캡션: 카드, 할인은 세 경우 모두 겹침
3. 아래(y 6.25 ~ 7.95): 「별칭 사전 만드는 법」 흐름도
   - [정식 카드명 64개 (예: 한빛 가족돌봄)] → [규칙: 접두어 "한빛", 접미어 "카드"를 떼고 3글자 이상] → [별칭 189개 (가족돌봄 → 한빛가족돌봄)] → [일반 명사 자동 제외 3개 (대중교통, 장보기, 출퇴근)] → [사람 검수 (추가, 제외 목록)]
   - 오른쪽 끝 콜아웃: 사전이나 별칭이 바뀌면 문서 낱말이 바뀌므로 새 세대로 다시 색인 (벡터는 재사용)

**발표자 노트**

카드명 사전은 "한빛 가족돌봄"을 한 단어로 묶어 줍니다. 그런데 사전만 넣으면 문서에는 한빛가족돌봄 한 단어만 남고,
"가족돌봄"이라고만 묻는 질문은 가족, 돌봄, 가족돌봄으로 잘려 카드명과 하나도 겹치지 않습니다.
사전이 없을 때보다 오히려 나빠지는 셈입니다. 별칭 사전은 줄여 부른 이름을 정식 카드명 단어로 바꿔 줘서 이 틈을 메웁니다.
별칭은 규칙으로 자동으로 만들되, 장보기처럼 일반 명사와 같은 별칭은 빼야 합니다. 그대로 두면 "장보기 할인"이라는
일반 질문이 특정 카드명으로 바뀌어 버립니다.
