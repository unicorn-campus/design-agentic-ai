# KG 그래프의 모양 장표 스크립트 (1장)

조항 단위로 뽑은 엔티티와 관계가 모인 KG가 실제로 어떤 모양이고, 청크 노드와 FROM_CHUNK로 어떻게 이어지는지 보여 주는 장표.  
사용자가 교재에 직접 붙여 넣음.  
빌드: `node build.js` → `python post.py KG그래프모양.pptx` → `python scripts/render-pptx.py ... --out preview`로 확인

`hybrid-ai-lab/indexer/graphrag/v0/data/generations/gen-sample-005-dbe57d45/kg_prepared.json`에서 가져옴.

- 노드 안 글은 원문을 줄여 적음. 제16조의2의 처리 노드 2개 가운데 「사유 안내」만 그리고 나머지 1개는 「처리 1개 더 있음」으로 적음
- 약관 문서 노드가 청크 노드 2개에 FROM_CHUNK로 이어지는 것은 이전 작업의 Neo4j 조회(같은 세대)로 확인한 값.  
  조항마다 뽑힌 문서 노드가 K5 병합에서 하나로 합쳐지며 두 청크 연결을 모두 가짐
- 엔티티별 FROM_CHUNK는 v0 `kg_build.apply`가 단위의 chunk_ids마다 하나씩 만듦. 그림에서는 묶음마다 선 하나로 모아 그림

## 장표 구성

- 제목: 2. 인덱싱: KG 구축 - KG 그래프의 모양
- 리드문: 조항 단위로 뽑은 노드와 관계가 그래프 하나로 모이고, 모든 노드는 자기 조항이 나온 청크 노드에 FROM_CHUNK로 이어짐
- 범례 왼쪽: 굵은 점선은 FROM_CHUNK. 점선 묶음은 설명용 표시이며 추출 단위는 그래프에 노드로 남지 않음
- 범례 오른쪽: 실선 관계 이름(HAS_CLAUSE, SETS_REQUIREMENT, SETS_DEADLINE, DEFINES_HANDLING)
- 맨 위 가운데: 약관 문서 노드. 양옆 청크 노드 2개로 FROM_CHUNK, 아래 조항 4개로 HAS_CLAUSE
- 가운데: 조항 묶음 4개(제15조, 제16조, 제16조의2, 제17조)와 그 아래 조건, 기한, 처리 노드
- 아래: 묶음에서 내려온 FROM_CHUNK 모음 선. 제15조는 왼쪽 청크만, 제17조는 오른쪽 청크만, 겹친 두 조항은 양쪽 모두

## 발표자 노트

build.js의 notes와 같음. 요지는 세 가지임.  
첫째, 문서 노드 아래 조항, 조항 아래 조건, 기한, 처리가 달리는 모양.  
둘째, 청크 노드는 검색 청크와 1대1이고, 묶음 안 모든 노드가 자기 조항이 나온 청크로 FROM_CHUNK를 가짐. 겹친 조항은 두 청크에 이어짐.  
셋째, 점선 묶음은 설명용이며 추출 단위는 그래프에 남지 않음.

## v2 변경 (2026-10-23, 사용자 지적: 엔티티와 관계 구분이 모호함)

- 엔티티는 원, 청크 노드는 둥근 사각형으로 모양을 나눔. 청크 노드는 LLM이 뽑은 엔티티가 아님을 범례에 적음  
- 모든 관계 선에 이름표를 붙임. 14pt 하한 때문에 선 위에는 우리말(조항 가짐, 조건 둠, 기한 둠, 처리 정함)을 쓰고,  
  범례에서 실제 관계 이름(HAS_CLAUSE, SETS_REQUIREMENT, SETS_DEADLINE, DEFINES_HANDLING)과 짝지음. FROM_CHUNK는 그대로 표기  
- 조항과 엔티티 사이를 0.3인치 벌려 이름표 자리를 만듦  
- 출력: `KG그래프모양-v2.pptx`(첫 판이 PowerPoint에서 열려 있어 새 이름으로 저장), 미리보기 `preview-v2/`

## v3 변경 (2026-10-23, 사용자 요청: 가장 위에 KG, 안을 Lexical Graph와 엔티티 그래프로 나눔)

- 관계 이름 범례는 KG 틀 바깥 한 줄로 옮김
