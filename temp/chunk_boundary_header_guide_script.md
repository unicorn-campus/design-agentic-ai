## 슬라이드 1. 청킹 경계와 머리말 설계 가이드

- breadcrumb: `Ⅲ. 문서 검색 아키텍처 › 청킹 › 경계·머리말 설계`
- 제목: `청킹 경계와 머리말 설계 가이드`
- 리드문: 경계는 「대상」을 넘지 않게, 머리말은 「잃어버린 상위 정보」만, 추가 여부는 「실측」으로 — 문서 유형마다 같은 세 단계로 판단

### ① 경계(구분자) 정하기 — 겹친 상자 도식

```
┌ 하드 경계 — 대상 단위(상품 · 카드 · 상담 건 · 조항) ─────┐   ← 넘어서 합치지 않음
│ ┌ 1순위 구분자 — 의미 단위(혜택 항목 · 발화 · 항) ──┐   │
│ │  [문장 · 줄 · 공백]  ← 그래도 길면                │   │
│ └───────────────────────────────────────────────┘   │
└───────────────────────────────────────────────────┘
```
- 규칙 4줄
  - 대상 경계는 넘어서 합치지 않음(분할기는 경계 안에서만 동작)
  - 경계 시작 = 구조 신호만 있는 줄(목차 · 참고 목록 속 언급은 제외)
  - 어디에도 안 속하는 구간(표지 · 목차 · 부록)은 「대상 없음」
  - 점검: 대상이 섞인 청크 · 대상 메타데이터 오류 → 0

### ② 머리말 항목 고르기 — 3문항 거름망

```
[메타데이터 후보]
   ↓
[Q1 청크마다 값이 달라 구별해 주나?] ─아니오▶ [문서 공통값]   ← 오른쪽 열 머리 「아니오 → 제외」
   ↓ 예
[Q2 분할로 청크가 잃어버린 상위 정보인가?] ─아니오▶ [이미 본문에 있음]
   ↓ 예
[Q3 사용자가 질문에 쓰는 말인가?] ─아니오▶ [내부 전용 값]
   ↓ 예
[머리말 항목]
항상 제외: 개인정보 · 가명 ID / 자유 텍스트 라벨(주제 등 — 채점 · 검색 왜곡)
```

### ③ 머리말 붙일지 판단 — 결정 흐름

```
◇ 정보가 본문에 이미 있나? ─예▶ [붙이지 않음]
   ↓ 아니오
◇ 대상이 섞인 청크가 많나? ─예▶ [경계부터 고침(①)]
   ↓ 아니오 · 고친 뒤
◇ A/B 실측 통과? ─예▶ [채택]
   통과 기준: 대상 질의 적중↑ · 일반 질문 1위 유지 · 다른 유형 질의 무손상 / 미달 시 보류
예산: 분할 전에 머리말 몫을 빼서 임베딩 상한 초과 0
```

### 하단 — 실측 예(카드 상품 문서, 2026-10-03)

| 문서 | 판단 | 결과 |
|---|---|---|
| 약관 | 조항 제목이 이미 본문 첫 줄 | 머리말 없음(10건 중 1건만 해당, 변화 없음) |
| 카드 혜택 | 카드 경계 분할 + 카드명 · ID 머리말 | 섞인 청크 66 → 12, hybrid 카드 질의 적중 4 → 8 / 11 |
| 상담 로그 | 주제 머리말이 평가 채점을 부풀리고 일반 질문을 흔듦 | 머리말 없음(카드 질의 성능 동일) |

- 출처: Anthropic Contextual Retrieval · LlamaIndex 메타데이터(임베딩 텍스트 포함 · 키별 제외) · LangChain 재귀 분할(구분자 우선순위) · 실측: 2026-10-03 우리 시스템

### 발표자 노트

- 세 단계는 순서가 중요함. 경계가 틀린 상태에서 머리말을 붙이면, 머리말이 가장 필요한 청크(대상이 섞인 청크)가 대상을 하나로 정할 수 없어 전부 빠짐.
- 경계는 「대상」 단위가 하드 경계이고, 그 안에서만 기존 구분자 우선순위로 자름. 경계 시작은 구조 신호만 있는 줄로 한정해야 목차나 참고 목록 속 언급이 경계로 오인되지 않음.
- 머리말 항목은 세 질문으로 거름: 청크를 구별하나, 분할로 잃어버린 정보인가, 사용자가 질문에 쓰는 말인가. 문서 전체에 같은 값(부서 · 버전)은 구별력이 없어 제외함.
- 자유 텍스트 라벨(상담 주제 등)은 평가 근거 문구와 글자가 겹쳐 채점을 부풀린 사례가 있음. 개인정보 · 가명 ID는 언제나 제외.
- 추가 여부는 실측으로 정함. 대상 질의가 좋아지고, 일반 질문의 1위가 유지되고, 다른 문서 유형 질의가 나빠지지 않아야 채택. 평가셋에 변별력 없는 문항이 섞이면 판단이 흐려지므로 평가셋부터 점검함.
