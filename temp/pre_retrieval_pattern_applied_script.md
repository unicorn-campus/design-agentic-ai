## 슬라이드 1. 아키텍처 패턴에 Pre-Retrieval 적용

- breadcrumb: `Ⅲ. 문서 검색 아키텍처 › Pre-Retrieval › 4. 패턴 적용 시 동작`
- 제목: `아키텍처 패턴에 Pre-Retrieval 적용`
- 리드문: 세 패턴 워크플로우에서 질문 변환은 두 자리에만 들어감 — 검색 전(질문만 보고)과 채점 「애매」 후(결과를 보고)

### 좌측 도식 — 워크플로우 흐름 (도형)

```
(단말) 질문 + 역할(agent/auditor)
   ↓
◇ Adaptive 분류기 — 질문 유형?  ─▶ [Self-RAG] 검색 불필요(인사·잡담) → 바로 답변
   │                          ─▶ [Pre-Retrieval ①] 복합 → Decomposition 하위 질문 + 원 질문 ─┐
   ↓ 단순 · 복합                                                                      │
(원통) 검색 + 합치기 — Vector·Hybrid·Rerank · 가중 RRF  ◀────────────────────────────────┘
   ↓                         ▲ (점선) 애매 → 재검색
◇ CRAG 채점(점수 기준)  ─▶  정확 → 답변으로
   │                       애매 → [Pre-Retrieval ②] 교정 후 재검색(상한)
   │                              Rewriting · Multi-Query · HyDE · Step-Back 중 1개
   │                       부정확 → web_search(선택) / 확인 필요
   ↓
[답변 생성]  ◀── (점선) 실패 → 재작성(최대 2회)
   ↓
[Self-RAG 근거 검증] ─ 통과 ─▶ (단말) 최종 답변
```
- 하단 한 줄: `↺ 분기는 개발자가 미리 그린 조건부 엣지 · 재검색·재작성은 고정 상한 · 끝내 부족하면 「확인 필요」로 종료`

### 우측 도식 — Pre-Retrieval이 들어가는 두 자리

- **① 검색 전 — 질문 문장만 보고**
  - 기법 필: `Decomposition`(채움) · `Multi-Query △`(테두리, 용어가 흔들리는 질문에 한해)
  - 이유: 복합 여부는 문장만 봐도 알 수 있음 → 원 질문으로 한 번 검색해 보는 낭비를 줄임
- **② 채점 「애매」 후 — 결과를 보고**
  - 기법 필 2 × 2: `Query Rewriting` · `Multi-Query` · `HyDE` · `Step-Back`
  - 이유: 결과가 나쁠 때만 의미가 있음 → 멀쩡한 질문에는 LLM 비용을 쓰지 않음
- **공통 원칙(다크 카드 3줄)**
  - 원 질문은 버리지 않고 항상 함께 검색 · 합침
  - 재검색 횟수는 고정 상한
  - 효과는 평가셋으로 On · Off 비교해 확인

### 출처 (하단 작게)

- 교재 「10. RAG」 4.1 Pre-Retrieval · 5.2 ~ 5.4 Self-RAG · CRAG · Adaptive
- Adaptive-RAG, Jeong et al.(2024) · CRAG, Yan et al.(2024)
- 기법 배치는 세 패턴 결합 워크플로우 기준의 설계안임(현재 소스 기준 아님)

### 발표자 노트

- 이 장은 현재 코드가 아니라, 앞에서 본 세 패턴 결합 워크플로우에 Pre-Retrieval을 얹었을 때의 설계안임.
- 질문 변환이 들어가는 자리는 둘뿐임. 질문 문장만 보고 판단할 수 있는 것(분해)은 검색 전에, 결과를 봐야 아는 것(재작성 · HyDE · Step-Back)은 채점 뒤에 둠.
- Multi-Query는 두 자리 모두 가능함. 카드사 용어와 일상어가 흔들리는 질문은 미리 써도 되고, 아니면 애매 판정 뒤에 씀.
- 분해한 하위 질문도 원 질문과 함께 검색 · 합침. 분해 시에는 원 질문 비중을 낮추고 하위 질문별 자리를 확보함(3장 참고).
- 모든 분기는 미리 그린 워크플로우이므로, 기법을 고르는 LLM이 있어도 흐름의 운전대는 개발자에게 있음 — Agentic과의 차이임.
