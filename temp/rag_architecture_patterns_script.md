# 문서 검색 아키텍처 패턴 — PPT 스크립트 (3장)

대상: RAG 기초(색인 · 검색 · Hybrid · Rerank)를 배운 교육생  
전달 목표: 5개 패턴(Basic · Self-RAG · CRAG · Adaptive · Agentic)을 **우리 카드 상품 문서 검색·답변 서비스에  
어떻게 적용하는지** 이해시킴  
공통 화면 사양: 16:9(1152 × 648pt), 흰 배경, Pretendard, 본문 최소 14pt, 팔레트는 Deep Navy `#1E2A5C` ·  
Bright Blue `#2E74C6` · Light Blue `#EEF3FA` · Pale Blue `#F5F8FC` · Soft Blue `#E2EEF9` · Dark Slate `#404155`

> 용어 정리(강사가 1장 시작 전에 짚을 것)  
> **패턴** = 질문이 답변이 되기까지의 전체 흐름과 제어 방식  
> **검색 부품** = 그 흐름 안에서 문서를 찾아오는 한 칸(Vector · Hybrid · Rerank)  
> 즉 Vector · Hybrid · Rerank는 패턴이 아니라 **패턴 안에 끼우는 부품**임

## 슬라이드 1. 5가지 패턴 한눈에

### breadcrumb

`Ⅲ. 문서 검색 아키텍처 › 1. 패턴 비교`

### 제목

`5가지 패턴 한눈에`

### 리드문

각 패턴은 "무엇을 스스로 판단하는가"로 갈림. 판단이 늘수록 똑똑해지지만 LLM 호출 수와 복잡도가 함께 올라감.

### 레이아웃 패턴

**패턴 D (데이터 테이블)** — 상단 전폭에 다크 배지 `패턴별 비교` + 비교표 1개, 하단에 인용 콜아웃 1줄.  
표가 5열이므로 좌우 분할하지 않고 전폭 1열로 배치함. 행 높이 0.55″ 이상으로 잡아 하단 여백을 1.0″ 미만으로 채움.

### 본문 — 다크 배지 + 비교표

다크 배지(`#404155`, 흰 글자) 텍스트: `패턴별 비교 — 무엇을 판단하고 얼마나 비싼가`

표 헤더행 배경 `#E2EEF9`, 짝수행 `#F5F8FC`, 본문 14pt 이상.

| 패턴 | 핵심 질문 | 작동 시점 | 하는 일 | LLM 호출 | 구현 복잡도 |
|---|---|---|---|---|---|
| **Basic RAG** | (판단 없음) | 항상 검색 | 검색 → 생성 단방향 | 1회 | 낮음 |
| **Self-RAG** | 검색할까? | 검색 전 | 검색 필요 여부 판단 + 결과·답변 자체 검증 | 1 ~ 2회 | 중간 |
| **CRAG** | 결과 맞나? | 검색 후 | 관련성 평가 후 교정(질문 재작성·웹 검색) | 2 ~ 3회 | 중간 |
| **Adaptive** | 어떤 전략? | 라우팅 시 | 질문 복잡도에 따라 전략 동적 선택 | 2 ~ 4회 | 높음 |
| **Agentic** | 어떻게 행동? | 전체 과정 | 계획–실행–평가 반복, 다른 패턴을 도구로 활용 | N회 | 최고 |

> 수정(클로니): 「적합 상황」 열은 3장 로드맵의 「이럴 때 도입」과 겹쳐 3장으로 옮기고,
> 교재 5절의 패턴 정의 문장과 「구현 복잡도」 열로 대체함

### 본문 — 하단 인용 콜아웃

좌측 5px `#2E74C6` 바 + 네이비 Bold Italic 텍스트, 1줄:

`모든 상황에 Agentic RAG는 과잉 설계임 — 요구사항에 맞는 최소 패턴 선택이 효율적`

### 본문 — 콜아웃 아래 캡션 (14pt, `#7C8598`)

`LLM 호출 수는 교재 기준 패턴 1개를 적용했을 때의 값이며, 패턴을 겹쳐 쌓았을 때의 합계가 아님`

### 출처

- 교재 「10. RAG」 5절 Architecture Patterns —
  https://github.com/cna-bootcamp/aistudy/blob/main/agentic-ai/textbook/10.RAG.md

### 발표자 노트

- 표를 왼쪽에서 오른쪽으로 읽으면 "무엇을 판단하나 → 언제 판단하나 → 얼마나 비싼가" 순서로 설명이 이어짐을 먼저 안내함.
- Basic RAG만 판단 단계가 없음을 강조함. 교재가 꼽은 Basic의 한계는 항상 검색함 · 결과 품질을 검증하지 않음 ·
  검색 전략이 하나뿐임 · 질문 변환이 없음 네 가지이며, 뒤의 네 패턴이 각각 이 한계 하나씩을 메우는 구조임.
- Self-RAG와 CRAG는 둘 다 품질을 검증하지만 교정 액션의 유무가 갈림. Self-RAG는 낮은 점수를 돌려줄 뿐이고,
  CRAG는 질문 재작성 · 웹 검색 같은 교정을 실제로 수행함.
- 마지막 콜아웃을 읽고 "오늘 목표는 가장 똑똑한 패턴 고르기가 아니라 가장 작은 패턴 고르기"라고 못박음.
- LLM 호출 수는 교재가 제시한 값 그대로이며 우리 서비스에서 측정한 값이 아님을 분명히 말함.

## 슬라이드 2. 우리 시스템에 적용하기

### breadcrumb

`Ⅲ. 문서 검색 아키텍처 › 2. 우리 시스템 적용`

### 제목

`우리 시스템에 적용하기`

### 리드문

우리 서비스의 뼈대는 이미 Basic RAG임. 패턴을 적용한다는 것은 이 뼈대의 정해진 자리에 부품을 끼운다는 뜻임.

### 레이아웃 패턴

**패턴 A (2단 헤더 바)** — 좌측: 단색 네이비 헤더 바 `공통 뼈대` + 틴트 박스 안에 도식.  
우측: 그라디언트 헤더 바 `패턴별로 끼우는 자리` + 넘버 스퀘어 배지 카드 5개.  
좌 : 우 너비 비율 약 4.5 : 5.5. 카드는 `#F5F8FC` 바탕 + `#D9E0EC` 테두리의 RoundRect.

### 본문 — 좌측 도식 (PPT 도형으로 작도)

틴트 박스(`#EEF3FA`) 안에 **세로 흐름 1줄**을 둠. 노드는 RoundRect, 화살표는 아래 방향 직선 화살표.

```
[질문]
   ↓
[검색 부품]   ← 네이비 노드. 안쪽에 작은 칩 3개: Vector / Hybrid(Vector+BM25) / Rerank
   ↓
[답변 생성]
   ↓
[근거 검증]   ← 인용문이 원문에 실제 있는지 확인
   ↓ 통과            ↘ 실패
[최종 답변]        [답변 재작성]  ← 점선 화살표로 [답변 생성]으로 되돌아감
```

근거가 부족한 경우를 나타내는 분기 1개를 검색 결과 채점 자리(배지 3) 오른쪽에 추가함.
(수정(클로니): 근거 부족 판단은 답변 전에 일어나므로 `[근거 검증]`이 아닌 검색 직후에 연결함)

```
[3 CRAG 결과 채점 자리] ──(근거 부족)──→ [확인 필요로 정지]   ← 다크 슬레이트 `#404155` 노드
```

도식 옆에 번호 배지를 붙여 "끼우는 자리"를 표시함. **배지 번호 = 우측 카드 번호(패턴 번호)** 로 통일함.
(수정(클로니): 초안은 자리 번호와 카드 번호가 달라 혼동 우려 → 패턴 번호 하나로 통일)

| 배지 | 붙이는 위치 | 설명 |
|---|---|---|
| 1 | 뼈대 전체(질문 → 검색 부품 → 답변 생성) | 지금의 Basic RAG |
| 4 | `[질문]` 과 `[검색 부품]` 사이 — 맨 앞 | 질문 복잡도로 전략을 고르는 자리 (Adaptive) |
| 2 | `[검색 부품]` 바로 위 | 검색을 할지 말지 정하는 자리 (Self-RAG) |
| 3 | `[검색 부품]` 바로 아래 | 찾아온 결과를 채점·교정하는 자리 (CRAG) |
| 2 | `[근거 검증]` 자리 | 답변이 문서에 근거하는지 보는 자리 (Self-RAG, 이미 있음) |
| 5 | 흐름 전체를 둘러싸는 점선 테두리 | 흐름 자체를 에이전트가 운전하는 자리 (Agentic) |

### 본문 — 우측 카드 5개 (넘버 스퀘어 배지 + 제목 + 3줄)

각 카드 구성: `위치` / `추가 부품` / `우리 질문 예시 동작` 3줄. 배지 색은 ①②④ `#2E74C6`, ③ `#1E2A5C`, ⑤ `#404155`.

**① Basic RAG — 지금의 뼈대 그대로**
- 위치: 끼우는 곳 없음 (현재 상태)
- 추가 부품: 없음
- 동작: "연회비 면제 조건은?" → Hybrid로 검색 → 답변 → 근거 검증. 판단 분기 없이 한 줄로 지나감

**② Self-RAG — 검색할지 먼저 묻기**
- 위치: 검색 전 (②), 답변 뒤 (④)
- 추가 부품: 검색 필요 판단기 (④ 자리는 이미 있는 근거 검증이 담당)
- 동작: 카드 문서가 필요 없는 인사·잡담은 검색을 건너뛰고, "연회비 면제 조건은?"은 검색으로 보냄

**③ CRAG — 검색 결과를 채점하고 고침**
- 위치: 검색 직후 (③)
- 추가 부품: 관련성 평가자 + 낮음 경로용 대체 검색(웹 검색 등, 현재 없음 → 추가 필요)
- 동작: 높음이면 그대로 답변, 애매하면 rewrite로 질문을 고쳐 재검색, 낮으면 대체 경로 또는 "확인 필요"로 정지

**④ Adaptive RAG — 질문 난이도에 맞춰 길을 가름**
- 위치: 질문을 받은 직후, 맨 앞 (①)
- 추가 부품: 질문 복잡도 분류기
- 동작: "연회비 면제 조건은?"은 단일 검색 1회로, "올해 비용 면제와 포인트 적립 조건을 함께"는
  decomposition으로 쪼개 여러 번 검색

**⑤ Agentic RAG — 흐름 자체를 에이전트가 운전**
- 위치: 흐름 전체를 감쌈 (⑤)
- 추가 부품: 계획–실행–평가를 반복하는 에이전트 + 도구 호출 (현재 외부 도구 없음 → 추가 필요)
- 동작: 검색 부품 · 질문 변환 · 위 ②③④ 판단을 전부 도구로 등록하고, 복합 질문은 스스로 단계를 나눠 반복 검색함

### 본문 — 하단 캡션 (14pt, `#7C8598`)

`Vector · Hybrid · Rerank는 패턴이 아니라 [검색 부품] 칸에 들어가는 선택지임. 패턴을 바꿔도 이 칸의 선택은 그대로 남음`

### 출처

- 교재 「10. RAG」 5.1 ~ 5.5 —
  https://github.com/cna-bootcamp/aistudy/blob/main/agentic-ai/textbook/10.RAG.md
- Self-RAG: Asai et al. (2023) — https://arxiv.org/abs/2310.11511
- CRAG: Yan et al. (2024) — https://arxiv.org/abs/2401.15884
- Adaptive-RAG: Jeong et al. (2024, NAACL) — https://arxiv.org/abs/2403.14403
- LangGraph Agentic RAG — https://docs.langchain.com/oss/python/langgraph/agentic-rag

### 발표자 노트

- 먼저 왼쪽 뼈대만 짚으며 "우리 서비스는 이미 Basic RAG"라고 확인시킴. 새 패턴은 뼈대를 갈아엎는 게 아니라
  정해진 자리에 부품을 끼우는 일임을 반복해 말함.
- ④ 근거 검증 자리는 우리에게 이미 있음을 강조함. 다만 원 논문의 Self-RAG는 점수만 돌려주는 데 비해
  우리 흐름은 검증 실패 시 답변을 다시 쓰므로, 이 부분은 CRAG식 교정에 가까운 성격임을 덧붙임.
- CRAG의 "낮음" 경로가 요구하는 웹 검색은 지금 우리 시스템에 없음을 분명히 말하고, 대신 "확인 필요"로 멈추는
  현재 동작이 안전한 대체임을 설명함.
- Adaptive 카드에서는 두 예시 질문을 소리 내어 비교함. 단순 질문에 복합 질문용 비용을 들이지 않는 것이 목적임.
- 마지막 캡션으로 "검색 모드 선택과 패턴 선택은 별개의 결정"임을 다시 못박고 3장으로 넘어감.

## 슬라이드 3. 단계적으로 쌓기

### breadcrumb

`Ⅲ. 문서 검색 아키텍처 › 3. 도입 로드맵`

### 제목

`단계적으로 쌓기`

### 리드문

패턴은 한 번에 다 올리는 것이 아니라 증상이 보일 때 하나씩 얹는 것임. 증상 없이 올린 단계는 비용만 늘림.

### 레이아웃 패턴

**패턴 D (데이터 테이블)** — 좌우 2열 배치. 두 표 모두 행 5개 이하이므로 좌우로 둠.  
좌측: 다크 배지 `도입 로드맵` + 표(5행). 우측: 다크 배지 `증상 → 점검할 패턴` + 표(3행).  
두 표의 상단 y좌표를 같게 정렬하고 중간 갭 0.25″ 확보. 하단 전폭에 인용 콜아웃 1줄.

### 본문 — 좌측 표: 도입 로드맵

다크 배지 텍스트: `도입 로드맵 — 증상이 보일 때 하나씩`

| 패턴 | 이럴 때 도입(교재 적합 상황) | 우리 서비스에서 보이는 신호 |
|---|---|---|
| **Basic** | 단순 Q&A, PoC | "연회비 면제 조건은?" 한 번 검색으로 충분 |
| **Self-RAG** | 검색 필요 여부가 다양, 결과 품질은 대체로 양호 | 인사·잡담에도 매번 검색함 |
| **CRAG** | 검색 품질 불안정, 재검색·웹 검색 등 교정 필요 | 찾아온 문서가 질문과 어긋나는 일이 잦음 |
| **Adaptive** | 쿼리 복잡도가 다양 | 단순 질문과 "면제 + 적립" 복합 질문이 섞임 |
| **Agentic** | 복잡한 멀티스텝 태스크 | 여러 단계 조사·외부 도구가 필요한 질문 |

> 수정(클로니): 초안의 순서 변경(CRAG를 2단계로)은 교재·출처 근거가 없어 교재 순서로 되돌리고,
> 도입 신호는 교재 「적합 상황」 문구를 그대로 사용함

표 아래 캡션(14pt, `#7C8598`):  
`위에서 아래로 갈수록 LLM 호출 수와 구현 복잡도가 커짐(1장 표 참고). 신호가 없으면 다음 줄로 내려가지 않음`

### 본문 — 우측 표: 증상 → 점검할 패턴

다크 배지 텍스트: `증상 → 점검할 패턴`

| 증상 | 점검할 패턴 |
|---|---|
| 검색 결과가 나쁨 | CRAG 교정 로직 점검 |
| 불필요한 검색이 일어남 | Self-RAG 판단 로직 점검 |

### 발표자 노트

- 왼쪽 표는 교재의 복잡도 순서 그대로이며, 「이럴 때 도입」 열은 교재 문구, 오른쪽 열은 우리 서비스에서
  그 상황이 어떻게 보이는지를 옮긴 것임을 먼저 설명함.
- 각 단계는 "그 줄의 도입 신호를 실제로 겪었는가"로만 판단하도록 안내함. 겪지 않은 증상에 미리 부품을 달면
  LLM 호출만 늘고 얻는 것이 없음.
- 오른쪽 표는 운영 중 장애 대응표로 쓰도록 안내함. 증상 한 줄을 보면 점검할 자리가 한 곳으로 좁혀짐.
- 2장의 도식을 다시 띄워 "①②③④⑤ 번호 = 점검할 자리 번호"로 연결지으면 두 슬라이드가 한 세트로 기억됨.
- 마무리 한 문장: 가장 좋은 아키텍처는 가장 똑똑한 아키텍처가 아니라, 지금 겪는 증상을 딱 덮는 가장 작은 아키텍처임.
