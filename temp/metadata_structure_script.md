# 메타데이터 상속과 범위 계산 슬라이드 설명 스크립트

## 제작 메모

16:9 화면과 Pretendard 글꼴을 사용합니다.  
왼쪽 도식과 오른쪽 표는 PowerPoint에서 직접 수정할 수 있는 도형과 네이티브 표로 구성합니다.

## 제목

`공통값은 상속하고, 범위값은 청크마다 계산합니다`

## 핵심 메시지

문서 전체에 같은 메타데이터는 모든 청크가 물려받습니다.  
페이지처럼 청크 범위에 따라 달라지는 값은 각 청크에서 다시 계산합니다.

## 화면 상단

`교육용 합성 PDF의 실제 인덱싱 결과`

`공통 문서: D1_개인회원표준약관_합성.pdf`

## 왼쪽 도식

상단의 공통 문서 도형을 청크 A와 청크 B에 연결합니다.

- 파란색 연결선: `doc_type`, `version`, `access_level`을 두 청크에 그대로 복사
- 청크 A 계산 도형: 겹치는 페이지 `6, 7`에서 최솟값과 최댓값 계산
- 청크 B 계산 도형: 겹치는 페이지 `10, 11`에서 최솟값과 최댓값 계산

도식 안의 계산식은 다음과 같이 표시합니다.

- 청크 A: `min(6, 7) = 6`, `max(6, 7) = 7`
- 청크 B: `min(10, 11) = 10`, `max(10, 11) = 11`

## 오른쪽 표

| 필드 | 자료형 | 청크 A | 청크 B |
|---|---|---|---|
| doc_type | string | regulation | regulation |
| version | string | 1.2 | 1.2 |
| access_level | enum | public | public |
| page | integer | 6 | 10 |
| page_end | integer | 7 | 11 |

표에서 공통값 세 행에는 `상속` 표시를, 페이지 두 행에는 `계산` 표시를 색으로 구분합니다.

## 발표자 설명

이 화면은 교육용 합성 약관을 실제로 인덱싱한 결과입니다. 두 청크는 같은 PDF에서 나왔기 때문에 문서 종류,
버전, 공개 등급이 같습니다. 현재 구현은 문서 메타데이터를 먼저 복사하므로 이 세 값이 두 청크에 그대로 전달됩니다.

페이지는 청크마다 다릅니다. 청크 A는 6쪽과 7쪽에 걸치므로 `page`는 6, `page_end`는 7입니다.  
청크 B는 10쪽과 11쪽에 걸치므로 `page`는 10, `page_end`는 11입니다. 구현에서는 청크와 겹치는 페이지 중
가장 작은 값을 `page`, 가장 큰 값을 `page_end`에 넣습니다.

조항도 같은 원리로 청크 범위에서 계산합니다. 청크 A의 대표 조항은 제6조이며 제6조부터 제9조까지 포함합니다.  
청크 B의 대표 조항은 제20조이며 제20조부터 제25조까지 포함합니다. 한 청크가 여러 조항에 걸치면 대표값은
`clause_no`, 전체 목록은 `clause_no_all`에 저장합니다. 이 내용은 화면의 가독성을 위해 발표자 설명에서만 다룹니다.

따라서 메타데이터를 모두 상속하거나 모두 새로 만드는 방식으로 나누지 않습니다. 문서 전체에 같은 값은 상속하고,
청크가 포함한 범위에 따라 달라지는 값은 계산합니다.

두 사례는 비교 파일의 새 인덱스에서 확인한 실제 청크입니다. 검색 결과에서 확인한 D1·D2 청크에는 한 페이지만 포함한
후보가 없어 임의의 한 페이지 사례를 만들지 않았습니다.
