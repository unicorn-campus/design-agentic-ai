## 슬라이드 1. 불확실 판정 시 LLM이 기법 선택

- breadcrumb: `Ⅲ. 문서 검색 아키텍처 › Pre-Retrieval › 6. 불확실 판정 후 변환`
- 제목: `불확실 판정 시 LLM이 기법 선택`
- 리드문: 코드는 판정 근거를 사실로 계산하고, LLM이 정보를 보고 기법을 골라 질문을 변환함 — 규칙은 금지 조건만 검사

### 좌측 도식 — LLM에 무엇을 함께 주나

```
◇ CRAG 채점: 불확실 ──▶ [코드: 판정 근거 계산 — 점수 구간 · 1·2위 격차 · 핵심어 유무 · 검색기 일치]
                                    │ 판정 근거(사실)
 [원 질문]                      ─┐     ▼
 [검색 결과 조각 + 제목]         ─┼──▶ ⬡ LLM: 기법 선택 · 질의 작성 ──▶ ◇ 금지 규칙 검사 ─통과▶ (원통) 재검색(상한)
 [이전 시도 기록: 같은 변환 반복 방지] ─┤                                  └위반▶ [keep · clarify]
 [기법 가이드 · 허용 선택지]      ─┘
                     [금지 규칙] 상품명 없음+상품 섞임 → clarify / 같은 기법·질의 반복 금지 / 상한 도달 → keep
```
- 허용 선택지: 5기법 전체 + keep + clarify(규칙이 미리 좁히지 않음)

### 우측 도식 — 원인별 기법 가이드 (LLM 참고용, 프롬프트에 넣음)

| 원인 | ▶ | 기법 |
|---|---|---|
| 핵심어가 결과에 하나도 없음 | ▶ | Multi-Query · Rewriting |
| 핵심어가 결과에 있는데 점수가 상한 미달. 질문이 상대적으로 짧음 | ▶ | HyDE |
| 구체 사례를 묻는데 상위 주제 문서만 걸림 | ▶ | Step-Back |
| 1 · 2위 격차 작음(비슷한 상품 경쟁) | ▶ | Rewriting(상품명 없으면 clarify) |

- 캡션: `가이드는 참고용 — 맞지 않으면 다른 선택 + 이유 기록`
- 수정(클로니): 「하위 질문 일부만 충족」 행은 삭제 — 분해된 질문은 하위 질문마다 따로 채점 · 진단하므로 위 4행이 그대로 적용됨
- 수정(클로니): 「일반 원칙 문서만 걸림」 → 「구체 사례를 묻는데 상위 주제 문서만 걸림」 — LLM이 결과 조각을 읽고 판단할 수 있는 표현

### 하단 — 가드레일 칩 4개 (사용자 수정 문구 유지)

1. **권한 필터 후 결과만** — 권한 밖 문서 조각 유출 방지
2. **결과 조각은 데이터로** — XML 태그로 감싸 지시 차단
3. **조각 수 · 길이 상한** — 토큰 · 비용 · 지연 억제
4. **원 질문 보존** — 원 질문과 상관없는 변환 안되게 함

- 콜아웃: `코드는 사실을 계산하고, LLM이 고르고, 규칙은 금지만 함`
- 출처: 교재 「10. RAG」 5.5 Router(LLM Router) · LangGraph Agentic RAG(LLM 채점 · 재작성 노드) · CRAG, Yan et al.(2024) · 설계안(현재 소스 기준 아님)

### 발표자 노트

- 실무에서는 기법 선택을 LLM에 맡기는 방식이 일반적임. 교재도 라우터를 LLM Router와 Semantic Router로 나누며, LangGraph 예제도 채점 · 재작성을 LLM 노드로 둠.
- 규칙으로 후보를 좁히려면 시소러스 · 상품 메타데이터를 먼저 만들어야 함. LLM 선택 방식은 그 준비 없이 시작할 수 있음.
- 대신 LLM이 짐작하지 않도록, 코드가 계산한 사실(점수 구간 · 격차 · 핵심어 유무 · 검색기 일치)과 결과 조각을 함께 줌.
- 오른쪽 가이드는 강제가 아니라 참고임. LLM은 맞지 않으면 다른 기법이나 keep · clarify를 고르고 이유를 남김.
- 규칙은 금지만 함: 상품명 없이 상품이 섞이면 clarify, 같은 변환 반복 금지, 상한 도달 시 keep. 평가셋에서 LLM 선택이 자주 틀리는 유형이 보이면 그 유형에만 규칙을 추가함.
