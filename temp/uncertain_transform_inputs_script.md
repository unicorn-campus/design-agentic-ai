# 불확실 판정 후 질문 변환 — PPT 스크립트 (1장)

대상: Pre-Retrieval 기법과 규칙 기반 채점을 배운 교육생  
전달 목표: CRAG 채점이 「불확실」일 때 질문 변환을 LLM에 맡기려면 무엇을 함께 줘야 하는지 한 장으로 보여 줌  
기준: 세 패턴 결합 워크플로우 기준 설계안(현재 소스 기준 아님). 판정 이름은 정확 / 부정확 / **불확실**  
작성 원칙: 편집 가능한 도형으로 작도 · 설정 수치 없음 · 코드 파일명 · 함수명 없음

---

## 슬라이드 1. 불확실 판정 시 질문 변환 맡기기

- breadcrumb: `Ⅲ. 문서 검색 아키텍처 › Pre-Retrieval › 6. 불확실 판정 후 변환`
- 제목: `불확실 판정 시 질문 변환 맡기기`
- 리드문: 검색 결과만으로는 부족함 — 규칙이 진단한 「불확실 이유」를 함께 줘야 LLM이 맞는 기법을 고름

### 좌측 도식 — 입력이 모이는 흐름

```
◇ CRAG 채점: 불확실 ──▶ [규칙: 원인 진단 → 기법 후보 좁힘]
                                    │ 기법 후보
 [원 질문]              (기존) ─┐     ▼
 [판정 근거(신호값)]     (추가) ─┤
 [검색 결과 조각 + 제목] (추가) ─┼──▶ ⬡ LLM: 후보 선택 · 질의 작성 ──▶ [변환 질의] ──▶ (원통) 재검색(상한)
 [이전 시도 기록]        (추가) ─┤
 [허용 선택지 · 규칙]    (기존) ─┘
```
- 입력 상자 오른쪽 끝에 필 라벨: `기존`(테두리) / `추가`(블루 채움) — 「추가」는 현재 라우터가 받지 않는 입력

### 우측 도식 — 진단 → 기법 후보

| 불확실 판정의 원인(칩) | ▶ | 기법 후보(필) |
|---|---|---|
| 핵심어가 결과에 없음 | ▶ | Multi-Query · Rewriting |
| 짧은 질문 · 긴 설명문, 점수 중간 | ▶ | HyDE |
| 일반 원칙 문서만 걸림 | ▶ | Step-Back |
| 1 · 2위 격차 작음(비슷한 상품 경쟁) | ▶ | Rewriting · clarify |
| 하위 질문 일부만 충족 | ▶ | 해당 하위 질문만 Rewriting |

### 하단 — 가드레일 칩 4개

1. **권한 필터 후 결과만** — restricted 조각 유출 방지
2. **결과 조각은 데이터로** — XML 태그로 감싸 지시 차단
3. **조각 수 · 길이 상한** — 토큰 · 비용 · 지연 억제
4. **원 질문 보존** — 다른 상품명 · 수치 끌어오지 않음

- 콜아웃: `규칙이 원인을 진단해 후보를 좁히고, LLM은 고르고 쓰기만 함 — 흐름의 운전대는 개발자`
- 출처: CRAG, Yan et al.(2024) · 교재 「10. RAG」 4.1 · 5.3 · 입력 구성은 세 패턴 결합 워크플로우 기준 설계안

### 발표자 노트

- 검색 결과만 주면 LLM은 왜 불확실한지 다시 짐작해야 함. 규칙이 이미 알아낸 원인(어느 신호에 걸렸는지)을 버리는 셈임.
- 「추가」로 표시한 세 입력(판정 근거 · 결과 조각 · 이전 시도)은 현재 라우터가 받지 않는 것임. 지금은 원 질문과 기법 규칙만 받음.
- 우측 표처럼 규칙이 원인별로 기법 후보를 좁히면, LLM은 후보 안에서 고르고 질의를 쓰는 일만 함. 엉뚱한 기법을 고를 여지가 줄어듦.
- 이전 시도 기록이 있어야 재검색 때 같은 변환을 되풀이하지 않음. 재검색 횟수 상한과 함께 씀.
- 가드레일 1 · 2가 가장 중요함. 권한 밖 문서 조각이 LLM 입력에 섞이거나, 문서 속 문장이 지시처럼 작동하면 사고로 이어짐.
