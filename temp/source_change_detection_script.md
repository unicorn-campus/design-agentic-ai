# 슬라이드 스크립트: 원천 파일 변경 감지

## 슬라이드 1. 바뀐 원천 파일만 다시 처리하는 원리

### 핵심 메시지

원천 파일 전체에서 만든 SHA-256 지문을 이전 색인의 지문과 비교함.  
지문이 같은 파일은 기존 청크를 재사용하고, 달라졌거나 새로 들어온 파일만 로드·청킹·정제함.

### 페이지 헤더

- breadcrumb: `RAG 인덱싱 › 원천 확인`
- 제목: `바뀐 원천 파일만 다시 처리하는 원리`
- 리드문: `파일 전체 바이트의 지문을 이전 색인과 비교해 비싼 후속 처리를 줄임`

### 권장 레이아웃

- 16:9, 흰색 배경, Pretendard 사용
- 상단: breadcrumb, 48pt 제목, 파란색 언더라인 룰
- 본문: 왼쪽부터 오른쪽으로 이어지는 3단계 흐름도
- 하단: 파일 3개의 비교 결과를 보여 주는 예시 카드
- 모든 상자·화살표·배지는 PowerPoint에서 수정 가능한 기본 도형으로 작성

### 본문 도식

#### ① 현재 지문 만들기

카드 제목: `원천 파일 전체를 읽어 지문 생성`  
카드 본문: `SHA-256(파일 바이트) → 현재 지문`  
보조 문구: `파일마다 내용이 같으면 같은 값, 한 바이트라도 달라지면 다른 값 생성`

오른쪽 화살표 레이블: `파일명으로 같은 원천 찾기`

#### ② 이전 색인과 비교하기

카드 제목: `이전 manifest 조회`  
코드형 예시:

```text
inputs_sha256 = {
  "약관.pdf": "a17…",
  "안내.pdf": "b29…"
}
```

카드 하단 판정식: `이전 지문 == 현재 지문 ?`

오른쪽에서 위·아래 두 갈래 화살표로 분기함.

#### ③ 처리 경로 결정하기

위쪽 네이비 틴트 카드:

- 배지: `같음`
- 제목: `기존 청크 재사용`
- 본문: `원문 로드·청킹·정제 생략`

아래쪽 파란색 틴트 카드:

- 배지: `다름 · 신규`
- 제목: `파일 다시 처리`
- 본문: `로드 → 청킹 → 정제·가명 처리`

두 카드 아래 강조 콜아웃:

`모든 파일과 처리 계약이 같으면 전체 실행을 바로 종료함`

### 하단 예시 카드

제목: `예시 — 짧은 해시는 설명용 가상 값`

| 원천 파일 | 이전 지문 | 현재 지문 | 판정 | 결과 |
|---|---:|---:|---|---|
| 약관.pdf | a17… | a17… | 같음 | 기존 청크 재사용 |
| 안내.pdf | b29… | c83… | 변경 | 로드·청킹·정제 |
| 상담.txt | 없음 | d40… | 신규 | 로드·청킹·정제 |

### 발표자 노트

SHA-256은 파일 전체 바이트를 일정한 길이의 지문으로 바꾸는 함수임. 파일 이름이 같아도 내용이 바뀌면 지문이 달라짐.  
현재 구현은 `discover_docs`에서 모든 원천의 지문을 먼저 모으고, 전체가 같은지 확인함. 모두 같고 청킹 정책,  
문서 프로필, 임베딩 계약도 같으며 강제 재색인이 아니면 다음 단계로 가지 않고 실행을 종료함.  

파일별 재사용 판단은 이어지는 `load_split_clean`에서 실제 적용함. 같은 파일명에 같은 SHA-256이 저장되어 있고,  
청킹 정책과 문서 프로필이 같으며, 강제 재색인이 아니고, 기존 청크가 있을 때 개인정보 처리 완료 청크를 재사용함.  
조건을 만족하지 않는 파일만 로더·분할기·정제 처리기를 통과함. 따라서 슬라이드의 "다음 단계로 보냄"은  
상태 흐름 자체를 파일별로 끊는다는 뜻이 아니라, 비용이 큰 원문 로드·청킹·정제를 다시 수행한다는 뜻임.  

현재 지문은 PDF에서 추출한 본문이 아니라 원천 파일의 전체 바이트로 계산함. 따라서 보이는 본문이 같아도 PDF 메타데이터나  
내부 저장 구조가 바뀌어 파일 바이트가 달라지면 변경으로 판정될 수 있음. 반대로 파일명과 바이트가 모두 같으면 같은 원천으로 봄.

### 구현 근거

- `hybrid-ai-lab/indexer/vector-bm25/app/infrastructure/loaders.py`
  - `FileSystemSourceCatalog.discover`: `sha256(path.read_bytes()).hexdigest()`로 원천 파일 전체 지문 생성
- `hybrid-ai-lab/indexer/vector-bm25/app/application/indexing_service.py`
  - `discover_docs`: 현재 원천 지문 수집과 전체 무변경 여부 판정
  - `_is_no_op`: 원천 지문과 처리·임베딩 계약이 모두 같을 때 전체 실행 종료 판정
  - `load_split_clean`: 파일별 지문과 정책 조건이 같으면 기존 청크 재사용, 아니면 로드·청킹·정제 수행
  - `_build_manifest`: 다음 비교에 사용할 `inputs_sha256` 저장

### 디자인 메모

- 1단계 카드는 `#EEF3FA`, 2단계 카드는 흰색, 3단계 결과 카드는 `#F5F8FC` 사용
- 결과 배지 중 `같음`은 `#1E2A5C`, `다름 · 신규`는 `#2E74C6` 사용
- 3단계 화살표는 왼쪽에서 오른쪽으로 읽히게 배치하고, 분기선이 텍스트를 가리지 않도록 카드 사이 여백 확보
- 하단 예시는 네이티브 표로 작성하고 헤더행 `#E2EEF9`, 본문 교차행 `#F5F8FC` 적용
- 본문 최소 14pt, 카드 제목 21pt 이상, 섹션 제목 24pt 이상 적용
