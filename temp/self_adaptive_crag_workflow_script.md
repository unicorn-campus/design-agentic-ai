## 슬라이드 1. Self-RAG + Adaptive + CRAG 결합

### breadcrumb

`Ⅲ. 문서 검색 아키텍처 › 5. 세 패턴 결합(워크플로우)`

### 제목

`Self-RAG + Adaptive + CRAG 결합`

### 리드문

판단 자리 3곳(검색 전 · 검색 후 · 답변 후)을 미리 그린 분기로 잇는 워크플로우.  
LLM이 흐름을 고르지 않으므로 비용과 동작을 예측할 수 있음

### 레이아웃 패턴

**패턴 A 변형 (2단 헤더 바)** — 좌측(약 8.3″): 단색 네이비 헤더 바 `워크플로우 흐름` + 틴트 박스 안 도식.  
우측(약 6.3″): 블루 헤더 바 `패턴별 자리와 Agentic과의 차이` + 다크 배지 2개(패턴 표 · 차이 리스트).

### 본문 — 좌측 도식 (PPT 도형으로 작도)

```
[질문 + 역할(agent/auditor)]
   ↓
[Adaptive 분류기 — 질문 문장만 보고 판단] ── 옆 메모 ── Self-RAG: 인사·잡담은 검색 없이 답변
   ↓                                                 Adaptive: 단순 → 원 질문 검색
   ↓                                                 Adaptive: 복합 → 미리 분해(+원 질문)
[검색 부품 — Vector · Hybrid · Rerank]  ◀──┐
   ↓                                      │ 애매 → 질문 바꿔 재검색(상한 있음)
[CRAG 채점 — 점수 기준] ── 옆 메모 ───────┘    정확 → 답변으로
   ↓                                         부정확 → web_search(선택) 또는 「확인 필요」로 정지
[답변 생성]  ◀──┐
   ↓            │ 실패 → 답변 재작성(최대 2회)
[Self-RAG 근거 검증 — 인용문 원문 대조] ── 통과 ──→ [최종 답변]
```

- 하단 한 줄: `↺ 모든 분기는 개발자가 미리 그린 조건부 엣지 · 재검색 · 재작성 횟수는 고정 상한 · 끝내 부족하면 「확인 필요」로 종료`

### 본문 — 우측 ① 패턴 표 (다크 배지 `패턴별 자리와 판단 방식`)

| 패턴 | 자리 | 판단 방식 | 상태 |
|---|---|---|---|
| Adaptive | 검색 전(맨 앞) | 질문 문장 기반 가벼운 분류 | 추가 |
| Self-RAG ① | 분류기 안 | 검색이 필요 없는 질문 걸러 냄 | 추가 |
| CRAG | 검색 직후 | 점수 채점 → 재작성 · 대체 검색 | 일부 |
| Self-RAG ② | 답변 후 | 인용문 원문 대조 | 기존 |

- 「일부」: 점수 미달 시 질문 변환 · 「확인 필요」 정지는 지금도 있고, 웹 검색 대체 경로는 없음

### 본문 — 우측 ② Agentic과 차이 (다크 배지 `Agentic과 차이 — 운전대는 개발자`)

1. **다음 단계** — 미리 그린 분기를 따라감 (Agentic: LLM이 실행 중에 선택)
2. **반복** — 재검색 · 재작성 횟수가 고정 (Agentic: 목표를 이룰 때까지 판단하며 반복)
3. **다단계 검색** — 미리 분해 후 한 번에 검색 (Agentic: 앞 결과를 보고 다음 질문 결정)

### 발표자 노트

- 세 패턴을 붙여도 다음 단계를 개발자가 그려 둔 분기가 정하면 워크플로우임. Agentic과의 차이는 패턴 수가 아니라  
  흐름의 운전대를 누가 잡았는지임.
- 단순 질문 「연회비 면제 조건은?」: 분류기에서 단순 → 원 질문 검색 → 채점 정확 → 답변 → 근거 검증 통과.
- 복합 질문 「올해 비용 면제와 포인트 적립 조건을 함께 알려주세요」: 분류기에서 복합 → 미리 분해 + 원 질문 검색 →  
  결과 병합 → 채점 → 답변 → 근거 검증.
- 분류기와 채점을 규칙 · 점수 기반으로 두면 이 두 자리에서는 LLM을 부르지 않음. LLM은 질문 변환 · 답변 · 재작성에만 씀.
- Self-RAG의 「답변이 유용한가」 판단은 이 설계에 넣지 않음. 필요하면 근거 검증 뒤에 별도 관문으로 추가.
