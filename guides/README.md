# AI 앱 아키텍처 설계 가이드 7종

작성: 2026-08-06 · 팀: design-agentic-ai · 토론·통합: 클로니(오케스트레이터)

AI 앱의 아키텍처를 **설계 산출물 7종**으로 만들 때 손에 들고 읽는 가이드임.
`prompts/architecture/`의 작성 프롬프트를 **사람이 판단할 수 있는 순서로 다시 쓴 것**임.

---

## 프롬프트와 가이드는 무엇이 다른가

| | 프롬프트 `prompts/architecture/` | **가이드 `guides/`(이 폴더)** |
|---|---|---|
| 받는 쪽 | AI 코딩 도구 | **사람** |
| 형식 | `{변수}` 치환 템플릿 · MUST / 완료조건 | 판단 순서 · 예시 · 함정 |
| 순서 | 규격을 빠짐없이 훑는 순서 | **사람이 실제로 판단하는 순서** |
| 쓰는 때 | 산출물을 자동 생성할 때 | **직접 설계할 때, 생성 결과를 검토할 때** |

가이드는 프롬프트의 해설이 아님. 두 가지를 더 함.

1. **순서를 뒤집음** — 프롬프트 ⑤는 `스택 → 경로` 순으로 시킴.
   사람은 `질문 유형 뽑기 → 경로 판정 → 버린 대안 기록` 순으로 판단하므로 가이드는 사람 순서를 따름
2. **프롬프트에 없는 칸을 메움** — 규격에 빠져 있어 설계자가 직접 채워야 하는 항목을 각 가이드 4절에 둠

| 2 | [② 논리 아키텍처](02-논리아키텍처-가이드.md) | 무엇이 어디에 있고 어디부터 통제 밖인가 | 클로니 |

④는 ③·⑤가 모두 있어야 시작됨. 자세한 것은 `prompts/architecture/00-산출물규격.md` 3절 임계 경로임.

각 가이드는 **180 ~ 360줄, 4,000 ~ 7,100자**임. 한 건을 20분 안에 읽도록 맞춤.

## 프롬프트에 없어 가이드가 메운 것

토론에서 팀원 3명이 각자 담당 프롬프트를 읽고 지목한 항목임.
**이걸 안 채우면 설계가 뚫린다**고 판단한 것들임.

| 가이드 | 메운 항목 | 왜 |
|--------|----------|-----|
| ③ | 단일·멀티 **판정 사다리** | 프롬프트는 "3줄 판정 근거"만 요구함. 결론 칸일 뿐 판단법이 없음 |
| ④ | **상태 필드 소유권 규칙** | 병렬 분기에서 두 노드가 같은 필드를 쓰면 덮어쓰기로 값이 사라짐 |
| ④ | **반복 상한과 소진 시 착지 노드** | 표에 칸 자체가 없음. "실패 시 재계획"이 무한 왕복이 됨 |
| ④ | **재시도 포함 최악값 합계** | 타임아웃 합계 검증이 성공 경로만 더해 예산을 통과시킴 |
| ⑤ | **원천 데이터 오류율 칸** | 기획서의 정합성 오류 25 ~ 30%가 그대로 검색 실패율이 됨 |
| ⑤ | **골든셋 20 ~ 30문항 만드는 법** | 평가 없이 청킹·모델부터 손대는 순서 오류를 막음 |
| ⑥ | **관측 기록을 마스킹 대상 표의 행으로** | 출력 직전 1회만 가리면 관측 기록·오류 로그에 원문이 남음 |
| ⑦ | **비밀값 위반 예시 3종** | 이미지 레이어 · 설정 파일 평문 · 로그 출력 |

## 실제 기획 자료에서 찾은 것

예시는 **KT 개통 자동화 플랫폼** 기획 자료(`~/workspace/oss/docs/plan/`)로 통일함.
지어낸 숫자를 쓰지 않았고, 값이 없으면 `[확인필요]`로 남김.

작성 중 실제로 발견한 사항임.

| 발견 | 내용 |
|------|------|
| **재시도 중첩이 기획 자료에 이미 있음** | `userstory.md` 679행 `5회 재처리 실패 시 DLQ 저장` + `es/08-*.puml` 109 ~ 110행 `DLQ 자동 재시도 3회` → 같은 낱말 `재시도`가 두 계층에 쓰여 **한 건이 최대 15회 처리**됨. 값 충돌이 아니라 계층 차이임. ④는 예산 관점, ⑥은 관측 기록 관점으로 나눠 다룸 |
| **응답 예산이 단계 하나로 이미 초과됨** | `userstory.md` 621행 화면 로딩 **2초** 목표인데 640·198행 GIS 조회 타임아웃이 **10초**임. 재시도 2회를 넣으면 최악 30초로 예산의 15배임. 기획에 `텍스트 목록 모드 전환` 폴백이 있으나 그건 **실패 시** 대응이고, 10초 걸려 **성공하는** 경우는 그대로 초과함. ④에서 동기 경로 분리로 처리하고 안 되면 `[확인필요]`로 되물음 |
| **원천 오류율이 곧 검색 실패율** | `비즈니스모델.md` 8절 정합성 오류 25 ~ 30%. ⑤에서 경로를 고르기 전에 원천 품질을 재야 함 |
