# 설계 가이드 공통 규격 v1

토론: 클로니·플로니·지식니·커넥니 · 확정: 클로니 · 2026-08-06

`prompts/architecture/`의 설계 산출물 7종 작성 프롬프트를 **사람이 읽고 스스로 설계할 수 있는 가이드**로
옮기기 위한 규격임. 가이드 7건은 `guides/` 아래에 두며 이 규격을 공유함.

---

## 0. 프롬프트와 가이드는 무엇이 다른가

| 구분 | 프롬프트 (`prompts/architecture/`) | **가이드 (`guides/`)** |
|------|-----------------------------------|----------------------|
| 받는 쪽 | AI 코딩 도구 | **사람** (KT 3일 과정 팀 · 신한카드 10주 조) |
| 형식 | `{변수}` 치환 템플릿 · MUST / MUST NOT / 완료조건 | 판단 순서 · 예시 · 함정 |
| 순서 | 규격을 빠짐없이 훑는 순서 | **사람이 실제로 판단하는 순서** |
| 목적 | 빠짐없이 생성 | **스스로 판단** |

**가이드는 프롬프트의 해설이 아님.** 아래 두 가지를 반드시 함.

1. **순서를 뒤집음** — 프롬프트 ⑤는 "기술 스택의 비정형 방식 전부를 1행씩"이라 `스택 → 경로` 순임.
   사람은 `질문 유형 뽑기 → 경로 판정 → 버린 대안 기록` 순으로 판단함. 가이드는 사람 순서를 따름
2. **프롬프트에 없는 칸을 메움** — 토론에서 3명이 각각 프롬프트에 없는 필수 항목을 지목함(4절 참조).
   그것을 채우지 않으면 가이드가 프롬프트 재탕이 됨

## 1. 섹션 구조 (8개 고정)

제목 문자열을 **글자 그대로** 사용함.

| 순서 | 섹션 제목 | 무엇을 쓰는가 | 분량 |
|------|----------|--------------|------|
| 0 | `# 설계서 {번호} {산출물명} — 작성 가이드` | H1 1줄 | 1줄 |
| 1 | `## 1. 이 설계서가 답하는 질문` | 한 줄 정의 · **이걸 안 하면 나는 사고 3줄** · 앞뒤 연결도(Mermaid) | 20줄 |
| 2 | `## 2. 시작 전 판정` | 5분 안에 끝나는 결정 트리 또는 판정표. 여기서 막히면 뒤가 다 막힘 | 35줄 |
| 3 | `## 3. 칸별 작성법` | 칸마다 `무엇을 / 어디서 가져오나 / 좋은 예 / 나쁜 예` 4열 표 | 45줄 |
| 4 | `## 4. 프롬프트에 없지만 반드시 채울 것` | 규격에 빠져 있어 설계자가 직접 메워야 하는 항목 | 30줄 |
| 5 | `## 5. 예시` | 두 도메인. `### 5-1.` KT 개통 자동화(한 줄기 완주) · `### 5-2.` 마이데이터 금융상품 추천 | 75줄 |
| 6 | `## 6. 자주 틀리는 5가지` | 실패 양상 · 왜 생기나 · 어떻게 막나 3요소 | 30줄 |
| 7 | `## 7. 제출 전 자가 점검표` | 프롬프트 완료조건을 사람이 확인 가능한 문장으로 옮김. 체크박스 | 20줄 |
| 8 | `## 8. 다음으로 넘기는 값과 근거 자료` | 후행 소비처 표 + 근거 아티클 표 | 20줄 |

**총 분량 — 1건당 180 ~ 360줄, 4,000 ~ 7,500자.**
근거: 3일 과정에서 **20분 넘게 걸리는 문서는 읽히지 않음**(커넥니). 세 명이 A4 6~8쪽으로 독립 수렴함.
상한 이력 — 예시 1종 기준 6,000자 → 예시 2종 체제로 7,100자 → **초보자 검토 반영으로 7,500자**(2026-08-06).
전체를 다 읽으면 1건당 20분을 넘김. 대신 README에 **최소 경로**(2절·3절·7절만, 1건 약 7분)를 둠.

## 2. 쉬운 언어 규칙

`CLAUDE.md` Lessons Learned의 `[Highly Important] 쉬운 언어 사용`을 이 문서에 맞게 편 것임.

- **G1** 한 문장 60자 이내를 원칙으로 함. 60자 초과가 전체의 10%를 넘지 않음(표·코드 제외)
- **G2** 영문 전문용어는 처음 나올 때 그 자리에서 한 줄로 풀어씀. 별도 용어표는 두지 않음
  (가이드는 참조 문서가 아니라 작업 중에 읽는 문서이므로 뒤로 넘기지 않음)
- **G3** 프롬프트의 규격 용어(`HARD`·`CYCLE`·`T-1`·`C-2` 등)를 쓸 때는 **뜻을 먼저 한 줄로 풀고** 씀
- **G4** "적절히"·"충분히"·"잘" 금지. 판단 기준은 숫자나 예/아니오 질문으로 씀
- **G5** 지시가 아니라 **설명**으로 씀. `~하시오`가 아니라 `~함` / `~이 낫습니다`
- **G6** 표를 우선함. 3개 이상 나열은 표로 바꿈
- **G7** 한 줄 120자 제약은 **산문과 목록에만 적용함.** 표 행은 줄바꿈이 안 되므로 제외함.
  실제 작성에서 4명이 같은 지적을 했음(③④⑥⑦)

### 3-2. 런치픽 설계 테스트로 추가 확정한 3건 (2026-08-06)

가이드 7종을 실제 기획 산출물에 적용해 설계서 7종을 만드는 과정에서 **소유자가 없어 충돌이 실제로 발생한** 항목임.
근거는 [`design/00-반영대조표.md`](../../design/00-반영대조표.md) 6절 `J-1` ~ `J-9`임.

| ID | 미결 | 확정 | 근거 |
|----|------|------|------|
| G-11 | 민감 필드 ID(`F-n`)를 ③·⑤ 중 누가 소유하나 | **⑤ 소유 · ③은 인용만.** ③에만 있는 필드는 ⑤가 뒤에 번호를 더하며 기존 번호를 재부여하지 않음 | ⑤가 민감 필드 분류표를 필수 출력으로 가짐. 실제로 `③ F-2 = 식이 유형` / `⑤ F-2 = 정확 좌표`로 갈려 ④·⑥이 인용할 표를 특정할 수 없었음 |
| G-12 | 입출력 **키 이름**을 ③·⑤ 중 누가 소유하나 | **③ 소유 · ⑤ 커넥터 규격이 맞춤** | ③에 `키 이름의 단일 출처` 선언이 이미 있음. 4건이 어긋난 것을 ④가 시퀀스를 그리다 발견함 |
| G-13 | 커넥터의 범위 | **외부 시스템 접근만 커넥터임.** 내부 저장소는 `커넥터 아님`으로 구분해 적음 | 내부 저장소는 ⑤ 정형 접근 경로 표의 대상임. 구분이 없어 ③이 저장소 접근 수단 이름을 ⑤에 되물었음 |

`G-11`과 `G-12`는 **서로 반대 방향**임 — 필드 ID는 ⑤가, 키 이름은 ③이 소유함. 근거가 각각 다름.

## 4. 프롬프트에 없어 가이드가 메워야 하는 항목

토론에서 3명이 지목한 것임. 해당 가이드의 4절에 반드시 넣음.

| 가이드 | 빠진 항목 | 왜 필요한가 |
|--------|----------|------------|
| ③ | **단일·멀티 판정 사다리** | 프롬프트는 "3줄 판정 근거"만 요구함. 결론 칸일 뿐 판단법이 없음 |
| ④ | **상태 필드 소유권 규칙** | 병렬 분기에서 두 노드가 같은 필드를 쓰면 덮어쓰기로 값이 사라짐. `필드당 갱신 주체 1개, 병렬이면 누적만` |
| ④ | **반복 상한(`max_iter`)과 소진 시 착지 노드** | 표에 칸 자체가 없음. "실패 시 재계획"이 무한 왕복이 됨 |
| ④ | **재시도 포함 최악값 합계** | 타임아웃 합계 검증이 성공 경로만 더해 예산을 통과시킴 |
| ⑤ | **원천 데이터 오류율 측정 칸** | KT 기획서의 정합성 오류 25 ~ 30%가 그대로 검색 실패율이 됨 |
| ⑤ | **골든셋 20 ~ 30문항 만드는 법** | 평가 없이 청킹·모델부터 손대는 순서 오류를 막음 |
| ⑥ | **관측 기록을 마스킹 대상 표의 행으로** | 출력 직전 1회만 가리면 관측 기록·오류 로그에 원문이 남음 |
| ⑦ | **비밀값 위반 예시 3종** | 이미지 레이어 · 매니페스트 평문 · 로그 출력. 금지만 적혀 있고 무엇이 위반인지 안 보임 |

### 4-2. 실제 설계에서 추가로 드러난 공백 (2026-08-06)

런치픽 설계 테스트에서 **가이드를 그대로 따르면 계산이 아무도 안 되거나 가드레일이 사라지는** 자리임.
전체 86건 중 성격이 다른 3종만 여기 올림. 나머지는
[`guides/00-검증결과-반영내역.md`](../00-검증결과-반영내역.md)에 있음.

| 성격 | 무엇이 빠졌나 | 왜 필요한가 |
|------|-------------|------------|
| **입력 전제 승계** | 가이드가 `prompts/architecture/00-파라미터블록.md`를 한 번도 언급하지 않음 | ⑦의 비밀값 도출이 `기술 스택 6행`에 걸려 있고, 그 표는 **②의 부속 표가 아니라 파라미터 `V-07`**임. ②에는 없고 있을 수도 없어 ⑦가 시작 지점에서 막힘 |
| **곱셈·나눗셈 담당** | 값의 **소유자**는 정했으나 두 문서의 값을 **곱하거나 나누는 계산**의 담당자가 없음 | `총량 ÷ 단계 수`(① ÷ ④) · `동시 사용자 × 자원 점유 비율`(① × ⑦) · `기간 상한 ÷ 건수 전제`(① ÷ 기획)를 아무도 하지 않았음. 교차검증 HIGH 8건 중 5건이 이 자리 |
| **칸 사이 모순 검사** | 7절 점검표가 **칸의 존재·개수만** 봄 | ③에서 `사용 모델`에 모델이 있는데 `사용 도구`에 그 모델을 부르는 도구가 없는 모순이 3판까지 10개 항목을 모두 통과했음 |

**7종 공통으로 넣을 점검 항목 2종**임. 각 가이드 7절에 형식을 맞춰 넣음.

| # | 항목 | 왜 |
|---|------|-----|
| 공통-1 | `칸과 칸이 서로 어긋난 행이 0건임` — 무엇과 무엇을 대조하는지 산출물마다 지정함 | 위 3번째 공백 |
| 공통-2 | 값이 필수인 칸은 `값이 있거나 [확인필요]로 되물어진 상태임(빈 칸 0건)` | ④⑤⑥⑦이 각각 **`공란 0건` 요구와 `추정값 금지` 요구가 부딪히는 것**을 기록했음. 원문에 숫자가 없으면 둘 중 하나를 어겨야 했음 |

## 6. 예시 작성 규칙 (5절)

## 8. 완료조건

가이드 1건이 아래를 전부 만족해야 완료임.

- ⓐ 총 180 ~ 360줄, 4,000 ~ 7,500자 — **글자 수는 개행 문자를 제외하고 셈**(통상 편집기 기준).
  **재는 방법을 아래로 고정함.** 눈으로 어림하지 않음
  ```bash
  # 개행을 LF로 고정한 뒤(.gitattributes 에 `*.md text eol=lf`) 아래를 돌림
  for f in guides/0*-*.md; do c=$(tr -d '\n\r' < "$f" | wc -m); l=$(wc -l < "$f"); \
    { [ "$c" -gt 7500 ] || [ "$c" -lt 4000 ] || [ "$l" -gt 360 ] || [ "$l" -lt 180 ]; } \
    && echo "규격 위반: $f (${l}줄 ${c}자)"; done
  ```
  **`\r`를 함께 지우는 것이 핵심임.** 윈도우 줄바꿈(`CRLF`)은 개행이 `\r\n` 2바이트인데
  `tr -d '\n'`만 쓰면 `\r`가 남아 **줄 수만큼 글자가 더 세어짐.** 2026-08-06 실제로 이 일이 났음 —
  잘못 재서 3종을 `초과`로 판정했고, 팀이 필요 없는 분량 축소를 했음. 다시 재니 전부 규격 안이었음.
  같은 파일이 재는 사람에 따라 다른 값이 나오면 판정이 갈리므로 **개행 방식을 먼저 고정함.**
  가이드를 고칠 때는 **넣는 만큼 줄임.** 규격을 깨고 넣지 않으며, 못 넣은 것은 미반영으로 기록함
- ⓑ 섹션 제목 8개가 규격 문자열과 일치
- ⓒ 1절에 앞뒤 연결도(Mermaid) 1개와 "안 하면 나는 사고" 3줄이 있음
- ⓓ 2절에 결정 트리 또는 판정표가 있고, 판단 기준이 예/아니오 또는 숫자로 되어 있음
- ⓔ 3절 칸별 표에 **좋은 예와 나쁜 예가 모든 행에** 있음
- ⓕ 4절에 프롬프트에 없는 항목이 1개 이상 있음(4절 표 참조)
- ⓖ 5절에 `### 5-1.`(KT 개통 자동화, 한 줄기 완주)과 `### 5-2.`(마이데이터)가 모두 있음

- ⓘ 7절 점검표가 체크박스이고 각 항목이 존재·개수·공란·수치 4형식 중 하나로 확인 가능함
