# 이탈 위험 방지 케이스 Event Modeling

`hybrid-ai-lab`의 카드사 하이브리드 AI 실습을 Event Modeling 네 층 형식으로 정리한 문서임.  
목적은 ② 논리아키텍처 2단계 「노드 수집」의 입력을 만드는 것이며, 이벤트스토밍 요약을 대체하지 않고 뒤에 붙임.

## 1. 범위와 근거

| 구분 | 내용 | 근거 |
|---|---|---|
| 업무 | 해지 문의 고객을 상담하는 상담사가 근거 있는 유지 제안 요약을 받음 | `hybrid-ai-lab/docs/D3_README.md` |
| 정형 조회 | 보유 상품·월별 사용액·연체 지표·기준일을 PostgreSQL `cardlab`에서 조회 | `s2.2/src/nl2sql/prompts/05_ask_with_context.md` |
| 지식 검색 | 약관 D1·혜택 D2·상담 이력 D3를 벡터 + BM25 하이브리드로 검색, 근거 검증 관문 통과 | `vector/indexer`, `vector/retriever` |
| 예측 모델 | **미연결.** 이탈 정답·확률·위험등급을 생성하지 않음 | `D3_README.md` 「예측 학습 범위」 |
| 요약 화면 | 결론·근거·출처·예측값·주의사항 5항목. 예측값은 `확인 필요` 고정 | `05_ask_with_context.md` [출력] |

**실습 범위 밖이라 설계 가정으로 둔 것**: 상담사 화면(실습은 CLI 출력), 제안 확정·안내, CRM 기록, 고객 반응 기록.  
가정 항목은 아래 표에서 `(가정)`으로 표시함.

## 2. 층과 줄 구성

Event Modeling은 네 층으로 그리며 **줄(스윔레인)이 있는 층은 화면 층과 이벤트 층 둘뿐임.**  
커맨드·읽기 모델·자동화는 줄 없이 화면과 이벤트 사이에 놓이고 선으로만 이어짐.

| 층 | 놓이는 카드 | 줄 나누는 기준 | 이 문서의 줄 |
|---|---|---|---|
| 화면 | 화면 조각 | 역할 1명 = 1줄 | `고객` · `상담사` · `운영자` |
| 커맨드·읽기 모델·자동화 | 파란 커맨드 · 초록 읽기 모델 · 톱니 자동화 | 줄 없음 | — |
| 이벤트 | 주황 이벤트만 | 이벤트 흐름을 따로 갖는 시스템 1개 = 1줄 | 아래 표 |
| 사양 | Given-When-Then | 줄 없음 | — |

**이벤트 줄 목록**

| 줄 ID | 줄 이름 | 소유 | 따로 둔 이유 |
|---|---|---|---|
| `L-1` | 상담 세션 | 우리 | 상담 1건의 상태 흐름. 요청을 받아 실시간으로 처리함 |
| `L-2` | 지식 색인 | 우리 | 같은 우리 시스템이지만 주기 배치로 돌아 실행 방식이 다름 |
| `L-3` | 정형 DB(`cardlab`) | 외부 | PostgreSQL. 소유자가 다름 |
| `L-4` | 예측 모델 | 외부 | 미연결. 줄만 두고 이벤트 없음 |
| `L-5` | 지식 저장소(벡터 + BM25) | 우리 | `L-2`가 쓰고 `L-1`이 읽는 공유 저장소. 두 줄이 같이 쓰므로 따로 둠 |
| `L-6` | LLM API | 외부 | 모델 벤더. 소유자가 다름 |
| `L-7` | CRM (가정) | 외부 | 상담 결과 기록처. 소유자가 다름 |

## 3. 이벤트 층 전체 시간표

가로는 시간(슬라이스), 세로는 이벤트 줄임. 칸에는 **이벤트만** 적음.

| 줄 | ⓪ 색인 배치 | ① 문의 접수 | ② 현황 조회 | ③ 위험 산출 | ④ 근거 검색 | ⑤ 초안 작성 | ⑥ 검토·안내 | ⑦ 반응 기록 |
|---|---|---|---|---|---|---|---|---|
| `L-1` 상담 세션 | | 상담이 시작되었음 | 고객 현황이 조회되었음 | 위험도 산출이 생략되었음 | 근거가 검색되었음 | 제안 초안이 작성되었음 | 유지 제안이 안내되었음 (가정) | 고객 반응이 기록되었음 (가정) |
| `L-2` 지식 색인 | 색인이 발행되었음 | | | | | | | |
| `L-3` 정형 DB | | | 현황 응답이 반환되었음 | | | | | |
| `L-4` 예측 모델 | | | | (없음) | | | | |
| `L-5` 지식 저장소 | 청크·임베딩이 저장되었음 | | | | 검색 결과가 반환되었음 | | | |
| `L-6` LLM API | | | | | (질문 변환 응답이 반환되었음) | 초안 응답이 반환되었음 | | |
| `L-7` CRM | | | | | | | | 상담 기록이 저장되었음 (가정) |

`L-4`는 전 구간 비어 있음. 이것이 예측값 `확인 필요`의 원천임.  
④의 `L-6` 이벤트는 근거 검증 관문을 통과하지 못했을 때만 생기므로 괄호로 표시함.

## 4. 슬라이스별 네 층 상세

각 표는 세로 슬라이스 하나임. 선 읽는 순서는 `이벤트 → 읽기 모델 → 화면` 또는 `화면 → 커맨드 → 이벤트`임.

### ⓪ 색인 배치 (사전 준비)

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 운영자 | 색인 실행 결과 보고(`report.json` · `validation.json`) |
| 커맨드·읽기 모델·자동화 | — | 톱니 `주기 실행` → 커맨드 `원문을 색인하라` · 읽기 모델 `색인 상태` |
| 이벤트 | `L-2` 지식 색인 | 색인이 발행되었음 |
| 이벤트 | `L-5` 지식 저장소 | 청크·임베딩이 저장되었음 |
| 사양 | — | Given D1·D2·D3 원문 · When 색인하라 · Then 가명화 잔존 0건이고 `active_index.json`이 교체됨 |

### ① 문의 접수

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 고객 | 해지 문의 발화("연회비가 부담돼서 해지하려고요") |
| 화면 | 상담사 | 문의 접수 화면 (가정) |
| 커맨드·읽기 모델·자동화 | — | 커맨드 `상담을 시작하라` |
| 이벤트 | `L-1` 상담 세션 | 상담이 시작되었음 |
| 사양 | — | Given 인증된 회원 ID · When 상담을 시작하라 · Then 회원 가명 ID와 문의 원문이 담긴 상담 세션이 생김 |

### ② 현황 조회

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 상담사 | 고객 현황 카드(보유 상품 · 월별 사용액 · 연체 지표 · 기준일) |
| 커맨드·읽기 모델·자동화 | — | 톱니 `상담 시작 감지` → 커맨드 `현황을 조회하라` · 읽기 모델 `고객 현황` |
| 이벤트 | `L-3` 정형 DB | 현황 응답이 반환되었음 |
| 이벤트 | `L-1` 상담 세션 | 고객 현황이 조회되었음 (번역) |
| 사양 | — | Given 상담이 시작되었음 · When 현황을 조회하라 · Then 기준일이 붙은 현황이 조회됨. 0원과 자료 없음을 구분함 |

### ③ 위험 산출

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 상담사 | 예측값 칸 `확인 필요(예측 모델 미연결)` |
| 커맨드·읽기 모델·자동화 | — | 톱니 `현황 조회 감지` → 커맨드 `위험도를 산출하라` · 읽기 모델 `예측값` |
| 이벤트 | `L-4` 예측 모델 | (없음) |
| 이벤트 | `L-1` 상담 세션 | 위험도 산출이 생략되었음 |
| 사양 | — | Given 예측 모델 미연결 · When 위험도를 산출하라 · Then 생략 사실이 기록되고 화면에 `확인 필요`가 표시됨 |

### ④ 근거 검색

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 상담사 | 근거 목록(출처 · 문서 유형 · 기준일) |
| 커맨드·읽기 모델·자동화 | — | 톱니 `현황 조회 감지` → 커맨드 `근거를 검색하라` · 읽기 모델 `근거 목록` |
| 이벤트 | `L-5` 지식 저장소 | 검색 결과가 반환되었음 |
| 이벤트 | `L-6` LLM API | (질문 변환 응답이 반환되었음: 관문 미통과 시에만) |
| 이벤트 | `L-1` 상담 세션 | 근거가 검색되었음 (번역) |
| 사양 | — | Given 문의 원문 · When 근거를 검색하라 · Then 점수 관문 통과 청크만 남고 다른 고객 상담은 섞이지 않음 |

### ⑤ 초안 작성

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 상담사 | 고객 현황 요약 화면: 결론 · 근거 · 출처 · 예측값 · 주의사항 |
| 커맨드·읽기 모델·자동화 | — | 톱니 `근거 검색 감지` → 커맨드 `제안 초안을 작성하라` · 읽기 모델 `제안 초안` |
| 이벤트 | `L-6` LLM API | 초안 응답이 반환되었음 |
| 이벤트 | `L-1` 상담 세션 | 제안 초안이 작성되었음 (번역) |
| 사양 | — | Given 현황 · 근거 · 생략 기록 · When 초안을 작성하라 · Then 근거 없는 문장 0건, 예측값은 `확인 필요`, 12줄 이내 |

### ⑥ 검토·안내 (가정)

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 상담사 | 제안 수정 · 확정 버튼 |
| 화면 | 고객 | 유지 제안 안내를 들음 |
| 커맨드·읽기 모델·자동화 | — | 커맨드 `제안을 확정하라` (사람 승인) |
| 이벤트 | `L-1` 상담 세션 | 유지 제안이 안내되었음 |
| 사양 | — | Given 제안 초안 · When 상담사가 확정 · Then 확정 문구와 확정자가 기록됨. 자동 확정 없음 |

### ⑦ 반응 기록 (가정)

| 층 | 줄 | 내용 |
|---|---|---|
| 화면 | 고객 | 수용 또는 거절 |
| 화면 | 상담사 | 반응 입력 |
| 화면 | 운영자 | 후속 관리 할 일 목록 |
| 커맨드·읽기 모델·자동화 | — | 커맨드 `반응을 기록하라` · 읽기 모델 `후속 관리 할 일` |
| 이벤트 | `L-1` 상담 세션 | 고객 반응이 기록되었음 |
| 이벤트 | `L-7` CRM | 상담 기록이 저장되었음 |
| 사양 | — | Given 유지 제안이 안내되었음 · When 반응을 기록하라 · Then 마스킹된 요약만 CRM에 저장됨 |

## 5. 줄 경계를 넘는 지점 (신뢰 경계 후보)

선이 우리 줄(`L-1` · `L-2`)과 다른 줄 사이를 건너는 지점만 모음. ② 논리아키텍처 판정 2의 입력임.

| 슬라이스 | 출발 줄 | 도착 줄 | 건너는 데이터 | 넘기지 않아야 할 것 |
|---|---|---|---|---|
| ⓪ | `L-2` 지식 색인 | `L-5` 지식 저장소 | 가명화된 청크 · 임베딩 · 메타데이터 | 고객명 · 카드번호 · 연락처 |
| ② | `L-1` 상담 세션 | `L-3` 정형 DB | 회원 ID · 기준일 | 쓰기 SQL |
| ③ | `L-1` 상담 세션 | `L-4` 예측 모델 | (미연결) | — |
| ④ | `L-1` 상담 세션 | `L-5` 지식 저장소 | 질의 · 접근 등급 | 권한 없는 계정의 `restricted` 조회 |
| ④ ⑤ | `L-1` 상담 세션 | `L-6` LLM API | 가명화된 현황 · 근거 · 질문 | 카드번호 · 고객명 · 인증 정보 |
| ⑦ | `L-1` 상담 세션 | `L-7` CRM | 마스킹된 요약 · 반응 | 상담 원문 |

`L-5`는 우리 소유라 신뢰 경계는 아니지만 `L-1`과 `L-2`가 공유하므로 결합 지점으로 따로 적음.

## 6. 완결성 검사

화면의 값마다 원천 이벤트를 추적한 결과임. 이어지지 않는 값이 설계 구멍임.

| 화면 값 | 읽기 모델 | 원천 이벤트 | 판정 |
|---|---|---|---|
| 보유 상품 · 월별 사용액 · 연체 지표 · 기준일 | 고객 현황 | ② 고객 현황이 조회되었음 | 이어짐 |
| 근거 · 출처 | 근거 목록 | ④ 근거가 검색되었음 | 이어짐 |
| 결론 · 주의사항 | 제안 초안 | ⑤ 제안 초안이 작성되었음 | 이어짐 |
| **예측값** | 예측값 | ③ 위험도 산출이 생략되었음 | **원천 없음.** `확인 필요` 고정 출력이 맞음 |
| 후속 관리 할 일 | 후속 관리 할 일 | ⑦ 고객 반응이 기록되었음 (가정) | 실습 범위 밖 |

## 7. ② 논리아키텍처로 넘기는 노드 목록

| 노드 | 종류 | 출처 줄 | 비고 |
|---|---|---|---|
| 고객 | 사용자 | 화면 줄 | |
| 상담사 | 사용자 | 화면 줄 | |
| 운영자 | 사용자 | 화면 줄 | |
| 상담 세션 처리 | 내부 실행 | `L-1` | 요청형 |
