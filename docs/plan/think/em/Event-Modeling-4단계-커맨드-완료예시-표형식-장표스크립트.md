# Event Modeling 4단계 Command 완료 예시 표형식 장표 스크립트

## 구성

- 대상: Event Modeling 1 ~ 3단계를 마치고 Command를 구체화하는 설계 참여자
- 분량: 기본 슬라이스 1장 + 전체 슬라이스 종합 1장 + 단계별 표 5장, 총 7장
- 사례: 카드 해지를 고민하는 고객 M-204의 상담 흐름
- 첫 장: PowerPoint 기본 도형과 연결선으로 Trigger → Command → Event 슬라이스 표현
- 2장: 전체 10개 슬라이스를 5개씩 두 줄로 배치하고 ID와 제목만 표시
- 3 ~ 7장: `레이어 | ID | 제목 | 내용` 구조의 PowerPoint 기본 표 사용
- 색상·글꼴: 기존 장표의 네이비·블루·흰색과 Pretendard 유지
- 자료: [이탈위험방지 Event Modeling 작성가이드](./이탈위험방지-이벤트모델링-작성가이드.md)
- 주의: 금액·확률·ID·모델 버전은 설계용 가상 예시임

## 표 작성 규칙

| 레이어 | ID | 제목 | 내용 작성 방식 |
|---|---|---|---|
| 화면·자동화 Trigger | `UT-{N}` 또는 `AT-{N}` | 사용자가 수행한 행동 또는 자동화 시작 조건 | `{조건 또는 행동}하면 {작업}이 시작됨` 형식의 Trigger 문장 |
| Command | `C-{N}` | 작업 이름 | 명령형 요청, 주요 입력 데이터, 담당자 유형 |
| Event | `E-{N}` | 결과 이름 | 과거형 발생 사실, 이후 단계가 참조할 결과 데이터 |

## 1장. 한 개 슬라이스의 기본 구조

- 도형 1: 화면·자동화 Trigger / `UT-1` / 상담 시작 선택
- 도형 2: Command / `C-1` / 문의 접수
- 도형 3: Event / `E-1` / 문의 접수
- 연결: `UT-1 → C-1 → E-1`
- 카드에는 ID와 제목만 표시
- 하단 안내: 세부 문장과 데이터는 다음 장부터 표의 내용 열에서 확인

## 2장. 전체 슬라이스 종합

- 상단: UT-1/C-1/E-1, AT-1/C-2/E-2, AT-2/C-3/E-3, AT-3/C-4/E-4, AT-4/C-5/E-5
- 하단: AT-5/C-6/E-6, AT-6/C-7/E-7, AT-7/C-8/E-8, AT-8/C-9/E-9, UT-2/C-10/E-10
- 각 슬라이스는 Trigger → Command → Event 세 개 도형으로 구성
- 각 도형에는 ID와 제목만 표시
- 안내: 가로 배치는 슬라이스 전체를 훑어보기 위한 구성임
- 안내: 병렬 실행과 선행 조건은 다음 장부터 표의 내용 열에서 확인

## 3장. 문의 접수와 실행 경로 결정

| 레이어 | ID | 제목 | 내용 |
|---|---|---|---|
| 화면·자동화 Trigger | UT-1 | 상담 시작 선택 | 상담사가 문의 접수 화면에서 상담 시작을 선택하면 문의 접수가 시작됨 |
| Command | C-1 | 문의 접수 | 요청: 문의를 접수하라 / 입력: 회원 ID, 상담 질문, 상담사 ID / 담당자 유형: 규칙 기반 코드 |
| Event | E-1 | 문의 접수 | 사실: 문의가 접수되었음 / 결과: 상담 ID, 접수 시각, 권한 확인 결과 |
| 화면·자동화 Trigger | AT-1 | 실행 경로 결정 시작 | ‘문의가 접수되었음’ Event가 발생하면 실행 경로 결정이 시작됨 |
| Command | C-2 | 실행 경로 결정 | 요청: 실행 경로를 결정하라 / 입력: 질문, 권한 확인 결과, 상담 제약 / 담당자 유형: 생성형 AI가 질문 해석 지원, 규칙 기반 코드가 경로 확정 |
| Event | E-2 | 실행 경로 결정 | 사실: 실행 경로가 정해졌음 / 결과: 선택 경로, 필수 여부, 대기시간, 선택 이유 |

## 4장. 정형검색과 유사도 검색의 병렬 시작

| 레이어 | ID | 제목 | 내용 |
|---|---|---|---|
| 화면·자동화 Trigger | AT-2 | 고객 현황 확보 시작 | E-2가 발생하고 C-3 경로가 선택되면 고객 현황 확보가 시작됨 |
| Command | C-3 | 고객 현황 확보 | 요청: 고객 현황을 확보하라 / 입력: 회원 ID, 조회 기준일 / 담당자 유형: 규칙 기반 코드 |
| Event | E-3 | 고객 현황 확보 | 사실: 고객 현황이 확보되었음 / 결과: 카드 ID, 상품 ID, 승인 사용액, 예측 특징, 출처, 기준시점 |
| 화면·자동화 Trigger | AT-3 | 문서 후보 확보 시작 | E-2가 발생하고 C-4 경로가 선택되면 문서 후보 확보가 시작됨 |
| Command | C-4 | 문서 후보 확보 | 요청: 문서 후보를 확보하라 / 입력: 질문, 회원 ID, 접근 범위 / 담당자 유형: 규칙 기반 코드 |
| Event | E-4 | 문서 후보 확보 | 사실: 문서 후보가 확보되었음 / 결과: 문서 ID, 관련 문단, 원문 위치, 버전 |

## 5장. 관계검색과 이탈 위험 예측의 병렬 시작

| 레이어 | ID | 제목 | 내용 |
|---|---|---|---|
| 화면·자동화 Trigger | AT-4 | 관계 경로 확보 시작 | E-2에서 C-5가 선택되고 E-3의 카드·상품 ID가 준비되면 관계 경로 확보가 시작됨 |
| Command | C-5 | 관계 경로 확보 | 요청: 관계 경로를 확보하라 / 입력: 회원 ID, 카드 ID, 상품 ID / 담당자 유형: 규칙 기반 코드 |
| Event | E-5 | 관계 경로 확보 | 사실: 관계 경로가 확보되었음 / 결과: 고객-카드-상품-문서 경로, 각 연결의 원천 |
| 화면·자동화 Trigger | AT-5 | 이탈 위험 예측 시작 | E-2에서 C-6이 선택되고 E-3의 예측 특징이 준비되면 이탈 위험 예측이 시작됨 |
| Command | C-6 | 이탈 위험 예측 | 요청: 이탈 위험을 예측하라 / 입력: 예측 특징, 예측 기간, 모델 버전 / 담당자 유형: 예측형 AI |
| Event | E-6 | 고객 이탈 위험 예측 | 사실: 고객 이탈 위험이 예측되었음 / 결과: 이탈 확률, 위험 등급, 판단 신호, 예측 기간, 모델 버전, 특징 기준시점 |

## 6장. 결과 취합과 초안 작성

| 레이어 | ID | 제목 | 내용 |
|---|---|---|---|
| 화면·자동화 Trigger | AT-6 | 근거 선정 시작 | 필수 E-3·E-4·E-5가 완료되고 보조 E-6이 완료 또는 보류되면 근거 선정이 시작됨 |
| Command | C-7 | 근거 묶음 선정 | 요청: 근거 묶음을 선정하라 / 입력: 실행 계획, E-3 ~ E-6 결과와 상태 / 담당자 유형: 규칙 기반 코드 |
| Event | E-7 | 근거 묶음 선정 | 사실: 근거 묶음이 선정되었음 / 결과: 근거 묶음 ID, 채택 근거, 제외 근거, 주의사항 |
| 화면·자동화 Trigger | AT-7 | 상담 초안 작성 시작 | ‘근거 묶음이 선정되었음’ Event가 발생하면 상담 초안 작성이 시작됨 |
| Command | C-8 | 상담 초안 작성 | 요청: 상담 초안을 작성하라 / 입력: 근거 묶음, 예측 결과 또는 상태, 고객 제약 / 담당자 유형: 생성형 AI가 초안 생성, 규칙 기반 코드가 검증·저장 |
| Event | E-8 | 상담 초안 작성 | 사실: 상담 초안이 작성되었음 / 결과: 초안 ID, 버전, 제안 내용, 근거 참조, 주의사항 |

## 7장. 초안 반환과 사람의 확인

| 레이어 | ID | 제목 | 내용 |
|---|---|---|---|
| 화면·자동화 Trigger | AT-8 | 초안 반환 시작 | E-8이 발생하고 화면 요청이 도착하면 초안 반환이 시작됨 |
| Command | C-9 | 초안 데이터 반환 | 요청: 초안 데이터를 반환하고 반환 이력을 기록하라 / 입력: 요청 ID, 상담 ID, 초안 ID, 초안 버전 / 담당자 유형: 규칙 기반 코드 |
| Event | E-9 | 초안 데이터 반환 | 사실: 초안 데이터가 반환되었음 / 결과: 요청 ID, 반환 초안 버전, 반환 시각, 반환 출처 |
| 화면·자동화 Trigger | UT-2 | 초안 확인 선택 | 상담사가 초안 검토 화면에서 확인을 선택하면 초안 확인 기록이 시작됨 |
| Command | C-10 | 초안 확인 기록 | 요청: 초안 확인 이력을 기록하라 / 입력: 상담 ID, 초안 ID, 초안 버전, 상담사 ID / 담당자 유형: 규칙 기반 코드 |
| Event | E-10 | 초안 확인 기록 | 사실: 초안 확인이 기록되었음 / 결과: 상담사 ID, 확인 초안 버전, 확인 시각 |

- 하단 안내: 저장된 초안을 다시 반환하면 E-9는 새로 생길 수 있으나, 새로 작성하지 않았다면 E-8은 반복하지 않음
