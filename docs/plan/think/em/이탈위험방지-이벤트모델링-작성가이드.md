# 이탈 위험 방지 사례로 따라 하는 Event Modeling 작성 가이드

[기존 이탈 위험 방지 예시](./이탈위험방지-이벤트모델링.md)를 이용해 모델을 직접 작성하는 가이드임.  
공식 7단계에 범위 정리와 완결성 점검을 더하고, 각 단계에서 작성할 결과를 표로 제시함.  
표는 완성된 **모델링 산출물 예시**이며, 실제 시스템 실행 결과나 구현 완료 증거가 아님.

## 먼저 알아둘 것

### 용어와 표 읽는 방법

| 용어 | 의미 | 이 사례의 예 |  
|---|---|---|  
| 레이어(Layer) | 요소의 종류를 구분하는 배치 영역 | 화면/자동화, 커맨드/읽기 모델, 이벤트 |  
| 스웜레인(Swimlane) | 같은 업무영역의 요소를 모으는 가로 방향 영역 | 상담 지원, 지식 관리 |  
| 담당자 유형 | 업무를 수행하는 주체의 유형 | 규칙 기반 코드, 예측형 AI, 생성형 AI, Human |  
| 커맨드(Command) | 처리하거나 기록할 작업을 요청하는 요소 | 초안을 작성하라 |  
| 읽기 모델(Read Model) | 화면이나 자동화에 필요한 정보를 구성하는 요소 | 제안 초안 조회 |  
| 이벤트(Event) | 발생한 사실 중 기록하기로 선택한 사실 | 초안이 작성되었음, 초안 데이터가 반환되었음 |  
| 업무 단계 | 이야기의 어느 지점에서 하는 일인지 구분 | 문의 접수, 초안 작성, 초안 조회 |  
| 슬라이스(Slice) | 입력부터 결과까지 하나의 동작을 설명하는 연결 | 화면 → 커맨드 → 이벤트 |  
| 사양(Specification) | 예시 입력에 대해 기대할 결과를 정한 조건 | Given·When·Then |

이 문서에서는 **스웜레인 이름을 업무영역으로 통일**함.  
`상담사`는 수행 역할이며 `Human`은 담당자 유형임. 둘을 업무영역인 `상담 지원`과 구분함.  
화면을 사용자 역할별로 나누는 표현도 가능하지만, 이 가이드에서는 역할을 카드 설명에 적음.  
레이어 하나에 여러 스웜레인이 있을 수 있으며, 같은 업무영역이 여러 레이어에 걸쳐 나타날 수 있음.  
이는 이 가이드의 배치 규칙이며, 모든 Event Modeling 도구가 동일한 배치를 요구한다는 뜻은 아님.

### 레이어별 설명

| 레이어 | 설명 | 담당자와의 관계 |  
|---|---|---|  
| 화면/자동화 | 업무를 시작하고 결과를 확인하는 접점 | 담당자가 요청을 보내거나 결과를 확인함 |  
| 커맨드/읽기 모델 | 요청할 작업과 보여 줄 정보의 구조를 정의 | 담당자가 받을 요청과 사용할 데이터의 형식을 정함 |  
| 이벤트 | 요청 처리 결과를 업무 사실로 기록 | 담당자가 요청을 처리한 뒤 발생한 사실을 남김 |  
| 사양〔연결 정보〕 | 요청과 결과가 맞는지 예시로 확인 | 담당자의 처리 결과를 판단할 기준을 정함 |

`요청을 처리하고 결과를 반환·기록`하는 것은 담당자의 역할임. 이벤트 카드 자체가 요청을 실행하지는 않음.  
사양은 커맨드 또는 읽기 모델에 붙이는 정보임. 별도 레이어처럼 표시해도 독립 실행 단계는 아님.  
모든 업무 단계에 모든 요소를 넣을 필요는 없으며, 한 업무 단계가 여러 슬라이스를 포함할 수 있음.

### 담당자 유형 표시 규칙

| 담당자 유형 | 의미 | 이 사례의 담당 업무 |  
|---|---|---|  
| 규칙 기반 코드 | 정해진 조건과 절차에 따라 수행 | 현황 조회, 접근 검사, 결과 기록, 색인 배치 제어 |  
| 예측형 AI | 학습한 모델로 수치·등급 등을 추정 | 이탈 위험 예측 후보. 현재 미연결 |  
| 생성형 AI | 제공된 입력을 바탕으로 문장 등의 내용 생성 | 제안 초안 생성 |  
| Human | 사람이 판단하거나 업무 수행 | 상담 문의 접수, 초안 검토, 제안 확정 |

한 업무에 여러 유형이 함께 참여할 수 있음. 결과 표에서는 `생성형 AI + 규칙 기반 코드`처럼 병기함.  
이벤트의 담당자 유형은 **그 사실을 발생시키는 업무의 담당자 유형**임.  
Human의 확정 판단이나 AI의 작성 결과를 전산에 저장하는 일은 규칙 기반 코드가 수행할 수 있음.  
사양의 담당자 유형은 사양 문서 작성자가 아니라 **검사 대상 업무의 담당자 유형**임.

### 실습 근거와 설계 예시 구분

정형 조회와 지식 검색 등 개별 실습 기능을 하나의 상담 흐름으로 통합하는 설계 예시임.  
상담 화면·이벤트 저장·반환 이력·확인 기록·CRM 연결이 실제로 구현되었다고 가정하지 않음.  
D3 상담 이력은 합성 자료이며, 아래 ID·금액·시각·문서 내용도 학습용 가상 값임.  
예측 모델은 미연결이며, 예측 확률·위험 등급을 만들지 않고 `확인 필요`로 표시함.  
이후 표의 기록 계약과 담당자 배정은 모두 설계 제안이며, 실제 적용 시 구현 여부를 별도 확인해야 함.

## 준비. 범위와 기준 사례 정하기 — 교육용 추가 단계

**목적:** 시작·끝·사전 준비·미연결 범위 확정.

**할 일**

1. 문의 접수부터 상담사의 초안 확인까지를 기본 범위로 정함.  
2. 색인 배치는 상담마다 실행하는 절차가 아니라 별도 사전 흐름으로 분리함.  
3. 제안 확정·실제 안내·반응 기록은 확장 가정으로 표시함.  
4. 같은 가상 상담을 끝까지 사용하도록 식별자와 기준 데이터를 정함.

**작성 결과 예시 — 범위표**

| 레이어 | 스웜레인 | 담당자 유형 | 범위 | 이번 모델의 결정 |  
|---|---|---|---|---|  
| 화면/자동화 | 상담 지원 | Human | 시작 | 상담사가 해지 문의 접수 |  
| 화면/자동화 | 상담 지원 | Human | 기본 종료 | 상담사가 초안 확인 버튼 선택 |  
| 화면/자동화 | 지식 관리 | 규칙 기반 코드 | 사전 준비 | 원문 준비 후 별도 색인 배치 실행 |  
| 화면/자동화 | 상담 지원 | Human | 확장 | 제안 확정·안내·반응 기록은 가정 |  
| 커맨드/읽기 모델 | 상담 지원 | 예측형 AI | 미연결 | 예측 담당 후보만 표시. 호출·산출 없음 |

모든 표는 상담 `S-104`, 가명 회원 `M-204`, 상담사 `A-07`을 기준으로 작성함.  
고객 문의는 `연회비가 부담돼서 해지하려고요`, 기준월은 `2026-08`, 사용액은 `420,000원`으로 설정함.  
기준일은 `2026-08-31`, 초안은 `DRAFT-01 / v1`, 선정 근거는 `R-01`로 설정함.

**완료 기준:** 기본 범위와 확장 가정이 구분되고, 모든 단계에서 같은 식별자를 사용함.

## 1단계. 기록할 이벤트 후보 모으기 — 공식 1단계: Brain Storming

**목적:** 업무에서 나중에 추적해야 할 사실 발굴.

**할 일**

1. 일어난 사실을 과거형으로 적고, 기록할 이유를 붙임.  
2. 생성·수정뿐 아니라 조회·반환·확인 이력도 후보에 포함함.  
3. 업무 추적에 필요한 사실을 선택하고, 단순 기술 로그는 필요에 따라 구분함.  
4. 아직 발생할 수 없는 사실은 제외함. 이 사례의 위험도 산출이 해당함.

**작성 결과 예시 — 이벤트 후보표**

| 레이어 | 스웜레인〔임시〕 | 담당자 유형 | ID·이벤트 후보 | 선택 이유 |  
|---|---|---|---|---|  
| 이벤트 | 지식 관리 | 규칙 기반 코드 | I-1 색인이 발행되었음 | 사용할 색인 버전 추적 |  
| 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-1 상담이 시작되었음 | 문의와 상담 ID 연결 |  
| 이벤트 | 상담 지원 | 규칙 기반 코드 | E-2 고객 현황이 확보되었음 | 상담 당시 현황 보존 |  
| 이벤트 | 상담 지원 | 규칙 기반 코드 | E-3 근거가 선정되었음 | 채택 근거와 출처 추적 |  
| 이벤트 | 상담 지원 | 생성형 AI + 규칙 기반 코드 | E-4 초안이 작성되었음 | 검증 후 채택한 초안 보존 |  
| 이벤트 | 상담 지원 | 규칙 기반 코드 | E-8 초안 데이터가 반환되었음 | 누구에게 어떤 버전을 반환했는지 추적 |  
| 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-9 초안 확인이 기록되었음 | 상담사의 명시적 확인 기록 |  
| 이벤트 | 상담 지원 | 예측형 AI〔미연결〕 | 위험도가 산출되었음〔제외〕 | 실제 산출이 없는 사실 |

스웜레인은 이 단계에서 임시 배정하며, 6단계에서 업무영역을 검토해 확정함.  
E-5·E-6·E-7은 앞선 가이드의 확정·안내·반응 기록 ID로 유지하고, 새 이력에는 E-8·E-9를 사용함.  
ID 번호는 시간 순서를 뜻하지 않으며, 기본 흐름에서 E-8·E-9가 E-5보다 먼저 발생할 수 있음.

**조회·반환 이벤트의 선택 기준**

초안 내용이 바뀌지 않아도 **반환 이력이라는 새로운 기록**이 생길 수 있음.  
캐시·체크포인트·DB 중 어디에서 읽었는지가 아니라, 반환 사실을 업무에서 추적할지가 선택 기준임.  
이 사례에서는 상담사에게 제공한 초안 버전을 추적하기 위해 E-8을 포함하기로 결정함.  
서버의 반환과 사람이 확인한 사실은 다르므로 E-8과 E-9를 분리함.  
E-9는 확인 버튼 선택을 기록한 사실이며, 사람이 내용을 완전히 이해했다는 보장은 아님.

**완료 기준:** 생성·반환·확인 이벤트가 구분되고, 각 후보의 선택·제외 이유가 있음.

## 2단계. 이벤트를 시간순으로 배치 — 공식 2단계: The Plot

**목적:** 같은 상담에서 이벤트가 어떤 순서로 연결되는지 확인.

**할 일**

1. 이벤트 ID와 별도로 발생 순서와 선행 조건을 적음.  
2. 사전 색인 배치와 상담 처리는 별도 흐름으로 놓음.  
3. 초안 작성·초안 반환·상담사 확인을 서로 다른 시점으로 구분함.

**작성 결과 예시 — 시간표**

| 순서 | 레이어 | 스웜레인 | 담당자 유형 | 이벤트 | 앞서 필요한 사실 |  
|---|---|---|---|---|---|  
| 별도 사전 | 이벤트 | 지식 관리 | 규칙 기반 코드 | I-1 색인 발행 | 원문과 색인 검증 완료 |  
| 1 | 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-1 상담 시작 | 인증된 상담사의 문의 접수 |  
| 2 | 이벤트 | 상담 지원 | 규칙 기반 코드 | E-2 현황 확보 | E-1과 회원 식별자 |  
| 3 | 이벤트 | 상담 지원 | 규칙 기반 코드 | E-3 근거 선정 | E-2와 사용 가능한 I-1 |  
| 4 | 이벤트 | 상담 지원 | 생성형 AI + 규칙 기반 코드 | E-4 초안 작성 | E-3과 현황, 예측 미연결 설정 |  
| 5 | 이벤트 | 상담 지원 | 규칙 기반 코드 | E-8 초안 반환 | E-4와 허용된 조회 요청 |  
| 6 | 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-9 확인 기록 | 반환된 초안에 대한 확인 입력 |  
| 확장 1 | 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-5 제안 확정 | 상담사의 확정 판단 |  
| 확장 2 | 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-6 제안 안내 | 실제 고객 안내 사실 |  
| 확장 3 | 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-7 반응 기록 | 고객 반응 입력 |

초안을 다시 조회하면 E-4 없이 E-8이 추가로 발생할 수 있음. 조회할 때마다 새로 작성된 것은 아님.  
동일 반환 건의 기록 재시도와 실제 새 조회는 요청 ID로 구분하는 계약을 제안함.

**완료 기준:** 배치가 매 상담에 포함되지 않고, 초안 작성과 반복 조회를 구분할 수 있음.

## 3단계. 화면과 자동화 배치 — 공식 3단계: The Story Board

**목적:** 누가 어디에서 요청을 시작하고 어떤 결과를 보는지 표시.

**할 일**

1. 업무영역별로 화면과 자동화 카드를 상단에 배치함.  
2. 화면을 사용하는 역할과 입력·출력 필드를 카드에 적음.  
3. 자동화에는 실행 조건을 적음. 없는 화면은 설계 가정으로 표시함.

**작성 결과 예시 — 화면·자동화 목록**

| 레이어 | 스웜레인 | 담당자 유형 | 카드·역할 | 입력 또는 표시 결과 |  
|---|---|---|---|---|  
| 화면/자동화 | 상담 지원 | Human | U-1 상담사 접수 화면 | M-204, 연회비 부담, 시작 버튼 |  
| 화면/자동화 | 상담 지원 | 규칙 기반 코드 | A-1 현황 확보 자동화 | S-104 시작됨, 현황 미확보 |  
| 화면/자동화 | 상담 지원 | Human | U-2 상담사 현황 화면 | 2026-08, 420,000원, 기준일 |  
| 화면/자동화 | 상담 지원 | 규칙 기반 코드 | A-2 근거 선정 자동화 | 현황·색인 존재, 근거 미선정 |  
| 화면/자동화 | 상담 지원 | 규칙 기반 코드 | A-3 초안 작성 자동화 | 근거 존재, 초안 미작성 |  
| 화면/자동화 | 상담 지원 | Human | U-3 상담사 초안 화면 | DRAFT-01/v1, R-01, 확인 버튼 |  
| 화면/자동화 | 지식 관리 | 규칙 기반 코드 | A-0 색인 배치 자동화 | 새 원문 존재, 직전 작업 종료 |

A-3의 담당자 유형은 실행 여부를 판단하는 코드 기준임. 초안을 실제로 만드는 담당자는 다음 단계에서 배정함.  
화면 사용자인 Human과 화면을 제공하는 코드를 혼동하지 않도록, 표의 담당자 관점을 카드·역할에 명시함.

**완료 기준:** 각 카드에 사용 역할 또는 자동 실행 조건과 실제 필드가 있음.

## 4단계. 요청과 담당자 연결 — 공식 4단계: Identify Inputs

**목적:** 어떤 요청을 누가 처리하고 어떤 사실을 기록할지 정의.

**할 일**

1. 화면·자동화에서 시작한 커맨드에 입력 필드를 적음.  
2. 커맨드별 담당자 유형과 성공 결과 이벤트를 연결함.  
3. 조회와 조회 이력 기록을 분리함. 읽기 모델 자체에 이력 저장 책임을 섞지 않음.  
4. 실패하면 성공 이벤트 대신 실패 상태와 다음 행동을 정의함.

**작성 결과 예시 — 요청 계약표**

| 레이어 | 스웜레인 | 담당자 유형 | 커맨드 | 입력 → 성공 결과 |  
|---|---|---|---|---|  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | C-1 상담을 시작하라 | M-204, 문의 → E-1/S-104 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | C-2 현황을 확보하라 | S-104, M-204 → E-2 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | C-3 근거를 선정하라 | S-104, 문의, 색인 버전 → E-3/R-01 |  
| 커맨드/읽기 모델 | 상담 지원 | 생성형 AI + 규칙 기반 코드 | C-4 초안을 작성하라 | 현황, R-01, 미연결 상태 → E-4 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | C-5 초안 반환 이력을 기록하라 | Q-301, A-07, DRAFT-01/v1 → E-8 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | C-6 초안 확인을 기록하라 | A-07의 확인, DRAFT-01/v1 → E-9 |  
| 커맨드/읽기 모델 | 지식 관리 | 규칙 기반 코드 | C-0 색인을 발행하라 | 검증된 색인 IDX-DEMO-01 → I-1 |

C-1·C-6의 요청자는 Human이고, 요청 검증과 전산 기록은 규칙 기반 코드가 담당함.  
C-4는 생성형 AI가 초안을 생성하고 코드가 검증·저장을 수행하는 협업 요청임.  
C-5는 새 초안 생성 요청이 아님. 기존 초안의 반환 사실을 추가 기록하는 별도 요청임.

**작성 결과 예시 — 초안 반환의 연결표**

| 순서 | 레이어 | 스웜레인 | 담당자 유형 | 연결 결과 |  
|---|---|---|---|---|  
| 1 | 화면/자동화 | 상담 지원 | Human | A-07이 DRAFT-01/v1 조회 요청 |  
| 2 | 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-3으로 기존 초안 데이터 구성 |  
| 3 | 화면/자동화 | 상담 지원 | 규칙 기반 코드 | 응답 처리 코드가 Q-301 반환 완료를 관측 |  
| 4 | 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | C-5에 요청자·버전·반환 시각 전달 |  
| 5 | 이벤트 | 상담 지원 | 규칙 기반 코드 | E-8 기록. 초안 내용은 변경 없음 |

여기서 `반환 완료`는 서버의 응답 전송 완료를 관측한 시점으로 정의함.  
클라이언트의 화면 표시나 사람의 확인을 뜻하지 않으며, 응답 전송 실패에는 E-8을 기록하지 않음.  
반환 후 기록에 실패하면 요청 ID Q-301로 이력 기록을 재시도하고 중복 기록을 막는 설계가 필요함.  
기록 재시도는 실제 응답 전송 완료를 확인한 건에만 적용함.

**완료 기준:** 요청자와 처리 담당자가 구분되고, 조회 슬라이스와 이력 기록 슬라이스가 연결됨.

## 5단계. 결과 데이터와 화면 연결 — 공식 5단계: Identify Outputs

**목적:** 어떤 정보가 반환되고, 그 정보와 반환 이력이 어디에서 왔는지 확인.

**할 일**

1. 화면 필드별 원천과 읽기 모델을 정의함.  
2. 실제 값과 자료 없음·미연결 상태를 구분함.  
3. 캐시·체크포인트를 읽더라도 초안 ID·버전을 유지하도록 정함.  
4. 반환 이력을 남길 때는 C-5와 E-8을 연결함. 모든 조회에 의무 적용하는 규칙은 아님.

**작성 결과 예시 — 읽기 모델 반환값**

| 레이어 | 스웜레인 | 담당자 유형 | 읽기 모델 | 결과 예시·원천 |  
|---|---|---|---|---|  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-1 고객 현황 | E-2 → 2026-08, 420,000원 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-1 고객 현황 | E-2 → 기준일 2026-08-31, 연체 값 없음 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-2 근거 목록 | E-3 → R-01, D2-DEMO 데모 2절 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-3 제안 초안 | E-4·E-3 → DRAFT-01/v1, 결론과 R-01 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-3 제안 초안 | E-4의 미연결 사유 → 예측값 확인 필요 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-4 초안 제공 이력 | E-8 → A-07, v1, 반환 시각 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | V-4 초안 제공 이력 | E-9 없음 → 명시적 확인 기록 없음 |

**작성 결과 예시 — 화면에 표시할 초안**

| 레이어 | 스웜레인 | 담당자 유형 | 화면 필드 | 표시 결과 |  
|---|---|---|---|---|  
| 화면/자동화 | 상담 지원 | Human | 결론 | 연회비 조건 확인 후 대안 상담 필요 |  
| 화면/자동화 | 상담 지원 | Human | 근거 | R-01: 연회비 조건 확인 필요 |  
| 화면/자동화 | 상담 지원 | Human | 출처 | 가상 문서 D2-DEMO, 데모 2절 |  
| 화면/자동화 | 상담 지원 | Human | 예측값 | 확인 필요〔예측 모델 미연결〕 |  
| 화면/자동화 | 상담 지원 | Human | 주의사항 | 실제 혜택 적용 여부 추가 확인 필요 |

위 문구는 학습용 가상 초안임. 실제 문서 내용이나 특정 카드의 혜택을 설명하는 문구가 아님.  
읽기 모델의 담당자는 데이터를 구성하는 코드이며, 화면의 담당자는 그 정보를 확인하는 상담사임.

**작성 결과 예시 — 생성·반환·확인 기록 비교**

| 레이어 | 스웜레인 | 담당자 유형 | 이벤트 | 저장할 값의 예 |  
|---|---|---|---|---|  
| 이벤트 | 상담 지원 | 생성형 AI + 규칙 기반 코드 | E-4 초안 작성 | DRAFT-01/v1, 내용, R-01, 10:00:00 |  
| 이벤트 | 상담 지원 | 규칙 기반 코드 | E-8 초안 반환 | Q-301, A-07, DRAFT-01/v1, 10:00:02 |  
| 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-9 확인 기록 | A-07, DRAFT-01/v1, 확인 입력, 10:00:10 |

시각은 모두 가상의 2026-09-22 KST 기준임. 실제 데이터에는 날짜·시간대를 함께 기록함.  
기존 초안을 반환하는 경우 E-4의 내용은 유지되고 E-8이 추가됨.  
E-8만 있으면 상담사가 받거나 읽었다고 단정하지 않고, E-9는 명시적 확인 입력이 있을 때만 생성함.

**완료 기준:** 반환 데이터와 이력 데이터의 원천이 구분되고, 내용 불변 상태에서도 이력 증가를 설명할 수 있음.

## 6단계. 업무영역별 스웜레인 확정 — 공식 6단계: Apply Conway's Law

**목적:** 각 요소가 속하는 업무영역을 정하고 담당자 유형과 구분.

**할 일**

1. 앞 단계의 임시 스웜레인을 독립적으로 책임질 업무영역으로 검토함.  
2. 레이어가 달라도 같은 업무영역에는 같은 이름을 사용함.  
3. 담당자 유형이 다르다는 이유만으로 스웜레인을 나누지 않음.  
4. DB·API·캐시라는 기술 구성요소만으로 업무영역을 만들지 않음.

**작성 결과 예시 — 레이어·스웜레인 배치표**

| 레이어 | 스웜레인 | 담당자 유형 | 배치할 카드 |  
|---|---|---|---|  
| 화면/자동화 | 지식 관리 | 규칙 기반 코드 | A-0 색인 배치 자동화 |  
| 화면/자동화 | 상담 지원 | Human | U-1 접수, U-2 현황, U-3 초안 확인 |  
| 화면/자동화 | 상담 지원 | 규칙 기반 코드 | A-1 현황, A-2 근거, A-3 초안 자동화 |  
| 커맨드/읽기 모델 | 지식 관리 | 규칙 기반 코드 | C-0 색인 발행 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | C-1 ~ C-3, C-5·C-6, V-1 ~ V-4 |  
| 커맨드/읽기 모델 | 상담 지원 | 생성형 AI + 규칙 기반 코드 | C-4 초안 작성 |  
| 이벤트 | 지식 관리 | 규칙 기반 코드 | I-1 색인 발행 |  
| 이벤트 | 상담 지원 | 규칙 기반 코드 | E-2 현황, E-3 근거, E-8 반환 |  
| 이벤트 | 상담 지원 | 생성형 AI + 규칙 기반 코드 | E-4 초안 작성 |  
| 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | E-1 시작, E-9 확인, 확장 E-5 ~ E-7 |

같은 레이어에서 `지식 관리`와 `상담 지원`은 서로 다른 스웜레인임.  
같은 레이어의 `상담 지원`이 여러 행으로 보이는 것은 담당자 유형을 구분해 적었기 때문임.  
이를 여러 스웜레인으로 해석하지 않으며, 스웜레인의 이름은 모두 `상담 지원`임.  
예측형 AI는 현재 미연결 표시만 유지하고, 위험 산출 이벤트를 추가하지 않음.  
사양은 다음 단계에서 대상 카드에 연결하며, 같은 업무영역 이름을 표에 표시함.

**완료 기준:** 스웜레인은 업무영역을, 담당자 유형은 수행 주체를 나타내며 둘을 혼용하지 않음.

## 7단계. 연결마다 사양 붙이기 — 공식 7단계: Elaborate Scenarios

**목적:** 어떤 조건에서 어떤 결과가 나와야 하는지 예시로 검사.

**할 일**

1. 사양 하나를 커맨드 하나 또는 읽기 모델 하나에 연결함.  
2. 커맨드는 Given·When·Then, 읽기 모델은 Given·Then으로 작성함.  
3. 반환 성공·실패·기록 재시도와 사용자 확인 유무를 구분함.  
4. 자료 없음·근거 없음·예측 미연결도 결과로 정의함.

**작성 결과 예시 — 커맨드 사양표**

`사양` 레이어 표시는 대상 카드에 연결된 검사 기준임.

| 레이어 | 스웜레인 | 담당자 유형 | 대상 | Given | When | Then |  
|---|---|---|---|---|---|---|  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-1 | 인증된 M-204, 문의 | 상담 시작 요청 | S-104와 E-1 기록 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-2 | S-104, 조회 성공 | 현황 확보 | E-2에 기준일 기록 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-2 | DB 조회 실패 | 현황 확보 | E-2 없음, 재시도 상태 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-3 | 검증 통과 0건 | 근거 선정 | 근거 없음 종료, E-3 없음 |  
| 사양 | 상담 지원 | 생성형 AI + 규칙 기반 코드 | C-4 | E-2·E-3, 예측 미연결 | 초안 작성 | E-4, 예측 수치 없음 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-5 | Q-301 반환 완료 | 반환 이력 기록 | E-8 1건, E-4 추가 없음 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-5 | Q-301 기록 완료 | 같은 기록 재시도 | E-8 중복 없음 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-5 | 응답 전송 실패 | 반환 이력 기록 요청 | 완료 증거 없음으로 거절 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | C-6 | A-07의 v1 확인 입력 | 확인 기록 | E-9에 사용자·버전 기록 |

**작성 결과 예시 — 읽기 모델 사양표**

| 레이어 | 스웜레인 | 담당자 유형 | 대상 | Given | Then |  
|---|---|---|---|---|---|  
| 사양 | 상담 지원 | 규칙 기반 코드 | V-1 | 2026-08 사용액 420,000원 | 기준월·금액·기준일 함께 반환 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | V-1 | 사용액 자료 없음 | 값 없음 반환. 0원으로 대체 금지 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | V-3 | 캐시의 DRAFT-01/v1, 접근 허용 | 저장된 v1 반환, 새 초안 생성 없음 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | V-3 | 예측 모델 미연결 | 확인 필요와 미연결 사유 반환 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | V-4 | E-8 존재, E-9 없음 | 반환 기록 있음, 확인 기록 없음 |

V-3은 반환할 데이터를 구성함. 이후 응답 처리 코드와 C-5가 반환 완료·이력 기록을 담당함.  
V-3의 결과가 생겼다는 사실만으로 E-8을 기록하지 않으며, 반환 완료 관측 조건을 별도로 확인함.  
근거 없음은 처리 완료 상태로 남기고 초안 생성 자동화를 종료함.  
현황 조회 실패는 정해진 재시도 한도 후 실패 종료·담당자 확인 상태로 바꾸는 계약을 제안함.  
재시도 한도와 구체 검증 기준은 실제 구현 전에 정할 항목임.

**완료 기준:** 사양별 대상이 하나로 특정되고, 반환·기록·확인과 실패 조건을 각각 검사할 수 있음.

## 마무리. 연결과 누락 점검 — Completeness Check 적용

**목적:** 결과 표만 읽어도 정보의 출발점·처리 담당·도착점을 추적할 수 있는지 점검.

**작성 결과 예시 — 완결성 점검표**

| 레이어 | 스웜레인 | 담당자 유형 | 점검 대상 | 모델 검토 결과 |  
|---|---|---|---|---|  
| 화면/자동화 | 상담 지원 | Human | 초안 화면의 출처 | V-3 → E-4·E-3 → R-01로 연결 |  
| 커맨드/읽기 모델 | 상담 지원 | 규칙 기반 코드 | 예측 안내 문구 | 미연결 상태에서 확인 필요 구성 |  
| 이벤트 | 상담 지원 | 규칙 기반 코드 | 반환 이력 | Q-301·A-07·v1·반환 시각 포함 |  
| 이벤트 | 상담 지원 | Human + 규칙 기반 코드 | 확인 기록 | 반환과 분리, 명시적 입력 필요 |  
| 이벤트 | 지식 관리 | 규칙 기반 코드 | 색인 발행 | 별도 배치의 I-1을 상담이 참조 |  
| 사양 | 상담 지원 | 규칙 기반 코드 | 이력 중복·반환 실패 | C-5의 별도 사양으로 연결 |

위 결과는 **문서 내 모델의 연결 확인**이며, 실제 기능 시험의 통과를 뜻하지 않음.  
적용할 때는 가상 값 교체, 데이터 계약·검증 기준 확정, 구현·시험을 별도로 수행해야 함.

다른 업무에 재사용할 때의 작성 순서는 다음과 같음.

1. 시작·종료·사전 준비·미연결 범위 정의.  
2. 생성·변경·조회·반환·확인 중 추적할 이벤트 선택.  
3. 시간순 배치 후 화면과 자동화 연결.  
4. 커맨드·읽기 모델별 요청·반환 데이터와 담당자 유형 지정.  
5. 업무영역별 스웜레인 확정.  
6. 각 결과 표에 레이어·스웜레인·담당자 유형 명시.  
7. 사양과 완결성 점검 수행.
