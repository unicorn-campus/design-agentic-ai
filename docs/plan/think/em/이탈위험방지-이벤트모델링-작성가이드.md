# 이탈 위험 방지 사례로 따라 하는 Event Modeling 작성 가이드

[기존 이탈 위험 방지 예시](./이탈위험방지-이벤트모델링.md)를 바탕으로 모델을 한 단계씩 만드는 가이드임.  
공식 7단계 앞에 범위 정리, 뒤에 완결성 점검을 추가함. 단계별 이미지는 설계 결과의 예시임.  
실제 화면·이벤트 저장소·반환 이력의 구현이나 시험 통과를 보여 주는 자료는 아님.

## 먼저 알아둘 것

**레이어**는 카드의 종류를 구분하는 배치 영역임. 이 가이드에서는 화면/자동화, 커맨드/읽기 모델,  
이벤트를 구분하고, 사양은 연결된 카드에 붙임. 화면/자동화는 업무 시작과 결과 확인,  
커맨드/읽기 모델은 요청과 반환 데이터의 구조, 이벤트는 처리 후 남길 사실을 표현함.  
요청을 처리하고 결과를 반환·기록하는 주체는 담당자이며, 이벤트 카드가 직접 처리하지 않음.

**스웜레인**은 같은 업무영역의 카드를 모은 가로 영역임. 이 사례에서는 상담 지원과 지식 관리가 그 이름임.  
**담당자 유형**은 수행 주체의 종류로, 규칙 기반 코드·예측형 AI·생성형 AI·Human의 네 가지임.  
예를 들어 상담 지원 스웜레인에 Human이 쓰는 화면과 생성형 AI가 참여하는 초안 작성 카드가 함께 놓임.  
같은 업무영역이 여러 레이어에 걸쳐 나타날 수 있으며, 담당자 유형이 달라도 스웜레인은 그대로임.

**업무 단계**는 문의 접수·초안 작성처럼 이야기의 시점임.  
**슬라이스**는 입력부터 결과까지 하나의 동작을 설명하는 카드와 연결의 묶음임. 업무 단계 하나에 여러 슬라이스가 들어갈 수 있음.  
모든 단계에 모든 레이어나 담당자 유형을 채울 필요는 없음. 필요한 카드와 관계만 표시함.

이 가이드의 ID와 값은 일관된 설명을 위한 가상 예시임. 상담은 S-104, 가명 회원은 M-204,  
상담사는 A-07, 초안은 DRAFT-01/v1, 근거는 R-01, 반환 요청은 Q-301로 설정함.  
고객 문의는 “연회비가 부담돼서 해지하려고요”, 2026-08 사용액은 420,000원, 기준일은 2026-08-31임.  
D3 상담 이력은 합성 자료이며, 가상의 금액·근거 문구를 실제 고객 정보나 상품 조건으로 해석하지 않음.  
예측형 AI는 현재 미연결이므로 위험 확률·등급은 없고 예측값은 “확인 필요”로 표시함.

## 준비. 범위와 기준 사례 정하기 — 교육용 추가 단계

**목적:** 한 상담의 시작과 끝, 별도 준비 작업, 이번에 다루지 않는 일을 먼저 결정.

**할 일**

1. 기본 흐름을 해지 문의 접수부터 상담사의 초안 확인까지로 한정함.  
2. 색인 배치는 매 상담 전에 반복하는 동작이 아닌 별도 사전 흐름으로 둠.  
3. 제안 확정·고객 안내·반응 기록은 확장 가정으로 표시함.

**결과 예시 — 범위 지도**

![기본 상담 흐름과 별도 색인 배치, 확장 범위를 나눈 범위 지도](./images/event-modeling-guide/00-scope.png)

**읽는 법**

- 기본 흐름의 시작은 상담사의 문의 접수, 끝은 초안에 대한 명시적 확인 입력임.  
- 지식 관리의 색인 발행은 상담과 다른 시계에서 진행되며, 상담에서는 발행된 버전을 참조함.  
- 상담 화면, 반환 이력, 확인 기록, 확장 흐름은 설계 가정이며 현재 구현 여부가 확인되지 않음.

**완료 기준:** 기본 범위, 사전 준비, 확장 가정, 미연결 기능을 서로 구분 가능.

## 1단계. 기록할 이벤트 후보 모으기 — 공식 1단계: Brain Storming

**목적:** 나중에 업무에서 추적할 사실을 순서와 무관하게 수집.

**할 일**

1. “무엇이 일어났음”처럼 과거형으로 쓰고, 기록할 이유를 덧붙임.  
2. 생성·변경뿐 아니라 조회·반환·확인 이력도 후보로 올림.  
3. 선택·보류·제외를 표시하고, 실제로 발생할 수 없는 사실은 제외함.

**결과 예시 — 순서 없는 이벤트 후보**

![선택·보류·제외로 나눈 이탈 위험 방지 이벤트 후보 카드](./images/event-modeling-guide/01-events.png)

**읽는 법**

- 선택: I-1 색인 발행, E-1 상담 시작, E-2 현황 확보, E-3 근거 선정, E-4 초안 작성,  
  E-8 초안 데이터 반환, E-9 초안 확인 기록임. 이 단계의 카드 배열은 시간 순서가 아님.  
- E-8은 상담사에게 제공한 초안 버전을 추적하기 위한 선택임. 캐시·체크포인트·DB 중 어디서 읽었는지는  
  선택 이유가 아님. E-9는 Human의 확인 버튼 입력으로 생성되며, E-8만으로는 생성하지 않음.  
- “위험도가 산출되었음”은 예측형 AI 미연결로 제외함. 화면 새로고침은 업무 기록 목적을 확인할 때까지 보류함.

**완료 기준:** 이벤트마다 선택 이유 또는 보류·제외 이유가 있고, 반환과 확인을 별개 사실로 설명 가능.

## 2단계. 이벤트를 시간순으로 배치 — 공식 2단계: The Plot

**목적:** 각 이벤트의 앞뒤 조건과 별도 흐름을 드러냄.

**할 일**

1. 한 상담의 이벤트를 발생 순서로 놓고 선행 조건을 확인함.  
2. I-1 색인 발행은 별도 배치 선에 두고, 상담이 참조하는 관계만 연결함.  
3. 저장된 초안을 재조회했을 때 새로 생기는 이력을 추가함.

**결과 예시 — 이벤트 시간축**

![색인 배치와 상담 흐름을 나누고 초안 재조회까지 표시한 이벤트 시간축](./images/event-modeling-guide/02-timeline.png)

**읽는 법**

- 기본 순서는 E-1 → E-2 → E-3 → E-4 → E-8 → E-9임. E-3은 사용 가능한 I-1을 참조함.  
- 저장된 DRAFT-01/v1을 다시 제공하면 새 E-8이 생길 수 있으나 E-4는 다시 생기지 않음.  
- E-5 제안 확정, E-6 실제 안내, E-7 반응 기록은 기본 종료 뒤의 확장 가정임.  
  ID 번호는 시간 순서를 뜻하지 않으므로 E-8·E-9가 E-5보다 앞설 수 있음.

**완료 기준:** 색인 배치와 상담을 구분하고, 작성·반환·재조회·확인 시점을 따로 표시 가능.

## 3단계. 화면과 자동화 배치 — 공식 3단계: The Story Board

**목적:** 사람이 어느 화면에서 시작하고, 어떤 조건에서 자동으로 다음 일이 시작되는지 표시.

**할 일**

1. 상담사가 입력·확인할 화면을 실제 필드가 있는 간단한 그림으로 만듦.  
2. 자동화에는 시작 조건을 적고, 사람의 선택과 구분함.  
3. 아직 없는 화면은 설계 가정으로 표시함.

**결과 예시 — 상담 화면과 자동 트리거**

![상담 접수·현황·초안 화면 와이어프레임과 자동 트리거](./images/event-modeling-guide/03-storyboard.png)

**읽는 법**

- U-1은 M-204의 문의를 받고 상담사가 시작 버튼을 누르는 화면임. U-3은 DRAFT-01/v1과  
  R-01 출처, 예측값 “확인 필요”, 확인 버튼을 보여 주는 가상 화면임.  
- A-1은 상담 시작 후 현황 미확보, A-2는 현황 확보 후 근거 미선정, A-3은 근거 선정 후  
  초안 미작성 상태가 각각 충족될 때 시작하는 규칙 기반 코드의 자동화임.  
- 색인 배치 A-0은 지식 관리의 별도 자동화임. 화면 사용자는 Human이지만 자동 트리거는 코드가 담당함.

**완료 기준:** 화면에 사용자·입력·출력 필드가 있고, 자동화마다 실행 조건이 있음.

## 4단계. 요청과 담당자 연결 — 공식 4단계: Identify Inputs

**목적:** 시작 트리거에서 처리 요청을 거쳐 결과 이벤트까지의 연결을 그림.

**할 일**

1. 커맨드에 필요한 입력을 쓰고 요청자와 처리 담당자를 구분함.  
2. 성공 시 남는 이벤트를 잇고, 실패 시 성공 이벤트를 남기지 않는 조건을 정함.  
3. 초안 생성과 기존 초안 반환 이력 기록을 서로 다른 요청으로 둠.

**결과 예시 — 상담 시작·초안 작성·확인 기록의 요청 연결**

![시작 트리거에서 상담 시작·초안 작성·확인 기록 커맨드와 이벤트까지의 연결](./images/event-modeling-guide/04-commands.png)

**읽는 법**

- A-3의 조건 충족 → C-4 “초안을 작성하라” → E-4 “초안이 작성되었음” 순서임.  
  C-4에는 E-2 현황, E-3의 R-01, 예측 미연결 상태가 입력됨.  
- C-4에서는 생성형 AI가 문장을 만들고 규칙 기반 코드가 검증·채택·저장을 담당함.  
  상단 카드의 Human은 상담을 시작하거나 초안을 확인하는 주체이고, 예측형 AI는 미연결임.  
- C-5는 응답 전송 완료가 관측된 Q-301의 반환 이력을 E-8로 기록함.  
  C-6은 A-07의 명시적 확인 입력을 E-9로 기록함. 전송 실패 때는 E-8을 남기지 않음.

**완료 기준:** 각 커맨드의 입력·담당자 유형·성공 이벤트와 실패 조건을 따라갈 수 있음.

## 5단계. 결과 데이터와 화면 연결 — 공식 5단계: Identify Outputs

**목적:** 화면에 표시한 각 값의 출처와 반환·확인 이력의 차이를 확인.

**할 일**

1. 이벤트에서 읽기 모델을 거쳐 화면 필드로 이어지는 경로를 그림.  
2. 자료 없음·예측 미연결 상태를 실제 수치와 구분함.  
3. 조회 데이터 구성, 응답 반환, Human의 확인을 다른 동작으로 표시함.

**결과 예시 — 읽기 모델과 초안 화면**

![이벤트에서 읽기 모델을 거쳐 화면에 표시되고 반환·확인이 기록되는 흐름](./images/event-modeling-guide/05-read-models.png)

**읽는 법**

- E-2 → V-1은 기준월·420,000원·기준일을, E-3 → V-2는 R-01과 가상 출처를 구성함.  
  E-4·E-3 → V-3은 DRAFT-01/v1의 결론·근거·출처·주의사항을 구성함.  
- V-3이 캐시·체크포인트의 기존 초안을 읽어도 초안 버전은 유지됨.  
  반환 완료가 관측되면 C-5가 E-8을 남기고, V-4가 반환 이력을 표시할 수 있음.  
- E-8은 서버 응답 전송 완료의 기록임. 화면 표시나 사람이 읽었다는 증거는 아님.  
  E-9는 A-07이 확인 버튼을 눌렀을 때만 남음. 예측값은 “확인 필요”이며 위험 수치가 아님.

**완료 기준:** 화면 값마다 원천이 있고, E-4 작성·E-8 반환·E-9 확인을 서로 혼동하지 않음.

## 6단계. 업무영역별 스웜레인 확정 — 공식 6단계: Apply Conway's Law

**목적:** 누적한 카드를 책임질 업무영역에 배치하고 레이어와 담당자 유형을 함께 확인.

**할 일**

1. 임시 업무영역을 검토해 지식 관리와 상담 지원 스웜레인을 확정함.  
2. 앞 단계의 화면·자동화·커맨드·읽기 모델·이벤트를 해당 레이어에 배치함.  
3. 처리 기술만 다르다는 이유로 새 스웜레인을 만들지 않음.

**결과 예시 — 누적 모델의 레이어·스웜레인**

![상담 지원과 지식 관리 스웜레인에 누적 카드를 레이어별로 배치한 모델](./images/event-modeling-guide/06-swimlanes.png)

**읽는 법**

- 한 레이어 안에 지식 관리와 상담 지원 스웜레인이 나란히 존재할 수 있음.  
  I-1은 지식 관리 이벤트, E-1 ~ E-4·E-8·E-9는 상담 지원 이벤트임.  
- C-4의 생성형 AI + 규칙 기반 코드, U-3의 Human은 담당자 유형 배지로 표시함.  
  담당자 유형이 달라도 두 카드는 상담 지원 업무영역에 속함.  
- DB·LLM API·캐시는 연결 대상이나 저장 수단일 수 있음. 이 이름만으로 별도 업무영역을 만들지 않음.  
  미연결 예측형 AI에는 위험 산출 이벤트를 놓지 않음.

**완료 기준:** 카드의 레이어·업무영역·담당자 유형을 그림에서 읽을 수 있고 서로 다른 개념으로 설명 가능.

## 7단계. 연결마다 사양 붙이기 — 공식 7단계: Elaborate Scenarios

**목적:** 같은 요청이 주어진 조건에 따라 어떤 결과를 내야 하는지 검사 기준 작성.

**할 일**

1. 사양 하나를 커맨드 또는 읽기 모델 카드 하나에 연결함.  
2. 커맨드는 Given·When·Then, 읽기 모델은 Given·Then으로 적음.  
3. 정상·자료 없음·전송 실패·중복 재시도 같은 경계 사례를 포함함.

**결과 예시 — 생성·재시도·조회 사양 카드**

![초안 작성 성공·반환 이력 재시도·확인 유무 조회의 사양 카드](./images/event-modeling-guide/07-specifications.png)

**읽는 법**

- 왼쪽은 C-4의 성공 사양임. 현황·근거가 있고 예측 모델이 미연결일 때 초안을 작성하면,  
  E-4에 초안·근거를 기록하고 예측 수치는 만들지 않음.  
- 가운데는 C-5의 재시도 사양임. Q-301의 E-8이 이미 있을 때 같은 기록을 재시도해도,  
  E-8은 1건으로 유지하고 새 E-4를 만들지 않음.  
- 오른쪽은 V-4의 읽기 사양임. E-8은 있고 E-9는 없으면 “반환 기록 있음 / 확인 기록 없음”을 반환함.  
  전송 실패에 E-8을 남기지 않는 사양이나 근거가 없을 때의 사양도 같은 방법으로 추가함.

**완료 기준:** 사양의 대상 카드가 분명하고, 성공·실패·재시도를 서로 다른 입력으로 검사 가능.

## 마무리. 연결과 누락 점검 — Completeness Check 적용

**목적:** 화면 값과 기록의 출발점·처리·도착점을 역으로 추적해 모델의 빈 곳 확인.

**할 일**

1. 초안 화면의 필드에서 읽기 모델과 원천 이벤트까지 거슬러 올라감.  
2. 요청 ID·버전·시각 등 이력 필드와 실패·중복 처리 조건을 점검함.  
3. 모델의 연결 확인과 실제 구현·시험 결과를 별도로 표시함.

**결과 예시 — 필드 출처 역추적**

![초안 화면 필드의 출처와 반환·확인 기록의 누락을 점검하는 그림](./images/event-modeling-guide/08-completeness.png)

**읽는 법**

- 결론·주의사항은 V-3 → E-4, 근거·출처는 V-3 → E-3 → R-01로 역추적함.  
  예측값 “확인 필요”는 미연결 상태에 따른 고정 표시이며 예측 결과 이벤트는 없음.  
- 반환 이력은 Q-301·A-07·DRAFT-01/v1·반환 시각과 E-8을 확인함.  
  확인 기록은 별도 Human 입력과 E-9가 있어야 함. I-1은 색인 버전 출처로 연결함.  
- 이 점검은 문서 안의 모델 연결 확인임. 가상 값 교체, 계약 확정, 구현·기능 시험은 아직 별도 작업임.

**완료 기준:** 표시 값과 기록의 출처를 추적 가능하고, 남은 가정·미연결·미구현 항목이 드러남.

## 출처와 적용 범위

공식 7단계와 기본 패턴을 참고함. 업무영역 중심 스웜레인과 네 가지 담당자 유형은 이 가이드의  
작성 규칙임. 초안 반환·확인 이력은 이 사례에서 선택한 기록 계약이며 모든 조회의 의무 규칙은 아님.  
E-8의 “반환 완료”는 서버 응답 전송 완료 관측으로 정의함. 클라이언트 표시나 Human의 확인과 구분함.  
기록 재시도는 전송 완료를 확인한 요청 ID에만 적용하며, 구체 관측 방식은 구현 시 확정 필요.
