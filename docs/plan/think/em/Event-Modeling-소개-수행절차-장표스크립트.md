# Event Modeling 소개·수행 절차 장표 스크립트

## 구성

- 대상: Event Modeling을 처음 접하는 논리 설계 참여자
- 분량: 개요 1장 + 단계 설명 3장, 총 4장
- 사례: 카드 해지를 고민하는 고객 M-204의 상담 S-104
- 색상·글꼴: 기존 개요 장표의 네이비·블루·흰색과 Pretendard 유지
- 자료: [이탈위험방지 Event Modeling 작성가이드](./이탈위험방지-이벤트모델링-작성가이드.md)
- 주의: GUIDE-DEMO와 CHURN-DEMO의 수치는 설계용 가상 예시임

## 1장. Event Modeling 개요

- 한 문장: 업무에서 일어난 사실을 시간순으로 놓고, 요청과 화면에 필요한 정보를 연결하는 설계 방법
- 사례: 상담에서 ‘초안 작성’, ‘초안 반환’, ‘상담사 확인’을 서로 다른 사실로 기록
- 수행 절차: 이벤트 후보 → 시간표 → 화면 → 커맨드 → 읽기 모델 → 스웜레인 → 사양
- 시작 전: 상담 범위와 문서 색인 같은 별도 준비 작업 구분
- 마지막: 화면 값의 출처를 이벤트까지 거슬러 확인

## 2장. 1~2단계: 사건 수집과 시간표

- 1단계 핵심: 나중에 추적할 사실을 과거형 이벤트로 수집
- 사례: E-8 초안 작성, E-9 초안 데이터 반환, E-10 상담사 확인은 각각 별개임
- 2단계 핵심: 한 상담에서 가능한 기록 순서로 이벤트 배열
- 상담 흐름: E-1 문의 접수부터 E-10 상담사 확인까지 표시
- 별도 흐름: 문서 색인과 관계 자료 준비 완료 I-1은 상담 전 작업임
- 주의: 이벤트 번호는 병렬 실행이나 선행 조건을 강제하지 않음

## 3장. 3~5단계: 화면·요청·결과 연결

- 3단계: U-1 문의 접수, U-2 고객 현황, U-3 초안 검토에서 입력·표시 항목 정함
- 4단계: C-2가 질문에 따라 정형 C-3, 벡터 C-4, 그래프 C-5, 예측 C-6 경로 선택
- 실행 조건: C-3과 C-4는 함께 시작 가능. C-5와 C-6은 C-3의 결과가 필요함
- 5단계: 필수 C-3·C-4·C-5 결과와 보조 C-6 완료·보류 상태를 C-7에서 취합
- 결과 연결: C-7 근거 묶음 R-01 → C-8 초안 DRAFT-01 → V-3 읽기 모델 → U-3 화면
- 주의: 예측값은 정책 근거와 분리. 데이터 반환 E-9와 사람 확인 E-10도 구분

## 4장. 6~7단계: 책임·사양·설계 입력

- 6단계: 스웜레인 행은 문의·결과 제공, 고객 정보, 지식·관계, 상담 판단 업무영역
- 6단계: 열은 접수·라우팅·조회/예측·취합/작성·반환/확인 같은 업무 진행 단계
- 레이어: 화면/자동화, 커맨드/읽기 모델, 이벤트, 사양을 카드의 종류로 구분
- 7단계: 사용액만 질문, 예측 5초 초과, 필수 관계 검색 실패, 캐시 반환을 사례로 검증
- 설계 입력: 스웜레인에서 내부 서비스 후보를 찾고 외부 시스템과 외부 사용자를 별도 식별
- 외부 사용자: 상담사 A-07은 직접 사용자, 고객 M-204는 이번 범위의 간접 참여자
