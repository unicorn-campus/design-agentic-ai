# 신용카드사 Help Desk 이벤트스토밍 요약

## 1. 범위

교육용 아키텍처 설계 입력물이며 워크플로우는 아래 3건으로 한정함.

| ID | 워크플로우 | 트리거 | 성공 결과 | 최종 실패 처리 |
|---|---|---|---|---|
| `W-01` | 고객 문의 동기 처리 | 인증된 고객의 문의 1건 | 근거가 표시된 답변 또는 상담사 인계 | 안전 안내 후 상담사 이관 |
| `W-02` | 상담 지식 개선 배치 | 매일 02:00 | 전일 상담 기반 FAQ 개선 후보 등록 | 재시도 1회 후 운영자 알림 |
| `W-03` | 상담 종료 이벤트 처리 | `상담이 종료되었음` 이벤트 | 마스킹된 CRM 기록과 설문 발송 결과 | 격리 큐 저장 후 운영자 재처리 |

## 2. 역할 명부

| 역할 ID | 분류 | 책임 | 실행 근거 |
|---|---|---|---|
| `R-L1` | `LLM` | 문의 해석, 가변 질의 작성, 근거 종합, 요약 초안 | L2 비정형 해석·L3 재구성 필요 |
| `R-D1` | `Deterministic` | 고정 입력으로 긴급도·민원 위험 점수 산출 | 예측형 AI, LLM 호출 0회 |
| `R-D2` | `Deterministic` | 권한·입력 검사, 고정 쿼리, SQL 검사, 외부 호출, 승인된 쓰기 | 규칙·코드 완결, LLM 호출 0회 |
| `R-H1` | `Human` | 고위험 답변 검토, FAQ 승인, CRM 기록 예외 재정의 | 사전 승인·진행 중 중단·사후 재정의 |

`R-D1`의 교육용 모델명은 `상담 위험 예측 모델`임. 입력은 문의 유형, 감정 지표, 반복 문의 횟수,
거래 영향 여부이며 출력은 `risk_score` 0.00 ~ 1.00과 `priority_class`임. 0.80 이상은 사람에게 이관함.

## 3. 이벤트스토밍 공통 요소

| 요소 | 내용 |
|---|---|
| 액터 | 고객, 상담사·검토자, 운영자 |
| 애그리게이트 | 문의 세션, 지식 개선 후보, 상담 기록 |
| 외부 시스템 | 고객·카드 조회계, 분석 뷰, 지식 저장소, 관계 그래프, 공식 웹·영상, CRM, 설문 시스템 |
| 공통 정책 | 최소권한, 읽기 전용 조회, 민감정보 제거, 근거 표시, 확률적 결과의 직접 상태 변경 금지 |
| 외부 문자열 | `<untrusted_contents>`로 격리 후 허용 필드·길이·문자 형식 검사 |

## 4. `W-01` 고객 문의 동기 처리

### 이벤트 흐름

| 단계 | 주책임 | 커맨드 → 과거형 이벤트 | 규칙·지식 | 입출력 | 성공·실패 처리 |
|---|---|---|---|---|---|
| `S-R1` | `R-D2` | 문의를 접수하라 → `문의가 접수되었음` | `K-ST-FQ-01`, LLM 0회 | 인증 세션·문의 → 허용 고객 상태 | 1초 내 조회, 실패 시 1회 재시도 후 이관 |
| `S-R2` | `R-L1` | 문의를 해석하라 → `문의가 해석되었음` | `K-GLS-01`, LLM 1회, L2 | 문의 → 대표어·의도·누락 정보 | 중의어면 고객 확인, 2회 실패 시 이관 |
| `S-R3` | `R-L1` | 분석 SQL 작성 → `SQL이 작성되었음` | `K-ST-NL-01`, LLM 1회, L2 | 질문 → SQL 후보 | 모호·금지 열이면 1회 재작성 |
| `S-R4` | `R-D2` | SQL 검사·실행 → `결과가 조회되었음` | `SELECT`·100행, LLM 0회 | SQL → 조회 결과 | 위반 차단, 시간 초과 1회 재시도 |
| `S-R5` | `R-L1` | 내부 근거 검색 → `근거가 검색되었음` | 의미·관계·온톨로지, LLM 1회 | 의도 → 문단·관계 | 근거 없음·상충 시 이관 |
| `S-R6` | `R-D2` | 외부 근거 조회 → `근거가 조회되었음` | 웹·영상, LLM 0회 | 검색어 → 출처 | 비공식·기간 초과·자막 없음 폐기 |
| `S-R7` | `R-D1` | 상담 위험도를 산출하라 → `상담 위험도가 산출되었음` | 예측형 AI, LLM 0회 | 고정 특성 → 점수·우선순위 | 500ms 초과·오류 시 고위험으로 처리 |
| `S-R8` | `R-L1` | 근거 답변을 작성하라 → `답변 초안이 작성되었음` | 전체 근거, LLM 1회, L3 | 검증 결과·근거 → 답변 초안 | 근거 없는 문장 발견 시 1회 재작성 |
| `S-R9` | `R-H1` | 고위험 답변을 검토하라 → `답변이 승인되었음` | 점수 0.80 이상·근거 상충 | 초안·근거·점수 → 승인·수정·중단 | 10분 미응답 시 자동 안내 후 대기열 유지 |
| `S-R10` | `R-D2` | 답변을 전달하라 → `고객 답변이 전달되었음` | 승인·출처·마스킹 검사, LLM 0회 | 승인 답변 → 고객 응답·감사 로그 | 전송 1회 재시도 후 상담사 이관 |

사람 개입은 `S-R9`의 진행 중 중단·사후 재정의임. 저위험이면서 근거와 규칙 검사를 모두 통과하면
`S-R9`를 생략하되 카드 상태·한도·보상 변경은 수행하지 않음.

### 용어사전과 온톨로지 예시

| 구분 | 교육용 예시 |
|---|---|
| 대표어·동의어 | `승인 거절` ← 결제 거절, 승인 실패 / `청구 이의` ← 결제 이의, 부인 청구 |
| 코드 정규화 | `DECLINED`, `D01` → `승인 거절`; 충돌 시 원천 시스템과 상담사 확인 |
| 노드 타입 | 고객, 카드, 상품, 거래, 가맹점, 문의, 분쟁, 수수료 |
| 방향 관계 | 고객→보유→카드, 카드→연결→상품, 거래→발생처→가맹점, 문의→관련→거래, 분쟁→대상→거래 |
| 개념 계층 | 문의 > 결제 문의 > 승인 거절 문의 / 분쟁 > 청구 이의 / 비용 > 수수료 > 해외이용 수수료 |

용어사전은 모든 지식 경로의 정규화 계층이며 독립 검색 경로가 아님. 온톨로지는 `K-REL-01`의
그래프 스키마·개념 계층이며 독립 검색 경로가 아님.

### 외부정보 계약

웹 결과는 `source_url`, `title`, `retrieved_at`, `content_excerpt`를 필수로 저장함. 영상 결과는
`transcript_range`를 추가함. 외부 결과는 아래처럼 지시문과 분리함.

```xml
<untrusted_contents source_url="..." title="..." retrieved_at="...">
  허용 길이로 자른 웹 본문 또는 공식 영상 자막 구간
</untrusted_contents>
```

카드번호, CVC, 주민등록번호, 인증 토큰은 검색어와 모델 입력에서 제거함. 외부정보만으로 권리, 금액,
카드 상태를 변경하지 않음.
