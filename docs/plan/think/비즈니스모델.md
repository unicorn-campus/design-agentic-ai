# 신용카드사 Help Desk 비즈니스 모델

## 0. 문서 목적과 교육용 가정

본 문서는 Agentic AI 아키텍처 설계 교육에 사용하는 최소 기획 입력물임.  
실제 카드사 정책·상품·법률을 확정하지 않으며 모든 수치는 교육용 가정임.

| 가정 ID | 교육용 가정 | 근거 상태 |
|---|---|---|
| `BM-A01` | 월 문의 100,000건, 피크 분당 200건 | 교육용 가정 승인됨 |
| `BM-A02` | 월 운영비 20,000,000원 이하, 문의당 200원 이하 | 교육용 가정 승인됨 |
| `BM-A03` | 고객 인증은 Help Desk 진입 전에 완료됨 | 교육용 가정 승인됨 |
| `BM-A04` | 조회는 읽기 전용이며 카드 상태·한도·보상은 자동 확정하지 않음 | 기본안 승인됨 |
| `BM-A05` | 웹·영상은 카드사·금융당국·공공기관의 공식 출처만 사용함 | 기본안 승인됨 |

## 1. Lean Canvas

### `BM-P01` Problem — 문제

- 고객이 카드 이용 거절, 청구 내역, 혜택 조건을 이해하기 어려움
- 상담사가 정형 조회·문서·관계·외부정보를 각각 찾아 첫 답변이 늦어짐
- 상담 기록 분석과 지식 개선이 수작업이라 반복 문의 대응이 느림
- 현재 대안은 정적 FAQ, 상담사 수기 검색, 부서별 보고임

### `BM-C01` Customer Segments — 고객군

- 주요 고객: 카드 이용 문제의 원인과 다음 행동을 빠르게 확인하려는 개인 고객
- 내부 사용자: 상담사, Help Desk 운영자, 지식·준법 검토자
- 초기 적용 범위: 이용 거절·청구 내역·혜택·분쟁 절차의 조회와 안내
- 고객 과업: 근거 있는 답변을 받고 필요한 경우 맥락을 유지한 채 상담사에게 연결되는 일

### `BM-U01` Unique Value Proposition — 고유 가치

- 핵심 가치: 승인된 내부 지식과 고객별 읽기 전용 정보를 연결한 근거 중심 답변
- 한 줄 개념: 신용카드 상담을 위한 안전한 지식 내비게이션

### `BM-S01` Solution — 해결책

- `W-01` 고객 문의 동기 처리: 문의 해석, 지식 경로 선택, 근거 답변, 사람 이관
- `W-02` 상담 지식 개선 배치: 매일 02:00 전일 상담 분석과 개선 후보 생성
- `W-03` 상담 종료 이벤트 처리: 요약·마스킹·CRM 저장·설문 발송
- 역할 분리: LLM 생성, 예측형 AI 점수, 결정론적 검증·실행, 사람 승인

### `BM-CH01` Channels — 채널

- 고객 채널: 카드사 모바일 앱과 웹 Help Desk
- 상담사 채널: 문의·근거·인계 요약 화면
- 운영 채널: 배치 결과, 실패 재처리, 지식 개선 후보 화면
- 외부정보 채널: 공식 웹사이트와 공식 영상의 메타데이터·자막

### `BM-R01` Revenue Streams — 가치 회수

직접 매출보다 비용 회피와 서비스 품질 향상으로 가치를 회수함.

- 자동 해결된 반복 문의의 상담 비용 절감
- 상담사 검색·후처리 시간 감소에 따른 처리량 향상
- 근거 없는 답변 감소에 따른 재문의·민원 비용 절감
- 교육용 목표: 안전한 자동 해결률 35% 이상

### `BM-CS01` Cost Structure — 비용 구조

- 고정비: 제품 개발, 내부 지식 정비, 온톨로지·용어사전 관리, 보안·준법 검토
- 변동비: LLM, 예측형 AI, 검색 저장소, 정형 조회, 공식 웹·영상 검색, 관측 로그
- 운영비 상한: 월 20,000,000원
- 문의당 비용 상한: 200원
- 손익분기 관점: 자동 해결 1건의 비용이 기존 상담 처리 비용보다 낮아지는 시점

### `BM-K01` Key Metrics — 핵심 지표

| 지표 ID | 지표 | 산식 | 주기 | 교육용 목표 |
|---|---|---|---|---|
| `BM-KM-01` | 근거 포함 첫 답변 시간 | 접수부터 답변까지 p95 | 일 | 5초 이내 |
| `BM-KM-02` | 안전한 자동 해결률 | 사람 이관 없이 안전 종료 ÷ 전체 문의 | 주 | 35% 이상 |
| `BM-KM-03` | 같은 사유 재문의율 | 7일 내 동일 사유 재문의 ÷ 해결 문의 | 주 | 15% 이하 |
| `BM-KM-04` | 답변 만족도 | 설문 점수 평균 | 주 | 5점 중 4.2점 이상 |
| `BM-KM-05` | 민감정보 원문 노출 | 입력·출력·로그 검출 건수 | 즉시 | 0건 |
| `BM-KM-06` | 배치 완료 | 전일 분석 종료 시각 | 일 | 06:00 이전 |
| `BM-KM-07` | 이벤트 처리 완료 | 종료 이벤트부터 CRM 기록까지 p95 | 일 | 60초 이내 |
| `BM-KM-08` | 근거 커버리지 | 출처가 있는 답변 문장 ÷ 근거 필요 문장 | 일 | 100% |

### `BM-UA01` Unfair Advantage — 경쟁우위

- 승인된 내부 지식과 실제 상담 해결 결과의 연결
- 정형·의미·관계·외부정보를 질문별로 선택하는 검색 구조
- LLM·예측형 AI·결정론적 처리·사람 승인의 분리
- 답변 근거와 감사 기록을 남기는 운영 체계

## 2. 필수 역할

| 역할 ID | 종류 | 역할명 | 책임 | 사용 모델 |
|---|---|---|---|---|
| `R-L1` | `LLM` | 문의 해석·답변 담당자 | 문의 의도, 근거 종합, 답변 초안 1건 생성 | LLM 제품은 설계 단계 확정 필요 |
| `R-D1` | `Deterministic` | 상담 위험 예측 담당자 | 고정 입력으로 긴급도·민원 위험 점수 1건 산출 | 비LLM 예측 모델은 설계 단계 확정 필요 |
| `R-D2` | `Deterministic` | 규칙·조회·실행 처리기 | 고정 쿼리, 권한 검사, 상태 검증, 승인된 실행 처리 | LLM 미사용 |
| `R-H1` | `Human` | 상담사·검토자 | 고위험 답변 검토와 되돌릴 수 없는 실행 승인 | 모델 미사용 |

예측형 AI의 결과는 이관 우선순위에만 사용함. 고객 권리, 카드 상태, 한도, 보상은 자동 변경하지 않음.

## 3. 필수 지식과 외부정보

| 지식 ID | 유형 | 교육용 원천 | 주요 사용 | 결과 계약 |
|---|---|---|---|---|
| `K-ST-FQ-01` | 정형·고정 쿼리 | 고객·카드·거래 읽기 전용 복제본 | 본인·카드 상태·사유 코드 조회 | 허용 열과 행 수 상한 내 결과 |
| `K-ST-NL-01` | 정형·NL2SQL | 마스킹된 상담·거래 분석 뷰 | 질문별 기간·상태·집계 조회 | 검사된 `SELECT`와 최대 100행 |
| `K-SEM-01` | 의미정보(RAG) | 승인 약관·상품 안내·상담 지침·FAQ | 표현이 다른 문의의 근거 문단 검색 | 문서 ID·버전·근거 구간 |
| `K-REL-01` | 관계정보(GraphRAG) | 고객·카드·상품·거래·문의·분쟁 그래프 | 연결 경로와 영향 관계 확인 | 방향 관계·원천 ID·최대 3홉 |
| `K-EXT-WEB-01` | 공식 웹 | 카드사·금융위원회·금융감독원 등 공식 사이트 | 최신 공지·소비자 안내 확인 | URL·제목·조회 시각 |
| `K-EXT-VIDEO-01` | 공식 영상 | 위 기관의 공식 영상 채널 | 영상 안내의 메타데이터·자막 확인 | URL·제목·조회 시각·자막 구간 |
| `K-GLS-01` | 용어사전 | 카드 상품·승인·매입·청구·분쟁 용어 | 코드 정규화·질의 확장·동일 개체 판별 | 대표어·동의어·충돌 상태 |
| `K-ONT-01` | 온톨로지 | 문의·거래·분쟁·수수료 개념 | 그래프 스키마와 상위·하위 개념 확장 | 노드·관계 타입·개념 계층 |

외부정보 결과는 실행 시 `source_url`, `title`, `retrieved_at`, `content_excerpt`를 기록함.  
영상은 `transcript_range`를 추가하며 자막이 없으면 근거로 사용하지 않음.

## 4. 안전·품질 정책

| 정책 ID | 정책 |
|---|---|
| `POL-01` | 카드번호 전체, CVC, 비밀번호, 인증 토큰을 모델·검색어·로그·답변에서 차단함 |
| `POL-02` | 고객별 조회 전에 인증·목적·최소권한을 결정론적으로 확인함 |
| `POL-03` | NL2SQL은 읽기 전용 `SELECT`, 허용 테이블·열, 최대 100행으로 제한함 |
| `POL-04` | RAG·GraphRAG·외부검색 결과만으로 카드 상태·한도·보상을 확정하지 않음 |
| `POL-05` | 위험 점수 0.80 이상 또는 근거 없음은 `R-H1`에게 이관함 |
| `POL-06` | FAQ 개선 후보와 CRM 요약은 사람 검토가 필요한 조건에서 승인을 기다림 |
| `POL-07` | 외부 문자열을 `<untrusted_contents>`로 분리하고 허용 필드만 사용함 |
| `POL-08` | 모든 답변에 내부 근거 ID 또는 외부 URL·제목·조회 시각을 표시함 |

## 5. 범위

### 포함 범위

- 텍스트 고객 문의와 읽기 전용 고객·카드·거래 조회
- 고정 쿼리, NL2SQL, RAG, GraphRAG, 공식 웹·영상 검색
- 용어사전 정규화와 온톨로지 기반 개념 확장
- 상담사 이관, 일일 지식 개선 배치, 상담 종료 후처리

### 제외 범위

- 카드 정지·재발급, 결제 취소·환불, 한도 변경의 무승인 자동 실행
- 신용평가·부정거래 탐지·상담사 성과평가 자동화
- 음성 인식·합성, 이미지·문서 OCR
- 고객 데이터로 예측 모델이나 LLM을 재학습하는 일
- 실제 제품·법정 보관 기간·운영 조직의 확정

## 6. 후속 설계 입력 요약

| 입력 항목 | 확정 내용 |
|---|---|
| 시작 트리거 | 동기 요청 1건, 매일 02:00 배치 1건, 상담 종료 이벤트 1건 |
| 필수 역할 | `R-L1`, `R-D1`, `R-D2`, `R-H1` |

| 비정형 경로 | RAG, GraphRAG, 공식 웹, 공식 영상 |
| 횡단 지식 | 용어사전과 온톨로지 개념 계층 |
| 사람 승인 | 고위험 답변, 외부 쓰기, 불가역 조치 전에 필요 |
| 민감정보 | 카드번호·CVC·비밀번호·토큰의 모델·외부검색·로그 유입 금지 |
