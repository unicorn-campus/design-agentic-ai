# 신용카드사 Help Desk 유저스토리

## 0. 범위와 작성 원칙

본 문서는 교육용 최소 범위로 작성한 유저스토리임.  
전체 NPD 기준인 UFR 20개 이상을 이번 범위에는 적용하지 않음.  
3개 워크플로우를 설명하는 UFR 9개, AFR 2개, NFR 2개만 포함함.

- 유저플로우 → Epic, 이벤트 → Story, 커맨드 → Task, 정책 → 인수기준으로 연결
- 모든 스토리에 Given-When-Then, MoSCoW 중요도, Story Point, 추적 ID 포함
- 실제 카드사 정책이 필요한 값은 `교육용 가정`으로 표시

## 1. Epic WF-01 — 동기 고객 문의

### UFR-HDK-010 고객 문의 접수

고객으로서 | 나는 카드 문제를 해결하기 위해 | 자연어 문의 제출과 접수 확인을 원함.

- 시나리오: 정상 문의 접수
- Given: 고객이 Help Desk 채널에 접근한 상태
- When: 문의 내용을 제출함
- Then: 요청 ID가 발급되고 문의가 접수됐다는 안내가 1초 이내 표시됨
- 입력 요구사항: 문의 본문 1자 이상 2,000자 이하, 채널, 고객 세션
- 실패 처리: 빈 문의는 제출하지 않고 수정 안내 제공
- 추적: `WF-01`, `CMD-01`, `EVT-01`, `OUT-01`
- 우선순위·점수: M/3

### UFR-HDK-020 근거 기반 답변

고객으로서 | 나는 안내를 신뢰하기 위해 | 최신 승인 문서의 근거가 있는 답변을 원함.

- 시나리오: 지식만으로 답할 수 있는 문의
- Given: 문의가 분류되고 유효한 승인 지식이 검색된 상태
- When: 답변 생성과 민감정보·금지 표현 검사가 완료됨
- Then: 문서명·버전·근거 구간과 다음 행동을 포함한 답변이 p95 5초 이내 제공됨
- 검증 요구사항: 근거 없는 문장 차단, 만료 문서 제외, 답변 신뢰도 0.80 이상
- 실패 처리: 근거가 없거나 신뢰도가 낮으면 `UFR-HDK-040`으로 연결
- 추적: `WF-01`, `EVT-02`, `POL-03`, `POL-07`, `DATA-01`, `TOOL-01`
- 우선순위·점수: M/8

### UFR-HDK-030 고객·거래 상태 조회

고객으로서 | 나는 맞춤 안내를 받기 위해 | 인증 후 안전한 카드·거래 상태 조회를 원함.

- 시나리오: 카드 이용 거절 사유 확인
- Given: 고객 본인 인증과 조회 목적·권한 확인이 완료된 상태
- When: 고객·카드 또는 거래 상태 조회를 요청함
- Then: 카드번호 원문 없이 안내 가능한 상태 코드와 다음 행동만 답변에 반영됨
- 검증 요구사항: 조회 3초 타임아웃, 최대 2회 재시도, 읽기 전용 호출
- 재시도 방식: 지수 백오프와 지터 적용
- 실패 처리: 상태를 추측하지 않고 조회 실패와 상담사 연결 선택지 제공
- 추적: `WF-01`, `POL-01`, `POL-02`, `POL-04`, `DATA-02`, `DATA-03`, `TOOL-02`, `TOOL-03`
- 우선순위·점수: M/13

### UFR-HDK-040 상담사 인계

고객으로서 | 나는 어려운 문제를 해결하기 위해 | 맥락이 유지된 상담사 연결을 원함.

- 시나리오: 민감 조치 문의 인계
- Given: 낮은 신뢰도, 근거 없음, 민원·분쟁, 민감 조치 중 하나가 감지된 상태
- When: 시스템이 상담사 인계를 결정하거나 고객이 연결을 선택함
- Then: 문의 요약·근거·조회 상태가 있는 인계 카드가 생성되고 연결 상태가 안내됨
- 검증 요구사항: 카드번호·CVC·비밀번호·토큰 원문 미포함
- 실패 처리: 대기열 생성 실패 시 요청 ID와 대체 연락 경로 제공
- 추적: `WF-01`, `CMD-02`, `EVT-03`, `OUT-02`, `TOOL-04`
- 우선순위·점수: M/8

## 2. Epic WF-02 — 상담 지식 개선 배치

### UFR-KNW-010 전일 상담 분석

운영자로서 | 나는 반복 문의와 오답 위험을 찾기 위해 | 매일 전일 상담 자동 분석을 원함.

- 시나리오: 02:00 정상 배치
- Given: 전일 종료된 상담 이력이 100건 이상 존재함
- When: 매일 02:00 배치가 시작됨
- Then: 마스킹 후 빈도·재문의율·만족도·수정률 기준 후보가 06:00 이전 생성됨
- 검증 요구사항: `기준일자+데이터버전` 멱등 키, 후보 해시, 체크포인트
- 재시도 방식: 실패 단계만 최대 2회 재시도
- 실패 처리: 미완료 시 운영자 경고 후 마지막 성공 단계부터 재개
- 추적: `WF-02`, `CMD-03`, `EVT-04`, `DATA-04`
- 우선순위·점수: M/13

### UFR-KNW-020 FAQ 개선 후보 생성

검토자로서 | 나는 반복 문의를 줄이기 위해 | 근거와 영향도가 있는 FAQ 후보를 원함.

- 시나리오: 검증 가능한 FAQ 후보 생성
- Given: 반복 문의 또는 오답 후보가 탐지된 상태
- When: 후보 생성과 근거 유효성·중복·금지 정보 검사가 완료됨
- Then: 질문, 답변 초안, 근거 문서, 빈도, 영향도가 포함된 후보가 승인 대기 상태로 저장됨
- 검증 요구사항: 승인 문서 없는 후보 제외, 고객 식별정보 원문 미포함
- 실패 처리: 검증 실패 후보는 사유와 함께 격리
- 추적: `WF-02`, `EVT-05`, `OUT-03`, `POL-05`
- 우선순위·점수: M/8

### AFR-KNW-030 FAQ 후보 승인·반려

검토자로서 | 나는 잘못된 안내를 막기 위해 | FAQ 후보의 승인·수정·반려를 원함.

- 시나리오: 후보 승인
- Given: 검토자에게 유효한 권한이 있고 후보가 승인 대기 상태임
- When: 근거·표현·준법 적합성을 확인하고 승인함
- Then: 승인자·시각·의견이 감사 기록에 남고 별도 게시 절차를 시작할 수 있음
- 검증 요구사항: 작성자와 승인자 분리, 무승인 자동 게시 차단
- 실패 처리: 권한이 없으면 상태를 변경하지 않고 접근 거부 기록 생성
- 추적: `WF-02`, `CMD-04`, `POL-05`, `POL-06`
- 우선순위·점수: M/5

## 3. Epic WF-03 — 상담 종료 후처리

### UFR-OPS-010 상담 요약·마스킹

상담사로서 | 나는 후처리 시간을 줄이기 위해 | 상담 종료 후 안전한 자동 요약을 원함.

- 시나리오: 상담 종료 이벤트 후 요약 생성
- Given: 유효한 상담 ID로 상담 종료 이벤트가 발행된 상태
- When: 상담 후처리가 시작됨
- Then: 문의 사유·확인 내용·안내 결과·후속 조치가 요약되고 민감정보 원문이 제거됨
- 검증 요구사항: `eventId` 중복 제거, 요약 10초 타임아웃
- 사람 확인: 낮은 신뢰도 또는 민감 상담
- 실패 처리: 요약 실패 시 원문을 CRM에 복사하지 않고 실패 보관함으로 이동
- 추적: `WF-03`, `CMD-05`, `EVT-06`, `POL-01`, `OUT-04`
- 우선순위·점수: M/8

### UFR-OPS-020 CRM 상담 요약 저장

상담사로서 | 나는 다음 상담에서 맥락을 잇기 위해 | 확인된 요약의 CRM 단일 저장을 원함.

- 시나리오: CRM 정상 저장
- Given: 요약이 마스킹 검사를 통과하고 필요한 상담사 확인이 끝난 상태
- When: CRM 저장을 요청함
- Then: 상담 ID에 연결된 요약이 한 번 저장되고 저장 결과가 p95 60초 이내 기록됨
- 검증 요구사항: `eventId+CRM저장` 멱등 키, 5초 타임아웃, 최대 3회 재시도, 감사 추적 ID 저장
- 실패 처리: 3회 실패 시 실패 보관함과 운영자 알림 생성
- 추적: `WF-03`, `EVT-07`, `TOOL-05`, `POL-06`
- 우선순위·점수: M/8

### UFR-OPS-030 만족도 설문 발송

고객으로서 | 나는 상담 경험을 평가하기 위해 | 동의한 채널의 짧은 만족도 설문을 원함.

- 시나리오: CRM 저장 후 설문 발송
- Given: 상담 요약이 CRM에 저장됐고 고객이 알림 수신에 동의한 상태
- When: 후처리 흐름이 설문 발송을 요청함
- Then: 상담 ID 토큰이 포함된 설문 링크가 한 번 발송됨
- 검증 요구사항: 원문 고객 ID·상담 내용 미포함, `eventId+설문발송` 멱등 키, 5초 타임아웃
- 실패 처리: 3회 실패 시 실패 보관함에 저장하며 CRM 기록은 되돌리지 않음
- 추적: `WF-03`, `EVT-08`, `TOOL-06`
- 우선순위·점수: S/5

### AFR-OPS-040 실패 작업 재처리

운영자로서 | 나는 누락된 후처리를 복구하기 위해 | 실패 확인과 안전한 재처리를 원함.

- 시나리오: CRM 저장 실패 재처리
- Given: 운영자 권한이 있고 실패 작업이 보관된 상태
- When: 원인을 확인하고 재처리를 승인함
- Then: 기존 멱등 키로 실패 단계만 다시 실행되고 결과가 감사 기록에 남음
- 검증 요구사항: 성공한 단계 재실행 금지, 재처리 횟수 상한 3회
- 실패 처리: 상한 초과 시 수동 처리 상태로 전환
- 추적: `WF-03`, `POL-06`, `DATA-05`
- 우선순위·점수: S/5

## 4. 비기능 요구사항

### NFR-SYS-010 보안·개인정보

시스템 운영자로서 | 나는 정보 보호를 위해 | 최소 권한과 민감정보 차단을 원함.

- Given: 문의·조회·요약·로그 데이터가 처리되는 상태
- When: 데이터가 언어 모델, 도구, 로그, 화면으로 이동함
- Then: 카드번호 전체·CVC·비밀번호·토큰이 차단되고 고객 ID가 토큰화됨
- 감사 조건: 모든 민감정보 접근 기록 보존
- 구현 태스크: 입력·출력 이중 마스킹, 도구별 권한 범위, 비밀값 저장소, 감사 로그 분리
- 추적: `POL-01`, `POL-02`, `POL-04`, `POL-06`
- 우선순위·점수: M/13

### NFR-SYS-020 성능·회복성·비용

시스템 운영자로서 | 나는 안정적인 운영을 위해 | 시간·재시도·비용 상한을 원함.

- Given: 정상 또는 부분 장애 상태에서 세 워크플로우가 실행 중임
- When: 외부 API 지연, 중복 이벤트, 일시 오류, 모델 실패가 발생함
- Then: 타임아웃·재시도·멱등성·체크포인트가 적용되고 비용 상한 전에 경고됨
- 목표: WF-01 p95 5초·하드 타임아웃 15초, WF-02 06:00 이전, WF-03 p95 60초, 월 20,000,000원 이하
- 구현 태스크: 구간별 타이머, 재시도 상한, 실패 보관함, 비용 계측, 추적 ID
- 추적: `BM-A01`, `BM-A02`, `BM-K01`, `WF-01`, `WF-02`, `WF-03`
- 우선순위·점수: M/13

## 8. 공통 완료 기준

- 모든 스토리의 단위 테스트와 통합 테스트 통과
- 세 PlantUML 흐름과 유저스토리의 ID·이벤트·정책 연결 확인
- 민감정보 입력·출력·로그 마스킹 시험 통과
- 타임아웃·중복 요청·재시도 초과·외부 시스템 장애 시험 통과
- 상담사와 지식·준법 검토자의 승인 경로 시험 통과
- 운영 지표와 감사 추적 ID 조회 가능
