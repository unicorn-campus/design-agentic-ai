# BM25 인덱싱의 원리와 설계 (1장, v2 스크립트)

## 수정 방향
- 쉽게: 전문용어를 동작 설명으로 바꾸고, 실제 문장 1개가 색인 단어가 되는 과정을 예시로 보여 줌  
- 정확하게: 코드와 다른 표현을 바로잡고, 예시는 활성 세대 사전으로 실제 실행한 결과만 사용

## v1 대비 바로잡은 표현
| v1 표현 | 문제 | v2 |
|---|---|---|
| Kiwi에 적용한 기술 | 내용어 필터·원형 보존은 Kiwi 기능이 아니라 우리 코드 규칙 | Kiwi 분석 + 우리 규칙으로 구분 |
| 파일 개수·해시 검증 | 코드는 파일 개수가 아니라 청크 수를 대조 | 청크 수·해시 검증 |
| 정규화 예시(형태소 목록 아님) | 정작 BM25에 들어가는 단어를 보여 주지 않음 | 실제 토큰화 결과 12개 단어 제시 |
| 한빛 가족돌봄 NNP 0.0 | 0.0을 BM25 점수로 오해할 여지 | Kiwi 등록 가중치라고 명시 |
| (없음) | 사전 등록 시 카드명이 한 단어로 묶이는 효과·한계 미기재 | 사전 있음/없음 비교 + 한계 1줄 |

## 장표 구성 (패턴 D 변형: 상단 흐름 + 좌 예시표 + 우 설정표)
- breadcrumb: 벡터DB 구성 원리 › BM25 키워드 색인  
- 제목: BM25 인덱싱의 원리와 설계  
- 리드문: 카드명·금액·코드처럼 글자가 같은 단어로 청크를 찾아, 뜻으로 찾는 벡터 검색을 보완합니다.

### 상단 4단계
1. 청크 본문 — 본문(text)만 단어로 바꿈 / chunk_id로 원문과 연결  
2. Kiwi 토큰화 — 표기 통일 → 형태소 분석 / 조사·어미 빼고 원형 보충  
3. bm25s 점수표(강조) — 빈도·희소성·길이로 점수 계산 / 검색 전에 미리 저장  
4. 저장·검증 — 임시 폴더에서 완성한 뒤 / 청크 수·해시 맞으면 교체

### 좌: 예시표 (실제 실행 결과)
| 단계 | 결과 |
|---|---|
| 원문 | 한빛 가족돌봄 카드로 30,000원 이상 결제하면 KB-PAY 할인을 받습니다. |
| ① 표기 통일 | 한빛 가족돌봄 카드로 30000원 이상 결제하면 kb-pay 할인을 받습니다. |
| ② 남긴 단어 | 한빛가족돌봄 · 카드 · 30000 · 원 · 이상 · 결제 · kb · pay · 할인 · 받 |
| ③ 버린 조각 | 로 · 하 · 면 · 을 · 습니다 · 하이픈 · 마침표  (조사·어미·접미사·기호) |
| ④ 원형 추가 | 30000원 · kb-pay  (금액·코드를 통째로도 찾도록) |
| 최종 | ②+④ = 12개 단어 → bm25s가 점수 계산 |

- 비교 박스: 사전 있음 = 한빛가족돌봄 1개 / 사전 없음 = 한빛·가족·돌봄·가족돌봄 (카드 64종이 모두 '한빛'으로 시작)  
- 한계: '한빛' 없이 '가족돌봄'만 쓴 질문은 이 카드명 단어와 일치하지 않음

### 우: 우리 코드의 설정값
| 항목 | 현재 값 |
|---|---|
| 색인 단위 | 청크 1개 = 문서 1개 |
| 점수 공식 | bm25s · Lucene 방식 |
| 조절값 | k1 = 1.5 · b = 0.75 |
| 카드명 사전 | D2 카드명 → 고유명사(NNP) |
| 검색과 일치 | 검색도 같은 규칙 사용(서명 대조) |
| 갱신 방식 | 새 세대로 전체 재색인 후 전환 |
| 기본 꺼짐 | 정적 사전 · 미등록어 후보 추출 |

- 캡션: k1 = 같은 단어 반복 시 점수가 더 오르는 정도 / b = 긴 청크 점수를 깎는 정도 /  
  NNP 0.0의 0.0은 Kiwi 등록 가중치(BM25 점수 아님)
