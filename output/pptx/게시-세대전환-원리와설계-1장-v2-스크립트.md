# 게시의 원리: 완성된 세대로 한 번에 전환 (1장, v2 스크립트)

## 수정 방향
- 세대 전환을 3장면 도식으로 표현: 포인터가 G1을 가리키다가 마지막에 G2로 옮겨 가는 모습  
- 설계 항목은 코드가 대신 정할 수 없는, 사람이 판단해야 하는 4개만 남김  
- 실제 `data/generations` 폴더 상태를 근거로 제시(미완성·이전 세대가 남아 있음)

## v1 대비 바로잡은 표현
| v1 표현 | 문제 | v2 |
|---|---|---|
| 게시 포인터를 G2로 → 벡터·BM25 경로를 함께 기록 | 검색기가 자동으로 따라온다고 오해할 수 있음. Retriever는 이 포인터를 읽지 않고 설정한 경로를 씀 | 주의 문구로 명시 |
| 동시 게시 제어·검색기 전환 | 잠금·재시도·재로딩은 엔지니어링 구현 항목이지 사람 판단 항목이 아님 | 사람이 정할 4개(합격선·승인·되돌리기·보관)로 축소 |
| 게시 핵심 코드 블록 | 초보자에게 코드 7줄은 부담 | 장면 ③ 설명과 발표자 노트로 이동 |

## 장표 구성
- breadcrumb: 벡터DB 구성 원리 › 마지막 단계: 게시  
- 제목: 게시의 원리: 완성된 세대로 한 번에 전환  
- 정의 2줄  
  - 세대 = 같은 시점의 벡터·BM25·본문·사전·manifest를 한 폴더에 묶은 검색 버전  
  - 게시 = 게시 포인터(active_generation.json)가 가리키는 세대를 새 세대로 바꾸는 일

### 3장면 도식
1. 만드는 중 — 포인터→G1(사용 중), G2(만드는 중, 점선)  
   G2를 다른 폴더에 만듦(같은 본문은 G1 벡터 재사용) / 그동안 검색은 G1
2. 검증 — 포인터→G1, G2(검증 중)  
   벡터 ID·본문·차원, BM25 청크 수·해시 확인 / 하나라도 틀리면 멈춤 → 포인터는 G1 그대로
3. 전환 — 포인터→G2(사용 중), G1(보관)  
   잠금 → 기준 세대(G1) 그대로인지 확인 → ready 기록 / 포인터 파일 1개만 교체, G1은 지우지 않음

- 주의: 현재 검색기(Retriever)는 이 포인터를 직접 읽지 않고, 설정한 경로(CHROMA_PATH·SEARCH_INDEX_ROOT)를 씀
