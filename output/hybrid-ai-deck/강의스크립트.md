## 슬라이드 4. Indexer 전체 흐름: 원문에서 검색 색인까지

- 원본 대응: 4장 재구성
- 핵심 메시지: Indexer는 원문 선택부터 저장 결과 검증까지 8개 노드를 순서대로 실행함.
- 설명 대본: Indexer는 파일을 바로 벡터 DB에 넣지 않습니다. 먼저 원문을 고르고, 내용을 추출하고, 메타데이터와
  개인정보를 검사한 뒤 청크와 임베딩을 만듭니다. 마지막에는 벡터 저장 건수와 BM25 색인 발행 결과까지 확인합니다.
- 도식: 가로 8단계 도형 흐름으로 구성함.
  `select_sources → extract → apply_profile → validate_metadata → chunk → embed → upsert → finalize_index` 순서임.
  `선택 결과 0건`, `메타데이터 오류`, `dry-run 또는 청킹 오류`는 아래쪽 `END`로 빠지는 조건선으로 표시함.
- 소스: `hybrid-ai-lab/vector/indexer/app/application/graph.py`

- 핵심 메시지: PDF는 단순 문자열이 아니라 글자의 위치를 함께 읽어야 머리말·본문·표를 구분할 수 있음.

## 슬라이드 8. PDF 표 보존: 표는 마크다운으로, 본문은 한 번만

- 원본 대응: 6장 분리 재구성
- 핵심 메시지: 표를 구조화하면서 같은 글자가 본문과 표에 이중으로 들어가는 문제를 막음.
- 설명 대본: 표가 감지되면 행과 열을 마크다운 표로 바꾸고, 같은 영역의 일반 텍스트는 본문에서 제거합니다.
  원문 글자와 추출한 표의 글자가 맞지 않으면 변환을 강행하지 않고 위치 기반 텍스트를 유지합니다. 마지막에는 본문과

## 슬라이드 10. 문서 유형별 청킹: D1·D2·D3의 경계를 다르게 사용

- 원본 대응: 7장 분리 재구성
- 핵심 메시지: 같은 글자 수로 자르지 않고 문서 의미가 끊기지 않는 경계를 먼저 사용함.
- 설명 대본: D1 약관은 조항 단위, D2 혜택은 카드·혜택 단위, D3 상담은 대화 턴 단위로 먼저 묶습니다.

## 슬라이드 11. 변경 감지와 벡터 저장

- 원본 대응: 8장 분리 재구성
- 핵심 메시지: 본문 또는 메타데이터가 달라진 청크만 다시 임베딩하고 Chroma에 갱신함.
- 설명 대본: 청크별로 본문 SHA-256과 메타데이터 SHA-256을 이전 manifest와 비교합니다. 둘 다 같으면 임베딩을
  건너뛰고, 하나라도 달라지면 새 벡터를 만듭니다. 메타데이터 변경도 권한 필터 결과에 영향을 주므로 재임베딩 대상입니다.
  임베딩은 정규화된 벡터로 만들고 Chroma에 본문·메타데이터와 함께 upsert합니다.
- 도식: `현재 청크 해시 ↔ 이전 manifest 해시` 비교 다이아몬드 뒤에
  `같음: skip`, `다름: SentenceTransformer → normalized vector → Chroma upsert` 두 갈래를 배치함.
- 소스: `hybrid-ai-lab/vector/indexer/app/infrastructure/embedder.py`,
  `hybrid-ai-lab/vector/indexer/app/infrastructure/chroma_store.py`,
  `hybrid-ai-lab/vector/indexer/app/application/graph.py`

## 슬라이드 13. Retriever 전체 검색 흐름

- 원본 대응: 9장 검색 부분 재구성
- 핵심 메시지: 원 질문을 한 번 검색한 뒤 필요할 때만 질문 변환을 검토하고, 선택한 모드에 따라 후보를 합침.
- 설명 대본: 먼저 입력과 색인을 확인하고 원 질문 벡터 검색을 정확히 한 번 실행합니다. 그 점수로 질문 변환 검토 여부를
  판단한 다음, 원 질문 결과를 완성하고 변환 질문이 있으면 별도로 검색합니다. 마지막 정리는 RRF 또는 리랭커가 맡습니다.
- 도식: 편집 가능한 도형으로
  `check_search_readiness → vector_search → assess_transform_gate → 원 질문 결과 완성 → search_transformed →
  merge_queries/rerank`를 배치함. `off·관문 통과`는 변환 노드를 우회하는 조건선으로 표시함.
- 소스: `hybrid-ai-lab/vector/retriever/app/application/graph.py`

## 슬라이드 14. Retriever 전체 답변 흐름

- 원본 대응: 9장 답변 부분 재구성
- 핵심 메시지: 검색 결과가 답변 관문을 통과해야 생성으로 가며, 생성한 인용은 다시 원문과 대조함.
- 설명 대본: 최종 검색 1위의 원 벡터 점수가 0.62보다 낮거나 없으면 `needs_check`로 종료합니다. 통과하면 검색 근거를
  XML 데이터로 감싼 프롬프트를 만들고 구조화 답변을 생성합니다. 인용 검증에 실패하면 수정 지침을 넣어 다시 생성하며,
  허용 횟수를 넘으면 멈춥니다.
- 도식: `최종 hits → answer gate 0.62 → build_prompt → generate_answer → verify_evidence` 흐름임.
  검증 실패는 `build_prompt`로 되돌아가는 루프, 통과는 `END`로 표시함.
- 소스: `hybrid-ai-lab/vector/retriever/app/application/graph.py`,
  `hybrid-ai-lab/vector/retriever/app/domain/scoring.py`

## 슬라이드 15. 네 가지 검색 모드

## 슬라이드 20. RRF: 점수 단위가 달라도 순위로 합치기

- 원본 대응: 12장 분리 재구성
- 핵심 메시지: 리랭킹이 없는 변환 검색은 원점수 대신 각 후보군의 순위를 가중 RRF로 합침.
- 설명 대본: 벡터 점수와 질문별 검색 점수는 크기를 직접 비교하기 어렵습니다. 그래서 각 후보가 원 질문과 변환 질문에서
  몇 위였는지를 사용하고, `가중치 ÷ (60 + 순위)`를 모두 더합니다. 일반 변환에서는 원 질문 가중치가 0.5이고,
  나머지 0.5를 변환 질문 수로 나눕니다.
- 도식: 세 개의 순위 목록에서 같은 청크 ID에 선을 연결하고, 가운데에
  `RRF = Σ weight / (60 + rank)` 공식을 배치함. 오른쪽에는 누적 RRF 순위 한 개를 표시함.

## 슬라이드 21. Rerank: 질문과 문서를 다시 함께 읽기

- 원본 대응: 12장 분리 재구성
- 핵심 메시지: 리랭커는 질문별 후보군을 해당 질문과 다시 짝지어 관련성을 직접 평가함.
- 설명 대본: 질문 변환이 없으면 원 질문 후보만 Cross-Encoder로 점수화하고 상위 결과를 고릅니다. 변환 질문이 있으면
  원 질문과 각 변환 질문의 후보군을 따로 리랭킹합니다. 일반 변환 기법은 각 그룹 안의 새 순위를 가중 RRF로 합치며,
  리랭커 점수 자체를 서로 더하지 않습니다.
- 도식: `질문 + 후보 본문 → Cross-Encoder → 그룹 내부 새 순위` 블록을 원 질문과 변환 질문에 반복함.
  그 뒤 `일반 기법: 새 순위 기반 RRF`로 합침.
- 소스: `hybrid-ai-lab/vector/retriever/app/infrastructure/reranker.py`,

## 슬라이드 22. Decomposition 리랭킹: 하위 질문을 먼저 보장

- 원본 대응: 12장 분리 재구성
- 핵심 메시지: 복합 질문은 각 하위 질문의 상위 3개 후보를 확보하고 가장 강한 하위 점수를 중심으로 합침.

  `0.1 × 원 질문 점수`로 남아 복합 질문의 각 부분과 전체 맥락을 함께 반영합니다.
- 도식: 하위 질문 1·2·3의 `Top3`가 `chunk_id 중복 통합 → max(sub-score)`로 모이고,
  원 질문 점수가 옆에서 들어와 `0.9 sub + 0.1 original` 계산 카드로 연결됨.

## 발표자 공통 주의사항

- `0.86 미만`을 질문 변환 확정이라고 설명하지 않음. 라우터 검토 시작 조건임.
- 질문 변환 기본값은 `off`이며, `auto`에서만 질문 변환 관문이 동작함.
- 답변 관문 점수는 최종 결과의 일반 융합 점수가 아니라 최종 1위가 보존한 원 `vector_score`임.
- Metadata만 바뀌어도 권한 필터 결과가 달라질 수 있으므로 재임베딩 대상임.
- 인용 자동 검증은 참조·원문 포함·위치 존재를 검사하며, 답변 의미의 옳고 그름은 사람 검토 대상임.
- 개인정보 예시는 항상 `[삭제]`, `m_해시`, `a_해시`, `30대` 같은 가상 표기만 사용함.
