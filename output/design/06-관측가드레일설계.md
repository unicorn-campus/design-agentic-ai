# ⑥ 관측·가드레일 설계

> 미검증 설계: 외부 커넥터와 모델을 실제 호출하거나 부하·장애 시험을  
> 수행하지 않은 설계값임.  
> 구현 정합성 기준: 사용자 확정안인 OpenTelemetry와 Prometheus·Grafana·Loki를 적용함.  
> 적재처의 제품·전송 키·물리 배치는 구현·운영 단계에서 확정함.

**9대 리스크 대응표**

| 리스크 | 막는 지점 | 이 문서의 항목 | 인용하는 값의 주인 |
|---|---|---|---|
| 무한 루프 | 도구 호출측 | 구간별 구조화 로그 항목 · 알림 임계값 | ③ 반복 구간·착지 노드 |
| 토큰 누수 | 도구 호출측 | 비용 상한 · 알림 임계값 | ④ 사용 모델 · ⑤ 검색 스펙 |
| Agent 폭주 | 도구 호출측 | 위임 호출 상한 · 커넥터 호출 상한 | ③ 호출 구조 · ⑤ 커넥터 ID |
| 시스템 마비 | 도구 호출측 | 연속 실패 차단 | ③ 단계 경계의 초과 시 처리 |
| 응답 지연 | 도구 호출측 | 단계별 구조화 로그 항목 · 알림 임계값 | ③ 시간 경계 · ① 응답시간 목표 |
| 할루시네이션 전파 | 출력측 | 차단 규칙(Kill-Switch) | ⑤ 검색 판정 기준 · ④ 성공기준 |
| Prompt Injection | 입력측 | 입력측 처리 | ⑤ 커넥터 응답 키·허용 도구 목록 |
| 데이터 유출 | 출력측 | 출력측 검사 · 마스킹 · 관측 적재처 | ② `SL-n` · ⑤ `F-n`·가리는 방법 |

### 입력측 처리

전 단계 공통으로 외부 문자열을 `<untrusted_contents> … </untrusted_contents>`로 감싸  
경계를 표시함.  
시스템 프롬프트에는 우리 지시만 두고 외부 문자열은  
유저 프롬프트·도구 결과 블록으로  
분리함.  
시스템 프롬프트에 구획 안 명령형 문장을 데이터로만 취급한다는

### 비용 상한

월 포트폴리오 상한 환산은 `20,000,000원 ÷ 100,000건 = 문의 생애주기당 200원`임.  
워크플로우 배분은 `W-1` 80% + `W-2` 5% + `W-3` 15% = 100%임.  
`W-2`는 월 30회 실행, 실행당 최대 10,000건을 전제로 함.  
`W-3`은 문의당 종료 이벤트 최대 1건을 전제로 함.
