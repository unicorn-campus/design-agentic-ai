# 설계서 ⑦ 배포 — 런치픽(LunchPick)

작성: 커넥니(도구 연동 엔지니어) · 2026-08-08 · **미검증 설계**(배포·측정을 실제로 하지 않음)

이 문서는 **이 시스템을 몇 덩어리로 포장해 어디에 올리고 열쇠를 어떻게 넣는가**만 정함.  
`비밀 객체`는 플랫폼이 값을 암호화해 보관하고 실행할 때만 꺼내 주는 저장소를 뜻함.  
`멱등성 키`는 같은 요청이 두 번 와도 한 번만 처리하게 하는 표식임.  
`복제본`은 같은 실행 꾸러미를 동시에 몇 개 띄웠는지를 세는 단위임.

`[확인필요]` **14건** — 말미 미확정 항목 표 15행 중 닫힌 1행을 뺀 수임(종전 11 · 추가 4 · 닫힘 1).

**갱신 이력**

- 2026-08-08 `V-02` 케이스 2번 추가로 감사 로그 용량·배치 실행 창·PG 연결점을 반영함

**이 문서가 정하지 않는 값 5종**(소유자가 다르므로 인용만 함) — 단계별 타임아웃은 ③ 소유 ·

## 2. 시작 전 판정

### 2-1. 나눌까 합칠까 — 4문 전건에 예·아니오와 이유를 적음

| # | 질문 | 답 | 이유 |
|---|------|----|------|
| 1 | 배포 형태가 다른가 | **예** | 프론트엔드는 화면 9종과 정적 자원을 CDN 엣지에 올리는 `정적 호스팅`이고 백엔드 3종은 `런타임 이미지`임. 형태가 달라 같은 절차로 못 올림 |
| 2 | 늘리고 줄이는 기준이 다른가 | **예** | 추천·이력만 12 ~ 13시 동시 1,000명으로 부하가 튀고, 결제는 구독 전환 시점에만 호출되며, 배치는 매일 03:00 1회 전체 회원을 순회함. 늘리는 신호가 서로 무관함 |
| 3 | 접근 권한 등급이 다른가 | **예** | 결제는 PG 가맹점 자격(`TB-5`)을, 회원은 인증 토큰·건강 민감정보를, 배치는 `S-4` 취향 벡터 **되돌림 불가 쓰기**를 가짐. 한 덩어리로 묶으면 요청 경로가 되돌림 불가 쓰기 자격을 함께 갖게 됨 |
| 4 | 나눠도 응답시간 목표를 지키나 | **예** | ③의 p95 합계 2,440ms가 **이미 서비스를 나눈 전제로 계산된 값**임 — 추천·이력 → 회원의 취향 프로파일·구독 상태 조회 2건이 단계 표에 들어가 있음. 나눔이 예산을 새로 늘리지 않음 |

**판정 결과 — 나눔.** `Q1` ~ `Q3`이 전부 `예`이고 `Q4`가 `예`라 거부권이 발동하지 않음.

**3덩어리를 넘긴 이유 1줄** — 이 과제는 MVP 14주 · 7스프린트이므로 3일 과정의 1 ~ 2덩어리 상한이
적용되지 않고 4문 결과를 그대로 따름. 대신 아래 2가지로 부담을 막음.

- **배포 절차를 2종으로 고정** — `런타임 이미지` 1종 절차를 백엔드 4단위가 같이 쓰고,
  프론트엔드만 `정적 호스팅` 절차를 씀. 절차 종류를 단위 수만큼 늘리지 않음
- **줄이는 순서를 미리 적음** — 무엇을 먼저 합칠지와 그 대가를 아래 표로 남김

| 순위 | 합치는 안 | 줄어드는 단위 수 | 대가 |
|------|----------|--------------|------|
| 1 | 결제 서비스 → 회원 서비스 | 5개 → 4개 | PG 가맹점 자격이 회원 서비스 이미지에 들어가 `TB-5` 권한 격리가 깨짐. 결제 배포마다 로그인 경로가 함께 내려감 |
| 2 | 일일 학습 배치 → 추천·이력 서비스 | 4개 → 3개 | `S-4` 되돌림 불가 쓰기 자격이 동기 요청 경로에 붙어 ④ 7절 최소권한이 깨짐. 03:00 배치가 복제본 메모리를 물고 있어 피크 확장 여력이 줄어듦 |
| 3 | 프론트엔드 → 백엔드 | — | **합칠 수 없음.** 배포 형태가 정적 호스팅이라 런타임 이미지 절차에 담을 대상이 아님 |

**7종 전부 `밖`임 · 안에 둔 저장소 0건.** `밖`이 하나라도 걸리면 밖이라는 규칙을 그대로 적용함.  
④ 국내 보관 제한은 원문에 `국내 보관`이라는 문자열로 적혀 있지 않고
`위치기반서비스 사업 신고 완료`·`위치정보 보유 기간 6개월`(US:NFR-SYS-040)에서 도출한
**설계판단**임. 근거 없이 법령명을 붙이지 않고 도출 경로만 밝힘.

**⑤가 걸린 저장소 3종의 처리** — 짧게 잡으면 남길 것을 지우고 길게 잡으면 지울 것이 남으므로
표 단위 자동 삭제를 걸지 않고 아래처럼 나눔.

| 저장소 | 섞인 것 | 처리 |
|--------|--------|------|
| S-1 | 동의 이력(보존 요구 있음) · 알레르겐·식이 유형(별도 키) · 회원 프로파일(기간 요구 없음) | 컬럼 단위 파기 — 알레르겐·식이 유형을 별도 암호화 키 컬럼군으로 떼고, 동의 이력을 별도 표로 나눔 |
| S-3 | 무료 30일 · 프리미엄 무제한 · 컨텍스트 스냅샷 | 행마다 보존 만료 시각 컬럼을 두고 삭제 배치가 그 값으로만 지움. 구독 상태 조회와 결합함 |
| S-7 | 결제 실패 7일 유예 · 결제ID·다음 결제일 | 컬럼 단위 파기 — 실패 이력만 7일 만료 컬럼을 가짐 |

## 5. 런타임 규모 상한 — 곱과 나눗셈을 실제로 함

뒤로 미루지 않고 여기서 계산함. 미루면 아무도 하지 않음.

### 5-1. 필요 커넥션을 먼저 셈 — ①이 기록한 초과를 다시 확인함

```
동시 사용자 수        = 1,000명 (피크 12 ~ 13시)          ← US:NFR-SYS-020 · ① G-1 채점 수단
요청당 관계형 점유    = 510 커넥션·ms                     ← ③ 10절(S-R3 60 + S-R4 300 + S-R5 150)
요청당 총 응답 시간   = 2,440ms (p95)                     ← ③ 9-1절
자원 점유 비율        = 510 ÷ 2,440 = 0.209
필요 동시 커넥션      = 1,000명 × 0.209 = 209개
커넥션 풀 상한        = 100개                             ← US:NFR-SYS-020#체크리스트
초과                  = 209 − 100 = 109개                 ← ①의 기록과 같은 값임
```

### 5-2. 복제본 수로는 흡수되지 않음 — 그 사실을 먼저 적음

풀 상한 100개는 **관계형 DB 1대가 받는 총 커넥션 수**이므로 복제본을 늘려도 늘지 않음.

```
복제본 3개  → 복제본당 풀 33개  ·  총 99개  ≤ 100  ·  필요 209  → 흡수 못 함
복제본 4개  → 복제본당 풀 25개  ·  총 100개 ≤ 100  ·  필요 209  → 흡수 못 함
복제본 10개 → 복제본당 풀 10개  ·  총 100개 ≤ 100  ·  필요 209  → 흡수 못 함
```

복제본 수는 자유 변수가 아니고 `복제본 수 × 복제본당 풀 ≤ 100`이라는 제약 아래 있음.

### 8-3. 되돌리는 판단 기준 — 배포 게이트

배포 뒤 아래 중 **하나라도 적중하면 되돌림**을 시작함. 점수 합산으로 판정하지 않음.

| # | 게이트 | 판정 기준 | 되돌림 대상 | 근거 출처 |
|---|-------|----------|-----------|----------|
| GA-1 | 추천 응답 p95 | 3,000ms 초과 | `D-2` · `D-4` | ① `Q-1`·`G-1` |
| GA-2 | 3필드 완전성 | `reason_line`·`confidence_score`·`context_tags` 누락 1건 이상 | `D-2` | ① `Q-2`(100%) |
| GA-3 | **사용자 입력 기반 식이 필터 동작** | 제외 식재료 코드와 겹치는 식당이 후보에 남은 건수 1건 이상 | `D-2` | ⑥ `B-1`·`B-2`, `V-10` 5번 |
| GA-4 | 민감정보 원문 노출 | 출력·로그에서 이메일·좌표·카드번호 패턴 적중 1건 이상 | 적중 단위 전부 | ⑥ `B-5`·`B-20`, `V-10` 13·21번 |
| GA-5 | 되돌림 불가 쓰기 앞의 검증 | `D-5`에서 `quality_passed` 거짓인 회원의 커밋이 1건 이상 | `D-5` | ④ `R-4` 성공 기준, ⑥ `B-7` |
| GA-6 | 차단 규칙 가동 | ⑥ 차단 규칙 `필수` 항목 중 미가동이 1건 이상(`B-13`은 이미 미가동으로 알려져 있어 제외) | 해당 단위 | ⑥ 6절 강도 2분 |

**`Q-3` 안전성 전체를 게이트에 넣지 않은 이유** — ⑤ 골든셋 28문항 중 `GS-19` ~ `GS-26` 8문항은
식당·메뉴가 어떤 재료를 쓰는지 알려 주는 원천이 없어(`V-04` 24번) 정답을 만들 수 없음.
채점할 수 없는 항목을 게이트에 두면 **배포가 영구히 막히거나 통과를 지어내게 됨.**
그래서 `Q-3` 중 **잴 수 있는 부분만** `GA-3`·`GA-4`로 두고,
**식당·메뉴 원재료 단위의 알레르겐 위반 판정은 게이트에서 뺐음.** 원천이 오면 게이트를 늘림.

**착지 노드는 되돌림 대상이 아님** — ③이 정한 착지 `S-R16`(캐시 폴백) · `S-B10`(이전 벡터 유지 +
사람 확인 알림) · `S-E8`은 **정상 설계된 낮춘 경로**임. 착지가 자주 발동한다는 사실 자체는
`GA-1` ~ `GA-6`으로 잡히므로 착지 발동 횟수를 별도 게이트로 두지 않음.
