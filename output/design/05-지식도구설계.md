# 설계서 ⑤ 지식/도구 — 런치픽(LunchPick)

작성: 지식니(지식·데이터 엔지니어) · 2026-08-08 · **미검증 설계**(색인·검색·평가를 실제로 돌리지 않음)

이 문서는 **"추천 담당자가 무엇을 근거로 답하는가"**와 **"민감한 값을 어디서 가리는가"**만 정함.  
`F-n`은 민감 필드 ID이며 **이 문서가 값의 주인**임(`G-11`). ④ 역할계약서는 이 번호를 인용만 함.  
`SL-n`·`TB-n`은 ② 논리아키텍처의 민감정보 라벨·신뢰 경계 식별자이며 **그 문서가 주인**임.

`[확인필요]` **15건** — 말미 미확정 항목 표 15행과 같음.

**갱신 이력**

- 2026-08-08 ④ 완료 후 왕복 1회 갱신함. 왕복은 종료됨
- 2026-08-08 `V-02` 케이스 2번 추가로 PG 커넥터 · 인사이트 집계를 더함
- 2026-08-08 ④ 왕복 2회차로 C-12 키 이름·D-8 예외를 확정함. 케이스 2 관련 왕복은 이것으로 종료함

## 2. 질문 표본과 경로 판정 — 순서를 뒤집어 판정함

기술 스택을 먼저 늘어놓지 않고 `질문 뽑기 → 경로 판정 → 버린 대안` 순으로 함.

**표본을 뽑기 전에 확인한 사실 1건** — 이 앱에는 **자연어를 치는 입력창이 없음**.
화면 9종을 전수 확인한 결과 자유 텍스트 입력은 닉네임 · 알레르기 직접 입력 · 수동 위치 입력
3곳뿐이며 **질의용이 아님**(`V-09` 8번). 따라서 아래 `사용자가 요구하는 문장`은
사용자가 화면 조작으로 요구하는 것을 자연어로 옮긴 것이며, **실제 입력 형태는 탭·스와이프**임.

## 3. 정형 접근 경로

**읽기 전용 원칙** — 이 경로에 부여하는 DB 계정은 `SELECT` 권한만 가짐.
`INSERT` · `UPDATE` · `DELETE` · DDL을 **부여하지 않음**. 담당자가 SQL 문자열을 만들지 않고
**미리 짠 쿼리 ID만 고름**(NL2SQL 미채택이므로 생성 SQL 자체가 없음).  
식사 기록 저장 · 피드백 저장 같은 쓰기는 이 경로가 아니라 **서비스 쓰기 API**로 나가며

여기서 확정하지 않고 위 요구사항만 넘김.
