# 지식 경로 묶음 — 런치픽 v1.1

담당자가 **무엇을 근거로 답하는가**를 코드로 고정한 자리임.  
설계서 ⑤ 지식/도구 2절 · 3절 · 4절 · 5절과 ④ 역할계약서 4절 · 5절 · 7절을 그대로 옮긴 것임.

> 여기서 만들지 않은 것 — 흐름 조립과 노드 배치(`06-workflow`) · 바깥 API 호출(`04-connector`) ·  
> 가리기 · 검사 · 기록(`05-guardrail`) · 골든셋 채점(`09-eval`). 자리(훅)만 남겨 둠.

**개발자가 이 README만 읽고 알아야 하는 것 3줄**

- 정형 조회는 `lookup(경로, 담당자, 원천)` 1개로 부름. 담당자 이름이 없으면 열지 않음
- 검색 결과는 `RetrievalResult` 1종으로 돌아옴. **후보마다 내용 · 출처 · 점수**가 있음
- 후보가 0건이면 `empty_reason`이 채워짐 — **모른다고 답해야 하는 자리**임

## 1. 무엇을 채택했고 무엇을 안 만들었나

⑤ 5절 후보 5종 + 정형 조회 + 질의 생성 = **판정 7행**임. 채택 4 · 미채택 3임.

| 경로 종류(일반명) | 채택 여부 | ⑤의 어디서 읽었나 | 만든 것 |
|-----------------|----------|-----------------|--------|
| 조회 | **채택** | ⑤ 3절 「정형 접근 경로」 18행 | `structured.py` — 조회 함수 18개 |
| 벡터 유사도(`K-1`) | **채택** | ⑤ 5절 K-1 | `vector_index.py` — 색인 만들기 1벌 + 검색기 1개 |
| 속성 필터 검색(`K-2`) | **채택** | ⑤ 5절 K-2 | `attribute_filter.py` — 검색기 1개 |
| 용어사전(`K-3`) | **채택** | ⑤ 5절 K-3 | `glossary_apply.py` — 적용 지점 2곳 |
| 문서 검색(`K-4`) | 미채택 | ⑤ 5절 K-4 — 색인할 문서가 0건 | **파일 안 만듦** |
| 관계 검색(`K-5`) | 미채택 | ⑤ 5절 K-5 — 2홉 질문이 0건 | **파일 안 만듦** |
| 질의 생성 | 미채택 | ⑤ 판정 3 · 3-B — 자연어 입력면이 0건 | **파일 안 만듦** |
| 결정론 선행 필터 | **필요** | ⑤ 판정 2 `Q6` · 판정 2-B `Q12` · `Q13` | `prefilter.py` — 필터 3개 + 모델 입력에서 필드 제거 |

**안 만들었다는 사실 1줄** — 미채택 3종의 파일 · 설정 · 의존성이 **0건**임.

0건임을 확인함. "나중에 쓸지 몰라서" 만들어 둔 것이 없음.

## 2. 어느 함수를 부르나

| 무엇이 필요하면 | 어디서 가져오나 |
|---------------|---------------|
| 정형 조회 1건 | `common.knowledge.lookup(경로, 담당자, 원천, params=…)` |
| 경로별 조회 함수 | `common.knowledge.LOOKUP_FUNCTIONS["T-5"]` (이름은 `lookup_t5`) |
| 취향 벡터 색인 만들기 | `common.knowledge.build_index(자리, 항목, 임베딩클라이언트)` |
| 유사도 검색 | `common.knowledge.search_similar(색인, 질의벡터, metadata_filter=…)` |
| 속성 필터 검색 | `common.knowledge.filter_by_attributes(후보, 조건)` |
| 용어사전 질의 확장 | `common.knowledge.expand_query_tags(태그, 사전)` |
| 알레르겐 라벨 → 제외 코드 + 필터 | `common.knowledge.to_excluded_ingredient_codes(라벨, 사전, 식당재료)` |
| 결정론 선행 필터 3종 | `allergen_hard_filter` · `cancel_confirm_filter` · `expiry_downgrade_filter` |
| 모델 입력 규격 만들기 | `common.knowledge.build_model_input(**칸)` |
| 재정렬 | `common.knowledge.rerank(결과, 축값)` |
| 색인 다시 만드는 절차 | `common.knowledge.plan_index_swap(자리)` |
| 기록 자리에 넘기기 | `common.knowledge.record_retrieval(훅, 단계, 결과)` |

**결과 그릇 1종만 씀** — `RetrievalResult(route_id, kind, candidates, empty_reason, notes, traces)`.  
`candidates[i]`는 `payload`(내용) · `source`(출처) · `score` · `score_kind`를 가짐.  
`payload`의 키 이름은 **④ 「입출력 형식」이 주인**이며 이 묶음이 새로 짓지 않았음.  
`score` · `source` 두 칸의 모양만 이 묶음이 소유함(⑤ · ④에 이름이 없는 값임).

## 7. 색인 다시 만드는 절차 (되묻기 1의 기본값)

`plan_index_swap("food_item")`이 이 순서를 그대로 돌려줌.

1. `{색인 이름}{접미}`로 **새로 만듦**(쓰는 색인은 그대로 둠)
2. 새 색인의 건수와 임베딩 모델 이름 · 버전을 확인함
3. 읽는 곳이 가리키는 이름을 새 색인으로 **갈아 끼움**
4. 되돌릴 일이 없다고 확인한 뒤에 옛 색인을 치움

**쓰는 색인을 먼저 지우고 덮는 길은 만들지 않았음** — 접미가 설정에 없으면 2단계에서 실패함.

**색인 제품이 정해진 뒤에 할 일 1줄** — 지금 검색기는 프로세스 안에서 코사인 유사도를 셈.
제품이 관계형 DB의 벡터 확장이면 `색인 <=> 질의벡터` 순으로 정렬하고 색인 연산자 부류를
코사인용으로 만드는 문법을 씀(context7로 확인함 · 확인일 2026-08-08). 그 값도 **설정으로만** 옴.

## 13. 확인하지 않은 것 (정직한 보고)

- **실제 벡터 색인 제품에 붙어 검색하지 못했음.** 제품 · 임베딩 모델 이름 · 버전이 정해지지 않았음.
  확인한 것은 여기까지임 — 설정이 비었을 때 무엇이 없는지 알리며 멈추는 것,
  대역 임베딩으로 색인을 만들어 필터 먼저 · 유사도 정렬 순서가 실제로 지켜지는 것,
  거르기 키가 ④ 소유 4축 밖이면 거부되는 것
- **임베딩 API를 실제로 부르지 않았음.** 색인 시험은 전부 대역임
- **골든셋 34문항을 돌리지 않았음.** 채점은 `09-eval` 몫이며 이 묶음은 결과를 돌려주기만 함
- 따라서 **검색 품질 실측값은 0건임.** 위 9절의 후보 수는 합성 시드를 센 값임
- 관계형 저장소에 붙어 조회를 돌려 보지 못했음(물리 표 · 열 이름 미확정 — 데이터 준비 묶음과 같음)
