## 5. 품질 리포트 읽는 법

리포트 위치 — `reports/source-quality-report.md`

| 항목 | 무엇을 센 값인가 |
|------|----------------|
| 행 수 | 실제로 읽어 온 행의 개수. 못 읽었으면 `0` |
| 빈 값(최악 열) | 열마다 값이 비어 있는 행의 비율을 재고 그중 가장 나쁜 열의 값 |
| 중복 | 열쇠(경로마다 정한 식별 열 묶음)가 두 번 이상 나온 비율 |
| 형식 어긋남 | 기대한 모양과 다른 값의 개수. 날짜 · 시각 · 숫자 · 참거짓 · 목록을 봄 |
| 실측 오류율 | 위 3항목을 합쳐 낸 값(필수 열 결측 최악값 + 중복 비율 + 형식 어긋남 비율) |
| ⑤에 적힌 값 | ⑤ 8절 「원천 오류율」에 적혀 있는 값. 고쳐 적지 않음 |
| 갱신 지연 | 캐시 · 배치 · 전파를 거치는 경로만 값이 있음 |
| `미측정` | **세지 못했다는 뜻임.** 짐작한 숫자를 넣지 않았음 |

**가장 중요한 한 줄** — `출처`가 `합성시드`인 행의 숫자는 **원천 실측이 아님.**  
연습용 데이터를 센 값이므로 원천 품질의 근거로 쓸 수 없음. 원천 실측은 저장소가 선 뒤에 함.

품질 문턱은 ⑤에 값이 없어 **자리만** 있음 → 판정 칸이 전부 `[확인필요: 원천 품질 문턱]`임.

시험은 `../tests/dataset/`에 있음 — 읽기 전용 · 상한 · 금지 필드 · 시드 재현 ·
사전 미등록어 · 경로 불가 6종을 각각 따로 둠.

**왜 `services/` 아래가 아니라 `common/dataset/`인가** — ⑤ 3절 18행이 서비스 4개와
저장소 5개에 걸쳐 있고, 관문 · 상한 강제 · 스냅샷 · 품질 리포트가 **한 벌이라야** 리포트를
한 장으로 낼 수 있음. 서비스별로 쪼개면 같은 코드가 4벌이 됨. 그래서 `D-05` 「공통 모듈 위치」
아래에 두고, 소유 서비스는 `readers/` 파일 이름과 경로 표의 `owner_service` 칸으로 표시했음.
서비스별 모듈에서는 이 묶음을 **가져다 쓰기만** 함.

## 7. 용어사전 쓰는 법

사전은 **파일 1벌만** 있음. 코드 안에 같은 매핑을 또 적지 않았음.

| 사전 | 파일 | 쓸 수 있는 대표어 | 비어 있는 행 | 1:N 충돌 처리 |
|------|------|----------------:|-----------:|-------------|
| 음식 카테고리 · 맛 태그(ⓐ) | `config/glossary_food_tags.csv` | 3건 | 2건 | 양쪽 후보를 모두 남김 |
| 알레르겐 → 제외 식재료 코드(ⓑ) | `config/glossary_allergen_codes.csv` | 7건 | 6건 | 코드를 합집합으로 합침 |

- **사전에 없는 낱말은 버리지 않음** — 원문을 그대로 넘기고 기록을 1건 남김
  (ⓐ는 필터에 넣지 않음 · ⓑ는 페일세이프로 해당 식당 전체 제외)
- **어디에 끼울지는 여기서 정하지 않았음** — 적용 지점은 `03-knowledge` 몫임
- ⓑ의 `excluded_ingredient_codes` 칸은 전부 `[확인필요: 제외 식재료 코드 체계]`임.
  라벨은 알아보나 **코드로 바꾸지는 못함** → `allergen_codes_for()`가 항상 페일세이프로 감

| 4 | 원천 오류율 실측값 | 리포트의 `⑤에 적힌 값` 칸 6경로 | 데이터 담당(실측 필요 · ⑤ 14절) |
| 5 | 보존 기간(`S-1` · `S-4` · `S-5` · `S-7`) | 스냅샷 딸림 정보의 `retention_days` | 기획 담당 · 개인정보 보호책임자(⑤ 7절) |
| 6 | 원천 품질 문턱 | 문턱 검사 판정. ⑤에 원천 품질 문턱이 없음 | 지식니 → ⑤ 10절에 원천 문턱 행 추가 필요 |
| 7 | 음식 카드 마스터 구축 주체 · 건수 · 태그 분류 체계 | 사전 ⓐ 대표어 2행 · 시드의 카테고리 값 | 기획 담당(⑤ 14절) |
| 8 | 제외 식재료 코드 체계 · 8대 알레르겐 3 ~ 8번째 라벨 | 사전 ⓑ 코드 칸 전건 · 라벨 6행 | 기획 담당 · 데이터 확보 담당(⑤ 14절 · 골든셋 GS-21 ~ GS-24) |
| 9 | `T-11`의 `E-n` 행 미배정 | ⑤ 8절에 `T-11`(추천 캐시)을 덮는 오류율 행이 없음. 리포트의 `⑤에 적힌 값` 칸이 비어 있음 | 지식니 → **⑤ 8절에 행 1개 추가 필요** |

1 ~ 8번은 **값이 오면 설정만 채우면 되는 것**이고, 9번은 **설계서에 행을 더할 일**임.
성격이 달라 표에 함께 두되 마지막 칸에 갈라 적었음.

## 11. 확인하지 않은 것 (정직한 보고)

- **실제 저장소에 붙어 읽지 못했음.** 물리 표 · 열 이름이 정해지지 않았고 접속 정보도 없음.
  확인한 것은 여기까지임 — 조회문 관문이 바꾸는 문장을 막는 것, 접속 정보가 없을 때
  무엇이 없는지 알리며 멈추는 것, 읽기 전용으로 접속을 여는 줄이 코드에 있는 것
- 따라서 **원천 오류율 실측값은 0건임.** 리포트의 숫자는 전부 합성 시드를 센 값임
- `psycopg`로 실제 데이터베이스에 붙여 조회를 돌려 보지 못했음. API 이름과 인자는
  context7로 확인함(`psycopg.connect(row_factory=dict_row)` · `Connection.read_only`)
- 사전 ⓑ의 코드 매핑은 **한 건도 성공하지 못함** — 코드 체계가 없어 항상 페일세이프로 감.
  이것은 버그가 아니라 원천 공백이 그대로 드러난 것임
