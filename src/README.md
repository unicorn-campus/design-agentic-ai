# 런치픽(LunchPick) — 설계서 ①~⑦ 구현

`design/` 폴더의 설계서 7종을 코드로 옮기고 컨테이너로 묶어 로컬에서 돌린 결과임.  
정형·비정형 데이터는 전부 **합성**으로 만들었음(`synth/generate.py`).

## 1. 빠른 실행

```bash
cd src
docker compose --env-file .env up -d --build
docker compose --env-file .env --profile seed run --rm lp-synth
```

화면: <http://localhost:8081> · API: <http://localhost:8080>

예약 작업 2종(설계상 스케줄 기동이므로 1회 실행 후 종료됨):

```bash

```

```bash
docker compose --env-file .env --profile jobs run --rm lp-scheduled-bat
```

시험:

```bash
python -m pytest src/tests -v
```

> 반경 내 식당을 전부 걸러 냄. 화면 상단에서 요청 시각을 고를 수 있음.

## 2. 만든 것 — ⑦ 2절 배포 단위 표 대응

| 설계 | 컨테이너 | 포트 | 담은 것 |
|------|---------|------|--------|
| I-1 `lp-gateway` | `lp-gateway` | **8080 외부 노출** | 진입 검사·요청 상한·프록시. 유일한 외부 진입 지점 |
| I-2 `lp-recommend` | `lp-recommend` | 8080 내부만 | FIL(A-1) + AGT(A-2) + HIS. LangGraph `S-R1` ~ `S-R13` |
| I-3 `lp-member` | `lp-member` | 8080 내부만 | 회원·취향·식이제한·동의. K-5를 갖는 2개 이미지 중 하나 |
| I-5 `lp-scheduled` | `lp-scheduled-bat` / `-sync` | **없음** | A-3 배치(`S-B1`~`S-B8`) · 동기화 워커(`S-B9`~`S-B15`) |
| I-4 `lp-payment` | — | — | **범위 밖**(사용자 결정). ③ 7절이 PAY 3건을 `범위외`로 판정 |
| I-6 `lp-app` | `lp-front` | 8081 | 앱스토어 배포라 컨테이너 대상이 아님. 확인용 React 화면으로 대체 |

저장소는 ⑦ 5-1절 판정대로 **6개 전부 런타임 밖**(`lp-postgres`).

### 설계에서 그대로 옮긴 것

- **에이전트 3개** — A-1·A-3은 `모델 미사용(결정론적 실행)`, A-2만 `claude-sonnet-5`.
  LLM 호출은 요청 경로 `S-R10` **한 곳뿐**임(J-5·J-7).
- **A-2 호출 설정**(③ 4-2절 D-11) — `thinking={"type":"disabled"}` ·
  `output_config={"effort":"low"}` · `max_tokens=1024`. 사고를 생략하면 적응형
  사고가 켜지고 사고 토큰이 출력 단가로 과금되므로 명시적으로 끔.
- **하드필터가 LLM 앞** — `S-R8 → S-R9 → S-R10` 고정 간선. 게다가 C-1 커넥터
  **입력 규격에 알레르기 필드가 아예 없음**(⑤ 5절). 스키마에 칸이 없으니 값을
  넣을 경로가 없음 = ② TB-2에 값이 도달하지 않음.
- **2중 방어** — ④가 순서로 막고, C-1 커넥터가 `filter_applied` 입력 검사로 다시 막음.
- **상태 스키마 23종**(④ 7절), 병렬 구간(`S-R5` ∥ `S-R6`)은 서로 다른 필드에 씀.
- **비밀값** — 이미지에 굽지 않고 실행 시 환경변수로만 주입. 이미지가 쓰지 않는
  키는 주지 않음(예: BAT 프로파일에 LLM 키 없음 — A-3은 모델 미사용).
- **저장소 계정 분리** — 조회는 읽기 전용(`lp_ro`), 이력 쓰기는 `lp_rw`,
  관측은 **쓰기 전용**(`lp_obs`). 업무 계정은 관측 기록을 고치거나 지울 수 없음.
- **개인정보 접근 로그 분리 저장**(⑦ 5-3 문제 3) — `obs_access_log`에
  주체·시각·항목 종류만 남기고 **값은 남기지 않음**.

## 4. 설계와 실제가 어긋난 곳 — 되돌려야 할 값

### 4-1. `S-R10` 배정값이 실측과 4배 이상 어긋남 ⚠️ 가장 무거움

④ 9-1절은 단계별 실측값이 없어 총 예산 3,000ms를 **나눠 배정**하고
`[확인필요: 실측]`을 붙였음. 그 실측을 했고, 배정값이 맞지 않음.

| | ④ 배정값 | 실측(2026-08-06, 5회) |
|---|---|---|
| `S-R10` p95 | 900ms | **약 5,000ms** |
| `S-R10` 타임아웃 | 1,200ms | 최대 5,222ms |

측정 조건: `claude-sonnet-5` · thinking=disabled · effort=low · max_tokens=1024 ·
후보 12건 · 입력 819토큰 / 출력 약 230토큰.

**양쪽을 다 돌려 본 결과 — 두 목표를 동시에 만족할 수 없음:**

| 설정 | p95 | 폴백률 | 결과 |
|------|-----|--------|------|
| 배정값 1,200ms | 1,234ms | **100%** | ① G-1 통과. 그러나 근거 문장이 전부 거리·평점 기본 문구 → **① Q-2 설명가능성 사망** |
| 실측 반영 8,000ms | 6,343ms | 9% | ① Q-2 살아남. 그러나 **① G-1 `p95 3초` 위반** |

빠른 쪽은 **생성을 포기해서** 빠른 것임. 그래서 M-Q1 시험의 합격 조건을
`p95 ≤ 3초` **그리고** `폴백률 ≤ 50%` 둘 다로 두었고, 어느 설정에서도
통과하지 않음. 값을 임의로 낮춰 시험을 통과시키지 않았음.

- 값의 주인은 ④임(G-4). 코드는 **설계값을 기본으로 두고** 실측치를
  `SR10_MEASURED_MS`로 나란히 기록했으며, `LP_SR10_TIMEOUT_MS`로 덮으면
  기동 로그와 관측 기록(`sr10_overridden`)에 그 사실이 남음.
- **되물어야 할 것**: ① Q-1의 `3초`를 지킬 것인지(→ C-1을 동기 경로에서 빼거나
  스트리밍으로 부분 응답), 아니면 목표값을 실측에 맞춰 다시 세울 것인지.
  ①·④ 소유 판단이라 여기서 정하지 않았음.

### 4-2. `[확인필요: 식당 식재료·알레르겐 정보 원천]`이 그대로 살아 있음

③ 4-1절이 "**A-1 계약은 문서상 통과하고 구현에서 추천 0개로 무너짐**"이라
경고한 자리를 코드로 확인했음. 합성 데이터에 원천 결측을 12% 섞어 두었고,
B-2 페일세이프가 그 식당들을 전부 뺌(실측 제외 16건/93건). 원천이 **아예**
없으면 반경 내 전 식당이 빠져 `no_candidate`가 됨 — 단위 시험
`test_gs09_원천이_아예_없으면_추천_0개로_착지함`이 이 상태를 고정해 둠.

### 4-3. B-4가 후보 풀을 빠르게 말림

⑥ B-4(최근 3일 내 동일 식당 제외)는 `권고`이나 대체 처리가 "3건이 안 되면
B-7 착지"임. 반경 500m·회원 1명 기준으로 하루 몇 번만 추천을 받아도 풀이
말라 후보 0건으로 떨어짐(실측: 강남 영업중 116곳 중 B-4로 18곳 차단).
**설계대로 도는 것이며 버그가 아니나**, 반경·상한을 실사용 기준으로 다시
볼 값임. 시험은 실행 전 데이터를 재시드해 이 오염을 끊음.

### 4-4. 원문에 값이 없어 임시로 채운 것

전부 환경변수로 빼고 기본값을 밝혔음 — 지어낸 값이 코드에 굳지 않게 함.

| `[확인필요]` | 임시값 | 환경변수 |
|---|---|---|
| 개별 거절 반복 상한(L-1) | 3 | `LP_MAX_REJECT_ITER` |
| 전체 새로고침 상한(L-2) | 2 | `LP_MAX_REFRESH_ITER` |
| 확신 스코어 임계값(B-5) | 0.35 | `LP_CONFIDENCE_THRESHOLD` |
| 표시명 길이 상한(G-1) | 60 | `LP_DISPLAY_NAME_MAX_LEN` |
| 캐시 신선도 상한 | 86,400초 | `LP_CACHE_FRESHNESS_MAX_SEC` |
| 배치 실패 허용률 | 20% | `a3_daily_learning.FAILURE_RATE_THRESHOLD` |
| 직군 데이터 수집 경로 | 합성값(**근거 없음**) | `job_cluster_prior` 표 |

## 5. 구현하면서 실제로 고친 것

설계 문서의 문제가 아니라 **구현 과정에서 드러난 것**임.

| # | 무엇 | 어떻게 드러났나 |
|---|------|---------------|
| 1 | **L-2 라벨 목록 오탐** — `게`가 `든든하게`에, `밀`이 `비밀`에 걸려 멀쩡한 근거 문장이 기본 문구로 교체됨 | 실물 `claude-sonnet-5` 출력에서 관측. 낱말 경계 매처로 바꾸고 회귀 시험 9건 추가. 오탐은 성가신 정도가 아니라 **① Q-2를 깎음** |
| 2 | **L-1/L-2 루프가 요청 시각을 잃음** | 거절 한 번에 후보가 통째로 사라짐. 서버가 현재 시각으로 다시 계산해 영업 필터가 다르게 걸린 것. `at` 전달 추가 |
| 3 | **B-5 차단 후 3건을 안 채움** | 콜드스타트는 확신 스코어가 낮아 자주 걸리는데 2건만 나감 → ⑥ M-Q7 `후보 3개 채움` 위반. ⑥ B-5 대체 처리대로 모자란 만큼 채우게 고침 |
| 4 | **가드레일 규칙이 두 벌** | `S-B11`과 `S-R5`가 조용히 갈라질 수 있었음. `lp_common.guardrails` 한 벌로 합침 |
| 5 | **업무 계정이 감사 기록을 지울 수 있었음** | 시드 스크립트가 `obs_access_log`를 TRUNCATE하려다 막힘. S-6 `변조 방지`대로 `lp_rw`에서 권한 회수 |
| 6 | Vite `plugins: [react()]` 누락 | 빌드는 통과하고 런타임에 `React is not defined`로 빈 화면. Playwright 콘솔로 잡음 |
